# FEATURE 008 — ENERGY — энергосбережение и сон простаивающих туннелей

| Поле | Значение |
|------|----------|
| Тип | Продуктовая фича |
| Build-tag | `with_lx_idle_suspend` (только мобильные сборки) |
| Состояние | ✅ Проверено на устройстве |

## Назначение

В профиле с большим числом WireGuard/AmneziaWG-узлов каждый живой узел
удерживает собственный набор приёмных буферов. При десятке узлов это
десятки мегабайт, которые сборщик мусора вынужден постоянно просматривать —
телефон греется и тратит батарею, даже когда трафик идёт через один узел.

Фича усыпляет простаивающие узлы, освобождая их ресурсы, и будит по обращению.
Узлы, к которым ещё не обращались, по желанию не собираются вовсе, а число
одновременно собранных ограничивается потолком. Клиент может выключить узел
вручную: тот засыпает и не просыпается от обращений, пока его не включат.

## Контролируемые параметры

В корневом блоке `lx`, подблок `wg` (SPEC 098). Прежние `route.lx_idle_suspend`,
`route.lx_idle_suspend_reachable`, `route.lx_idle_teardown` — устаревшие алиасы на один релиз:
предупреждение на каждый ключ, разные значения в двух местах — ошибка старта.

| Ключ | Тип | Дефолт | Смысл |
|------|-----|--------|-------|
| `lx.wg.idle_suspend` | длительность | не задан = выключено | Простой, после которого усыпляется **недостижимый** узел |
| `lx.wg.idle_suspend_reachable` | длительность | не задан = не усыплять | Простой, после которого усыпляется **достижимый** узел (участник пула, выбранный, финальный). Должен быть не меньше `lx.wg.idle_suspend` |
| `lx.wg.idle_teardown` | длительность | не задан = значение `lx.wg.idle_suspend_reachable` | Сколько узел может **спать** до полного освобождения. Отсчитывается от засыпания, не от последнего обращения. Явный `0` выключает освобождение: узлы остаются усыплёнными, и пробуждение стоит одно рукопожатие вместо пересборки. Отсутствие ключа и явный `0` — разные состояния |
| `lx.wg.lazy_build` | bool | `false` | Старт без сборки устройств, сборка при первом обращении. Узлы с `listen_port` не затрагивает. Требует `lx.wg.idle_suspend` |
| `lx.wg.build_max` | целое ≥ 0 | `0` = без потолка | Не больше N собранных устройств одновременно. Без `lazy_build` действует с первой пересборки |
| `lx.wg.build_overflow` | `wait` · `build` | `wait` | Все N заняты живыми соединениями: ждать до дедлайна обращения (не дольше 15 с) или собрать сверх потолка с предупреждением |

### Ручной переключатель

gRPC `SetEndpointEnabled(tag, enabled)` (`with_lx_command`) выключает и включает
WG/AWG-узел. Выключение усыпляет узел (установленные соединения рвутся) и
отвергает обращения ошибкой `WireGuard endpoint is disabled`; включение будит
спящий узел сразу, а освобождённый или несобранный собирается следующим
обращением. Состояние не сохраняется: перезагрузка конфига включает все узлы.
Работает и без `with_lx_idle_suspend`. Контракт и коды ошибок —
[SPEC 106](../../TASKS/106-WG_ENDPOINT_TOGGLE/SPEC.md).

Смежный ключ в группах: `urltest.passive_check` — не будить узлы отдельными
проверками, если недавнее соединение уже подтвердило их живость
(см. [URLTEST_BALANCE](../007-URLTEST_BALANCE/FEATURE.md)).

### Сборка

| Ручка | Значение |
|-------|----------|
| `with_lx_idle_suspend` | Только мобильные сборки. Десктопная сборка, получившая конфиг с любым ключом `lx.wg` (кроме дефолтного `build_overflow: wait`), **останавливается с явной ошибкой** — вместо тихого игнорирования |

Причина разделения: выигрыш определяется размером приёмных буферов,
а на десктопе они малы — фича там почти ничего не сэкономила бы,
и молчаливое отсутствие эффекта хуже явного отказа.

## Входы

- **Конфиг** (пороги выше).
- **Активность узлов** — обращения к ним и время последнего трафика.
- **Ручной переключатель** узла (`SetEndpointEnabled`).
- **Достижимость узла** из активного дерева маршрутизации.

## Выходы

- **Освобождённые ресурсы** спящих узлов.
- **Задержка первого обращения** к спящему или ещё не собранному узлу.
- **Состояние узла** в наблюдаемости (`GetOutbounds`): `never_built` /
  `building` / `up` / `asleep` / `torn_down` / `down` / `disabled` (выключен
  вручную, поверх любого уровня сна) и время с последнего обращения.

## Data flow

Три уровня, по нарастанию экономии и цены пробуждения:

```
узел активен
     │ простой дольше порога (своего для достижимых и недостижимых)
     ▼
узел спит — приёмные буферы освобождены
     │ обращение → пробуждение (цена ≈ один сетевой обмен)
     │
     │ сон дольше lx.wg.idle_teardown
     ▼
узел освобождён полностью — остался только конфиг
       обращение → полное восстановление (заметно дороже)
```

Замер на устройстве: приёмные обработчики 16 → 0, потребление памяти −31 %.

Ленивая сборка (`lx.wg.lazy_build`) начинает узел сразу с нижней ступени:
```
старт → узел не собран (never_built)
     │ первое обращение → сборка (building) → узел активен
```

Потолок (`lx.wg.build_max`) проверяется на каждой сборке:
```
нужна сборка, собрано N из N
     │ есть кандидат (нет живых соединений) → он освобождается, место занято
     │   порядок: сверх потолка → меньше ручных ссылок (селектор, final,
     │   правило) → меньше авто-ссылок (urltest, detour, цепочка,
     │   DNS-detour) → давнее последнее обращение
     │ кандидата нет → wait: ждать освобождения до дедлайна обращения
     │               → build: собрать сверх потолка с предупреждением
```

## Правила и гарантии

- **Засыпанию подлежат все WG/AWG-узлы профиля** независимо от способа
  объявления в конфиге.
- **Достижимые узлы по умолчанию не усыпляются** — только при явно заданном
  втором пороге.
- **Пробуждение прозрачно для трафика**: обращение к спящему узлу не теряется,
  оно оплачивается задержкой.
- **Отсчёт освобождения идёт от засыпания**, а не от последнего обращения.
- **Выключенная фича не запускает ничего** — без порога периодический
  обход не начинается вовсе.
- **Потолок не рвёт живое**: узел с незавершённым обращением, установленным
  TCP-потоком или заметным трафиком с прошлой выборки не освобождается.
- **Выключенный узел не просыпается от обращений**, но может быть освобождён
  полностью по `lx.wg.idle_teardown` или стать жертвой потолка.
- **«Не собран» — состояние, а не ошибка**: приложение показывает «узел не
  поднят» и не пугает таймаутом.

## Границы

- **Только мобильные сборки** — см. выше.
- **Пробуждение не бесплатно.** Спящий узел стоит примерно одного сетевого
  обмена, полностью освобождённый — заметно дороже, потому что
  восстанавливается с нуля.
- **Фича не уменьшает расход активных узлов** — она убирает расход
  на неактивные.
- **Потолок удлиняет пробы.** Группа из K узлов при потолке N замеряется
  волнами по N сборок; хвост, не уложившийся в таймаут пробы, на этом круге
  помечается недоступным. Потолок ниже числа одновременно используемых узлов
  заставляет их разбирать друг друга при каждом переключении.
- **Нагрев не лечится уменьшением буферов.** Их размер связан с
  производительностью приёма: урезание вернёт другую, уже закрытую проблему
  со скоростью загрузки. Лечится числом живых узлов — см.
  [UPSTREAM_SYNC](../005-UPSTREAM_SYNC/FEATURE.md).

## Особенности сопровождения

- **Любой новый периодический механизм обязан уважать сон.** Регулярные
  отправки будят спящие узлы и обнуляют экономию — это касается в том числе
  таймированных приманок в [AWG](../003-AWG/FEATURE.md).
- **Взаимодействие с проверками живости.** Проверки узлов — тоже
  пробуждения; для них есть отдельный переключатель.
- **Меряй на устройстве.** Ни нагрев, ни расход батареи на десктопе
  не воспроизводятся.
- **Остановка ядра пересекается с пробуждениями** — см.
  [HOTFIXES](../004-HOTFIXES/FEATURE.md).
