# FEATURE 019 — Настраиваемый ClientHello uTLS

## Назначение

Клиент может задать конкретный TLS ClientHello для outbound вместо готового браузерного профиля. Это нужно для воспроизведения измеренных TLS-отпечатков на TCP-соединениях к VPN-ноде.

## Контролируемые параметры

В `tls.utls`: `enabled: true`, `fingerprint: "custom"`, `client_hello` — объект с упорядоченными `cipher_suites`, `compression_methods` и `extensions` в формате JSON ClientHelloSpec библиотеки uTLS. Неизвестное расширение можно задать как `{"name":"generic","id":65000,"data_base64":"AQID"}`; содержимое статично. Порядок элементов сохраняется. Сборка требует `with_utls` и `with_lx_utls_custom`.

## Входы и выходы

Вход — конфиг outbound и TCP-соединение. Выход — ClientHello с заданными шифрами и расширениями, затем обычное TLS-рукопожатие и поток трафика.

## Data flow

Конфиг проверяется при создании TLS-клиента. Для каждого соединения создаётся отдельный ClientHelloSpec, чтобы рукопожатия не разделяли изменяемые поля. Спецификация применяется до отправки ClientHello.

## Правила и гарантии

- `client_hello` допустим только вместе с `fingerprint: "custom"`.
- `fingerprint: "custom"` требует `client_hello`.
- Ошибки в структуре и неизвестные имена отклоняются при загрузке конфига.
- Отсутствие build-тега даёт явную ошибку.
- Существующие браузерные профили сохраняют прежнее поведение.

## Границы

Только клиентский TCP TLS. Серверный Xray/node-agent, QUIC/HTTP3 и TLS библиотеки запросов приложения к API не меняются. Сырые `generic`-байты не создают автоматически корректный динамический ECH/PSK; произвольный payload может оборвать рукопожатие. Совпадение JA3 не гарантирует совпадение JA4 или поведения HTTP.
