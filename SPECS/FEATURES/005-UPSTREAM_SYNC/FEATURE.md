# FEATURE 005 — UPSTREAM_SYNC — синхронизация с апстримом

| Поле | Значение |
|------|----------|
| Тип | Процессная фича (постоянная работа форка) |
| Апстрим | [SagerNet/sing-box](https://github.com/SagerNet/sing-box), ветка `testing` |
| Наша ветка | `lx-1.14` (релизная), `lx` — ff-follower |
| Состояние | Живой watchlist |

Форк живёт поверх чужой базы, и база движется. Эта фича — про то, чтобы
движение апстрима не ломало нас тихо.

Наивная модель («мержим, разрешаем конфликты, поехали») ловит только один
класс проблем — текстовые конфликты. Опаснее второй класс: апстрим **сменил
логику под нашим патчем**, патч по-прежнему накладывается чисто, тесты зелёные,
а поведение уже не то, что задумывалось. Такое не находится мержем — только
явным watchlist'ом.

## Четыре исхода

Для каждой нашей дельты возможны четыре реакции на изменение апстрима:

| Исход | Что случилось | Что делаем |
|-------|---------------|------------|
| **DROP** | Апстрим починил то же самое | Удаляем наш патч |
| **REWORK** | Сменил логику под патчем — накладывается, но семантика другая | Переписываем под новую базу |
| **HOLD** | Не тронул | Держим как есть |
| **CONSTRAINT** | Его изменение накладывает ограничение на нас | Не код, а правило: «не делать X» |

`CONSTRAINT` — самый неочевидный и самый опасный: он не виден ни в диффе,
ни в тестах, и нарушается через полгода тем, кто не знает предыстории.

## Ритуал мержа

1. **Проверить дрейф** апстрима перед любым релизным тегом — и обычно
   смержить до сборки, а не после.
2. ⚠️ **`upstream/testing` force-push'ится.** Счётчик `git rev-list` врёт;
   честная дельта считается как diff от `<merge>^2`.
3. Пройти watchlist: по каждому триггеру проверить, не сменился ли исход.
4. Собрать, `gofmt -l` по lx-файлам, `lx-check` — и только затем тег.
5. Submodule `wireguard-go`: после `make lx-proto` он может остаться `-dirty`
   из-за `gofumpt` — вернуть `git checkout -- .` внутри submodule.

Подробный runbook — [docs-lx/lx-release-runbook.md](../../../docs-lx/lx-release-runbook.md).

## Особенности сопровождения

- **Наполнение реестра — от известного.** Watchlist собран из того, что уже
  зафиксировано в спеках. Полная инвентаризация дельты (314 файлов против
  `upstream/testing`) не проводилась — это отдельная работа масштаба
  аудита ([AUDITS](../010-AUDITS/FEATURE.md)).
- **Инвариант сильнее ревью.** Где можно, страж семантики — дешёвый тест
  (как в 013), а не «посмотреть глазами при мерже».
- **Полная миграция версии — не рядовой мерж.** Переход 1.13 → 1.14 стоил
  переграфта submodule; такие переходы планируются отдельно.
