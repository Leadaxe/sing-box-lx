# FEATURE 007 — URLTEST_BALANCE — балансировка нагрузки в urltest

| Поле | Значение |
|------|----------|
| Тип | Продуктовая фича |
| Build-tag | — (для выдачи состояния пула в UI нужен `with_lx_command`) |
| Состояние | ✅ Проверено на устройстве |

## Назначение

Штатная группа `urltest` отправляет весь трафик в один самый быстрый узел.
Эта фича добавляет режим распределения нагрузки по нескольким узлам —
со sticky: связанные соединения держатся на одном узле, чтобы распределение
не ломало сессии приложений, — и режим `failover`: держаться за рабочий
узел до его отказа, пробуя только его.

## Контролируемые параметры

Внутри блока outbound'а типа `urltest`.

### Режим

| `mode` | Выбор | Переключение | Что пробуется каждый `interval` |
|---|---|---|---|
| `least_test` (по умолчанию) | самый быстрый | как только кто-то быстрее на `tolerance` | все узлы |
| `round_robin` | пул живых | ротация по пулу | члены пула (лениво) |
| `failover` | самый быстрый на момент выбора | только при отказе или подтверждённой деградации текущего (больше 2× медленнее остальных); следующий — снова самый быстрый | только текущий узел |

### Балансировщик

Блок `balancer`, применим только при `mode: round_robin`; при другом
режиме его наличие — ошибка.

| Ключ | Тип | Дефолт | Смысл |
|------|-----|--------|-------|
| `pool` | целое ≥ 1 | 3 | Сколько узлов держать в пуле одновременно |
| `pool_tolerance` | целое 0…15000, мс | 0 | `0` — заполнять пул первыми живыми узлами; `> 0` — брать лучшие по задержке и вытеснять тех, кто хуже порога. Больше 15000 — ошибка старта: задержки живых узлов всё равно упираются в 15-секундный таймаут пробы |
| `sticky_hash` | список | `["process","domain"]` | Из чего складывается sticky-ключ |

**Компоненты `sticky_hash`:** `process`, `domain`, `source_ip`, `dest_ip`,
`dest_port`. Чтобы **выключить** sticky, задаётся `["none"]`.

⚠️ Пустой список `[]` для выключения **не подходит** — он неотличим
от опущенного ключа и означает дефолт.

Плюс штатные ключи `urltest`: `outbounds`, `url`, `interval`, `tolerance`,
`idle_timeout`, `interrupt_exist_connections`.

## Входы

- **Конфиг** группы: список узлов и параметры выше.
- **Соединения от приложений** с их атрибутами: процесс-инициатор, домен
  запроса, адрес источника и назначения.
- **Результаты проверок живости** узлов.
- **Исход боевых соединений** `round_robin`: явный отказ с кодом, отказ
  открытия, закрытие без единого байта, первый байт, ожидание дольше 5 и 15 с,
  уход клиента.
- **Сигналы платформы**: пробуждение устройства, смена сети, расхождение
  настенных и монотонных часов больше 10 с.

## Выходы

- **Выбор узла** для каждого соединения.
- **Состояние пула** — занятые слоты и их узлы, у `round_robin` ещё карантин
  и счётчики слотов, число сдвинутых и помеченных ключей и заморозка;
  доступно клиенту через [OBSERVABILITY](../006-OBSERVABILITY/FEATURE.md)
  (`GetPool`, `sing-box api group pool`).
- **Узел соединения** в списке соединений — тот, через который соединение
  реально пошло, в том числе после повтора.

## Data flow

```
соединение → сбор атрибутов (процесс, домен, адреса)
           → sticky-ключ из компонентов sticky_hash
           → хеш ключа (+ сдвиг ключа) → номер слота в пуле
           → узел, занимающий этот слот
                    │
      узел слота мёртв или в карантине → живой слот пула (сам слот не меняется)
      слот под подозрением → другой слот, пока есть слот без подозрения
                    │
           открытие → первый байт → успех
                    │
      не открылось → один повтор через другой слот
                   → быстрый отказ: проба жизни узла (промолчала → обход и проверка)
      явный отказ узла или сайта → повтор + ключ сразу на следующий слот
      закрылось без байта / сайт молчит > 15 с → признак ключа на узле;
                   второй признак при ответе узла другим между ними → сдвиг ключа
      ожидание > 5 с → подозрение на слот + проба жизни (промолчала → проверка)
                    │
      проверка пула (после паузы раундов): пробы всех узлов пула,
        никто за 5 с — кандидаты вне пула пачками; первый ответ — контроль
        узел молчит на решающей пробе, контроль ответил до и после →
             узел вычеркнут: history стёрта, его открытия — в повтор,
             соединения без первого байта закрыты, слот пуст до замены;
             вычеркнут второй раз за интервал прогона → карантин до прогона
        контроль не ответил → вердикта нет, ничего не трогается
        замена в слот — только кандидат, ответивший на свою пробу
        ключ, сдвинутый столько раз, сколько слотов, → «проблема в адресе»
      пустой слот на выборе → поиск замены среди кандидатов, пул не трогается
      раунд без ответа при опрошенных всех кандидатах → пауза 15 → 30 → 60 → 120 с;
        ответ любой пробы или сигнал платформы → снова 15 с

подтверждённые отказы узла ≥ 5 % и > 2× медианы пула → карантин до прогона

сигнал платформы (пробуждение, смена сети, часы > 10 с) → заморозка 15 с:
        работает только повтор через другой слот; выводов и записей нет

дотест: слот пуст или узел мёртв → занять слот ответившим кандидатом;
        ленивый — до pool + max(⌈pool/2⌉, 1) живых: запас в слот не встаёт,
        но первым берётся на замену; карантинные узлы пробуются всегда;
        снять пометки «проблема в адресе» и карантин
```

Пул — набор слотов фиксированного размера. Узлы меняются **внутри слота**,
сами слоты не переставляются: одинаковый ключ всегда приходит в один
и тот же слот (сдвинутый ключ — в слот со своим сдвигом). Проверка живости
узла делается лениво — по обращению, а не по расписанию для всего списка;
между плановыми проверками `round_robin` узнаёт о смерти узла по отказам
боевых соединений.

## Правила и гарантии

- **Sticky-ключ считается от домена исходного запроса**, а не от адреса,
  в который он разрешился. Повторный DNS-резолв и смена IP узла
  sticky не срывают.
- **Одинаковый ключ → тот же слот.** Привязка ключа к слоту считается из
  хеша, поэтому переподключения и перезапуски не размывают распределение.
  Единственное исключение — сдвиг ключа, через узел которого недоступен сайт
  (правило ниже); сдвиги живут в памяти до рестарта.
- **Замена мёртвого узла не трогает соседние слоты** — остальные
  потоки остаются на своих узлах. Исключение — `pool_tolerance > 0`: прогон
  может сменить живой узел слота на более быстрый (больше порога), в этом
  смысл режима; ключи слота переходят к новому узлу.
- **Мёртвый узел не получает новых соединений, пока в пуле есть живые.**
  Слот узла, не ответившего на последнюю пробу или вычеркнутого, — пустой
  слот до замены; число слотов не меняется, и выбор пустой слот обходит: со sticky — ключи мёртвых слотов расходятся по
  живым слотам поровну, каждый ключ всегда на один и тот же, и возвращаются,
  как только слот снова занят; ключи живых слотов не двигаются. Без sticky
  ротация идёт по живым слотам поровну. Мертвы все — выбор как прежде. Обход
  начинается с провала плановой пробы или раньше — с вердикта проверки пула.
- **Зависший узел обходится до вердикта.** Соединение или открытие, ждущее
  дольше 5 с, ставит подозрение на слот и запускает пробу жизни узла; выбор
  обходит такой слот, пока в пуле есть слот без подозрения. Проба промолчала —
  группа запускает проверку пула, и узел вычёркивается примерно за 41 с от
  начала простоя; узел, отказывающий в подключении, — меньше чем за секунду. Подозрение — не вывод: history, сдвиги и счётчики оно не
  трогает и снимается само.
- **Мягкие признаки сами ничего не доказывают.** Молчание, обрыв без кода,
  отказ узла и уход клиента дают только безвредное: повтор через другой слот,
  пробу и счёт. Не открывшееся соединение один раз повторяется через другой
  слот — приложение не теряет соединение. Уход клиента не даёт ничего. Ответ
  SOCKS «general failure» — отказ узла, не сайта: сайт он не переносит.
  В цепочке вложенных групп `round_robin` соединение повторяет только
  внешняя группа.
- **Вывод делается тремя путями.** Статистика против медианы пула — карантин.
  Собственная проба узла против контроля — вычёркивание: узел промолчал на
  решающей пробе, а контрольный узел ответил до и после; history стирается,
  его открытия в полёте уходят в повтор, соединения без первого байта
  закрываются, слот получает замену. Не ответил никто — вердикта нет, ничего
  не трогается. Второй отказ того же ключа на том же узле, когда узел между
  попытками отвечал другим, — сдвиг ключа на следующий слот; пришедший позже
  ответ сдвиг возвращает. Явный отказ с кодом (SOCKS, HTTP CONNECT; у
  `direct`, endpoint и MASQUE — отказ сайта в подключении) сдвигает ключ
  сразу и повторяет соединение. Ключ, сдвинутый столько раз, сколько слотов в
  пуле, без единого ответа помечается «проблема в адресе» и возвращается на
  свой слот.
- **«Сеть лежит» по пробам не выводится.** Обрыв сети без сигнала платформы
  заморозкой не становится: каждое соединение повторяется один раз и падает,
  проверки кончаются без вердикта, вычёркиваний, сдвигов и счёта нет.
- **Замена в слот — только кандидат, ответивший на свою пробу** в этой
  проверке: сначала кандидаты с живой history по задержке (среди них узлы
  запаса прогона), затем остальные от курсора. Живые узлы пула замена не
  трогает. Никто не ответил — слот остаётся пустым, выбор его пропускает.
- **Проверки дёшевы.** Один раунд (проверка пула или поиск замены) на
  группу, не раньше конца паузы после прошлого; сто одновременных отказов
  дают одну проверку. Пауза 15 с; если раунд никому не ответил, а все
  кандидаты с последнего ответа опрошены, она растёт 15 → 30 → 60 → 120 с.
  Ответ любой пробы группы или сигнал платформы возвращает её к 15 с;
  соединение, открытое во время длинной паузы, даёт один внеочередной раунд.
  Проба жизни — не чаще раза в 3 с на узел и не больше 4 за 15 с на группу,
  в длинной паузе её нет. На всё ядро в полёте не больше 16 проб
  самовосстановления; узел с одним URL пробы пробуется одной пробой для всех
  групп.
- **Заморозка только по сигналу платформы.** Пробуждение, смена сети или
  расхождение часов больше 10 с замораживают группу на 15 с: соединение, не
  открывшееся через узел, по-прежнему повторяется через другой слот, а выводы
  (вычёркивание, сдвиг, счёт, карантин) и запись состояния запрещены; идущая
  проверка обрывается без вердикта.
- **Карантин по сравнению с соседями.** Узел, который отвечает на пробу, но
  рвёт подтверждённо больше соединений, чем удвоенная медиана пула (от 8
  соединений, 3 засчитанных отказов и доли 5 %), выводится из ротации и
  заменяется до ближайшего планового или ручного прогона или сигнала смены сети. Его history не стирается.
  Узел, вычеркнутый дважды за интервал прогона («мигающий»), уходит в такой
  же карантин. Прогон карантинные узлы пробует всегда.
- **Тест соединения и замер задержки не меняют состояние** группы: тест
  делает повтор, но не пробует узлы и ничего не записывает; замер через
  группу идёт мимо самовосстановления.
- **Живость узла — общая для всех групп и ручных тестов.** Ручной тест
  задержки с коротким таймаутом, который не успел, или отказ соединения
  через тот же узел в группе `least_test` выводит узел из ротации
  `round_robin` до ближайшей проверки пула — не дольше `interval` плюс
  таймаут пробы.
- **`balancer` вне `round_robin` — ошибка конфига**, а не молчаливое
  игнорирование.
- **`pool_tolerance` выше 15000 мс — ошибка старта.** Задержки живых узлов
  всё равно упираются в 15-секундный таймаут пробы, поэтому больший порог
  бессмыслен и отвергается сразу, а не притворяется работающим.

### Режим `failover`

- **Выбор — самый быстрый узел**, без `tolerance` и без учёта порядка в
  списке; до первого результата проб — первый узел списка (холодный старт
  апстрима). TCP и UDP держатся раздельно.
- **Пока узел жив, выбор не меняется**, даже если другой стал быстрее;
  возврата на бывшего лучшего нет. Исключение — деградация (SPEC 126):
  узел больше 2× медленнее лучшего соседа той же сети, подтверждено второй
  пробой → полный прогон → переезд, если кто-то больше 1,5× быстрее.
- **Каждый `interval` пробуется только удерживаемый узел.** Не ответил —
  тот же тик делает полный прогон и переносит выбор на самого быстрого
  живого. Отказ боевого дайла «путь мёртв» переносит выбор через штрафы
  (раздел ниже).
- **Ручной тест меряет всех и перевыбирает самого быстрого** — единственный
  штатный способ вернуться на лучший узел, пока текущий жив.
- **`balancer` с `failover` — ошибка старта; `tolerance` не действует** и
  даёт предупреждение.

### Реакция на отказы боевых соединений (`least_test`, `failover`)

Прежде группа реагировала только на результаты проб: выбор оставался прибит
к мёртвому узлу до хвоста следующего прогона — то есть до `interval`.
Пользователь всё это время ловил отказы.

- **Штрафуется только отказ вида «путь мёртв»** — истёкшее время ожидания,
  недостижимость сети или хоста, а у прокси-узла ещё отказ в подключении и
  сброс при открытии: там отвечает его собственный сервер. У `direct` и
  endpoint (WireGuard, AWG, Tailscale) отказ и сброс — ответ сайта, штрафа
  нет; отмена самим клиентом штрафа не даёт.
- **После штрафа делается ровно одна запасная попытка** через лучшего
  кандидата, и не более двух попыток на запрос. Успех переносит выбор
  группы на запасной узел, **не разрывая живые соединения**. Провал
  возвращает приложению исходную ошибку, но выбор уже сдвинут — его
  собственный повтор пойдёт по другому пути.
- **Штраф снимается только доказательством жизни** — успешным боевым
  соединением или ответом на пробу. Ни по таймеру, ни по давности штрафы
  не истекают: «давно не падал» не значит «жив».
- **Когда лучший по скорости узел набирает штрафы, ранжирование становится
  двухуровневым** — сначала меньше штрафов, затем меньше задержка.
  Победители по штрафам соревнуются по скорости, то есть это тот же
  `least_test`, просто без штрафников. Выход из режима естественный:
  узел ответил → штраф снят → критерием снова становится скорость.
- **Когда оштрафованы все кандидаты, прогон проб запускается немедленно**,
  не дожидаясь `interval` — ранжировать больше нечего. Повторно такой
  запуск возможен не чаще раза в две минуты, считая **от конца** прошлого
  прогона, чтобы длинный прогон по большой мёртвой группе не позволял
  следующему стартовать впритык.
- **`round_robin` штрафами не пользуется** — у него своё
  самовосстановление по отказам (раздел выше).

## Границы

- **Балансировка идёт по слотам, а не по нагрузке.** Число активных
  соединений или занятая полоса при выборе не учитываются — это
  сознательный отказ ради минимального состояния: группа помнит только
  сдвиги ключей, счётчики отказов слотов и карантин.
- **Самовосстановление видит только соединения через группу.** Потоки,
  которые роутер ведёт мимо выбора группы, в нём не участвуют; закрытие без
  байта не повторяется — запрос повторяет приложение. UDP получает повтор и
  пробу жизни, но не сдвигает ключи и не идёт в счёт.
- **Смена сети без сигнала платформы** (в том числе Modern Standby на
  Windows), уместившаяся между контролем до и после, может один раз
  вычеркнуть живой узел для всех групп через общую history. Узел возвращается
  сам на ближайшей замене или прогоне; это принятое ограничение. На узлах,
  массово рвущих соединения без ответа, возможны редкие лишние сдвиги ключей;
  узел, который на половину проб отвечает дольше 15 с, вычёркивается. Полный список
  ограничений — в [SPEC 138](../../TASKS/138-URLTEST_RR_SKIP_DEAD_SLOT/SPEC.md#ограничения).
- **Гарантий равномерности на коротких интервалах нет**: распределение
  равномерно статистически, при малом числе потоков перекос нормален.
- **`failover` удешевляет проверки ценой точности** отображаемых
  задержек: у невыбранных узлов числа в UI — на момент последнего полного
  прогона.

## Особенности сопровождения

- **Равномерность меряется на устройстве.** На стенде распределение
  выглядело идеальным и скрывало дефект атрибуции домена, который проявлялся
  только на реальном трафике.
- **Семантику списочных ключей проверяй живым запуском.** Разбор конфига
  схлопывает пустой список в «ключ не задан» — юнит-тест на прямом разборе
  этого не показывает.
- **Профилировщик показывает не то, что видел код в момент выбора.**
  Значения нужно смотреть там, где решение принимается.
