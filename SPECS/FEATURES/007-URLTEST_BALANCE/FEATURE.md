# FEATURE 007 — URLTEST_BALANCE — балансировка нагрузки в urltest

| Поле | Значение |
|------|----------|
| Тип | Продуктовая фича |
| Build-tag | — (для выдачи состояния пула в UI нужен `with_lx_command`) |
| Состояние | ✅ Проверено на устройстве |

## Назначение

Штатная группа `urltest` отправляет весь трафик в один самый быстрый узел.
Эта фича добавляет режим распределения нагрузки по нескольким узлам —
с закреплением связанных соединений за одним узлом, чтобы распределение
не ломало сессии приложений.

## Контролируемые параметры

Внутри блока outbound'а типа `urltest`.

### Режим

| Ключ | Тип | Дефолт | Смысл |
|------|-----|--------|-------|
| `mode` | `least_test` · `round_robin` | `least_test` | `least_test` — штатное поведение (весь трафик в лучший узел); `round_robin` — распределение по пулу |

### Балансировщик

Блок `balancer`, применим только при `mode: round_robin`; при другом
режиме его наличие — ошибка.

| Ключ | Тип | Дефолт | Смысл |
|------|-----|--------|-------|
| `pool` | целое ≥ 1 | 3 | Сколько узлов держать в пуле одновременно |
| `pool_tolerance` | целое 0…15000, мс | 0 | `0` — заполнять пул первыми живыми узлами; `> 0` — брать лучшие по задержке и вытеснять тех, кто хуже порога. Больше 15000 — ошибка старта: задержки живых узлов всё равно упираются в 15-секундный таймаут пробы |
| `sticky_hash` | список | `["process","domain"]` | Из чего складывается ключ закрепления |

**Компоненты `sticky_hash`:** `process`, `domain`, `source_ip`, `dest_ip`,
`dest_port`. Чтобы **выключить** закрепление, задаётся `["none"]`.

⚠️ Пустой список `[]` для выключения **не подходит** — он неотличим
от опущенного ключа и означает дефолт.

### Проверка живости

| Ключ | Тип | Дефолт | Смысл |
|------|-----|--------|-------|
| `passive_check` | флаг | выкл | Считать недавнее успешное TCP-соединение через узел доказательством его живости и не тратить отдельную проверку |

Плюс штатные ключи `urltest`: `outbounds`, `url`, `interval`, `tolerance`,
`idle_timeout`, `interrupt_exist_connections`.

## Входы

- **Конфиг** группы: список узлов и параметры выше.
- **Соединения от приложений** с их атрибутами: процесс-инициатор, домен
  запроса, адрес источника и назначения.
- **Результаты проверок живости** узлов.

## Выходы

- **Выбор узла** для каждого соединения.
- **Состояние пула** — занятые слоты и их узлы, доступно клиенту
  через [OBSERVABILITY](../006-OBSERVABILITY/FEATURE.md).

## Data flow

```
соединение → сбор атрибутов (процесс, домен, адреса)
           → ключ закрепления из компонентов sticky_hash
           → хеш ключа → номер слота в пуле
           → узел, занимающий этот слот
                    │
      слот пуст или узел мёртв → занять слот живым узлом
```

Пул — набор слотов фиксированного размера. Узлы меняются **внутри слота**,
сами слоты не переставляются: одинаковый ключ всегда приходит в один
и тот же слот. Проверка живости узла делается лениво — по обращению,
а не по расписанию для всего списка.

## Правила и гарантии

- **Закрепление считается от домена исходного запроса**, а не от адреса,
  в который он разрешился. Повторный DNS-резолв и смена IP узла
  закрепление не срывают.
- **Одинаковый ключ → тот же слот, всегда.** Состояние между соединениями
  не хранится, поэтому переподключения и перезапуски не размывают
  распределение.
- **Замена мёртвого узла не трогает соседние слоты** — закрепление
  остальных потоков сохраняется.
- **`balancer` вне `round_robin` — ошибка конфига**, а не молчаливое
  игнорирование.
- **`pool_tolerance` выше 15000 мс — ошибка старта.** Задержки живых узлов
  всё равно упираются в 15-секундный таймаут пробы, поэтому больший порог
  бессмыслен и отвергается сразу, а не притворяется работающим.
- **`passive_check` не действует при `pool_tolerance > 0`** и сопровождается
  предупреждением: этот режим ранжирует все узлы по свежей задержке каждый
  цикл, а пассивное подтверждение живости замера не заменяет.

## Границы

- **Балансировка идёт по слотам, а не по нагрузке.** Число активных
  соединений или занятая полоса при выборе не учитываются — это
  сознательный отказ ради нулевого состояния.
- **Гарантий равномерности на коротких интервалах нет**: распределение
  равномерно статистически, при малом числе потоков перекос нормален.
- **`passive_check` удешевляет проверки ценой точности** отображаемых
  задержек — числа в UI становятся более старыми.

## Особенности сопровождения

- **Равномерность меряется на устройстве.** На стенде распределение
  выглядело идеальным и скрывало дефект атрибуции домена, который проявлялся
  только на реальном трафике.
- **Семантику списочных ключей проверяй живым запуском.** Разбор конфига
  схлопывает пустой список в «ключ не задан» — юнит-тест на прямом разборе
  этого не показывает.
- **Профилировщик показывает не то, что видел код в момент выбора.**
  Значения нужно смотреть там, где решение принимается.
