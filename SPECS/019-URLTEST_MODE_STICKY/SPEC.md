## Зачем v2

v1 (`round_robin` по всем живым) не масштабируется: на 1000 нод URL-тест пингует **все** ноды каждые `interval`, `live` нестабилен, jumphash по индексу `live` ломает прилипание при смене состава. v2 вводит **пул фиксированного размера**, **ленивый health-check** (тестируем не больше нужного) и **sticky по фиксированным слотам** (`hash(key) % pool`, строгий ноль переездов для живого узла, без состояния).

## Конфиг

```json
{
  "type": "urltest",
  "tag": "balanced",
  "outbounds": ["vpn-1", "...", "vpn-1000"],

  "url": "https://www.gstatic.com/generate_204",
  "interval": "15m",
  "idle_timeout": "30m",
  "interrupt_exist_connections": false,

  "mode": "round_robin",

  "balancer": {
    "pool": 3,
    "pool_tolerance": 0,
    "sticky_hash": ["process", "domain"]
  }
}
```

### Поля

**Корень urltest (апстрим-поля, код не меняем — но каждое влияет на round_robin, разъясняем):**

- **`url`** (дефолт `https://www.gstatic.com/generate_204`) — URL health-check'а. Каждая проба = реальный коннект через ноду к этому URL; ответ → нода жива + замер delay. В round_robin это **единственный** источник «жива/мертва» для наполнения пула (дайл-ошибки пул не трогают). Бить нужно в нейтральный URL (gstatic), а не в сайт назначения — иначе падение сайта пометит живую ноду мёртвой.

- **`interval`** (дефолт **3m**) — период тикера дотеста (`urltest.go:317`, `time.NewTicker(interval)`). В round_robin это период, с которым пересматривается состав пула. Один дефолт для всех режимов; рекомендованные **15m** для round_robin — только в доку (на 1000 нод частый дотест избыточен). Апстрим требует `interval ≤ idle_timeout` (`urltest.go:221`), иначе ошибка старта.

- **`tolerance`** (дефолт **50**, мс) — апстрим-**гистерезис** выбора лучшего (`urltest.go:364`: меняем выбор, только если новый быстрее текущего на `> tolerance` — защита least_test от дёрганья на микроколебаниях delay). `0` в конфиге **затирается на 50** (`urltest.go:215`), поэтому как переключатель непригоден — для пула у нас своё поле `pool_tolerance`. В `round_robin` апстрим-`tolerance` **не участвует** (ротация/пул его не читают) → при `mode==round_robin` и заданном `tolerance` — **варн** «use balancer.pool_tolerance».

- **`idle_timeout`** (дефолт **30m**) — простой-таймаут (`urltest.go:392`). `Touch()` обновляет `lastActive` на каждом соединении; если трафика не было `> idle_timeout` — тикер дотеста **глушится** (`loopCheck` выходит), следующее соединение его поднимает. Смысл: не пинговать ноды, когда через группу никто не ходит. Для round_robin прозрачно: при простое пул не обновляется (балансировать некого), при первом коннекте дотест оживает.

- **`interrupt_exist_connections`** (дефолт **false**) — при смене выбранного узла (`performUpdateCheck` → `interruptGroup.Interrupt`, `urltest.go:425`) рвать ли уже установленные соединения. В round_robin «единого выбранного узла» нет (каждое соединение садится само), поэтому массового interrupt от смены пула не происходит — поле фактически влияет только на least_test-путь. Оставляем как есть.

**lx-корень:**

| поле | дефолт | примечание |
|---|---|---|
| `mode` | `least_test` | `least_test` (апстрим, без изменений) \| `round_robin`. Индикатор, что читать `balancer` |
| `balancer` | — | объект; при `round_robin` без него → дефолты; при `mode != round_robin` с ним → **ошибка** |
| `passive_check` | `false` | пассивное подтверждение живости вместо проб, см. раздел ниже |

**`balancer`:**

| поле | дефолт | примечание |
|---|---|---|
| `pool` | 3 | размер пула; `0`/опущено → дефолт 3 (omitempty не отличает 0 от «нет»); `< 0` → ошибка; фактический = `min(pool, len(outbounds))` |
| `pool_tolerance` | 0 | мс. `0` — держать `pool` живых, скорость не важна; `> 0` — отбирать лучших по delay, вытеснять при разнице `> pool_tolerance`. Сравнение вытеснения ведётся в uint32 (`delay+tolerance` в uint16 переполнялось при больших значениях и инвертировало гистерезис в агрессивный churn). ⚠️ Энергия (mobile): режим обязан мерить ВСЕХ кандидатов каждый `interval` — будит всех спящих вне пула (SPEC 020); на Android предпочитать `0` |
| `sticky_hash` | `["process","domain"]` | компоненты ключа липкости (slot-hash). См. ниже про дефолт |

**`sticky_hash`** — массив компонентов ключа: `process`, `domain`, `source_ip`, `dest_ip`, `dest_port`. Привязка одним механизмом **slot-hash** (`slot[hash(key) % pool]`, см. «Выбор узла»), выбора алгоритма нет — поэтому плоское поле, не объект.

**Дефолт и выключение (важно):**
- поле **не указано** или **`[]`** → дефолт **`["process","domain"]`** — липкость включена из коробки (на практике сессии почти всегда нужны);
- **`"sticky_hash": ["none"]`** → липкость **выключена** → чистый round_robin по counter;
- непустой массив компонентов → липкость по указанным компонентам;
- `"none"` вперемешку с реальными компонентами → ошибка (неоднозначно).

**Почему sentinel `"none"`, а не `[]`.** Конфиг проходит через `badjson.UnmarshallExcludedContext`, который **ре-маршалит** структуру (`json.MarshalContext` в `merge.go`) — пустой JSON-массив `[]` при этом схлопывается в `nil`, неотличимый от «поле отсутствует». Поэтому различить nil-vs-`[]` на проде НЕЛЬЗЯ (прямой `encoding/json` различал бы, но реальный декодер — нет; подтверждено живым прогоном). Явный sentinel `["none"]` переживает любой round-trip. Это был баг rc.13/14 (выключить липкость было невозможно), исправлен в rc.15.

## Модель пула: слоты + ноды

Два **независимых** представления — в этом разделении весь смысл v2:

| | что | порядок | для чего |
|---|---|---|---|
| **Слоты** | массив `[0 .. pool-1]`, `slot[i].tag` | **фиксированный** (`i` = const, не пересортировывается **никогда**) | привязка sticky (`hash(key) % pool` → номер слота) |
| **Ранг нод** | сортировка нод по delay | меняется | выявить **худшую** для вытеснения |

- Ноды **текут сквозь слоты**. Слоты физически не двигаются.
- Худшая нода (по delay-рангу) может сидеть в **любом** слоте, хоть в середине. Её номер слота на ранг не влияет.
- Замена идёт **в слоте худшей**: победитель занимает **тот же** слот. Слоты `≠ k` не тронуты.

> **Две сортировки — НЕ путать (это был корень бага v1):**
> - **по слотам** (`slot[0..pool-1]`, фиксированный порядок) — для slot-hash: `slot[hash(key) % pool]`. Этот порядок **никогда** не меняется.
> - **по delay** (последний результат теста ноды) — только чтобы найти, какую ноду вытеснять. Это **отдельное вычисление поверх**, не перестановка слотов.
>
> Реализация: НЕ хранить ноды одним списком, отсортированным по delay, и хешировать по его индексу — это и ломало v1. delay-ранг считается на лету при дотесте, slot-hash смотрит на фиксированный массив слотов.

## Старт (трафик идёт до первого теста)

Пул нужен сразу, тест ещё не готов:

- **история жива** (процесс не выгружался, `HistoryStorage` in-memory) → слоты = top-`pool` по истории;
- **холодный старт** (истории нет) → слоты = первые `pool` нод по порядку конфига.

Первый дотест перестраивает содержимое слотов по реальным результатам.

## Ручной тест группы (URLTest RPC / clash-api)

`URLTestGroup.URLTest(ctx)` (путь ручного теста группы) для round_robin идёт **force**: тестирует все ноды и перестраивает пул из свежих результатов (`rebuildPool`, replace-in-slot при `pool_tolerance==0`). Для least_test сохранена апстримная не-force семантика. Известное ограничение: если в момент ручного теста уже идёт ленивый тик (`checking.Swap`), ручной вызов молча возвращает пустой результат — без очереди/ретрая; клиент ретраит сам (окно = длительность lazy-проверки).

## `passive_check` — пассивное подтверждение живости (opt-in)

Идея: **успешный TCP-дайл через узел = доказательство двусторонней живости** — SYN/SYN-ACK прошёл всю цепочку (туннель, узел, до цели и обратно). Пока такое доказательство свежо (< `interval`), URL-probe узла не несёт новой информации о живости — только жжёт трафик/радио и (в связке SPEC 020) будит усыплённые эндпоинты.

Механика (`passive_check: true`):
- группа при каждом успешном TCP-дайле штампует `passiveOK[tag] = now` (только отметка времени, БЕЗ обёртки соединения — fast-path/splice не затронуты; UDP-дайл сигнала не даёт: `ListenPacket` не подтверждает доставку);
- **least_test**: периодический (не-force) цикл проб **пропускается целиком**, пока выбранный узел пассивно подтверждён (TCP-selected свеж; UDP-selected отсутствует или тот же узел). Выбор остаётся приколоченным к работающему узлу — меньше переключений; history стареет (delay в UI обновляется только при лапсе сигнала или ручном тесте — согласованная цена). Узел умер → дайлы перестают удаваться → сигнал лапсится за ≤ interval → пробы возобновляются, переизбор работает;
- **round_robin `pool_tolerance==0`**: пассивно подтверждённый слот считается живым **без пробы** (замер на нём не выполняется, delay в GetPool стареет); слоты без сигнала пробуются как раньше. При активной ротации по всем слотам пробы исчезают полностью;
- **`pool_tolerance > 0`**: не влияет (режим обязан мерить всех — при включении пишется warn);
- ручной тест (`force`) всегда полный.

Дефолт `false` — апстримное поведение бит-в-бит. На mobile с WG/AWG-узлами включать (см. ТЗ LxBox §272): активная группа перестаёт периодически будить весь список.

## Гейтинг проб по достижимости (связка SPEC 020)

Перед каждым цикла дотеста `loopCheck` спрашивает `adapter.ReachabilityReporter`: **недостижимая** из активного дерева группа (селектор ушёл) пропускает пробы — иначе каждый цикл будил бы усыплённых членов впустую до `idle_timeout`. С выключенным idle-suspend гейт не вмешивается (reporter отвечает true). Детали — SPEC 020 §«Гейтинг проб»; сводная матрица «кто кого будит/глушит», таймлайны и полная state-модель — SPEC 020 §«Полная модель работы»; пользовательский гайд по энергооптимизации — [docs-lx/lx-energy.ru.md](../../docs-lx/lx-energy.ru.md).

## Дотест по таймеру (`interval`)

### `pool_tolerance == 0` (держать `pool` живых)

```
need = pool − (живых нод в слотах)
if need == 0: стоп                      // все слоты живы, не тестируем

по нодам НЕ в слотах, в порядке конфига:
    тест ноды
    если живая (test > 0):
        занимает слот одной мёртвой ноды (1:1, в её слоте)
        need--
        if need == 0: стоп
ноды кончились, need > 0:
    мёртвые остаются в своих слотах (пул не пустеет)
```

Тест прекращается, как только пул укомплектован живыми — **не** идём по всем 1000.

### `pool_tolerance > 0` (отбирать лучших)

```
тест ВСЕХ нод (до конца)
для каждого слота:
    если есть нода НЕ в слотах быстрее текущего жильца на > pool_tolerance:
        жилец слота заменяется на лучшую (в ТОМ ЖЕ слоте)
слоты не двигаются; меняется только содержимое
```

## Замена (общее правило)

- мёртвую / вытесняемую **не убираем, пока не найден живой кандидат**;
- нашли → замена **1:1 в её слоте**;
- не нашли → жилец остаётся (даже мёртвый);
- слоты всегда заполнены: `min(pool, len(outbounds))`, **пул не пустеет**.
- **живой жилец НИКОГДА не меняет индекс слота.** Меняется только содержимое вытесненного слота. Перепаковка/сдвиг живых нод (compact, re-rank) запрещены — они бы переместили все sticky-ключи, висящие на сдвинутом слоте. Дотест строит новую раскладку как `copy(current)` фикс. длины, переписывая **только** мёртвые/пустые слоты по индексу.

Следствие: если все ноды мертвы — слоты держат последних известных (мёртвых), round_robin крутит по ним, дайлы фейлят; сеть вернулась → следующий дотест найдёт их живыми, восстановление само.

## Ошибка дайла

Слоты/пул **не трогаем**. По одной ошибке дайла причина неизвестна (мёртвая нода / упавший сайт назначения / своя сеть пропала — неразличимы). Состав пула меняет **только дотест** (честный health-check через `url`). Соединение просто фейлится для этого запроса.

## Выбор узла — только на НОВОЕ соединение

`DialContext` (TCP) / `ListenPacket` (UDP). Существующие соединения привязаны к своему узлу, не трогаются. UDP/QUIC-сессия целиком на одном узле.

### round_robin без sticky
`counter` — отдельный `atomic uint64`, инкремент на каждое новое соединение:
```
node = slot[(counter++ % pool)].tag     // редукция по модулю В uint64, ДО сужения в int
```
Переполнение `uint64` оборачивается на 0 — раз в 2^64, разрыв ротации в точке оборота ничтожен, не обрабатываем. Порядок операций важен: сужение `int(counter)` ДО модуля на 32-битных платформах (armeabi-v7a AAR) после 2^31 соединений давало отрицательный индекс → panic; редукция выполняется в uint64.

### Узел слота не поддерживает network соединения
`pick` резолвит тег слота с фильтром по network; TCP-only узел в слоте для UDP-соединения даёт nil → соединение уходит на **fallback** (`Select(network)` — лучший по истории), минуя пул и липкость. Соседние слоты НЕ перебираются (это сдвинуло бы sticky-раскладку). Планирование пула network-blind (HTTP-проба — TCP). Для WG/AWG-узлов (TCP+UDP) не проявляется; смешивать TCP-only и UDP-трафик в одной round_robin-группе — не рекомендуется.

### sticky slot-hash (единственный механизм, без состояния)
```
node = slot[ hash64(key) % pool ].tag
```
- `pool` (число слотов) **фиксировано** → `hash64(key) % pool` для одного ключа даёт **стабильный** номер слота всегда. Простой модуль достаточен именно потому, что pool не меняется — плавный ресайз (jump-hash/rendezvous) не нужен;
- привязка к **номеру слота**, не к позиции/тегу узла → вылет ноды из середины **не сдвигает** другие слоты;
- **строгий ноль реконнектов для живого узла:** пока узел сидит в своём слоте, новые соединения с его ключами садятся на тот же узел → переключений/реконнектов по этим ключам нет, что бы ни менялось в других слотах. Реконнект случается **только** для ключей слота, чей жилец сменился (умер/вытеснен) — остальные слоты не тронуты;
- **0 памяти** — таблицы нет, чистить нечего (выпавший тег просто перестаёт выбираться при пересчёте);
- `hash64` = FNV-64a (есть в `hash/fnv`, уже использован в rc.11); ключ строится как в v1 (см. ниже).

`ttl_map` (таблица `key→tag` из rc.11) **удалён**: slot-hash даёт ту же гарантию (строгий ноль для живого) без памяти и без чистки протухших тегов. Он был бы нужен только для **недетерминированного** repick (least_connection / random), а тех режимов нет (см. «не в scope»).

## Ключ липкости (как в v1)

- ключ = конкатенация компонентов `sticky_hash[]` в порядке массива, разделитель `\x00`;
- источники в момент дайла: `process` ← `adapter.ContextFrom(ctx).ProcessInfo` (AndroidPackageNames[0] / ProcessPath), `domain` ← `destination.Fqdn`, `source_ip` ← `Source.Addr`, `dest_ip` ← `destination.Addr`, `dest_port` ← `destination.Port`;
- пустой компонент → `""`; все пусты → ключ `""` → один фиксированный слот (без ротации).

## `Now()`

- `round_robin` → `lastSelected` (последний фактически выбранный тег). UI-индикатор «через что идём сейчас». Пул целиком — отдельным `GetPool` (ниже).
- `least_test` → как rc.12 (selectedOutbound* + cold-start fallback на `Select()`).
- `URLTestOutbound("balanced")` (SPEC 014) дайлит **через группу** → round_robin выбирает ноду пула → меряется реальный путь; история пишется под `RealTag = Now() = lastSelected`. Корректно (delay фактического маршрута), но «прыгает» с ротацией — это by design.

## Экспозиция пула на клиент — `GetPool` (RPC, SPEC 014/015-территория)

`Now()`/`All()` недостаточны: `All()` отдаёт **все** ноды конфига (1000), `Now()` — одну. Состав пула (какие N нод в слотах сейчас) клиент так не узнает. Новый unary RPC:

```
GetPool(group_tag) → repeated PoolSlot
PoolSlot {
  slot  uint32   // номер слота 0..pool-1 (фиксированный)
  tag   string   // нода в слоте сейчас
  delay uint32   // последний delay, мс. 0 = не измерена/мёртвая (живая всегда ≥1)
}
```

- **unary snapshot** (не стрим): клиент тянет при раскрытии деталей группы. Пул меняется раз в `interval` — стрим избыточен, добавим позже если нужен «живой» пул.
- **`delay` кламп `0→1` на чтении** (наш код GetPool, апстрим-запись не трогаем): апстримный `urltest.URLTest` пишет `t = uint16(since/ms)`, что даёт `0` для sub-ms ноды и **не** клампит (проверено — клампа нет). Поэтому в `GetPool`: история есть → `max(1, history.Delay)`; истории нет → `0`. Так `delay==0` в выдаче **однозначно** = «не измерена/мёртвая», `alive`-флаг не нужен.
- **не-round_robin группа** (selector / least_test / urltest без `balancer`) → **пустой список** (не ошибка: «у этой группы пула нет»).
- источник: `slot[i].tag` из балансировщика + `history.LoadURLTestHistory(tag)` для delay (то же чтение, что и для живости — бесплатно).

Реализация: метод `Pool() []PoolSlot` на `*URLTest` (за `balancer`; nil-balancer → пусто) → RPC `GetPool` в daemon → libbox `CommandClient.GetPool(tag)`. Зеркалит SPEC 014 `URLTestOutbound`/`GetGroups` (proto regen, error-model Variant B, behind `with_lx_command`).

## Валидация (fail-fast при старте)

- `balancer` задан и `mode != round_robin` → ошибка;
- `pool_tolerance > 15000` → ошибка (мс; живые delay капятся 15s TCP-таймаутом пробы — больший гистерезис означает «никогда не вытеснять», это режим `0`; заодно закрывает uint16-переполнение диапазона 50536..65535 на дальних подступах);
- `passive_check` + `pool_tolerance > 0` → **варн** (не ошибка): режим обязан мерить всех, пассивный сигнал не подменяет замер;
- `pool < 0` → ошибка; `pool == 0` или опущено → дефолт 3 (Go-int omitempty не отличает 0 от отсутствия);
- `mode == round_robin` без `balancer` → дефолты `{pool:3, pool_tolerance:0}`;
- элемент `sticky_hash ∉ {process, domain, source_ip, dest_ip, dest_port}` → ошибка;
- `sticky_hash` не указан или `[]` → дефолт `["process","domain"]`; `["none"]` → липкость выключена; `"none"` вперемешку с реальным компонентом → ошибка;
- апстрим `tolerance` задан и `mode == round_robin` → **варн** (не ошибка): «ignored in round_robin, use `balancer.pool_tolerance`».

## Совместимость

- **`least_test`** (дефолт) — не затронут, бит-в-бит апстрим.
- **`round_robin`** — поведение v1 «крутить по всем живым» **убрано**; теперь всегда ограничен пулом. **Breaking** для конфигов rc.11/12 с `mode: round_robin` (прод-конфигов нет — только тесты).
- `sticky` (объект `{mode,timeout,cap,hash}` в корне, rc.11) → плоское `balancer.sticky_hash` (массив). Старые `mode`/`timeout`/`cap` удалены вместе с двумя механизмами rc.11 (`jumphash` по индексу `live` и `ttl_map`) — оба заменены единственным `slot_jump_hash`. Дефолт сменился: было «нет sticky → нет липкости», стало «нет `sticky_hash` → липкость по `["process","domain"]`, `["none"]` выключает» (rc.15: выключение через sentinel `["none"]`, а не `[]` — см. п.1 журнала).

## Принятые решения (журнал)

1. `balancer`-объект; `mode` снаружи как индикатор. Липкость — плоское `balancer.sticky_hash []string` (не вложенный объект — механизм один, выбирать нечего). Дефолт (омит или `[]`)→`["process","domain"]` (липкость из коробки); выключение через sentinel **`["none"]`**. *(rc.15: изначально планировали `[]`→выкл через nil-vs-`[]`, но `badjson.UnmarshallExcludedContext` ре-маршалит структуру и схлопывает `[]`→nil — различить на проде нельзя, подтверждено живым прогоном. `["none"]` переживает round-trip.)*
2. `pool_tolerance` — **наше** поле; апстрим `tolerance` затирается на 50, для round_robin не используется (варн).
3. `pool < 0` → ошибка; `pool==0`/опущено → дефолт 3; `round_robin` без `balancer` → дефолты.
4. Дайл-ошибка слоты не трогает (причина неизвестна).
5. Пул не пустеет — замена только при наличии живого кандидата.
6. **Слоты фиксированы; ноды текут сквозь; delay-ранг — отдельное вычисление для выявления худшей, не перестановка слотов.**
7. **sticky slot-hash: `slot[hash(key) % pool]` (`pool` фиксирован) → строгий ноль реконнектов для живого узла, 0 памяти.** Единственный механизм. Заменяет ОБА механизма rc.11. Модуль достаточен, т.к. число слотов не меняется — преимущество jump-hash/rendezvous (плавный ресайз) здесь не нужно.
8. **`ttl_map` удалён.** Раньше считался «строгим нолём против 1/n у jumphash», но slot-hash при фиксированном `pool` даёт тот же строгий ноль реконнектов для живого узла — а ttl_map ещё и требует таблицу + чистку протухших тегов. ttl_map имел бы смысл только при **недетерминированном** repick (least_connection / random), которых нет.
9. **Отвергнутые алгоритмы:** v1-`jumphash` по индексу `live` (ломал многих при вылете из середины), HRW/rendezvous (2/n при смене состава: 1/n за выход + 1/n за вход новичка). slot-hash по фиксированным слотам строго лучше обоих, и при фиксированном pool даже jump-hash избыточен — хватает модуля.
10. **`least_connection` отвергнут совсем** (не отложен): round_robin статистически равномерен; least_connection — искусственная конструкция, требует per-node счётчиков с декрементом на закрытии (риск утечки) ради краевого случая неравной длины соединений. Выгода для прокси-трафика сомнительна, сложность реальна. С ним отпал и единственный кейс для ttl_map.
11. Один `interval` дефолт 3m; рекомендованные 15m — в доку.
12. `counter` — отдельный `atomic uint64`, только round_robin без sticky.
13. Выбор узла — только на новое соединение.
14. Конкурентность дотеста — апстримный лимит 10 (`batch.WithConcurrencyNum`), не меняем.
15. **`Now()` = lastSelected** (одна нода, UI-индикатор); состав пула — через отдельный `GetPool` RPC.
16. **`GetPool(tag)`** — unary RPC, `[]PoolSlot{slot, tag, delay}`. `delay` кламп `0→1` на чтении (живая всегда ≥1, `0`=мёртвая/не измерена → `alive`-флаг не нужен). Не-round_robin группа → пустой список. proto/libbox аддитивно (SPEC 014/015-стиль).
17. **(rc.15) slot-shift баг — найден девайс-трейсом, исправлен.** Реализация дотеста нарушала инвариант п.6/«Замена»: `balancePoolFirstLive` собирал новую раскладку фильтрующим `append` (мёртвый слот не оставлял placeholder → живые ноды за ним **сдвигались** влево), а `planTolerantPool` делал `delete(inPool, occupant)` (вытесненный живой узел **рециркулировал** в более поздний слот). Оба перемещали живые ноды между слотами → sticky-ключи съезжали. На устройстве это дало единичный выброс `DE→FI→DE` для одного ключа за окно трейса. Фикс: replace-in-slot везде (`next = copy(current)` фикс. длины, переписываются только мёртвые/пустые слоты по индексу); ручной `URLTest` при `pool_tolerance==0` идёт через `planFirstLivePool` (а не `planTolerantPool`, который ранжировал бы first-live пул по delay и тасовал живых). Регресс-тесты пиннят выживших к индексам.
18. **(2026-07-15) `passive_check`** — по предложению владельца: пробы не нужны, пока трафик сам подтверждает живость. Сигнал = успешный TCP-дайл через узел (двустороннее доказательство сильнее «оба счётчика движутся» — и без обёртки соединений, которая глушила бы ReadWaiter/splice, см. [lx-conn-trace-probe-and-env]). least_test пропускает цикл при живом выбранном; first-live-пул не пробует подтверждённые слоты. Валидация `pool_tolerance ≤ 15000` — fail-fast вместо тихого uint32-спасения (само uint32-сравнение оставлено как страховка).
19. **(2026-07-15, аудит SPEC 020-связки) края закрыты.** (a) 32-bit counter panic — редукция по модулю в uint64 до сужения; (b) uint16-переполнение `delay+tolerance` — сравнение в uint32; (c) `URLTestGroup.URLTest` для round_robin теперь force (ручной тест обязан тестировать всё — раньше шёл ленивым pool-путём, п. «Ручной тест»); (d) гонка Touch/Close — `started` читается/сбрасывается под `access` (дайл, гонящийся с Close, воскрешал тикер на остановленной группе); (e) первый auto-выбор legacy инвалидирует reach-кэш SPEC 020 (был lost-update); (f) auto-switch и pool rebuild зовут AWG-guard (SPEC 007 §3.3(c)); (g) live-путь `balancePoolFirstLive` получил прямые тесты (httptest-сервер: replace-in-slot, dead-keeps-slot, полный-пул-не-пробует-вне-пула).

## Тест-план

- **Старт:** история жива → слоты = top-`pool` по истории; холодный → первые `pool` по конфигу.
- **`pool_tolerance == 0`:** добор первыми живыми до `pool`, стоп; пул не пустеет; мёртвая держит слот, пока нет замены.
- **`pool_tolerance > 0`:** тест всех, вытеснение жильца слота при кандидате быстрее на `> pool_tolerance`; слот сохраняет номер.
- **Слоты фиксированы:** вылет ноды из середины не двигает другие слоты; победитель занимает слот вытесненного.
- **slot-hash:** один ключ → стабильный слот при неизменном `pool`; **живой узел в своём слоте держит ВСЕ свои ключи** при замене жильцов в других слотах (ноль реконнектов); замена в слоте `k` трогает только ключи `→ k`; ключ `""` → фиксированный слот.
- **Замена 1:1:** нет живых → мёртвая держит слот; `min(pool, nodes)`.
- **Дайл-ошибка** не меняет состав пула.
- **Валидация:** `pool<1`, `balancer`+wrong-mode, неизвестный `sticky_hash`-компонент → ошибки; `tolerance`+round_robin → варн.
- **Дефолт sticky_hash:** `nil` (поле опущено) → `["process","domain"]` (липкость есть); `[]` → липкости нет (round_robin по counter); различение nil-vs-`[]` после unmarshal.
- **`least_test` дефолт** — без изменений.
- **GetPool:** round_robin-группа → `[]PoolSlot` со слотами/тегами/delay; не-round_robin → пустой список; `delay` живой ноды ≥1 (кламп 0→1), мёртвой/неизмеренной = 0.
- **Live health-check (`balancePoolFirstLive`, httptest):** мёртвый жилец заменяется в СВОЁМ слоте первым живым кандидатом (сосед пиннится); нет живой замены → мёртвый держит слот; полный живой пул НЕ пробует ноды вне пула (энерго-инвариант lazy).
- **`passive_check`:** пассивно подтверждённый слот не пробуется и держит слот; сигнал не считается при выключенной опции и при возрасте > interval; least_test-цикл пропущен при живом выбранном и возобновляется после лапса; `pool_tolerance > 15000` отвергается на старте (граница 15000 принимается).
- **Края:** counter-редукция в uint64 (32-bit safe); uint32-сравнение tolerance; force ручного теста при balancer; Touch после Close — no-op.
- `go build ./...`, `-tags with_lx_command`, `go test -race ./protocol/group/`, `gofmt` чисто.
