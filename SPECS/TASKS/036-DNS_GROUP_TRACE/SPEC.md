## 1. Проблема

035 дала в потоке `SubscribeDNSQueries` фактически ответивший сервер — но
контекст группы при этом затирается: из события не видно, что запрос шёл
через группу, какие участники были опрошены и с каким исходом, была ли это
гонка. Для UI LxBox этого мало: диагностика «почему медленно/кто деградирует»
требует хронологии проб и состояния группы. Задача 035 закрыта и не
редактируется; её DoD «прото не менялось» эта задача **осознанно отменяет**
(есть конкретный запрос LxBox — §3.1(а1) выполнен, §4 SPEC 035 размораживается).

## 2. Слой 1 — трасса проб в событии потока

### Прото (аддитивно, поверх `DnsQueryEvent` 1–12)

```proto
message DnsQueryEvent {
  // …existing 1–12 unchanged…
  repeated string dnsGroupPath = 13;         // путь групп ИЗНУТРИ НАРУЖУ; пусто = мимо группы
  repeated DnsGroupAttempt attempts = 14;    // хронология проб этого запроса
  bool racer = 15;                           // этот запрос был гонщиком (race)
}
message DnsGroupAttempt {
  string server = 1;       // тег участника
  string serverType = 2;   // тип участника (udp/tls/…)
  string outcome = 3;      // answered | timeout | network_error | servfail
  uint32 rttMs = 4;        // длительность пробы, мс
}
```

`outcome` — строка с фиксированным словарём (в духе `source = 5`), не enum:
`answered` (валидный ответ, включая NXDOMAIN/пустой), `timeout` (дедлайн),
`network_error` (прочие ошибки обмена), `servfail`.

### Семантика (контракт для LxBox)

| Сценарий | `dnsGroupPath` | `attempts` | `racer` |
|----------|----------------|------------|---------|
| `failover` | путь групп | все опрошенные по порядку, включая сбойные ДО ответившего | false |
| `race`, гонщик | путь групп | снимок на момент выдачи ответа: победитель + успевшие сбойнуть; **опоздавшие живые ответы НЕ попадают** (на момент эмита их не существует — их место в state-RPC) | true |
| `race`, межгоночный | путь групп | одна запись — текущий победитель | false |
| исчерпание (`emitFailedQuery`) | путь групп | единственная сделанная last-resort-проба и её исход | false |
| кеш-попадание | пусто | пусто | false |

- Кеш-попадание: `dnsServer` = тег группы — правило 035 сохраняется
  (ответ отдан кешем группы, не участником).
- Вложенные группы: `dnsGroupPath` = `[внутренняя, внешняя]`; в `attempts`
  попадают только **листовые** пробы (участник-группа как проба не
  записывается — её историю рассказывают её собственные листья; иначе UI
  получает дубли времени с типом `group`).
- Поздние записи в холдер после эмита безвредно теряются — эмит читает
  снимок под мьютексом.

### Переработка холдера `common/dnstrack`

Холдер 035 (`EffectiveServer`) расширяется до трассы запроса:

- **`effective` — write-once**: первым пишет самая внутренняя группа →
  в событии лист, а не тег вложенной группы. (Багфикс: при «последняя запись
  побеждает» из 035 внешняя группа затирала лист тегом внутренней группы —
  закрепляется юнитом с вложенной группой.)
- **`group_path`** — prepend на входе каждой группы (внешняя входит первой →
  prepend даёт порядок изнутри наружу).
- **`attempts`** — append по мере разрешения проб (в т.ч. из фонового
  коллектора гонки — снимок эмита просто не увидит поздних).
- **`racer`** — ставит гонщик.
- **Аллокация только при активной подписке**: шов в клиенте вешает холдер
  через `dnstrack.WithQueryTraceIfTracking(ctx)` — без менеджера в ctx или
  без подписчиков возвращается тот же ctx; запрос без подписчиков платит,
  как раньше, проверку типа транспорта + один lookup.

## 3. Слой 2 — state-RPC группы (`GetDNSGroups`)

Размороженный §4 SPEC 035 (запрос LxBox есть). Аналог `GetPool` (SPEC 019).
Живёт за `with_lx_command` (§3.6: handler в `*_lx.go`, stub `Unimplemented`,
шов `.proto` в существующей `lx_command`-зоне).

```proto
rpc GetDNSGroups(google.protobuf.Empty) returns (DnsGroupList) {}

message DnsGroupMember {
  string tag = 1;
  string serverType = 2;
  bool up = 3;                     // false = в down_time
  int64 downRemainingMs = 4;       // сколько осталось до возврата в строй; 0 = up
  uint32 consecutiveFailures = 5;  // подряд, сбрасывается успехом
  uint32 lastRttMs = 6;            // последняя успешная проба; 0 = не мерялся
}
message DnsGroupState {
  string tag = 1;
  string mode = 2;                 // failover | race
  string winner = 3;               // race: текущий победитель; "" = гонки не было
  repeated string ranking = 4;     // race: порядок прихода последней гонки
  int64 raceAgeMs = 5;             // мс с последней гонки; -1 = гонки не было
  repeated DnsGroupMember members = 6;
}
message DnsGroupList { repeated DnsGroupState groups = 1; }
```

- Снимок по **всем** группам конфига разом (у них нет тегов-запросов, как
  у пула, — групп мало, а UI рисует все).
- Состояние в события НЕ тащится: рейтинг в момент эмита ещё не достроен.
- Ядро: пакет `group` расширяет учёт участника (`consecutiveFailures`,
  `lastRTT`) и отдаёт снимок методом-интерфейсом, который handler
  обнаруживает type-assertion'ом по транспортам менеджера (образец —
  `poolProvider` в GetPool).

## 4. Слой 3 — лог решений группы

Текстовый лог (не поток), уровни:

| Событие | Уровень |
|---------|---------|
| Участник помечен в остывание (причина + срок) | debug |
| Итог гонки: участники, победитель, порядок прихода | debug |
| Смена победителя (после гонки, если тег изменился) | debug |
| Полное исчерпание (все в down_time, last-resort) | **warn** |

## 5. Совместимость и границы

- Прото — **только добавление** полей; существующие номера/типы не трогаются.
  Регенерация `.pb.go` фиксируется в том же наборе коммитов
  (`make -f Makefile.lx lx-proto`, pinned toolchain).
- Двусторонняя совместимость: старый клиент игнорирует новые поля; новый
  клиент терпит пустые (правило «пустое поле = состояние, не поломка»).
- Клиентские обёртки libbox: gomobile-совместимые (итераторы, не срезы),
  по образцу `GetPool`/`DnsQuery.Outbound()`.

## 6. Критерии приёмки

- Юниты:
  - failover-цепочка со сбойным первым → `attempts` = [сбойный, ответивший];
  - гонщик со сбойным участником → `racer=true`, сбойный в трассе;
  - межгоночный запрос → одна запись-победитель;
  - вложенная группа → `effective` = лист, `dnsGroupPath` = [внутр., внешн.],
    attempts без записи типа `group`;
  - кеш-попадание → путь/трасса пусты, `dnsServer` = тег группы;
  - исчерпание → warn + трасса единственной last-resort-пробы;
  - `GetDNSGroups`: снимок после гонки (победитель/рейтинг/rtt), участник
    в down (`up=false`, `downRemainingMs>0`, счётчик), не-группы в списке
    отсутствуют; stub без тега → `Unimplemented`.
- Живой `box.New` с группой и медленным участником: снимок трассы гонщика
  **не** содержит опоздавший живой ответ.
- DoD 033 (build ± теги, vet, gofmt) + обе сборки §3.6 (с тегом/без).
