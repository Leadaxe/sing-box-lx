## 1. Проблема

Поток `SubscribeDNSQueries` атрибутирует запись тегом транспорта, с которым
вызван обмен, — для группы это тег группы. UI LxBox нужны: фактически
ответивший участник, хронология проб (кто опрошен, с каким исходом, был ли
веер, был ли режим выживания) и живое состояние группы (чистота, ошибки,
победы, текущая цель).

## 2. Механизм: трасса запроса в контексте

Без изменений против v2: мутабельный холдер в operation-ctx
(`common/dnstrack`), вешается клиентом только для типа `group` и только при
живой подписке; `effective` — write-once (лист при вложенности);
`group_path` — prepend (изнутри наружу); `attempts` — append по мере
разрешения проб; эмит читает снимок под мьютексом, поздние записи безвредно
теряются. Новое: флаги `fanned` (в запросе был веер) и `survival` (ответ
получен «наименее грязным» при полном отсутствии чистых).

## 3. Контракт потока

```proto
message DnsQueryEvent {
  // …1–12 без изменений…
  repeated string dnsGroupPath = 13;      // путь групп ИЗНУТРИ НАРУЖУ; пусто = мимо группы
  repeated DnsGroupAttempt attempts = 14; // хронология проб этого запроса
  bool fanned = 15;                       // в запросе был веер (спасение/выборы/parallel)
  bool survival = 16;                     // режим выживания: чистых не было,
                                          // одна попытка к наименее грязному
}
message DnsGroupAttempt {
  string server = 1;
  string serverType = 2;
  string outcome = 3;   // answered | timeout | network_error | servfail
  uint32 rttMs = 4;
}
```

### Семантика (контракт для LxBox)

| Сценарий | `dnsServer` | `attempts` | `fanned` | `survival` |
|----------|-------------|------------|----------|-----------|
| штатный одиночный (цель ответила) | цель | одна запись | false | false |
| сбой цели → веер спас | победитель веера | цель (сбой) + участники веера на момент ответа | true | false |
| выборы `fastest` / любой запрос `parallel` | победитель веера | участники веера на момент ответа | true | false |
| выживание (чистых нет) | ответивший наименее грязный | одна запись | false | true |
| полный сбой (`emitFailedQuery`) | **тег группы** | все сделанные пробы | по факту | по факту |
| кеш-попадание | **тег группы** | пусто | false | false |

- Опоздавшие живые ответы веера в `attempts` события не попадают (их не
  существовало на момент эмита); полная картина — в state-RPC.
- Заброшенные пробы веера (сбой при уже завершённом контексте запроса —
  ответ отдан и клиент отменил операцию, либо бюджет умер) — не исход:
  не попадают ни в здоровье, ни в трассу.
- Вложенные группы: только листовые пробы; `dnsGroupPath` изнутри наружу.
  Если веер затронул **несколько** вложенных групп (группы-сиблинги как
  участники), путь — множество затронутых групп в порядке входа; ветка
  фактического ответа определяется по `dnsServer` (write-once лист),
  а не по пути.

## 4. State-RPC `GetDNSGroups`

За `with_lx_command` (§3.6: handler + stub `Unimplemented`, шов в
существующей `lx_command`-зоне). Схема v3 (замена v2-полей — см. шапку):

```proto
rpc GetDNSGroups(google.protobuf.Empty) returns (DnsGroupList) {}

message DnsGroupMember {
  string tag = 1;
  string serverType = 2;
  bool clean = 3;              // ноль живых ошибок
  uint32 liveErrors = 4;       // счёт живых ошибок
  int64 lastErrorAgeMs = 5;    // возраст последней живой ошибки; -1 = нет
  uint32 liveWins = 6;         // счёт живых побед (fastest)
  bool current = 7;            // текущая цель группы
  uint32 lastRttMs = 8;        // последняя успешная проба; 0 = не мерялся
}
message DnsGroupState {
  string tag = 1;
  string mode = 2;             // stable | fastest | parallel
  string current = 3;          // текущая цель; "" = ещё не выбиралась / parallel
  repeated DnsGroupMember members = 6;
}
message DnsGroupList { repeated DnsGroupState groups = 1; }
```

Снимок по всем группам разом; UI по нему считает «когда очистится»
(возраст + известный ему `error_ttl` из конфига) и видит выживание
(все `clean=false`).

## 5. Лог решений

| Событие | Уровень |
|---------|---------|
| Запись ошибки участнику (причина) | debug |
| Веер (состав) и его победитель | debug |
| Смена текущей цели | **info** |
| Все сбойнули / вход в выживание | **warn** |

## 6. Критерии приёмки

- Юниты: каждая строка таблицы §3 (включая survival и негонщика-конкурента
  выборов); вложенная группа (лист + путь); write-once; кеш; полный сбой.
- `GetDNSGroups`: чистые/грязные счёты и возраст, победы, `current`,
  `clean`; stub без тега → `Unimplemented`.
- Живой `box.New` с медленным участником: опоздавший ответ не в снимке
  трассы события.
- Прото: только lx-зона; регенерация pinned-тулчейном; build ± теги.

## 7. Вне скоупа

Push-подписка на состояние групп; выдача `error_ttl`/`win_ttl` через RPC
(UI знает их из конфига).
