## 1. Проблема

Поток `SubscribeDNSQueries` (SPEC 018) атрибутирует запись тегом транспорта,
с которым был вызван обмен. Для группы это тег **группы** — и диагностика
«какой из серверов группы деградировал» из приложения невозможна.
FEATURE.md требует: в записи — тег и тип **фактически ответившего**
участника.

## 2. Архитектура

Точка записи атрибуции одна — `emitQueryEvent`/`emitFailedQuery`
в `dns/client_log.go` (lx-файл SPEC 018): `event.DNSServer = transport.Tag()`.

Механизм передачи «кто реально ответил» из группы наверх: **мутабельный
холдер в контексте запроса**.

- Пакет `common/dnstrack` получает пару функций: обогащение контекста
  холдером и чтение/запись фактического сервера (`WithEffectiveServer(ctx)`,
  `SetEffectiveServer(ctx, tag, type)`, `EffectiveServerFromContext(ctx)`).
- Холдер кладётся в ctx в `dns/client_log.go` рядом с существующей точкой
  входа обмена SPEC 018 (если существующие lx-швы в `dns/client.go`
  не дают такой точки — расширение существующего шва на 1 строку в той же
  маркированной зоне; НОВЫХ немаркированных касаний upstream не появляется).
- Группа при успехе пишет в холдер тег+тип ответившего участника
  (failover — ответивший; race — победитель гонки этого запроса,
  для межгоночных запросов — текущий победитель, он и отвечал).
- `emitQueryEvent`/`emitFailedQuery`: если холдер заполнен — `DNSServer`/
  `DNSServerType` берутся из него, иначе как раньше. Прото-схема
  НЕ меняется (те же поля, честнее значение) → регенерация pb не нужна,
  клиент LxBox совместим без изменений.
- Кеш-попадания (`SourceCached`/`SourceOptimistic`): обмена не было,
  холдер пуст → остаётся тег группы. Это корректно: ответ отдан кешем
  группы, а не участником.

## 3. Критерии приёмки

- Юнит: обмен через группу → событие несёт тег/тип участника;
  прямой обмен (не группа) → поведение прежнее; кеш-попадание →
  тег группы.
- Сбойная запись (`emitFailedQuery`) при полном исчерпании группы несёт
  тег группы (отвечавшего нет — валидное состояние по правилу
  «пустое/групповое поле = состояние»).
- DoD 033 + отсутствие изменений `.proto`/`.pb.go` (git diff пуст по ним).

## 4. Вне скоупа (отложено)

**RPC состояния группы** (победитель, рейтинг, down-список — аналог
`GetPool`) — отложен до конкретного запроса LxBox (§3.1(а1)): интеграция
группы в UI ещё не начата, а поток уже даёт диагностику по фактическим
серверам. При появлении запроса — отдельная задача по режиму §3.6.
