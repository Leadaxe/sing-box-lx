Задача — вся наблюдаемость DNS-группы: атрибуция фактического сервера,
трасса проб в потоке, state-RPC `GetDNSGroups`, лог решений. Первая
редакция ограничивалась атрибуцией и не трогала прото; смена архитектуры
и её причины — в [HISTORY.md](HISTORY.md).

## 1. Проблема

Поток `SubscribeDNSQueries` (SPEC 018) атрибутирует запись тегом транспорта,
с которым был вызван обмен. Для группы это тег **группы** — диагностика
«какой из серверов группы деградировал» из приложения невозможна. UI LxBox
нужны: фактически ответивший участник, хронология проб запроса (кто был
опрошен и с каким исходом, была ли гонка) и живое состояние группы.

## 2. Механизм: трасса запроса в контексте

Точка записи атрибуции одна — эмиты потока (`dns/client_log.go`, lx-файл
SPEC 018). Данные из группы наверх передаёт **мутабельный холдер-трасса
в контексте запроса** (`common/dnstrack`):

- Холдер кладётся в operation-ctx клиентом (3-строчный маркированный шов
  в `dns/client.go`) **только** для транспортов типа `group` и **только**
  при живой подписке (`WithQueryTraceIfTracking`) — запрос без подписчиков
  платит проверку типа + один lookup, аллокаций нет.
- **`effective` — write-once**: первым пишет самая внутренняя группа, поэтому
  при вложенности в событие попадает **лист**, а не тег внутренней группы.
- **`group_path`** — prepend на входе каждой группы (внешняя входит первой →
  итоговый порядок изнутри наружу без разворота на эмите).
- **`attempts`** — append по мере разрешения проб, в т.ч. из фонового
  коллектора гонки.
- **`racer`** — ставит запрос-гонщик.
- Эмит читает **снимок под мьютексом**; записи после эмита (доигрывающие
  гонщики) безвредно теряются — их место в state-RPC.

## 3. Контракт потока (прото — аддитивно поверх `DnsQueryEvent` 1–12)

```proto
message DnsQueryEvent {
  // …existing 1–12 unchanged…
  repeated string dnsGroupPath = 13;         // путь групп ИЗНУТРИ НАРУЖУ; пусто = мимо группы
  repeated DnsGroupAttempt attempts = 14;    // хронология проб этого запроса
  bool racer = 15;                           // этот запрос был гонщиком (race)
}
message DnsGroupAttempt {
  string server = 1;       // тег участника
  string serverType = 2;   // тип участника (udp/tls/…)
  string outcome = 3;      // answered | timeout | network_error | servfail
  uint32 rttMs = 4;        // длительность пробы, мс
}
```

`outcome` — строка с фиксированным словарём (в духе `source = 5`), не enum:
`answered` (валидный ответ, включая NXDOMAIN/пустой), `timeout` (дедлайн),
`network_error` (прочие ошибки обмена), `servfail`.

### Семантика (контракт для LxBox)

| Сценарий | `dnsServer` | `dnsGroupPath` | `attempts` | `racer` |
|----------|-------------|----------------|------------|---------|
| `failover` | ответивший участник | путь групп | все опрошенные по порядку, включая сбойные до ответившего | false |
| `race`, гонщик | победитель | путь групп | снимок на момент выдачи ответа: победитель + успевшие сбойнуть; **опоздавшие живые ответы НЕ попадают** | true |
| `race`, межгоночный | текущий победитель | путь групп | одна запись — победитель | false |
| исчерпание (`emitFailedQuery`) | **тег группы** (никто не ответил — это состояние) | путь групп | единственная last-resort-проба и её исход | false |
| кеш-попадание | **тег группы** (ответ отдан кешем группы) | пусто | пусто | false |

- Вложенные группы: `dnsGroupPath` = `[внутренняя, внешняя]`; в `attempts`
  только **листовые** пробы (участник-группа как проба не записывается —
  её историю рассказывают её собственные листья; иначе UI получает дубли
  времени с типом `group`).

## 4. State-RPC `GetDNSGroups`

Аналог `GetPool` (SPEC 019), за `with_lx_command` (§3.6: handler в `*_lx.go`,
stub `Unimplemented`, шов `.proto` в существующей `lx_command`-зоне).

```proto
rpc GetDNSGroups(google.protobuf.Empty) returns (DnsGroupList) {}

message DnsGroupMember {
  string tag = 1;
  string serverType = 2;
  bool up = 3;                     // false = в down_time
  int64 downRemainingMs = 4;       // сколько осталось до возврата в строй; 0 = up
  uint32 consecutiveFailures = 5;  // подряд, сбрасывается успехом
  uint32 lastRttMs = 6;            // последняя успешная проба; 0 = не мерялся
}
message DnsGroupState {
  string tag = 1;
  string mode = 2;                 // failover | race
  string winner = 3;               // race: текущий победитель; "" = гонки не было
  repeated string ranking = 4;     // race: порядок прихода последней гонки
  int64 raceAgeMs = 5;             // мс с последней гонки; -1 = гонки не было
  repeated DnsGroupMember members = 6;
}
message DnsGroupList { repeated DnsGroupState groups = 1; }
```

- Снимок по **всем** группам конфига разом (групп мало, UI рисует все).
- Состояние в события НЕ тащится: рейтинг в момент эмита ещё не достроен.
- Ядро: пакет `group` ведёт учёт участника (`consecutiveFailures`,
  `lastRTT`) и отдаёт снимок методом-интерфейсом, который handler
  обнаруживает type-assertion'ом (образец — `poolProvider` в GetPool).
- Клиент libbox: gomobile-обёртки (итераторы, не срезы) — `GetDNSGroups()`,
  у `DnsQuery` геттеры `GroupPath()`/`Attempts()`/`Racer`.

## 5. Лог решений группы

Текстовый лог (не поток): пометка участника в остывание (причина + срок),
итог гонки (порядок прихода, сбойные), смена победителя — debug; полное
исчерпание (все в down_time, last-resort) — **warn**.

## 6. Совместимость

- Прото — только добавление полей; существующие номера/типы не тронуты.
  Регенерация `.pb.go` — `make -f Makefile.lx lx-proto` (pinned toolchain).
- Двусторонняя совместимость: старый клиент игнорирует новые поля; новый
  терпит пустые (правило «пустое поле = состояние, не поломка»).

## 7. Критерии приёмки

- Юниты:
  - failover-цепочка со сбойным первым → `attempts` = [сбойный, ответивший];
  - гонщик со сбойным участником → `racer=true`, сбойный в трассе;
  - межгоночный запрос → одна запись-победитель;
  - вложенная группа → `effective` = лист, `dnsGroupPath` = [внутр., внешн.],
    attempts без записи типа `group`;
  - кеш-попадание → путь/трасса пусты, `dnsServer` = тег группы;
  - исчерпание → warn + трасса единственной last-resort-пробы;
  - `GetDNSGroups`: снимок после гонки, участник в down (`up=false`,
    `downRemainingMs>0`, счётчик), не-группы отсутствуют; stub без тега →
    `Unimplemented`.
- Живой `box.New` с группой и медленным участником: снимок трассы гонщика
  **не** содержит опоздавший живой ответ.
- DoD 033 (build ± теги, vet, gofmt) + обе сборки §3.6 (с тегом/без).

## 8. Вне скоупа

Полевой device-verify (runbook требует перед промоутом rc→final);
push-подписка на состояние групп (пока pull-RPC — UI опрашивает).
