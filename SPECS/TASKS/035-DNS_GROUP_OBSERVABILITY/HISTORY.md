# HISTORY 035

## v3 — стык с TTL-моделью группы (2026-07-26, ночь)

Группа переработана на TTL-модель (033 v2, см. её HISTORY): умерли режимы
`failover`/`race`, гонка по `interval`, состояние down. Следствия для
наблюдаемости: поле `racer` → `fanned` (веер теперь — спасение после сбоя,
выборы `fastest` или каждый запрос `parallel`); добавлен `survival = 16`
(без него деградация «отвечаем через наименее грязного» неотличима от
здоровья — находка адверсариальной панели); state-RPC перекроен —
`winner`/`ranking`/`raceAgeMs`/`downRemainingMs`/`consecutiveFailures`
заменены на `clean`/`liveErrors`/`lastErrorAgeMs`/`liveWins`/`current`.
Замена, а не добавление: v2-поля не были в релизном теге, потребителей нет.

## v1 — только атрибуция, прото не тронуто (2026-07-26, утро)

Первая редакция задачи ограничивалась атрибуцией фактически ответившего
сервера: холдер `EffectiveServer` в контексте (последняя запись побеждает),
эмиты подменяли `dnsServer`/`dnsServerType`, прото-схема сознательно
не менялась (DoD «git diff пуст по .proto/.pb.go»). State-RPC был отложен
в §4 «до конкретного запроса LxBox» (§3.1(а1)).

## v2 — трасса проб + state-RPC + лог (2026-07-26, вечер)

Запрос LxBox появился (интеграция группы в UI): диагностика «почему
медленно / кто деградирует» требует хронологии проб и живого состояния —
одной атрибуции мало. Отложенный §4 разморожен, DoD «прото не менялось»
осознанно отменён; заодно эта работа была начата как отдельная задача 036,
но зона ответственности та же (наблюдаемость группы), поэтому по §3.2
слита обратно в 035 — одна область = одна задача-владелец.

Архитектурные изменения против v1:

- Холдер `EffectiveServer` → `QueryTrace`: к effective добавились
  `group_path`, `attempts`, `racer`.
- **Write-once вместо «последняя запись побеждает»** — багфикс: при
  вложенных группах внешняя группа затирала лист тегом внутренней группы,
  атрибуция была неверной. Закреплено юнитом с вложенной группой.
- Аллокация холдера получила гейт по живой подписке (v1 аллоцировала
  на каждый group-запрос независимо от подписчиков).
- Прото расширено аддитивно (поля 13–15 + `DnsGroupAttempt` +
  `GetDNSGroups`); совместимость двусторонняя.
