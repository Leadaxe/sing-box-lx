# IMPLEMENTATION_REPORT 034 — режим `race`

## Файлы

Всё в lx-пакете, upstream не тронут: `dns/transport/group/race.go`,
`race_test.go`, правки `group.go` (ветвление по mode, гоночное состояние,
снята временная ошибка конструктора).

## Ключевые решения реализации

- `ExchangeRace` из `exchange_strategy.go` не подошёл (отменяет проигравших,
  рейтинг не построить) — свой фан-аут: горутина на участника с контекстом
  `context.WithoutCancel(ctx)` + таймаут `C.DNSTimeout`, коллектор доигрывает
  всех и заполняет рейтинг в фоне.
- Сериализация кандидатов флагом `running`; ожидающие до первой гонки —
  канал `firstDone` (закрывается один раз; после `Reset` не пересоздаётся —
  межгоночные запросы падают в failover-порядок, поведение корректное).
- `reset()` бампает `gen` — доигрывающая гонка старого поколения не пишет
  победителя/рейтинг после смены сети.
- Все члены получают `message.Copy()` (участники мутируют Id).

## DoD

- Юниты (`-race`, `-count=2`): победитель = первый успешный, рейтинг по
  приходу, повтор до `interval` идёт только победителю, перегонка после
  `interval`, down-участник исключён из следующей гонки, сбой победителя →
  второй по рейтингу, NXDOMAIN валиден как победа, all-fail → ошибка без
  немедленной перегонки, одна гонка на параллельных кандидатов,
  ноль фоновой активности при простое (ENERGY), Reset форсирует новую гонку.
- `sing-box check` с `mode: race` + `interval` — OK; build/vet/gofmt — чисто.
