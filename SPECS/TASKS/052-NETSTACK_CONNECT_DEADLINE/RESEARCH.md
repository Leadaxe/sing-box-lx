# RESEARCH — природа «молчаливого зависания» (netstack-дайлы, прилипание urltest, заморозка процесса)

Исследование 2026-08-06: 7 агентов с построчными цитатами (5 фактосборщиков +
2 адверсариальных критика) + стендовые замеры. Триггер — полевой дамп горутин
(CPH2411): 16 дайлов припаркованы в `DialTCPWithBind` на одном WARP-эндпоинте
при жалобе «на Wi-Fi виснет всё, на LTE работает». Сама жалоба разрешилась
вендорской настройкой («приостановка кешированных приложений», процесс
замораживался системой), но дамп вскрыл класс поведения, который стоит понимать
целиком.

## Три механизма (все — апстрим-дизайн, не lx-регрессии)

### 1. Netstack-дайл без предохранителя: тихие ~127 секунд

Полная анатомия таймаутов дайла (verified end-to-end):

| Путь | Эффективный connect-таймаут |
|---|---|
| direct / системный leaf любой прокси-цепочки | 5s (`C.TCPConnectTimeout` в `net.Dialer`) |
| прокси-цепочка (vless→detour→…) | 5s только на leaf; сами хопы — ничего |
| **TCP через WG/AWG-netstack (IP-назначение)** | **нет нигде → ~127s SYN-бэкофф gVisor** |
| **то же, домен** | **DialSerial по адресам → до N×127s** |
| **TCP через netstack openvpn / openconnect / tailscale** | **тот же класс — сабмодульный `gonet.DialTCPWithBind`, дедлайна нет** (найдено адверсариальной проверкой диффа, закрыто тем же швом) |
| tuic / hysteria2 | ~5s (собственный дефолт quic-go, не заслуга sing-box) |
| urltest health-probe | 15s (`C.TCPTimeout`) |

127s = 1+2+4+8+16+32+64 (InitialRTO=1s, удвоение до MaxRTO=120s,
DefaultSynRetries=6). `TCPSynRetriesOption` в нашем пине gVisor — мёртвая
ручка: хранится/валидируется, но нигде не читается ⇒ единственный рычаг —
ctx-дедлайн. Файл `device_stack_gonet.go` байт-в-байт совпадает с upstream;
апстрим о классе знает (2023: keepalive для established на этом пути), connect
оставил безлимитным. Оговорки: 127s — для ТИХОЙ дыры (RST/ICMP рвут раньше);
приложения чаще видят свой таймаут раньше (sing-tun не SYN-ACK-ает инбаунд до
успеха исходящего дайла — gLazyConn), после чего ретраят в тот же узел;
брошенные дайлы никто не отменяет, каждый держит слот форвардера (кап 1024).

### 2. Прилипание urltest — осознанный апстрим-дизайн

Реакции на ошибку дайла нет и в апстриме: только `DeleteURLTestHistory` в
least_test (нулевой маршрутизирующий эффект), в round_robin — намеренно ничего.
Комментарий в коде прямо: «причина ошибки неизвестна — мёртвый узел vs мёртвое
назначение vs локальная сеть». Переизбор — исключительно в хвосте пробного
прогона (таймер 3 мин / InterfaceUpdated / ручной RPC); `Touch()` на каждом
дайле лишь заводит тикер. passive_check (SPEC 019) — age-based: узел умер →
сигнал протухает за ≤interval → пробы возобновляются; но в окне до этого каждый
пользовательский дайл висит по механизму №1. Сценарий «дайлы перестают
УДАВАТЬСЯ» из SPEC 019 подразумевает ошибки, которых механизм №1 не поставляет.

### 3. Заморозка процесса: ядро о ней не знает

Вся pause/wake-машинерия кооперативная (Pause/Wake зовёт приложение; вендорский
freezer не зовёт ничего). Детекции разрыва времени нет нигде (core, wireguard-go,
sing-tun, gVisor). Восстановление после оттаивания — эмерджентное, demand-driven,
и оно РАБОТАЕТ (замер E3 ниже): WG-рехендшейк на первом пакете, gVisor
ретрансмитит сразу, SPEC 041 добивает за 15–90с, `RebindStaleEndpoints` — на
USER_PRESENT. ⚠️ Непроверенное допущение: расчёт верен для freezer-класса
(монотонные часы идут); при SoC-suspend (doze) `CLOCK_MONOTONIC` на Android
СТОИТ — «таймеры стрельнут при оттаивании» не доказано, SIGSTOP-стенд это не
имитирует (needs-device). Попутная находка: split-clock рассинхрон SPEC 041 —
`sessionProvablyDead` меряет wall-временем (`time.Unix` срезает monotonic),
send-path — монотонным (`time.Since(keypair.created)`); после doze предикаты
расходятся, последствия не разобраны (desk-work, открыто).

## Реестр ловушек наивного фикса (S1–S6, каждая с code-verified причиной)

- **S1 (худшая):** ctx-дедлайн, переживающий connect, убивает живые соединения —
  XHTTP привязывает stream-one request к dial-ctx (`request.WithContext`),
  route оборачивает UDP-сессии в ctx-циклы. Класс SPEC 050, уже наступали.
  Безопасный шов ровно один: leaf select `DialTCPWithBind` + `defer cancel()`.
- **S2:** реселект по неклассифицированной ошибке: RST мёртвого САЙТА через
  живой узел неотличим от мёртвого узла → пинг-понг между узлами +
  `interruptGroup.Interrupt` всех соединений на каждый переезд.
- **S3:** фиксированные 5s < легитимных холодных дайлов: потерянный первый
  WG-initiation ретраится через RekeyTimeout=5s (успех ~6s), L3-rebuild
  0.5–1s + DNS пира + handshake, RRC-раскачка радио 0.5–2s, двойные туннели
  (два хендшейка) — легитимно 8–10s+.
- **S4:** очередь на `resumeMu` жжёт бюджеты: параллельные дайлы burst'а
  сериализуются за одним rebuild, их клоки тикают в очереди.
- **S5:** асимметрия probe(15s)/dial(<15s): узел с connect 6–8s проходит пробы
  и держит history, а 100% пользовательских дайлов падают — перманентный outage.
- **S6:** реакция на ошибку пробингом = wake-storm: force-прогон будит все
  спящие эндпоинты (probe → resumeOnDial → Up/rebuild), ломая экономию SPEC 020.

## Стендовые замеры (2026-08-06, desktop-бинарь + локальный WG-пир, RTT≈0)

Метод: два инстанса sing-box на Mac (клиент mixed-inbound → WG-эндпоинт;
сервер — WG-эндпоинт в listen-режиме → direct), python http.server как
назначение; blackhole = peer на TEST-NET-1.

| Эксперимент | Результат |
|---|---|
| E1: дайл в blackhole | `real 2m7.065s` — предсказанные 127s с точностью до секунды; ошибка в конце ЕСТЬ (`operation timed out`, ERROR-лог); self-heal SPEC 041 ребиндит (trigger=early), но против дыры бессилен |
| E2: длительности дайлов | warm 0.19–0.55s; cold L2 (suspend→Resume) 0.35–1.95s; **cold L3 (teardown→rebuild) 2.48–4.82s при RTT≈0** |
| E3: SIGSTOP 200s (>RejectAfterTime) → CONT | восстановление **2.4s** на первом дайле — перманентного зависания нет; артефакты оттаивания (косметика): idle-tick видит дельту 3м24с и суспендит под входящий дайл (flap suspend→wake, +1 handshake); burst буферизованных initiations → серия ERROR «handshake initiation must be consumed first» |
| E1-повтор с фиксом SPEC 052 | ~15s до ошибки (см. SPEC.md §Верификация) |

## Открытые вопросы

- [needs-device] Поведение при doze+SoC-suspend (монотонные часы стоят) —
  SIGSTOP-стенд не покрывает; нужен реальный девайс с 10-мин заморозкой при
  выключенном экране.
- [desk] Split-clock рассинхрон SPEC 041 (wall vs monotonic предикаты) —
  протрассировать через таймлайн 10-мин suspend.
- [needs-device] Полевые хвосты E2 (реальный RTT/радио) — контроль бюджета 15s.
- [отдельная спека] Реакция группы на ошибки: дельты на demand-пути (директива
  владельца), классификация ошибок (DeadlineExceeded ≠ Canceled ≠ RST),
  гистерезис против S2, не-пробинговая реакция против S6, границы с LxBox §308.
  ⚠️ Номер 034 для неё НЕ брать (занят и освобождён в DNS-контексте).
