Релей, который сниффит UDP, чтобы подменить назначение именем из SNI (Xray `sniffing` с
`destOverride` и `routeOnly: false`), решает по первой датаграмме потока. Если первая датаграмма
не long-header пакет QUIC, QUIC-сниффер выбывает из потока; идущий следом ClientHello не
разбирается, поток уходит на адрес, который набрал клиент. Мы шлём один байт `0x00` до первого
Initial QUIC-дозвона. Серверы QUIC отбрасывают его не разбирая.

Клиент не видит, сниффит ли релей. Поэтому байт не уходит на первой попытке: первый дозвон идёт
чистым, и только неудавшийся дозвон повторяется с байтом впереди. Какие outbound'ы это делают,
через релеи каких типов и на каких путях — объект `lx.quic_sniff_decoy` (§4); без ключа не
отправляется ничего.

## 1. Проблема

Через релей с Xray `sniffing` `destOverride: ["quic", …]` без `routeOnly` релей расшифровывает
Initial-пакеты клиента (ключи выводятся из общеизвестной соли и DCID), собирает ClientHello,
берёт SNI и подменяет назначение этим именем. Резолвящееся SNI уводит на хост этого имени
(masque: `remote endpoint has a different public key than pinned`; hysteria2/tuic с подставным
SNI: чужой сервер или пустота), нерезолвящееся обрывается. Релей не наш, пользователь часто не
может его поправить (релеи `[BL]`, SPEC 150 §1.1); h2 проходил только благодаря фрагментации
записей SPEC 060, h3, hysteria2 и tuic — никогда.

## 2. Почему решает первая датаграмма

Xray `app/dispatcher/default.go` `sniffer()` и `app/dispatcher/sniffer.go` `Sniffer.Sniff`
(`v26.10.31`):

- Диспетчер копит всё прочитанное из потока в кэш и каждый круг зовёт `Sniff` по всему кэшу, в
  бюджете 200 мс и двух попыток «no clue».
- `Sniff` гоняет все снифферы сети. Ответ `ErrNoClue` оставляет сниффер в списке на следующий
  круг; `ErrProtoNeedMoreData` сужает список до этого сниффера и читает дальше; **любая другая
  ошибка выбрасывает сниффер из списка насовсем**. Если не осталось никого, `Sniff` возвращает
  `errUnknownContent`, диспетчер сразу прекращает сниффинг и ведёт по исходному адресу.
- `SniffQUIC` разбирает кэш с первого байта. Первый байт без бита long-header (0x80) или fixed
  bit (0x40) сразу даёт `errNotQUICInitial`. Long-header пакет другого типа (Handshake, 0-RTT)
  **пропускается**, а исчерпанный кэш отвечает `ErrProtoNeedMoreData` — обманка в форме
  Handshake заставила бы сниффер ждать настоящий Initial и разобрать его; обманка должна
  провалить самую первую проверку.

Значит, первая датаграмма `0x00` даёт `errNotQUICInitial`, QUIC-сниффер выходит из потока до
прихода Initial, а оставшийся, возможно, uTP-сниффер QUIC не опознаёт. Порядок внутри одного
чтения кэша не важен: кэш в любом случае начинается с обманки.

На стороне сервера обманка инертна: RFC 9000 §17 требует fixed bit, quic-go
(`wire.IsPotentialQUICPacket`) и другие стеки отбрасывают такую датаграмму до поиска соединения,
а один байт намного короче минимального пакета, способного вызвать stateless reset (21 байт).
hysteria2 с Salamander отбрасывает её при деобфускации (короче соли).

sing-box в роли релея: в актуальной линии (1.13+) подмены назначения по сниффу нет вовсе
(`sniff_override_destination` удалён в апстриме коммитом `8ae93a98e`); снифнутый домен идёт
только в маршрутизацию, так что sing-box-релей эти протоколы не ломает и контрмеры не требует.
Пакетный снифф там тоже решает по первому пакету (`route/route.go`, «packet sniff skipped due
to previous error»), обманка сработала бы и там.

## 3. Реализация

### 3.1 Политика — `common/lxdatagram/decoy.go`

- `sniffDecoy = []byte{0x00}`; `WriteSniffDecoy(conn, logger)` пишет его один раз, ошибка записи
  — debug-строка, дальше игнорируется (обманка вспомогательная, сломанный conn проявит сам
  хендшейк).
- `SniffDecoyPolicy` — разобранный ключ (`option.LXResolved.QUICSniffDecoy`, читается один раз на
  outbound через `SniffDecoyFromContext(ctx)`): `Mode`, множества `OutboundTypes` и `DetourTypes`,
  `Retry`. `policy.Enabled(outboundType)` включает всю машинерию для потребителя: `mode: off` или
  тип вне `outbound_type` — ни байта, ни памяти повторов, ни записи несущего.
- `policy.Applies(path)` решает на каждом дозвоне по пути, каким он набран: `direct` — сокет ядра
  (`IsKernelSocket`, `common/lxdatagram/kernel.go`, общая проверка SPEC 150; без `detour`,
  `detour` на outbound `direct` или `detour` на группу, в которой сейчас выбран `direct`);
  `detour` — conn, который несёт другой outbound, **тип которого есть в `detour_type`**; `all` —
  оба. Несомый conn с неизвестным типом несущего (записи в контексте нет) считается не
  подходящим.

### 3.2 Тип несущего — `adapter/carrier_lx.go`

Сниффящий релей — ближайший хоп, который распаковывает нашу датаграмму: outbound, названный в
`detour`, или, когда `detour` — группа, участник, которого группа выбрала для этого дозвона.
Набранный conn не говорит, кто его несёт, поэтому потребитель кладёт в контекст дозвона
`CarrierRecord` (`adapter.ContextWithCarrierRecord`), а два существующих lx-шва заполняют его
через `adapter.RecordCarrier(ctx, outbound)`:

- `DetourDialer.DialContext` (`common/dialer/detour.go`, внутри блока SPEC 139) записывает
  outbound, в который разрешился `detour`;
- `adapter.ResolveChainLeaf` (хук SPEC 073, который каждая группа зовёт с выбранным участником)
  записывает этого участника.

Группа не записывается никогда, так что вложенные группы разрешаются до участника; побеждает
первая не-групповая запись, поэтому собственный `detour` участника (второй хоп) не перетирает
ближайший. Outbound'ы `chain` (SPEC 073) проходят через тот же хук со звеном, несущим исходный тег
и тип. Запись стоит одного значения контекста на дозвон и существует только при включённой
политике потребителя.

### 3.3 Память повторов — `lxdatagram.SniffDecoy`

Один `SniffDecoy` на потребителя (outbound или endpoint), nil, когда политика для его типа
выключена. `Begin(ctx)` возвращает `Attempt` с записью несущего в контексте; `attempt.Dialed(conn,
writeTo)` классифицирует путь, решает, несёт ли эта попытка байт, и пишет его в `writeTo` (conn,
в который будет писать QUIC-стек, после собственных обёрток потребителя); `attempt.Done(err)`
записывает исход и сообщает, надо ли потребителю повторить дозвон прямо сейчас.

На каждый путь (`direct` или `detour:<тип>`) память — автомат из трёх состояний:

| Состояние | Эта попытка | Удача | Неудача |
|---|---|---|---|
| `clean` (начальное) | без байта | остаётся `clean` | → `armed` |
| `armed` | байт | → `decoy` | → `clean` |
| `decoy` | байт | остаётся `decoy` | → `clean` |

Неудача с байтом возвращает в `clean`: просто лежащий узел не должен закрепить байт на пути, где
сам байт и ломает поток (отчёт 2026-11-06). Другой путь (группа переключилась с `direct` на релей
или на релей другого типа) начинает с `clean`; память живёт с потребителем и умирает с ним
(outbound пересобран, box перезапущен). При `send: always` памяти нет: каждый подходящий дозвон
несёт байт, как в lx.30–lx.32.

`Done(err)` просит немедленный повтор, когда попытка была чистой, политика применима к пути,
ошибка — не таймаут (`net.Error.Timeout()`, `context.DeadlineExceeded`) и контекст вызывающего ещё
жив. Быстрая ошибка — обычная сигнатура сниффера (masque: `remote endpoint has a different public
key than pinned` за один RTT); молчащий релей выжидает дедлайн вызывающего, и повтор с байтом —
следующий дозвон, из `armed`.

| Потребитель | Файл | Дозвон и хендшейк | Повтор |
|---|---|---|---|
| `masque` h3 | `protocol/masque/outbound.go` `connectH3WithBudget` | наши; байт идёт после обёрток SPEC 150/146, до `quic.DialEarly` | в том же вызове при быстрой ошибке, иначе следующий дозвон. В `auto` повтор идёт до отката на h2; молчащий h3 откатывается на h2 как раньше, следующая h3-нога — `armed` |
| `hysteria2`, `tuic` | `common/lxdatagram/truncate.go` `truncDialer` (шов SPEC 150) | внутри `sing-quic`, результат не виден | косвенно: conn, выданный дайлером, оборачивается; conn, закрытый меньше чем через 30 с после дозвона, считается неудачной попыткой, проживший дольше или ещё открытый — удачей; решение при следующем дозвоне. Ложное срабатывание стоит одного байта на следующем дозвоне. Port hopping идёт через `ListenPacket` и вне скоупа |
| `trusttunnel` h3 | `transport/trusttunnel/client_quic.go` `connectQUIC` | наши, только при `quic: true` у узла | как masque |
| XHTTP h3 (`vless`, `vmess`, `trojan`) | `transport/v2rayxhttp/http3.go` `Dial` у `http3.Transport` | наши, только когда транспорт договорился о h3 | как masque; проверяемый `outbound_type` — тип узла (`vless`, `vmess` или `trojan`), передаётся в транспорт при создании |
| `wireguard` (AmneziaWG) | `transport/wireguard/handshake_burst_lx.go` (фильтр SPEC 153), `client_bind.go` | bind записывает тип несущего и проверку сокета ядра на каждом поколении сокета | нет: повторы рукопожатия переиспользуют сокет, значит тот же поток — релей уже решил по первой датаграмме. Байт идёт перед QUIC-образной пачкой (`ip: quic` или статичный `i1` с QUIC-дампа) на каждом рукопожатии, к которому применима политика; `send` не действует |

`lx.awg_masquerade` (SPEC 153) удалён вместе со своей веткой фильтра: маскировочная пачка шлётся на
любом пути, как это делал дефолт `all` с lx.32. Ключ в конфиге — ошибка загрузки (§4).

### 3.5 Что ретрай не ловит

- **AmneziaWG**: ошибки нет, только неотвеченное рукопожатие, неотличимое от мёртвого сервера.
  Поэтому там повтора нет, байт идёт сразу.
- **Хендшейк, который без ошибки уходит не туда**: `tuic` с `insecure` и SNI, разрешающимся в
  живой QUIC-хост, завершает QUIC-хендшейк там; неудача проявляется позже как мёртвое соединение,
  которое 30-секундное окно §3.4 ловит только при быстром сбросе сервером. `masque` защищён пином
  ключа, `hysteria2` — кругом аутентификации.
- **Молчащий релей** (неразрешимый SNI): первый дозвон выжидает дедлайн. Первый URL-тест такого
  узла падает, второй проходит; в `auto` masque на этом поднятии откатывается на h2.
- **Релей, сниффящий TLS на h2**, — вне этой спеки, обманка только для QUIC.

### 3.6 Удалено

Прототип задержки SPEC 150 §3.2 (`protocol/masque/initial_delay_lx.go`) остаётся удалённым;
запасной ход §3.3 прошлой редакции (обманка-Initial со своими connection ID) остаётся на бумаге:
сниффера, пропускающего мусор в начале, не знаем.

## 4. Конфиг

Решения владельца 2026-11-02 (один ключ в корневом блоке `lx`, SPEC 098) и 2026-11-06/07 (только
объектная форма, сначала без байта, списки типов, `awg_masquerade` удалён):

```jsonc
"lx": {
  "quic_sniff_decoy": {
    "mode": "detour",             // off (дефолт) | direct | detour | all
    "outbound_type": ["masque"],  // дефолт: masque
    "detour_type": ["vless"],     // дефолт: vless
    "send": "retry"               // retry (дефолт) | always
  }
}
```

| Ключ | Значения | Без ключа | Смысл |
|---|---|---|---|
| `mode` | `off`, `direct`, `detour`, `all` | `off` | На каких путях байт разрешён: `direct` — UDP-сокет является сокетом ядра (без `detour`, `detour` на `direct` или на группу, в которой сейчас выбран `direct`); `detour` — UDP несёт другой outbound типа из `detour_type`; `all` — оба. `off` не шлёт ничего нигде |
| `outbound_type` | `masque`, `hysteria2`, `tuic`, `trusttunnel`, `vless`, `vmess`, `trojan`, `wireguard` | `["masque"]` | Какие outbound'ы шлют байт. Тип выбирает узел; байт идёт только там, где узел действительно открывает QUIC: `masque` на h3, `trusttunnel` с `quic: true`, `vless`/`vmess`/`trojan` с XHTTP по h3, `wireguard` перед QUIC-образной пачкой AmneziaWG |
| `detour_type` | любой тип outbound, кроме групп (`selector`, `urltest`) | `["vless"]` | Через какие релеи. Релей — ближайший хоп, несущий датаграмму, читается при дозвоне: outbound из `detour`, или участник, которого группа выбрала для этого дозвона |
| `send` | `retry`, `always` | `retry` | `retry` — первая попытка чистая, неудавшаяся повторяется с байтом (§3.3); `always` — каждый подходящий дозвон несёт байт, поведение lx.30–lx.32. На `wireguard` не действует |

Ошибки загрузки, все с именем ключа: строка или булево (`lx.quic_sniff_decoy must be an object:
{mode, outbound_type, detour_type, send}`), неизвестный `mode` или `send`, тип вне списка выше в
`outbound_type`, тип группы или пустая строка в `detour_type`, неизвестный ключ в объекте, тип в
`detour_type`, которого не знает ни реестр outbound, ни реестр endpoint сборки (проверка при старте
бокса в `box_lx.go`, ловит и `sing-box check`; при `mode: off` пропускается), и
`lx.awg_masquerade` с любым значением (`lx.awg_masquerade is removed: the AmneziaWG masquerade
burst is sent on every path`).

Объект с четырьмя дефолтами и `mode: off` канонизируется в отсутствие ключа. Переопределения из
окружения нет. Конфиг, записанный LxBox 2.25.x (`"quic_sniff_decoy": "detour"`,
`awg_masquerade`), на этом ядре не загружается: бамп пина ядра в LxBox идёт вместе с его
генератором конфига (решение владельца 2026-11-07, отменяет ограничение «старые конфиги стартуют»
из постановки задачи). Пользовательская документация — `docs-lx/lx-config.ru.md` §13.

## 5. Проверка — объектная форма

Юниты:

- `option/lx_test.go` — объект разбирается с дефолтами, объект из одних дефолтов канонизируется,
  строковая и булева формы и `awg_masquerade` падают со своими сообщениями, неизвестные типы и
  типы групп отвергаются, схема — строгий объект.
- `common/lxdatagram/decoy_test.go` — трёхсостоянная память на путь; `Done` просит повтор только
  при быстрой ошибке; `Applies` против сокета ядра, несомого conn с подходящим, неподходящим и
  отсутствующим типом несущего; `send: always` шлёт на каждом подходящем дозвоне; окно
  `truncDialer`: рано закрытый conn взводит следующий дозвон, долгоживущий — нет.
- `adapter/carrier_lx_test.go` — побеждает первая не-групповая запись, группы пропускаются.
- `transport/wireguard/handshake_burst_lx_test.go` — байт идёт перед QUIC-образной пачкой по
  политике, никогда перед пачкой dns/stun/sip; снятия пачки больше нет.

### 6.0 Стенд 2026-11-02

Стенд на Mac владельца (`scratchpad/xr`, `scratchpad/ht`), Xray `v26.10.31` vless-inbound со
`sniffing` `destOverride: ["http","tls","quic"]`, `routeOnly: false`; выход Mac не трогался.

| Клиент | Путь | Без обманки | С обманкой |
|---|---|---|---|
| masque h3 → WARP `162.159.198.2` | vless XUDP | 0 из 5, 40 × чужой ключ | 5 из 5, хендшейк 454 мс |
| masque h3 → WARP | vless plain UDP | 0 из 5, 40 × чужой ключ | 5 из 5, хендшейк 478 мс |
| masque h3, жизнь 2 минуты | vless XUDP | — | 12 из 12 запросов раз в 10 с, один туннель, без смертей, 20 МБ на 2,6 МБ/с |
| hysteria2 → loopback-сервер, SNI `www.cloudflare.com` | vless XUDP | 0 из 4 (Xray: `sniffed domain`, маршрут на `www.cloudflare.com:4443`) | 4 из 4 (`default route for udp:127.0.0.1:4443`) |
| tuic → loopback-сервер | vless XUDP | 0 из 4 | 4 из 4 |

Loopback-стенду нужен `finalRules: [{"action":"allow","ip":["127.0.0.0/8"]}]` у freedom в Xray:
по умолчанию он блокирует приватные адреса. Для сравнения: прототип задержки SPEC 150 §3.2
проходил при ≥ 200 мс с хендшейком 658–760 мс.

Сам ключ (без env) на тех же стендах: без ключа — masque 0 из 5, hysteria2/tuic 0 из 4; `true` —
5 из 5 и 4 из 4. Режимы на стенде xr: `"detour"` через сниффящий релей 5 из 5 (обманка ушла);
`"direct"` через тот же релей 0 из 5, чужой ключ (на detour-conn обманки нет, как и задумано);
`"direct"` на узле без detour 5 из 5 (обманка ушла по сокету ядра, туннель поднят).

Юниты (`common/lxdatagram/decoy_test.go`, `option/lx_test.go`): дайлер шлёт обманку первой только
на `udp`, без ключа или с `off` — ничего; `direct`/`detour`/`all` против настоящего сокета ядра и
detour-conn; все формы значения разбираются, `off` каноникализуется в отсутствие ключа, `true`
пишется обратно как `"all"`, неизвестные значения отвергаются; схема — `anyOf(enum, boolean)`;
обманка не long header, fixed bit снят, короче триггера stateless reset.

### 6.1 Живые релеи `[BL]` (2026-11-02, сборка rc.3)

14 vless-релеев стенда 2026-11-01 (SPEC 150 §1.1), на каждый релей узел masque h3 через XUDP и
узел h2 как контроль живости; по три пробы задержки `generate_204` через clash API на узел, один
бинарь без ключа и с `true`. Выход Mac не трогался.

| Релей | h2 (контроль) | h3 без ключа | h3, `quic_sniff_decoy: true` |
|---|---|---|---|
| n001 | 3 из 3 | 0 из 3, чужой ключ ×3 | 3 из 3 (431–1477 мс) |
| n002 | 2 из 3 | 0 из 3, чужой ключ ×3 | 3 из 3 (414–1423 мс) |
| n009 (без сниффинга) | 3 из 3 | 3 из 3 | 3 из 3 |
| n011 | 3 из 3 | 0 из 3, чужой ключ ×3 | 2 из 3, родной ключ; туннель умирает после каждого запроса |
| остальные 10 | 0 из 3 (у четырёх чужой ключ на h2 — сниффят и TLS) | 0 из 3 | 0 из 3 |

Обманка переводит каждый живой сниффящий релей с чужого ключа на родной ключ WARP. Туннель n011
затем умирает с `received a stateless reset` и `use of closed network connection`, как и с
прототипом задержки §3.2: через секунду WARP уже не знает соединения — похоже на то, что релей
шлёт следующие пакеты с другого выхода (другая точка anycast), а не на обманку, на которую сервер
ответить не может. Здесь не разбиралось. Мёртвые релеи и четыре, сниффящие TLS на h2, — вне этой
спеки: обманка только для QUIC.

### 6.2 Не покрыто: маскировка AWG `ip: quic` через сниффящий релей (2026-11-03)

Тот же сниффер ломает WireGuard/AmneziaWG-endpoint, маскировка которого шлёт QUIC-обманку (`ip: quic`, SNI из `id`), когда его `detour` — релей с Xray `sniffing`, `quic` в `destOverride` и без `routeOnly`.

- Случай из поля (zomg, LxBox 2.25.19-rc.2-dev.38 на `1.14.4-lx.30-rc.1`, два дампа 2026-11-03): узел к собственному WireGuard-серверу репортёра — `jc 4/40/70`, `id: cdn.jsdelivr.net`, `ip: quic`, `ib: chrome`, `detour` через селектор `[BL]`-релеев — падает на каждом URL-тесте с `context deadline exceeded`; чистый WireGuard к WARP через тот же селектор проходит (391 и 440 мс).
- Механизм: QUIC Initial маскировки — первая датаграмма потока. QUIC-сниффер Xray расшифровывает его, берёт SNI из `id` и уводит поток на `<id>:<порт>`; хендшейк WireGuard до сервера не доходит. Чистый WireGuard и мусор AWG (`jc`) ни один сниффер не распознаёт — они проходят.
- Loopback-стенд на lx.30 (WireGuard-сервер sing-box, клиент через vless, релей Xray `v26.10.31` с `destOverride` `http`/`tls`/`quic`): чистый WireGuard 3/3, AWG `jc` 3/3, AWG `ip: quic` + `id` 0/3 в XUDP и без упаковки, то же без релея 3/3; через vless-релей sing-box все варианты 3/3. Лог Xray называет подменённое назначение: `failed to open connection to udp:nonexistent.invalid:51820` при `id: nonexistent.invalid`.
- Решение 2026-11-03 было оставить это конфигу (убрать `id`/`ip`/`ib` у узла с `detour`, `routeOnly: true` на релее). Два независимых полевых отчёта в тот же день (issue #64) превратили его в [SPEC 153](../153-AWG_MASQUERADE_OVER_DETOUR/SPEC.md): `lx.awg_masquerade: "direct"` (дефолт `all`) через `detour` маскировочную пачку не шлёт вовсе, а `lx.quic_sniff_decoy` дошёл до хендшейка AmneziaWG — байт идёт перед QUIC-образной пачкой на путях, которые выбирает режим.
