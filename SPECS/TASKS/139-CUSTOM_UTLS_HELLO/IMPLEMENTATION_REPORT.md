# Отчёт 139

Добавлен `tls.utls.fingerprint: "custom"` с объектом `tls.utls.client_hello` в формате JSON ClientHelloSpec uTLS. Для расширений без именованной схемы добавлены числовой ID и статические байты в base64. Профиль проверяется при создании конфига и разбирается заново для каждого TCP-соединения. Реализованы обычный TLS и REALITY. Без `with_lx_utls_custom` конфиг отвергается с явной ошибкой.

## Проверка

- Красный тест: `custom` отклонялся как неизвестный профиль; лишний `client_hello` при `chrome` игнорировался; REALITY не отправлял ClientHello с `HelloCustom`; числовое расширение не разбиралось. Зелёный тест проверяет его ID и payload на проводе.
- `go test -tags 'with_utls with_lx_utls_custom' ./common/tls ./option -count=1`: 165 тестов прошли на базе v1.14.3-lx.23.
- `go test -tags with_utls ./common/tls ./option -count=1`: 157 тестов прошли.
- `go test ./common/tls ./option -count=1`: 96 тестов прошли.
- Полный CI, сборка релизного бинарника и VPN-дозвон на устройстве ещё не проверены.

## Файлы и зона ребейза

- Новые файлы: `common/tls/utls_custom_lx{,_stub,_test}.go`, пример конфига, документы фичи и задачи.
- Маркированные upstream-швы: `option/tls.go`, `common/tls/utls_client.go`, `common/tls/reality_client.go`, `cmd/internal/build_libbox/main.go`.
- Собственные сборочные файлы: `Makefile.lx`, `.github/workflows/lx-ci.yml`.
- Зависимостей не добавлено.

Не выпускался релиз, не пересобирались и не устанавливались мобильные приложения. Сетевой тест проверяет локальный TLS-сервер; работу конкретного профиля против живой VPN-ноды следует проверять после выбора этого профиля в клиенте. Прямые API-запросы приложения вне sing-box и QUIC не затронуты. Статические байты расширения не заменяют корректную динамическую реализацию ECH/PSK.
