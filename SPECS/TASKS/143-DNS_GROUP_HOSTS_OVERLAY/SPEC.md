# SPEC: 143 — DNS_GROUP_HOSTS_OVERLAY

**Фича:** [013-DNS_GROUP](../../FEATURES/013-DNS_GROUP/FEATURE.md)

|------|----------|

Группа получает необязательный ключ `hosts`: список серверов типа `hosts`, которые
опрашиваются **до** выбора цели. Имя из их списка отвечается локально, сетевые участники
не трогаются. Имя не из списка идёт сетевым участникам по режиму группы без изменений.
Группа без ключа ведёт себя как сейчас.

## 1. Проблема

Адреса серверов outbound и endpoint резолвятся через `domain_resolver` (у узла или
`route.default_domain_resolver`). Этот путь идёт в транспорт напрямую, минуя DNS-правила
(`Router.Lookup`, ветка `options.Transport != nil`, [dns/router.go](../../../dns/router.go)),
поэтому ни `predefined`-действие, ни правило `server: hosts` до адреса сервера не доходят.

Сам `hosts` резолвером по умолчанию быть не может: на любое имя не из списка он отвечает
NXDOMAIN ([hosts.go](../../../dns/transport/hosts/hosts.go)), и все остальные узлы перестают
резолвиться. Поставить `hosts` на `domain_resolver` одного узла можно уже сегодня, но это
не покрывает подписки и общий резолвер по умолчанию.

Группа `hosts` + сетевой сервер сегодня не собирается: `Start` отвергает `hosts` в `servers`.
Снять запрет нельзя: NXDOMAIN для группы — валидный ответ (`isFailure`), и `hosts` выиграл бы
любую гонку `parallel`, копил бы победы в `fastest`, а в `stable` не уступал бы никому.
Любое имя вне списка ломалось бы.

## 2. Поведение

### 2.1 Слой `hosts`

1. **Порядок.** В `Exchange` группы, после `PushGroup` и до `selectTarget`, участники `hosts`
   перебираются в порядке ключа. Первое попадание отвечает на запрос. Ни один из них не
   попадает в выбор цели, веер и режим выживания.
2. **Попадание** — выполняются все три условия:
   - `Qtype` ∈ {A, AAAA};
   - участник знает имя: `adapter.DNSTransportWithPreferredDomain.PreferredDomain(name)`
     для `mDNS.CanonicalName(question.Name)` (так же проверяет rule-item `preferred_by`);
   - `Exchange` участника вернул ответ без ошибки с `Rcode == NOERROR`.
   Ответ отдаётся как есть. Это включает **пустой NOERROR**, когда для имени есть адреса
   только другого семейства (`FixedResponse` фильтрует по `Qtype`): запись только с IPv4
   на запрос AAAA даёт пустой ответ, и запрос в сеть **не уходит**. Следствие: `strategy:
   ipv6_only` на имени только с IPv4 даёт `empty result` и отказ dial — так же ведёт себя
   `/etc/hosts` в ОС; документируется, не чинится.
3. **Промах** — не выполнено любое условие попадания (имя не известно, другой `Qtype`,
   участник ответил не NOERROR или ошибкой: гонка с перечитыванием файла после
   положительного `PreferredDomain`). Проверяется следующий участник `hosts`; когда они
   кончились, запрос уходит сетевым участникам по режиму группы с тем же сообщением —
   путь SPEC 033 не меняется ни в одном режиме.
4. **Здоровье.** Участники `hosts` не получают записей ERROR и WIN, не входят в множество
   чистых, не участвуют в веере и выживании, не становятся `current`, не попадают
   в `GroupState().Members`. `Reset` их не касается (сбрасывать нечего).
5. **Кеш** — без изменений: ответ попадания кешируется над группой под её тегом с TTL ответа
   `hosts` (`C.DefaultDNSTTL`), как сегодня кешируется ответ `hosts` через правило.

### 2.2 Состав и валидация

6. **`servers`** — обязательный и непустой, как сейчас: группа без сетевых участников
   не стартует (существующая проверка конструктора). `hosts` и `fakeip` в `servers`
   по-прежнему отвергаются на старте; текст ошибки для `hosts` подсказывает ключ `hosts`.
7. **`hosts`** — необязательный список тегов. Каждый тег: существует в менеджере; тип
   строго `hosts` (любой другой, включая `fakeip`, `udp`, `group` — ошибка старта);
   без дубликатов; не равен тегу группы; не входит в `servers` той же группы.
   Пустой список (`[]`, badjson схлопывает в nil) равен отсутствию ключа.
8. **Зависимости.** Теги `hosts` входят в `Dependencies()` группы вместе с `servers`:
   менеджер стартует их раньше группы и ловит циклы тем же механизмом.
9. **Вложенность.** Внутренняя группа со своим ключом `hosts` для внешней — обычный
   участник: её слой работает внутри её `Exchange`, внешняя об этом не знает.

### 2.3 Наблюдаемость (SPEC 035, SPEC 139)

10. **Попадание:** фактически ответивший сервер (`SetEffectiveServer`) — тег и тип
    участника `hosts`; в трассу пишется одна проба `answered` с его тегом, типом `hosts`
    и rtt; стадия `dns_member` теста соединения (SPEC 139) записывается по факту
    попадания — открыта и закрыта сразу после обмена (стадия видна с момента открытия,
    а промах стадий не оставляет; обмен локальный, дочерних стадий у него нет), subject —
    тег участника, `type: hosts`; лог debug «hosts hit via <tag>».
11. **Промах:** ничего — ни пробы, ни стадии, ни записи здоровья; `fanned` / `survival`
    не трогаются. Трасса промаха байт в байт равна трассе той же группы без ключа `hosts`.
12. **`GetDNSGroups`:** снапшот не меняется, участники `hosts` в `Members` не входят.
    Прото не трогается.

## 3. Конфиг

Поле в lx-блоке `option.GroupDNSServerOptions`:

```go
Hosts badoption.Listable[string] `json:"hosts,omitempty" reference:"dns_server"`
```

```jsonc
{
  "dns": {
    "servers": [
      { "type": "hosts", "tag": "local",
        "predefined": { "wg.home": ["203.0.113.10", "2001:db8::10"] } },
      { "type": "udp", "tag": "google",     "server": "8.8.8.8" },
      { "type": "udp", "tag": "cloudflare", "server": "1.1.1.1" },
      { "type": "group", "tag": "resolver",
        "hosts": ["local"],
        "servers": ["google", "cloudflare"],
        "mode": "stable" }
    ],
    "final": "resolver"
  },
  "route": { "default_domain_resolver": { "server": "resolver", "strategy": "prefer_ipv6" } }
}
```

`wg.home` в адресе endpoint'а получает оба адреса из `local`, `strategy` выбирает
семейство; любое другое имя идёт в `google`/`cloudflare` по режиму `stable`.

## 4. Совместимость

- Конфиг без ключа `hosts` — поведение группы прежнее во всех режимах, трасса та же.
- Конфиг с `hosts` в `servers` падал на старте и падает; ошибка называет ключ `hosts`.
- Upstream типа `group` не имеет; апстримные файлы не меняются (`option/dns.go` — внутри
  существующего lx-блока).
- LxBox: валидатор и контракт конфига получают новое необязательное поле группы; запрет
  `hosts` в `servers` остаётся. Вне скоупа ядра.

## 5. Критерии приёмки

Юниты `dns/transport/group` (`-race`, `-ldflags=-checklinkname=0`):

- попадание A: ответ из `hosts`, сетевые участники не вызывались — в `stable`, `fastest`,
  `parallel`;
- запись только с IPv4, запрос AAAA: NOERROR без ответов, сеть не вызывалась;
- промах: результат и число вызовов сетевых участников равны группе без ключа `hosts` —
  в трёх режимах, включая веер `parallel` и режим выживания;
- имя из списка, `Qtype` TXT → сеть;
- два участника `hosts`: отвечает первый по порядку ключа, знающий имя;
- `PreferredDomain` true, `Exchange` вернул NXDOMAIN → промах, сеть вызвана;
- здоровье: после серии попаданий и промахов у участников `hosts` нет записей,
  `GroupState().Members` их не содержит, `Current` не их тег;
- трасса: на попадании `effective` = тег `hosts` и ровно одна проба `answered` типа
  `hosts`; на промахе пробы только сетевых; стадия `dns_member` SPEC 139 есть на попадании
  и отсутствует на промахе;
- хотя бы один тест против **реального** транспорта `hosts` (`predefined`, без файлов)
  через менеджер — закрепляет контракт NOERROR/NXDOMAIN и `PreferredDomain`;
- валидация: тег `hosts` не найден; тип не `hosts` (`fakeudp`, `fakeip`); дубликат
  в `hosts`; тег и в `hosts`, и в `servers`; тег равен группе; `hosts` без `servers` —
  существующая ошибка; `hosts` в `servers` — ошибка с подсказкой.

DoD: `go vet` и `gofmt` по затронутым пакетам, `go build ./...`, `sing-box check`
с конфигом §3 принимается.

## 6. Вне скоупа

- LxBox: валидатор, контракт, форма `hosts` в редакторе DNS.
- Слой для других локальных типов с `PreferredDomain` (`local`, `mdns`, `resolved`):
  механизм к ним применим, но решения нет — ключ принимает только `hosts`.
- Сетевой фолбэк для семейства, которого нет в записи (`A`-only + AAAA → сеть):
  противоречит семантике hosts ОС, не делается.
- Изменения прото `GetDNSGroups`.
