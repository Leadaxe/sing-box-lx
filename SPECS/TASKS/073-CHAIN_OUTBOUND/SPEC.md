## 0. TL;DR

Новый outbound `chain` с упорядоченным списком позиций `outbounds` (порядок
пакета: `[0]` — вход, последний — выход). Любая позиция — узел, endpoint или
группа. Группы **не копируются**: цепочка зовёт `DialContext` оригинальной
группы, а в пяти точках, где группа дозванивается до выбранного узла, один хук
подменяет узел на его **звено** — рантайм-экземпляр «узел через предыдущую
позицию», созданный штатным реестром из копии опций узла с `detour` на
внутренний тег предыдущей позиции. Звенья ленивые (по факту выбора, плюс прогрев
детерминированных позиций), с одним тегом с оригиналом, удаляются по простою
при нуле соединений. `direct` на позиции ≥ 1 прозрачен (выключатель хопа),
`block` терминален. Звено = оригинал − `strip` + `rewrite`, MTU понижен на
точные накладные IP-туннелей под ним. Путь соединения — в `detourList`;
состояние цепочки — в lx RPC и Clash API; задержка по слоям — URLTest по
внутренним тегам `<tag>#i`.

---

## 1. Проблема

1. **Многохоп без дублирования конфига.** Сегодня `exit.detour = entry` зашивает
   связь в узел: тот же узел в другой комбинации = вторая копия в конфиге.
2. **Группа не может быть звеном.** `detour` на `selector` переадресует один
   узел; «узел X через *выбираемый* вход» или «выбираемый выход через X» —
   невозможно без копии каждого участника группы с нужным `detour`.
3. **Управление путём на лету.** Хочется переключать любой хоп (в том числе
   выключать его) из UI, не трогая конфиг и не перезапуская ядро.
4. **Stateful-транспорты.** WG-endpoint, hy2/tuic, mux, grpc/xhttp держат
   **одно** соединение к серверу на весь экземпляр. «Через какой путь поднят
   туннель» — свойство экземпляра, не вызова: один `warp-exit` не может
   одновременно ездить через `node1` для цепочки и напрямую для обычного
   маршрута. Отсюда — рантайм-экземпляр на пару (узел, позиция) как
   семантическая необходимость, а не способ обойти ограничение.

## 2. Контракт конфига

```json
{
  "type": "chain",
  "tag": "virtualisation",
  "outbounds": ["selector-in", "selector-mid", "selector-exit"],
  "idle_timeout": "5m",
  "strip_evasion": true,
  "strip": { "multiplex.padding": false, "tls.utls": true },
  "rewrite": { "wireguard": { "mtu": 1200 }, "vless": { "tls": { "fragment": false } } }
}
```

| Ключ | Тип | Дефолт | Семантика |
|------|-----|--------|-----------|
| `outbounds` | `[]string`, ≥ 2 | обязательное | Позиции в порядке пакета. Любая — узел / endpoint / группа любой вложенности. Позиция 0: любой тип, в т.ч. другой `chain`; позиции ≥ 1: узел с dial-полями, `direct`, `block`, группа из таких |
| `idle_timeout` | `Duration` | `5m` | Простой, после которого звено без соединений удаляется; `0` — жить до `Close` |
| `strip_evasion` | `bool` | `true` | Применять каталог `strip` по умолчанию к звеньям (позиции ≥ 1) |
| `strip` | `map[string]bool` | `{}` | Патч каталога: `false` — оставить, `true` — снимать дополнительно. Неизвестный ключ — ошибка старта |
| `rewrite` | `map[type]json` | `{}` | Merge-patch (RFC 7396) поверх опций узла данного типа; звенья позиций ≥ 1 |

Три формы, которые обязаны работать одинаково (и любой длины ≥ 2):

```
["selector-in", "selector-mid", "selector-exit"]   // все группы
["node-in",     "node-mid",     "node-exit"]       // все узлы
["node-in",     "selector-mid", "node-exit"]       // смешанно
```

## 3. Семантика

### 3.1 Термины и инварианты

- **Позиция i** — `outbounds[i]`; **цель позиции** — оригинальный outbound по
  тегу (узел, endpoint или группа).
- **Хоп i** — внутренняя обёртка позиции с тегом `<chain>#<i>`; существует для
  каждой позиции. Хоп — единственная сущность, адресуемая по тегу (как цель
  `detour` звеньев и как цель URLTest-по-префиксу).
- **Звено (clone)** — рантайм-экземпляр узла L для позиции i ≥ 1, созданный
  штатным реестром из преобразованной копии опций L с `detour = <chain>#(i−1)`.
  Ключ `(i, tag L)`. `Tag()` звена = тег оригинала. Звено **не** регистрируется
  в менеджере (недоступно по тегу, приватно цепочке).
- **Позиция 0 никогда не имеет звена** — цель используется как есть.
- **Инвариант пути:** трафик через хоп i идёт к серверу выбранного узла
  позиции i **только** через хоп i−1 — это гарантирует `detour` звена, а не
  поведение вызывающего кода.
- **Группы не копируются** ни в какой форме.

### 3.2 Дозвон

`Chain.DialContext/ListenPacket → хоп n−1`. Хоп i:

```
i == 0             → цель.DialContext(ctx БЕЗ привязки, …)          // реальная сеть, как есть
цель — узел        → звено(i, узел).DialContext(ctx, …)
цель — группа      → цель.DialContext(ctx + привязка{хоп i}, …)
```

Привязка — значение в `ctx` («этот дозвон принадлежит хопу i»). Хоп
**всегда перезаписывает** привязку, хоп 0 — стирает: в хоп приходят и с
пользовательским ctx, и из фонового реконнекта звена (WG-bind, QUIC), и через
штатный `DetourDialer` от звена сверху — путь не должен зависеть от того, что
принёс вызывающий.

**Хук в группах** — одна функция `ResolveChainLeaf(ctx, picked)` в каждой
точке, где группа дозванивается до выбранного участника (selector: dial и
listen-packet; urltest: dial, listen-packet и **fallback-дайл штрафного режима**
SPEC 054 — пропустить его значит молча увести соединение мимо цепочки).
Без привязки или если `picked` — группа (вложенность) — no-op; иначе —
звено для `(хоп из привязки, picked)`. Вся логика групп (ручной выбор,
`pickForDial`, sticky, штрафы/fallback, `interruptGroup`, passive-check)
остаётся нетронутой: звено несёт тег оригинала, ключи истории/штрафов совпадают.

### 3.3 Прозрачный `direct`, терминальный `block`

- Узел типа `direct` на позиции ≥ 1 → **passthrough**: хоп i зовёт хоп i−1
  напрямую. Путь укорачивается; `direct` участником селектора — выключатель
  позиции на лету. Звена и прогрева нет. Dial-поля такого `direct`
  игнорируются (как у всех не-входных позиций). Все-`direct` позиции ≥ 1 ⇒
  цепочка эквивалентна позиции 0.
- На позиции 0 `direct` — настоящий (его dial-поля действуют).
- `block` на любой позиции — соединение отвергается его поведением; звена нет.
- Прочие типы без dial-полей (`dns`, вложенный `chain` на позиции ≥ 1) —
  отказ на старте.

### 3.4 Жизненный цикл звеньев

- **Создание** — лениво при первом выборе узла (singleflight по ключу):
  опции узла из менеджера → поверхностная копия → `strip` → `rewrite` → MTU →
  `detour = <chain>#(i−1)` → реестр (outbound или endpoint по месту тега) →
  стадии старта → в карту. Ошибка создания = ошибка дозвона (группа
  обрабатывает её как падение узла).
- **Прогрев на `Start`** — звенья позиций, чей выбор детерминирован: узлы и
  селекторы любой вложенности, **пока на пути выбора нет urltest** (у него на
  старте нет замеров; `Now()` — случайный первый участник). Ошибка прогрева =
  ошибка старта. Прогретое звено получает `lastPicked = время старта`.
- **Удаление по простою** — тикер цепочки: `activeConns == 0 && now −
  lastPicked > idle_timeout` → закрыть, удалить из карты. Живые соединения
  считаются счётной обёрткой над conn, выданными звеном. Переключение
  группы само по себе звено **не** удаляет: без `interrupt_exist_connections`
  старые потоки доживают через старое звено.
- **Сон** — уснувший WG-туннель звена подчиняется ENERGY (SPEC 020): цепочка
  отдаёт свои endpoint-звенья в тот же обход, что idle-тик, пауза при
  переключении сети и quiesce при закрытии (SPEC 030). Без этого отсидевший
  WG-клон держал бы горячий стек бесконечно (§208).
- **Закрытие** — от старшего индекса к младшему (верхние держат соединения
  через нижние); затем снятие внутренних тегов.
- **Interrupt** — соединения цепочки прошли через `DialContext` группы и
  обёрнуты её `interruptGroup`; переключение с флагом рвёт их, включая
  WG-bind звена выше, который переподнимается через новый выбор.

### 3.5 MTU звеньев-туннелей

Только у IP-туннелей (WG, MASQUE, openvpn/openconnect) есть MTU; прокси-звенья
не трогаются. Для туннельного звена на позиции i:

```
capacity(i−1) = узел i−1: IP-туннель → его (уже подогнанный) MTU;
                          поток (TCP-прокси, UoT, mux) / direct / датаграммный прокси → ∞
                группа i−1: min по всем достижимым узлам (рекурсивно)
clone.mtu     = min(orig.mtu_effective, capacity(i−1) − overhead(тип звена))
overhead: WG внутри IP-туннеля = 60 (v4) / 80 (v6; домен → 80); MASQUE ≈ 90
```

Смотрим только на непосредственно нижний узел — глубже учтено в его MTU или
сброшено потоком. Min по группе — чтобы не пересоздавать звено при
переключении группы ниже (MTU WG фиксируется при создании). Контракт: `mtu`
в конфиге узла = «как самостоятельного», цепочка только понижает. Над
датаграммными прокси — без изменений (как при обычном `detour`); над
`tuic` в `native` — предупреждение в лог и состояние.

### 3.6 `strip` и `rewrite`

- Каталог `strip` и его дефолты — в FEATURE (`tls.fragment`,
  `multiplex.padding`, `xhttp.padding` снимаются; `tls.utls` доступен;
  `record_fragment` — вне каталога, это защита пути SPEC 060).
- `effective = (strip_evasion ? каталог_по_умолчанию : ∅) ⊕ strip`.
- `rewrite` — JSON merge-patch поверх сериализованных опций узла данного типа;
  декодируется обратно в типизированные опции (валидация типов и неизвестных
  полей — от декодера).
- Порядок: `strip` → `rewrite` → MTU. Оба применяются только к звеньям
  (позиции ≥ 1). `strip` реализуется как предопределённые патчи того же
  механизма.
- **Сухой прогон на старте:** преобразование прогоняется для каждого узла,
  достижимого на позициях ≥ 1 (без создания экземпляров) — ошибки `rewrite`
  и `strip` (`tls.utls` при `reality`) — ошибки старта.

### 3.7 Внутренние теги и валидация

- Хопы регистрируются как **внутренние** outbound'ы: видны `Outbound(tag)`
  (для `DetourDialer` и URLTest-по-тегу), не входят в `Outbounds()`, не
  стартуются/закрываются менеджером — владелец цепочка.
- На старте: ≥ 2 позиции; теги существуют; типы достижимых узлов позиций ≥ 1
  допустимы; ни один пользовательский тег не совпадает с `<chain>#<i>`;
  `Dependencies()` = теги позиций → штатный lint ловит цикл «группа содержит
  цепочку».

## 5. Критерии приёмки

1. Три формы из §2 (длины 3 и 5) поднимаются и несут TCP+UDP через стенд из
   локальных серверов; `Path()`/`detourList` совпадают с фактическим путём.
2. Переключение селектора на позиции ≥ 1: новое звено создаётся на первом
   дозвоне; старое живёт при живом потоке и удаляется через `idle_timeout`
   при нуле; с `interrupt_exist_connections` — поток рвётся, WG-звено выше
   переподнимается через новый выбор.
3. `direct` в селекторе на позиции ≥ 1 укорачивает путь; все-`direct` ⇒
   эквивалентно позиции 0; `block` отвергает.
4. Fallback-дайл urltest (SPEC 054) идёт в звено, не в оригинал (тест с
   подменой).
5. Прогрев: узлы и селекторы подняты на старте, urltest-позиции — нет;
   ошибка прогрева валит старт.
6. MTU: WG над WG получает `−60/−80`; WG над vless-TCP — без изменений;
   WG над селектором {vless, WG} — под WG; `rewrite` mtu учитывается до
   понижения.
7. `strip`: у звена vless с `fragment: true` фрагментация снята, а
   `record_fragment` SPEC 060 активен; `strip: {"tls.fragment": false}`
   возвращает; `tls.utls: true` при `reality` — ошибка старта; неизвестный
   ключ — ошибка старта.
8. `rewrite` с неизвестным полем для типа — ошибка старта (сухой прогон);
   валидный — применён и виден в `ChainInfo.rewritten`.
9. Endpoint-звенья участвуют в idle-suspend (SPEC 020) и quiesce (SPEC 030):
   после простоя WG-звено спит; `box.Close` с живыми звеньями — доли секунды.
10. URLTest по `<tag>#i` работает; `<tag>#i` отсутствуют в `Outbounds()`.
11. Ошибка UDP-над-TCP содержит обе позиции.
12. Без `with_lx_chain` сборка поведенчески равна upstream (`type: chain`
    отвергается на чтении конфига; хук в группах — no-op); с тегом —
    `go vet`, gofmt lx-файлов, сборки `lx-build` зелёные.
13. Документация: `docs-lx/lx-config.md` §10 (поля, порядок, три формы,
    каталог `strip`, MTU-контракт, оговорка про DPI между хопами); секция в
    changelog релиза.

## 6. Намеренно не делаем

- Замер групп «через цепочку» (ранжирование остаётся прямым; слои — через
  `<tag>#i`).
- Статическая проверка UDP-способности хопа.
- Вложенный `chain` на позициях ≥ 1.
- Per-позиционные переопределения вне `rewrite`-по-типу; лимит звеньев;
  собственная проверка здоровья цепочки (она участник внешнего urltest).
- Серверная сторона.

## 7. Риски и открытые точки

- **Приписывание фидбека** (passive-check, штрафы SPEC 054) тегу узла, общему
  для прямой и цепочечной роли. Гейтить фидбек при наличии привязки —
  одно условие; решение — по результатам стенда, по умолчанию не гейтим.
- **Синхронное создание WG-звена** на первом дозвоне — задержка пользователя;
  смягчено прогревом детерминированных позиций.
- **Min-по-группе MTU** консервативен: селектор {vless, WG} под WG даёт
  WG-MTU даже при выбранном vless. Цена — пропускная способность, не
  корректность.
