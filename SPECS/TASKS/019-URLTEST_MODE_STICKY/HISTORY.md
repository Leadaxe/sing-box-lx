# HISTORY — SPEC 019: удалённый `passive_check`

Хронология изменений [SPEC 019](SPEC.md), убранных из актуального состояния.

## 2026-10-07 — удаление `passive_check` (SPEC 116)

**Почему удалён.** Флаг склеивал две разные вещи: энергетическую ручку
(не будить узлы пробами, пока трафик сам подтверждает живость) и политику
выбора. Пропуск циклов проб в `least_test` неявно превращал режим «гонимся
за скоростью» в «держимся за рабочий узел»: другие узлы не мерились,
переключений по `tolerance` не было, задержки в UI устаревали. Пользователь,
включавший флаг ради тишины радио, получал другую политику выбора, нигде не
заявленную, кроме комментария в коде.

**Чем заменён.** Решение владельца 2026-10-07: политика выбора живёт в
`mode`. Явный режим `mode: failover`
([SPEC 116](../116-URLTEST_FAILOVER_MODE/SPEC.md)) выбирает самый быстрый
узел, держится за него до отказа и каждый `interval` пробует только его.
`least_test` снова всегда меряет все узлы. Флаг удалён без периода
совместимости (его никто не внедрил): конфиг с ключом `passive_check` не
стартует с ошибкой неизвестного поля.

Удалены: поле `option.URLTestOutboundOptions.PassiveCheck`, штамп успешного
TCP-дайла (`passiveOK`, `markPassiveAlive`), пропуск цикла least_test,
пропуск подтверждённых слотов в `balancePoolFirstLive`, штамп в
`penaltyFailoverDial`, предупреждение `passive_check` + `pool_tolerance > 0`,
тесты флага.

### Раздел

#### `passive_check` — пассивное подтверждение живости (opt-in)

Идея: **успешный TCP-дайл через узел = доказательство двусторонней живости** — SYN/SYN-ACK прошёл всю цепочку (туннель, узел, до цели и обратно). Пока такое доказательство свежо (< `interval`), URL-probe узла не несёт новой информации о живости — только жжёт трафик/радио и (в связке SPEC 020) будит усыплённые эндпоинты.

Механика (`passive_check: true`):
- группа при каждом успешном TCP-дайле штампует `passiveOK[tag] = now` (только отметка времени, БЕЗ обёртки соединения — fast-path/splice не затронуты; UDP-дайл сигнала не даёт: `ListenPacket` не подтверждает доставку);
- **least_test**: периодический (не-force) цикл проб **пропускается целиком**, пока выбранный узел пассивно подтверждён (TCP-selected свеж; UDP-selected отсутствует или тот же узел). Выбор остаётся приколоченным к работающему узлу — меньше переключений; history стареет (delay в UI обновляется только при лапсе сигнала или ручном тесте — согласованная цена). Узел умер → дайлы перестают удаваться → сигнал лапсится за ≤ interval → пробы возобновляются, переизбор работает;
- **round_robin `pool_tolerance==0`**: пассивно подтверждённый слот считается живым **без пробы** (замер на нём не выполняется, delay в GetPool стареет); слоты без сигнала пробуются как раньше. При активной ротации по всем слотам пробы исчезают полностью;
- **`pool_tolerance > 0`**: не влияет (режим обязан мерить всех — при включении пишется warn);
- ручной тест (`force`) всегда полный.

Дефолт `false` — апстримное поведение бит-в-бит. На mobile с WG/AWG-узлами включать (см. ТЗ LxBox §272): активная группа перестаёт периодически будить весь список.

### Валидация

- `passive_check` + `pool_tolerance > 0` → **варн** (не ошибка): режим обязан мерить всех, пассивный сигнал не подменяет замер;

### Тест-план

- **`passive_check`:** пассивно подтверждённый слот не пробуется и держит слот; сигнал не считается при выключенной опции и при возрасте > interval; least_test-цикл пропущен при живом выбранном и возобновляется после лапса; `pool_tolerance > 15000` отвергается на старте (граница 15000 принимается).
