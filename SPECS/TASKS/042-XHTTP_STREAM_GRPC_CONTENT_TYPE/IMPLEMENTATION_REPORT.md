# IMPLEMENTATION REPORT: 042 — XHTTP_STREAM_GRPC_CONTENT_TYPE

**Фича:** [XHTTP](../../FEATURES/002-XHTTP/FEATURE.md) · **Спека:** [SPEC.md](SPEC.md)

## Что сделано

Запросы с телом в `stream-one` и `stream-up` получают `Content-Type: application/grpc`; `no_grpc_header` стал действующей ручкой отказа вместо заглушки.

| Файл | Изменение |
|------|-----------|
| `transport/v2rayxhttp/conn.go` | `applyGRPCHeader` + вызовы в `dialStreamOne` и `dialStreamUp` |
| `transport/v2rayxhttp/client.go` | Поле `noGRPCHeader`, проброс из опций в `NewClient` |
| `option/v2ray_xhttp.go` | Переписан комментарий `NoGRPCHeader` — опция действующая |
| `transport/v2rayxhttp/xhttp_test.go` | `TestGRPCHeaderOnStreamedBody` — три случая |

Гейт — `c.noGRPCHeader || request.Body == nil`, то есть заголовок ставится ровно там же, где у Xray в `FillStreamRequest`. `packet-up` не затронут: его аплинк-нагрузка проходит через `applyUplinkData` со своим типом контента, даунлинк-`GET` тела не имеет.

## Живой прогон: фикс жалобу не закрыл

Ядро пересобрано и поставлено на устройство. **XHTTP-ноды остались 0/14** — ровно как до фикса. Разбор в [SPEC §6](SPEC.md); коротко: мертвы также hysteria2 (11) и все noTLS-транспорты (18), жив единственный профиль vless+gRPC+TLS (14/14). XHTTP на общем фоне не выделяется, поэтому причина лежит вне фичи 002 и вне этого фикса.

Отсюда честная оценка сделанного:

- расхождение с Xray было **реальным** и устранено — это самостоятельная ценность (паритет контракта);
- но **дефект, который фикс должен чинить, воспроизвести не удалось** — стенда, где отсутствие заголовка ломает соединение, нет;
- следовательно объяснение «буферизующий прокси перед нодой» — правдоподобная гипотеза, **не** подтверждённый механизм. В SPEC она помечена именно так.

Гипотеза «виноват `mode:auto`», с которой начиналась диагностика, по ходу работы была опровергнута: разрешение `auto` у нас совпадает с Xray, а `packet-up` оживлял ноды в промежуточных замерах, но на итоговом прогоне с новым ядром картина не воспроизвелась — то есть тот эффект тоже не был устойчивым.

## Заметки на будущее

- **Xray-сервер `Content-Type` не читает.** Стенд из голого Xray-сервера этот баг не воспроизведёт — нужен реальный обратный прокси/CDN перед сервером, как у нод подписки. Учитывать при построении тест-стендов для XHTTP.
- **Методическая ловушка LxBox.** `PUT /config` сам по себе не всегда доводит конфиг до ядра: `rebuild-config` перезаписывает файл, но работающий box остаётся на прежнем. Нужен `POST /action/reload-vpn`, а фактический режим сверять по `GET /config/running` — иначе замеряешь не то, что положил. На этом был испорчен один из промежуточных замеров.
- **Разрешение `auto` сверено с актуальным Xray** (v26.7.28, 2026-07-28): REALITY-эвристику не убирали, наш код ей соответствует. Не поддерживаем только третью ступень (`downloadSettings` → `stream-up`).
