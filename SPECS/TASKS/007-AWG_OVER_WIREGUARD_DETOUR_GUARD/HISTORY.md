## Неатомарное переключение селектора после снятия guard'а (исправлено 2026-11-26)

Selector-guard (коммит `e1a96eabe`) должен был опустить AmneziaWG-потребителей
группы до того, как она начнёт указывать на WireGuard-узел. Для этого апстримную
строку `if s.selected.Swap(detour) == detour` разрезали на проверку через `Load`
и отдельный `Store`, а хук поставили между ними. Guard сняли в `5fa3a0a17`, хук
ушёл, но разрезанная пара осталась — без маркера `// lx:`. Позже SPEC 020 вставила
сразу после `Store` сброс кэша достижимости.

Чем это било. Проверка и запись перестали быть одной операцией. Если два вызова
`SelectOutbound` на один и тот же новый узел приходят одновременно (clash API,
демон `lxd`, command server LxBox, CLI `api group select`), оба видят старый узел
и оба выполняют всё переключение: дважды пишут выбор в cache-file, дважды рвут
соединения при `interrupt_exist_connections` (второй разрыв может задеть
соединение, уже открытое через новый узел), дважды сбрасывают кэш достижимости
и дважды шлют обновление истории. Итоговый выбор при этом верный. Тест показал
2–3 прохода на 16 одновременных вызовов. Ни демон, ни clash API вызовы не
сериализуют. Сообщений о таком не было: нужен почти одновременный выбор из двух
клиентов.

Исправление. Возвращена апстримная строка со `Swap`; сброс кэша SPEC 020 остался
одной помеченной строкой сразу после неё и срабатывает один раз на реальную
смену выбора, как раньше при последовательных вызовах. Одновременные переключения
на разные узлы `Swap` не упорядочивает: каждое выполняет побочные эффекты, и в
cache-file может остаться тег проигравшего. Так же ведёт себя апстрим. Отличие от
апстрима в `SelectOutbound` сократилось до этой строки. Регрессионные тесты —
`protocol/group/selector_atomic_lx_test.go`: на старом коде падает тест
одновременных вызовов на один узел.
