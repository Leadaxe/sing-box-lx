# ALGORITHM: 165 — цепочка как перезапись `detour`, общий `lx.detour`

Источник истины для задачи. Код пишется по правилам ниже, у каждого правила есть тест
с его номером в имени. Находка стенда или ревью сначала правит этот документ.

## 1. Модель

Ядро видит:

- конфиг: исходящие, endpoint'ы, группы, цепочки, блок `lx`;
- во время работы: что выбрала каждая группа сейчас, какие позиции цепочек выключены,
  чем оказалось соединение после дозвона через `detour` — настоящим сокетом ядра или
  потоком внутри туннеля.

Ядро не видит:

- есть ли DPI между нижним хопом и сервером узла;
- сколько сессий на одну учётку допускает сервер.

## 2. Аксиомы

- **А1.** У WireGuard-ключа на сервере одна сессия. Два экземпляра узла с одним ключом
  на двух путях мешают друг другу. Для других stateful-протоколов это может быть так же.
- **А2.** `detour` узла резолвится один раз и не меняется до перезагрузки конфига
  (dialer запоминает цель; WG резолвит при старте).
- **А3.** Порядок запуска исходящих строится только по общему списку исходящих.
  Тег, которого там нет, — «зависимость не найдена».
- **А4.** Группа проверяет своих членов теми экземплярами, что лежат в общем списке.

## 3. Определения

- **Позиция** цепочки `i` — элемент `outbounds[i]`: узел, endpoint или группа.
- **Достижимые узлы позиции** — сама позиция, если это узел, или все листья группы
  любой вложенности, кроме `direct` и `block`.
- **Перехват** — запись «узел N получает `detour` = хоп `<C>#<i−1>`, по позиции `i`
  цепочки `C`».
- **Хоп** `<C>#<i>` — внутренний исходящий типа `chain-hop` с полями `chain`, `position`,
  `outbound` (тег позиции `i`) и, для `i ≥ 1`, `below` (хоп `<C>#<i−1>`).

## 4. Правила

### 4.1 Перезапись при загрузке

Выполняется в lx-предобработке опций до создания узлов, раньше выравнивания MTU и
сборки `sniff_guard`.

- **П1. Хопы.** Для каждой цепочки `C` с позициями `0..n−1` в общий список исходящих
  добавляются хопы `<C>#0 … <C>#n−1`. Тег хопа, занятый пользователем, — ошибка.
- **П2. Перехват.** Для каждой позиции `i ≥ 1` каждый достижимый узел получает
  `detour = <C>#<i−1>`. Прежний `detour` узла (включая отсутствие) перекрывается и
  пишется в `changes` с `by = {type: chain, chain: C, position: i}`.
- **П3. Позиция 0** не перехватывается: её узлы идут своими путями.
- **П4. Группы не перехватываются.** Меняются только листья; группа остаётся одной и
  проверяет те же экземпляры, что несут трафик.
- **П5. `rewrite`.** Для перехваченного узла применяется `rewrite` цепочки по его типу.
  Каждое изменённое поле — запись `changes` с `by = {type: chain_rewrite, chain,
  position, node_type}`.
- **П6. Вход цепочки.** Исходящий `C` дозванивается через хоп `<C>#<n−1>`.
- **П7. Удалённые ключи цепочки.** `idle_timeout`, `strip_evasion`, `strip` в конфиге
  цепочки — ошибка при старте с текстом, что их заменило (как у удалённых
  `awg_masquerade` и `quic_sniff_decoy`).

### 4.2 Конфликты (ошибки при старте)

- **К1.** Узел перехвачен дважды: на позиции ≥ 1 в двух цепочках или на двух позициях
  ≥ 1 одной цепочки.
- **К2.** Узел перехвачен в одной цепочке и достижим на позиции 0 любой цепочки.
- **К3.** Тип `chain-hop` во входном конфиге.
- **К4.** Цикл: группа на позиции содержит саму цепочку или цепочку, которая её
  перехватывает. Вложенная цепочка допустима только на позиции 0.
- **К5.** Тип листа на позиции ≥ 1 не умеет дозваниваться через `detour`.
- **К6.** Цикл через перехват: `detour` узла позиции ниже (собственный, не перехваченный)
  ведёт в узел, который перехвачен на этой же или более высокой позиции. Ошибка называет
  цепочку и узлы, а не только теги хопов, как сказал бы общий порядок запуска.

Текст ошибки называет узел, обе цепочки и позиции.

### 4.3 Хоп во время работы

- **Х1.** Хоп `i`, позиция включена, на позиции узел — дозвон через этот узел.
- **Х2.** Хоп `i`, позиция включена, на позиции группа — дозвон через группу; группа
  выбирает по своей логике, выбранный член идёт своим `detour` (= хоп `i−1`).
- **Х3.** Выбран `direct` (позиция — `direct` или группа выбрала `direct`), `i ≥ 1` —
  дозвон через хоп `i−1`.
- **Х4.** Позиция `i ≥ 1` выключена — дозвон через хоп `i−1`.
- **Х5.** Позиция 0 выключена — дозвон в сеть напрямую, обычным dialer'ом ядра.
- **Х6.** `block` — отказ.
- **Х7.** Группа, дозваниваясь через выбранного члена, отмечает носителя соединения,
  как сейчас; удаление подмены узла эту отметку не трогает.

### 4.4 `lx.detour.strip`

В каталоге один фильтр — разрез ClientHello на пакеты (`tls.fragment`). Только у него
есть измеримая цена в туннеле: на соединении без настоящего сокета ядра разрез не может
дождаться подтверждения каждого куска и спит `fragment_fallback_delay` (500 мс по
умолчанию) между кусками, то есть 0,5–1,5 с на каждое рукопожатие. uTLS, padding
мультиплексора и padding XHTTP в каталог не входят: за туннелем их видят релей и сеть от
релея до сервера, а цены, которую снятие убирало бы, у них нет.

- **С1.** Узел без `detour` или из `except_outbounds` — фильтр не применяется.
- **С2.** Решение принимается на каждом рукопожатии. Соединение от `detour` — настоящий
  сокет ядра (проверка та же, что у SPEC 150/151/153, включая группу с выбранным
  `direct`) — разрез из конфига узла остаётся. Поток внутри туннеля — разрез из конфига
  узла не делается (`fragment`, `fragment_fallback_delay`); `record_fragment` не
  трогается.
- **С3. Решение `sniff_guard` сильнее фильтра.** Если `sniff_guard` сам формирует это
  рукопожатие (подозревает сниффящий релей на пути), применяется его форма. Фильтр
  снимает только разрез, который пришёл из конфига узла, и не отменяет защиту, которую
  добавил guard.
- **С4.** Опции узла не меняются, в `changes` фильтр не попадает. Применённый фильтр
  виден в наблюдаемости соединения.

### 4.4а `lx.detour.skip_kernel_only`: механизмы TLS без сокета ядра

- **Я1.** Соединение от `detour` — не настоящий сокет ядра (та же проверка, что в С2) —
  `tls.spoof` не применяется: ни обёртки, ни сырого пакета. В лог одна строка: узел,
  причина.
- **Я2.** То же условие — kTLS (`kernel_tx`, `kernel_rx`) не включается, соединение
  остаётся на TLS в пространстве пользователя. В лог одна строка.
- **Я3.** Я1 и Я2 действуют, когда `skip_kernel_only` включён (по умолчанию — да) и
  узла нет в `except_outbounds`. Выключенный ключ или `"detour": false` — поведение
  апстрима: spoof и kTLS пробуются и падают на соединении без сокета ядра.
- **Я4.** `tls.engine: apple` без сокета ядра — ошибка рукопожатия, как сейчас: замена
  движка сменила бы отпечаток.

### 4.5 `lx.detour.mtu_align`

- **М1.** Правило выравнивания — как в SPEC 120/144, без изменений.
- **М2.** Хоп для выравнивания — путь с ёмкостью
  `min(ёмкость позиции i, ёмкость хопа i−1)`: позиция может быть выключена или выбрать
  `direct` (Х3, Х4), и узел над хопом должен работать в любом из этих состояний.
  Для хопа 0 — ёмкость позиции 0 и прямой сети.
- **М3.** Узел из `except_outbounds` не выравнивается.
- **М4.** Каждое изменённое поле — запись `changes` с `by = {type: mtu_align, mode,
  below, overhead, reason}`; `reason` совпадает со строкой лога.

### 4.6 Разбор `lx.detour`

- **Р1.** Ключа нет → `mtu_align: clamp`, `skip_kernel_only: true`, `strip` выключен.
- **Р2.** `true` → `mtu_align: clamp`, `skip_kernel_only: true`, `strip` = каталог ядра.
- **Р3.** `false` → `mtu_align: off`, `skip_kernel_only: false`, `strip` выключен.
- **Р4.** Объект → каждый подключ по своим правилам; нет `mtu_align` → `clamp`; нет
  `skip_kernel_only` → `true`;
  нет `strip` → выключен.
- **Р5.** `strip`: `true` → каталог ядра; `false` → выключен; объект → только
  `filters`; нет `filters` → ничего не снимается.
- **Р6.** `filters`: `true` → каталог ядра; `false` → ничего; объект → полное
  перетирание: не указанный фильтр выключен.
- **Р7.** Каталог ядра: `tls.fragment` включён. Других фильтров нет.
- **Р8.** Ошибки при старте: неизвестный ключ на любом уровне; неизвестный тег в
  `except_outbounds`; `lx.mtu_align` — с текстом, куда ключ переехал. Ключи прежнего
  каталога цепочки (`tls.utls`, `multiplex.padding`, `xhttp.padding`) в `filters` —
  неизвестные ключи.
- **Р9.** В итоговом конфиге `lx.detour` записан развёрнутым: все подключи и все
  фильтры явно.

### 4.7 Ручки конфига

- **Н1.** `GetRunningConfig` — снимок до предобработки, как сейчас.
- **Н2.** `GetEffectiveConfig` — снимок после всей предобработки, в той же каноничной
  форме.
- **Н3.** `GetOutboundConfig(tag)` — `original` (узел из Н1), `effective` (из Н2),
  `changes` в порядке применения: П2 → П5 → М4. Одно поле, изменённое дважды, — две
  записи, `from` второй равно `to` первой.
- **Н4.** У хопа есть только `effective`.
- **Н5.** Неизвестный тег — ошибка «не найдено».
- **Н6.** Ручки есть в демоне и в `libbox`. `GetChainCloneConfig` удаляется везде.

## 5. Инварианты

- **И1.** У каждого узла один экземпляр и один `detour` на всё время работы box'а.
- **И2.** Узел перехвачен не более одной цепочкой и на одной позиции.
- **И3.** Группа на позиции ≥ 1 проверяет своих членов тем путём, которым идёт трафик.
- **И4.** `changes`, применённые к `original`, дают `effective` — для каждого узла.
- **И5.** Без ключа `lx.detour` поведение под `detour` совпадает с сегодняшним, кроме
  того, что `strip` бывших звеньев цепочки выключен.
- **И6.** Новых вставок в файлы апстрима нет. В апстримных файлах только удаляются наши
  lx-вставки: подмена узла в селекторе и обход звеньев в роутере.
- **И7.** Фильтр `strip` никогда не отменяет форму рукопожатия, выбранную `sniff_guard`.

## 6. Сценарии

**Т1. LxBox#233.** `c-proton = [o-direct, o-proton]`, `o-proton` — urltest из WG-узлов
с `detour: o-ru`. П1 добавляет `c-proton#0`, `c-proton#1`. П2: каждый член `o-proton`
получает `detour = c-proton#0`, в `changes` — `o-ru → c-proton#0`. Проверки группы
идут через `o-direct` (И3). Мёртвый по этому пути узел краснеет и уходит из пула. Сессия
WG одна (И1).

**Т2. Селектор с `direct` на позиции 1.** `[A, S, C]`, `S` выбирает `direct`. Узел `C`
идёт через хоп 1 → Х3 → хоп 0 → `A`. Мимо `A` трафик не уходит.

**Т3. Выключенная позиция.** `[A, B, C]`, позиция 1 выключена. `C` → хоп 1 → Х4 →
хоп 0 → `A`. MTU узла `C` выровнен по М2 и подходит для обоих путей.

**Т4. Группа в двух цепочках.** `X = [A, g]`, `Y = [B, g]`, `g` — группа из vless. К1:
ошибка с именами `X`, `Y` и первого члена `g`.

**Т5. Узел вне цепочек.** Маршрут ведёт прямо на перехваченный узел `N`. Соединение
идёт через хоп цепочки. Не ошибка: путь у `N` один.

**Т6. strip через селектор.** Узел `N` (TLS с `fragment`) с `detour: S`,
`S` = [`direct`, `wg-relay`]. `S` выбрал `direct` → рукопожатие с разрезом (С2).
`S` переключился на `wg-relay` → следующее рукопожатие без разреза, без пауз по 500 мс.

**Т6а. guard и фильтр.** Узел `N` с `detour: wg-relay`, `sniff_guard` пометил релей
как сниффящий и формирует рукопожатие сам. Применяется форма guard'а (С3), фильтр её не
отменяет (И7). Пометка снята — следующее рукопожатие по С2, без разреза.

**Т6б. spoof через ws.** Узел `N` с `tls.spoof` и транспортом ws, `detour: wg-relay`.
Под ws нет сокета ядра — Я1, рукопожатие без обманки, в логе строка «spoof skipped».
Тот же узел с `detour: S`, `S` выбрал `direct` — сокет ядра, обманка уходит.

**Т6в. kTLS на роутере.** Узел с `kernel_tx: true` за WG-релеем — Я2, TLS без kTLS,
рукопожатие проходит. С `"detour": false` — поведение апстрима, рукопожатие падает (Я3).

**Т7. Исключение.** `foreign-node` в `except_outbounds`: ни один фильтр не применяется
(С1), MTU не выравнивается (М3).

**Т11. Узел на входе и на позиции.** `X = [N, B]`, `Y = [A, N]`. В `Y` узел `N`
перехвачен на позиции 1, в `X` он на позиции 0 — К2, ошибка с именами `X`, `Y`, `N`.

**Т12. Выключенный вход.** `[A, B]`, позиция 0 выключена. Узел `B` → хоп 0 → Х5 →
прямой dialer ядра. Фильтр видит настоящий сокет ядра и разрез оставляет (С2).

**Т13. Носитель соединения.** `c-proton = [o-direct, o-proton]`, группа выбрала
`NL-FREE#114`. В наблюдаемости соединения путь: `c-proton → o-proton → NL-FREE#114 →
c-proton#0 → o-direct` (Х7). Тот же путь, что показывался при копиях.

**Т14. rewrite и выравнивание.** У цепочки `rewrite: {wireguard: {mtu: 1200}}`, ниже
WG-туннель. Узел получает две записи `changes` по полю `mtu`: `1420 → 1200` от
`chain_rewrite` и `1200 → 1120` от `mtu_align`; `from` второй равно `to` первой (Н3, И4).
Цифры условные.

**Т15. Цикл через перехват.** `[A, N]`, у `A` собственный `detour: N`. `N` перехвачен с
`detour = <C>#0`, хоп 0 ведёт в `A`, `A` ведёт в `N` — К6, ошибка называет цепочку,
`A` и `N`.

**Т8. Объект `filters` без ключей.** `"strip": {"filters": {}}` — ничего не снимается
(Р6).

**Т9. Ручка хопа.** `GetOutboundConfig("c-proton#0")` — только `effective` с
`type: chain-hop`, `outbound: o-direct`, без `below` (Н4).

**Т10. Старый ключ.** Конфиг с `lx.mtu_align: "fill"` — ошибка «переехал в
`lx.detour.mtu_align`» (Р8).

## 7. Что проверить в коде

1. Порядок шагов предобработки: перезапись цепочек → выравнивание MTU → сборка
   `sniff_guard` (он строит носителей по графу `detour` из опций и должен видеть хопы).
2. Выравнивание MTU умеет тип `chain-hop` по М2.
3. Регистрация `chain-hop` в реестре и запрет в пользовательском конфиге (К3) не
   конфликтуют: хопы добавляются после разбора входного конфига.
4. Порядок запуска: узел → хоп ниже → позиция; WG-endpoint резолвит `detour` при старте
   (SPEC 029) и видит запущенный хоп.
5. Пять точек подмены узла в группах: подмена уходит, отметка носителя (Х7) остаётся.
6. Роутер: отдельный обход звеньев цепочек для смены сети и доступности уходит;
   перехваченные WG-узлы — обычные endpoint'ы в общем обходе.
7. Хранилище выключенных позиций (SPEC 075) работает с хопами без звеньев.
8. Разрез ClientHello (С2) встраивается в тот же путь, которым `sniff_guard` формирует
   рукопожатие: решение едет вместе с соединением, вставок в апстримный TLS-слой нет.
   Проверка «настоящий сокет ядра» доступна в этой точке для потоковых соединений.
10. Статус цепочки для UI: поля звеньев (состояние, соединения, MTU, снятое) уходят;
    по позициям остаются выбранный узел, выключение и счётчики ошибок.
11. Каноничная запись итогового конфига совпадает по форме с `GetRunningConfig`, чтобы
    разница `original` / `effective` состояла только из `changes`.
12. Шаг перезаписи живёт за `with_lx_chain`: общая lx-предобработка зовёт его через
    include-файл, как сейчас регистрируется сам тип `chain`. Без тега в сборке нет ни
    перезаписи, ни типа `chain-hop`.
13. Итоговый конфиг берётся из box после предобработки: демон сейчас снимает
    `GetRunningConfig` до создания box, поэтому `GetEffectiveConfig` и
    `GetOutboundConfig` читают снимок, который box сохраняет сам. Так же в `libbox`.
14. Я1 и Я2 — по одной lx-строке: в применении spoof (`common/tls/client.go`, файл уже с
    lx-вставками) и в рукопожатии kTLS (`common/tls/ktls.go`). Решение о сокете ядра
    едет на conn от того же шва, где `sniff_guard` формирует рукопожатие.
15. Счётчики трафика для отчёта об энергопотреблении оборачивают сокет на прямом пути.
    По чтению кода обёртка не прозрачна для поиска TCP-сокета в разрезе ClientHello, и
    тогда разрез спит по 500 мс и без туннеля. Не воспроизведено; проверить, и если так —
    это отдельный баг, не эта задача. Проверка С2 и Я1–Я2 обязана обходить эти счётчики.
16. Связи, которые не меняются (SPEC §2.4): сетевые опции узла при `detour` не
    применяются апстримом; QUIC над туннелем закрыт выравниванием MTU и усечением
    датаграмм (задачи 120/144/150); `sniff_guard` решает по пути. Тесты перезаписи
    проверяют, что хопы попадают в оба графа — выравнивания и носителей guard'а.

## 8. Решения владельца

Приняты 2026-11-25/26:

- цепочка перехватывает `detour` любого узла на позиции ≥ 1, собственный `detour`
  перекрывается без ошибки;
- двое не могут перехватить один узел — ошибка при старте;
- хоп — обычный исходящий в конфиге, внутренний тип, клиенты фильтруют по типу;
- `strip` и `mtu_align` — внутри `lx.detour`, один `except_outbounds` на уровне
  `lx.detour`; `filters` вложенные; объект — полное перетирание;
- починки — явные ключи, включённые по умолчанию; трюки по умолчанию выключены;
  `true` — всё по умолчанию плюс каталог `strip`; `false` — всё выключено, как апстрим;
- ручки `GetRunningConfig`, `GetEffectiveConfig`, `GetOutboundConfig`; в ответе
  `original`, `effective`, `changes`; `by` — объект с `type`;
- `GetChainCloneConfig` удаляется целиком;
- новая задача вместо правок по старым, со ссылками из старых.
- `idle_timeout`, `strip_evasion`, `strip` цепочки — ошибка загрузки с объяснением (П7);
  клиентам изменения доносятся issue на бамп пина после релиза (SPEC §5);
- решение `sniff_guard` сильнее фильтра `strip` (С3, И7);
- в каталоге `strip` только `tls.fragment`; uTLS и оба padding убраны: за туннелем их
  видят релей и сеть до сервера, а цены, как у паузы разреза, у них нет;
- `tls.spoof` и kTLS без сокета ядра пропускаются (Я1–Я3) — явный ключ
  `lx.detour.skip_kernel_only`, по умолчанию включён, как все починки; `"detour": false`
  выключает и его: это форма приведения к апстриму;
- статус цепочки — унарный по тегу, как статусы endpoint'ов: позиции, выбранный узел на
  каждой, выключение, счётчики ошибок; общий список `GetChains` уходит.

## 9. Константы

Новых нет. Режимы `mtu_align` прежние; каталог `strip` сокращён до `tls.fragment`.
