# ALGORITHM: 165 — цепочка как перезапись `detour`, общий `lx.detour`

Источник истины для задачи. Код пишется по правилам ниже, у каждого правила есть тест
с его номером в имени. Находка стенда или ревью сначала правит этот документ.

## 1. Модель

Ядро видит:

- конфиг: исходящие, endpoint'ы, группы, цепочки, блок `lx`;
- во время работы: что выбрала каждая группа сейчас, какие позиции цепочек выключены,
  чем оказалось соединение после дозвона через `detour` — настоящим сокетом ядра или
  потоком внутри туннеля.

Ядро не видит:

- есть ли DPI между нижним хопом и сервером узла;
- сколько сессий на одну учётку допускает сервер.

## 2. Аксиомы

- **А1.** У WireGuard-ключа на сервере одна сессия. Два экземпляра узла с одним ключом
  на двух путях мешают друг другу. Для других stateful-протоколов это может быть так же.
- **А2.** `detour` узла резолвится один раз и не меняется до перезагрузки конфига
  (dialer запоминает цель; WG резолвит при старте).
- **А3.** Порядок запуска исходящих строится только по общему списку исходящих.
  Тег, которого там нет, — «зависимость не найдена».
- **А4.** Группа проверяет своих членов теми экземплярами, что лежат в общем списке.

## 3. Определения

- **Позиция** цепочки `i` — элемент `outbounds[i]`: узел, endpoint или группа.
- **Достижимые узлы позиции** — сама позиция, если это узел, или все листья группы
  любой вложенности, кроме `direct` и `block`.
- **Перехват** — запись «узел N получает `detour` = хоп `<C>#<i−1>`, по позиции `i`
  цепочки `C`».
- **Хоп** `<C>#<i>` — внутренний исходящий типа `chain-hop` с полями `chain`, `position`,
  `outbound` (тег позиции `i`) и, для `i ≥ 1`, `below` (хоп `<C>#<i−1>`).

## 4. Правила

### 4.1 Перезапись при загрузке

Выполняется в lx-предобработке опций до создания узлов, раньше выравнивания MTU и
сборки `sniff_guard`.

- **П1. Хопы.** Для каждой цепочки `C` с позициями `0..n−1` в общий список исходящих
  добавляются хопы `<C>#0 … <C>#n−1`. Тег хопа, занятый пользователем, — ошибка.
- **П2. Перехват.** Для каждой позиции `i ≥ 1` каждый достижимый узел получает
  `detour = <C>#<i−1>`. Прежний `detour` узла (включая отсутствие) перекрывается и
  пишется в `changes` с `by = {type: chain, chain: C, position: i}`.
- **П3. Позиция 0** не перехватывается: её узлы идут своими путями.
- **П4. Группы не перехватываются.** Меняются только листья; группа остаётся одной и
  проверяет те же экземпляры, что несут трафик.
- **П5. `rewrite`.** Для перехваченного узла применяется `rewrite` цепочки по его типу.
  Каждое изменённое поле — запись `changes` с `by = {type: chain_rewrite, chain,
  position, node_type}`. Поле записи — путь через точку до листа (`tls.server_name`);
  удалённое патчем `null` поле — запись без `to`.
- **П6. Вход цепочки.** Исходящий `C` дозванивается через хоп `<C>#<n−1>`.
- **П7. Удалённые ключи цепочки.** `idle_timeout`, `strip_evasion`, `strip` в конфиге
  цепочки — ошибка при старте с текстом, что их заменило (как у удалённых
  `awg_masquerade` и `quic_sniff_decoy`).

### 4.2 Конфликты (ошибки при старте)

- **К1. Колец нет; ядро ловит только конфликт перезаписи.** Решение владельца 2026-11-26,
  заменяет прежние К1, К2, К6 и их варианты.
  - **Кольцо** — узел или группа, которые после перезаписи замыкают `detour` на себя:
    `[A, Dir{A, X}]`, `[Dir{A}, A]`, `[Dir1{A, X}, B, Dir2{A, Y}]`, `[A, N]` с
    собственным `detour: N` у `A`. Своего анализа колец ядро не делает: это обычный цикл
    `detour`, и его ловит апстримная проверка порядка запуска (`circular outbound
    dependency`, `adapter/outbound/manager.go`, топосорт по `Dependencies()` — `detour` и
    все члены групп любой вложенности). В ошибке — теги узлов и хопов `<цепочка>#<i>`.
    Перезапись кольцо не маскирует: узел, достижимый на позиции 0, на позиции выше
    перехватывается как любой другой.
  - **Конфликт перезаписи** — то, чего апстрим не увидит, потому что одному узлу или группе
    нужны два разных пути: узел или группа достижимы в двух цепочках, если хотя бы одно
    место — позиция ≥ 1 (вход одной цепочки и позиция другой тоже), или на двух позициях
    ≥ 1 одной цепочки. Общий вход двух цепочек (`[A, B]` и `[A, C]`, Направление на входе
    двух цепочек) — не конфликт: позиция 0 не перехватывается, у узла один свой путь и нет
    управляющего. *Решение владельца 2026-11-26 («у узла один управляющий»; общий вход
    двух цепочек — не конфликт).*
    тег, поставленный в `outbounds` цепочки дважды (`[A, B, A]`, `[Dir, A, Dir]`).
    Достижимость — по всем членам групп любой вложенности, выбор групп не учитывается;
    `direct` и `block` путей не имеют и не считаются. Ошибка короткая и техническая: какой
    тег и каким двум местам (цепочка, позиция) он нужен.
  - Понятные пользователю объяснения и сборка цепочек без колец и конфликтов — задача
    клиентов.
- **К3.** Тип `chain-hop` во входном конфиге.
- **К4.** Цикл: группа на позиции содержит саму цепочку или цепочку, которая её
  перехватывает. Вложенная цепочка допустима только на позиции 0.
- **К5.** Узел на позиции ≥ 1 не может работать через `detour` (решение владельца
  2026-11-26: ошибка загрузки, ключи молча не снимаются, как делали звенья):
  - тип без полей дозвона;
  - фиксированный локальный порт: WireGuard/AWG `listen_port` (апстрим тоже отвергает его
    с `detour`, ошибка перезаписи раньше и называет цепочку), Tailscale `listen_port` и
    `relay_server_port`, OpenConnect `dtls_local_port`. У MASQUE, hysteria, hysteria2,
    tuic, TrustTunnel и OpenVPN-клиента локального порта в конфиге нет;
  Ошибка называет цепочку, позицию, узел и поля.
- **К5а.** `rewrite` цепочки не проверяется на поля соединения: что под `detour` не
  действует, показывает Д1 для любого узла.

### 4.3 Хоп во время работы

- **Х1.** Хоп `i`, позиция включена, на позиции узел — дозвон через этот узел.
- **Х2.** Хоп `i`, позиция включена, на позиции группа — дозвон через группу; группа
  выбирает по своей логике, выбранный член идёт своим `detour` (= хоп `i−1`).
- **Х3.** Выбран `direct` (позиция — `direct` или группа выбрала `direct`), `i ≥ 1` —
  дозвон через хоп `i−1`.
- **Х4.** Позиция `i ≥ 1` выключена — дозвон через хоп `i−1`.
- **Х5.** Позиция 0 выключена — дозвон в сеть напрямую, обычным dialer'ом ядра.
- **Х6.** `block` — отказ.
- **Х7.** Группа, дозваниваясь через выбранного члена, отмечает носителя соединения,
  как сейчас; удаление подмены узла эту отметку не трогает. Хоп носителем не бывает:
  отметка пропускает `chain-hop`, хоп с узлом на позиции отмечает этот узел.
- **Х8. Как хоп выполняет Х3 для группы.** Выбор группы делается на каждом соединении
  (round_robin, sticky, ретрай failover), поэтому проверка выбора в хопе до дозвона
  неверна. Хоп позиции `i ≥ 1` кладёт в контекст дозвона «`direct` = хоп `i−1`», точки
  выбора в группах, где сегодня стоит отметка носителя, подменяют выбранный `direct`
  этим хопом. Хоп 0 метку стирает, хоп выше перезаписывает своей. Других подмен нет:
  выбранный узел идёт сам, своим `detour`. `direct` внутри цепочки значит «на этом
  уровне без дополнительного прыжка», а не «мимо цепочки». Решение владельца 2026-11-26.

### 4.4 `lx.detour.strip`

Фильтр не даёт узлу применить свой механизм, когда под соединением нет настоящего сокета
ядра. В каталоге четыре фильтра, у каждого измеримая цена в туннеле и нет пользы на
участке от релея до сервера:

- `tls.fragment` — разрез ClientHello на пакеты. Без сокета ядра не может дождаться
  подтверждения кусков и спит `fragment_fallback_delay` (500 мс по умолчанию) между
  ними: 0,5–1,5 с на рукопожатие;
- `tls.spoof` — поддельный ClientHello сырым TCP-пакетом. Через ws, grpc, xhttp,
  httpupgrade, mux, QUIC, WireGuard роняет каждое рукопожатие; через vless/trojan поверх
  TLS вбрасывает обманку в поток релея;
- `tls.kernel` — kTLS (`kernel_tx`, `kernel_rx`). Роняет каждое рукопожатие;
- `tls.engine` — движок `apple` (системный TLS macOS/iOS). Требует сокет и роняет
  каждое рукопожатие.

uTLS, padding мультиплексора и padding XHTTP в каталог не входят: за туннелем их видят
релей и сеть от релея до сервера, а цены, которую снятие убирало бы, у них нет.

- **С1.** Узел без `detour` или из `except_outbounds` — фильтры не применяются.
- **С2.** Решение принимается на каждом рукопожатии. Соединение от `detour` — настоящий
  сокет ядра (проверка та же, что у SPEC 150/151/153, включая группу с выбранным
  `direct`) — механизмы узла работают как в конфиге. Поток внутри туннеля — включённые
  фильтры действуют:
  - `tls.fragment` — разрез из конфига узла не делается (`fragment`,
    `fragment_fallback_delay`); `record_fragment` не трогается;
  - `tls.spoof` — ни обёртки, ни сырого пакета;
  - `tls.kernel` — kTLS не включается, TLS остаётся в пространстве пользователя;
  - `tls.engine` — `apple` заменяется на `go` для этого рукопожатия; отпечаток меняется
    на отпечаток Go.
- **С3. Решение `sniff_guard` сильнее фильтра.** Если `sniff_guard` сам формирует это
  рукопожатие (подозревает сниффящий релей на пути), применяется его форма. Фильтр
  снимает только разрез, который пришёл из конфига узла, и не отменяет защиту, которую
  добавил guard. Разрез, снятый фильтром на этом рукопожатии, для guard'а — не выбор
  узла: если узел не задал `record_fragment` явно, guard вправе формировать ClientHello
  сам. Иначе снятие оставило бы ClientHello голым на сниффящем релее.
- **С4.** Опции узла не меняются, в `changes` фильтры не попадают. Снятое видно в
  наблюдаемости соединения и одной строкой в логе: узел, фильтр, причина.
- **С5.** Выключенный фильтр или `"detour": false` — поведение апстрима: механизм
  пробуется на соединении без сокета ядра и, кроме разреза, падает.

### 4.4б Что `detour` не применяет

Апстрим при заданном `detour` строит dialer хопа и не строит dialer узла
(`common/dialer/dialer.go`, `NewWithOptions`: при `Detour != ""` — `NewDetour`, без
`NewDefault`). Поля сокета читает только `NewDefault` (`common/dialer/default.go`), поэтому под
`detour` они молча не действуют. `lx.detour` это поведение не меняет, а делает видимым.

- **Д1.** У любого узла с `detour` (своим или от цепочки) поля `bind_interface`,
  `inet4_bind_address`, `inet6_bind_address`, `bind_address_no_port`, `protect_path`,
  `routing_mark`, `reuse_addr`, `netns`, `connect_timeout`, `tcp_fast_open`,
  `tcp_multi_path`, `disable_tcp_keep_alive`, `tcp_keep_alive`, `tcp_keep_alive_interval`,
  `udp_fragment`, `network_strategy`, `network_type`, `fallback_network_type`,
  `fallback_delay` убираются из представления итогового конфига (`effective` в
  `GetEffectiveConfig` / `GetOutboundConfig`); опции, которые уходят в апстримный код, не
  меняются, поведение целиком за апстримом. Каждое поле — запись `changes`
  `{field, from, by: {type: lx.detour, reason}}` без `to`. `fallback_delay` формально уходит в
  резолвер, но с `detour` параллельного дозвона нет и значение не используется.
- **Д2.** Применяются под `detour` и не трогаются: `domain_resolver`, устаревший
  `domain_strategy` (через тот же резолвер).
- **Д3.** Где апстрим не молчит, поле остаётся как есть: anytls `tcp_fast_open` (ошибка
  загрузки всегда, `protocol/anytls/outbound.go`), openconnect `disable_tcp_keep_alive`,
  `tcp_keep_alive`, `tcp_keep_alive_interval` (протокол применяет их сам,
  `protocol/openconnect/client.go`), impair `connect_timeout` (`protocol/impair/outbound.go`).
- **Д4.** Ни ключа, ни выключателя: `"detour": false` и `except_outbounds` на Д1 не влияют,
  поле не заработало бы ни при каких настройках. Предупреждений в лог нет, рантайм не
  меняется. Решение владельца 2026-11-26.
- **Д5.** Список Д1 сверяется с `common/dialer` на каждом мерже апстрима
  (`docs-lx/lx-release-runbook.md` §3). Устаревший список ошибается только в показе:
  поведение остаётся за апстримом.

### 4.5 `lx.detour.mtu_align`

- **М1.** Правило выравнивания — как в SPEC 120/144, без изменений.
- **М2.** Хоп для выравнивания — путь с ёмкостью
  `min(ёмкость позиции i, ёмкость хопа i−1)`: позиция может быть выключена или выбрать
  `direct` (Х3, Х4), и узел над хопом должен работать в любом из этих состояний.
  Для хопа 0 — ёмкость позиции 0 и прямой сети.
- **М3.** Узел из `except_outbounds` не выравнивается.
- **М4.** Каждое изменённое поле — запись `changes` с `by = {type: mtu_align, mode,
  below, overhead, reason}`; `reason` совпадает со строкой лога. QUIC-узел меняет два
  поля — `initial_packet_size` и `disable_path_mtu_discovery`, это две записи.

### 4.6 Разбор `lx.detour`

- **Р1.** Ключа нет — то же, что `true` (значение по умолчанию).
- **Р2.** `true` → `mtu_align: clamp`, `strip` = каталог ядра.
- **Р3.** `false` → `mtu_align: off`, `strip` выключен — поведение апстрима.
- **Р4.** Объект → каждый подключ по своим правилам; нет `mtu_align` → `clamp`; нет
  `strip` → каталог ядра.
- **Р5.** `strip`: `true` → каталог ядра; `false` → выключен; объект → только
  `filters`; нет `filters` → каталог ядра.
- **Р6.** `filters`: `true` → каталог ядра; `false` → ничего; объект → полное
  перетирание: не указанный фильтр выключен.
- **Р7.** Каталог ядра: `tls.fragment`, `tls.spoof`, `tls.kernel`, `tls.engine` — все
  включены.
- **Р8.** Ошибки при старте: неизвестный ключ на любом уровне; неизвестный тег в
  `except_outbounds`; `lx.mtu_align` — с текстом, куда ключ переехал. Ключи прежнего
  каталога цепочки (`tls.utls`, `multiplex.padding`, `xhttp.padding`) в `filters` —
  неизвестные ключи.
- **Р9.** В итоговом конфиге `lx.detour` записан развёрнутым: все подключи и все
  фильтры явно.

### 4.7 Ручки конфига

- **Н1.** `GetRunningConfig` — снимок до предобработки, как сейчас.
- **Н2.** `GetEffectiveConfig` — снимок после всей предобработки, в той же каноничной
  форме.
- **Н3.** `GetOutboundConfig(tag)` — `original` (узел из Н1), `effective` (из Н2),
  `changes` в порядке применения: П2 → П5 → Д1 → М4. Одно поле, изменённое дважды, — две
  записи, `from` второй равно `to` первой.
- **Н4.** У хопа есть только `effective`.
- **Н5.** Неизвестный тег — ошибка «не найдено».
- **Н6.** Ручки есть в демоне и в `libbox`. `GetChainCloneConfig` удаляется везде.

## 5. Инварианты

- **И1.** У каждого узла один экземпляр и один `detour` на всё время работы box'а.
- **И2.** Узел перехвачен не более одной цепочкой и на одной позиции.
- **И3.** Группа на позиции ≥ 1 проверяет своих членов тем путём, которым идёт трафик.
- **И4.** `changes`, применённые к `original`, дают `effective` — для каждого узла.
- **И5.** `"detour": false` — поведение под `detour` как в апстриме. Без ключа —
  выравнивание MTU как сегодня, а фильтры `strip` действуют на любой узел с `detour`,
  не только на бывшие звенья цепочек.
- **И6.** В апстримных файлах удаляются lx-вставки звеньев: обход WG-звеньев в роутере,
  память опций и внутренние исходящие в менеджерах. Остаются короткие вставки: хук выбора в
  селекторе (носитель соединения и Х8, тот же вызов, что был) и по одной строке на фильтры
  `tls.spoof`, `tls.kernel`, `tls.engine` (§7.14). Других новых вставок нет.
- **И7.** Фильтр `strip` никогда не отменяет форму рукопожатия, выбранную `sniff_guard`.

## 6. Сценарии

**Т1. LxBox#233.** `c-proton = [o-direct, o-proton]`, `o-proton` — urltest из WG-узлов
с `detour: o-ru`. П1 добавляет `c-proton#0`, `c-proton#1`. П2: каждый член `o-proton`
получает `detour = c-proton#0`, в `changes` — `o-ru → c-proton#0`. Проверки группы
идут через `o-direct` (И3). Мёртвый по этому пути узел краснеет и уходит из пула. Сессия
WG одна (И1).

**Т2. Селектор с `direct` на позиции 1.** `[A, S, C]`, `S` выбирает `direct`. Узел `C`
идёт через хоп 1 → Х3 → хоп 0 → `A`. Мимо `A` трафик не уходит.

**Т3. Выключенная позиция.** `[A, B, C]`, позиция 1 выключена. `C` → хоп 1 → Х4 →
хоп 0 → `A`. MTU узла `C` выровнен по М2 и подходит для обоих путей.

**Т4. Группа в двух цепочках.** `X = [A, g]`, `Y = [B, g]`, `g` — группа из vless. К1:
ошибка с именами `g`, `X`, `Y` и позиций.

**Т5. Узел вне цепочек.** Маршрут ведёт прямо на перехваченный узел `N`. Соединение
идёт через хоп цепочки. Не ошибка: путь у `N` один.

**Т6. strip через селектор.** Узел `N` (TLS с `fragment`) с `detour: S`,
`S` = [`direct`, `wg-relay`]. `S` выбрал `direct` → рукопожатие с разрезом (С2).
`S` переключился на `wg-relay` → следующее рукопожатие без разреза, без пауз по 500 мс.

**Т6а. guard и фильтр.** Узел `N` с `detour: wg-relay`, `sniff_guard` пометил релей
как сниффящий и формирует рукопожатие сам. Применяется форма guard'а (С3), фильтр её не
отменяет (И7). Пометка снята — следующее рукопожатие по С2, без разреза.

**Т6б. spoof через ws.** Узел `N` с `tls.spoof` и транспортом ws, `detour: wg-relay`.
Под ws нет сокета ядра — С2, рукопожатие без обманки, в логе строка. Тот же узел с
`detour: S`, `S` выбрал `direct` — сокет ядра, обманка уходит.

**Т6в. kTLS на роутере.** Узел с `kernel_tx: true` за WG-релеем — С2, TLS без kTLS,
рукопожатие проходит. С `"detour": false` — поведение апстрима, рукопожатие падает (С5).

**Т6г. apple за туннелем.** Узел с `tls.engine: apple` на macOS, `detour: wg-relay` — С2,
рукопожатие движком `go`, в логе строка. `"filters": {"tls": {"fragment": true}}` —
`engine` не указан, рукопожатие падает с ошибкой апстрима (Р6, С5).

**Т7. Исключение.** `foreign-node` в `except_outbounds`: ни один фильтр не применяется
(С1), MTU не выравнивается (М3).

**Т11. Узел на входе и на позиции.** `X = [N, B]`, `Y = [A, N]`. У `N` два места — К1,
ошибка с именами `X`, `Y`, `N`.

**Т12. Выключенный вход.** `[A, B]`, позиция 0 выключена. Узел `B` → хоп 0 → Х5 →
прямой dialer ядра. Фильтр видит настоящий сокет ядра и разрез оставляет (С2).

**Т13. Носитель соединения.** `c-proton = [o-direct, o-proton]`, группа выбрала
`NL-FREE#114`. В наблюдаемости соединения путь: `c-proton → o-proton → NL-FREE#114 →
c-proton#0 → o-direct` (Х7). Тот же путь, что показывался при копиях.

**Т14. rewrite и выравнивание.** У цепочки `rewrite: {wireguard: {mtu: 1200}}`, ниже
WG-туннель. Узел получает две записи `changes` по полю `mtu`: `1420 → 1200` от
`chain_rewrite` и `1200 → 1120` от `mtu_align`; `from` второй равно `to` первой (Н3, И4).
Цифры условные.

**Т15. Цикл через перехват.** `[A, N]`, у `A` собственный `detour: N`. `N` перехвачен с
`detour = <C>#0`, хоп 0 ведёт в `A`, `A` ведёт в `N` — кольцо (К1): апстримная ошибка
`circular outbound dependency` с тегами `A`, `N`, `C#0`.

**Т8. Объект `filters` без ключей.** `"strip": {"filters": {}}` — ничего не снимается
(Р6).

**Т9. Ручка хопа.** `GetOutboundConfig("c-proton#0")` — только `effective` с
`type: chain-hop`, `outbound: o-direct`, без `below` (Н4).

**Т10. Старый ключ.** Конфиг с `lx.mtu_align: "fill"` — ошибка «переехал в
`lx.detour.mtu_align`» (Р8).

**Т16. DNS узла позиции.** Узел позиции 1 резолвит свой сервер через DNS-сервер с
`detour: dns-sel`, `dns-sel` выбрал `direct`. Запрос уходит напрямую: метка Х8 живёт только
до выбора узла группой (хук выбора возвращает контекст без метки), хоп с узлом на позиции
её стирает. Ревью 2026-11-26.

### 6.1 Ограничения

- **Л1. Проба `direct` в группе на позиции ≥ 1.** urltest меряет член `direct` прямым
  путём: проба группы идёт мимо хука выбора и без метки Х8, а трафик при выбранном
  `direct` идёт через хоп ниже. Группа может выбрать `direct` по задержке, которой у
  реального пути нет. Свести пробу к пути трафика можно только вставкой в апстримный код
  проб; не делаем.
- **Л2. Цикл через DNS.** Если `detour` DNS-сервера ведёт в перехваченный узел, а узел
  нижней позиции резолвит свой сервер через этот DNS, во время работы получается петля.
  Проверка порядка запуска её не видит: граф `detour` из опций DNS-серверов не содержит. Раньше оригинал узла
  шёл своим путём, и петли не было.
- **Л3. Группа на позиции ≥ 1 — вся в цепочке.** Маршрут прямо на такую группу (правило,
  `final`, другая группа) тоже идёт путём цепочки (Т5). При загрузке — одна строка Warn со
  списком таких групп.

## 7. Что проверить в коде

1. Порядок шагов предобработки: перезапись цепочек → выравнивание MTU → сборка
   `sniff_guard` (он строит носителей по графу `detour` из опций и должен видеть хопы).
2. Выравнивание MTU умеет тип `chain-hop` по М2.
3. Регистрация `chain-hop` в реестре и запрет в пользовательском конфиге (К3) не
   конфликтуют: хопы добавляются после разбора входного конфига.
4. Порядок запуска: узел → хоп ниже → позиция; WG-endpoint резолвит `detour` при старте
   (SPEC 029) и видит запущенный хоп.
5. Пять точек подмены узла в группах: подмена уходит, отметка носителя (Х7) остаётся.
6. Роутер: отдельный обход звеньев цепочек для смены сети и доступности уходит;
   перехваченные WG-узлы — обычные endpoint'ы в общем обходе.
7. Хранилище выключенных позиций (SPEC 075) работает с хопами без звеньев.
8. Разрез ClientHello (С2) встраивается в тот же путь, которым `sniff_guard` формирует
   рукопожатие: решение едет вместе с соединением, вставок в апстримный TLS-слой нет.
   Проверка «настоящий сокет ядра» доступна в этой точке для потоковых соединений.
10. Статус цепочки для UI: поля звеньев (состояние, соединения, MTU, снятое) уходят;
    по позициям остаются выбранный узел, выключение и счётчики ошибок.
11. Каноничная запись итогового конфига совпадает по форме с `GetRunningConfig`, чтобы
    разница `original` / `effective` состояла только из `changes`.
12. Шаг перезаписи живёт за `with_lx_chain`: общая lx-предобработка зовёт его через
    include-файл, как сейчас регистрируется сам тип `chain`. Без тега в сборке нет ни
    перезаписи, ни типа `chain-hop`.
13. Итоговый конфиг берётся из box после предобработки: демон сейчас снимает
    `GetRunningConfig` до создания box, поэтому `GetEffectiveConfig` и
    `GetOutboundConfig` читают снимок, который box сохраняет сам. Так же в `libbox`.
14. Фильтры `tls.spoof`, `tls.kernel`, `tls.engine` — по одной lx-строке: в применении
    spoof и в выборе движка `apple` (`common/tls/client.go`, файл уже с lx-вставками) и в
    рукопожатии kTLS (`common/tls/ktls.go`). Решение о сокете ядра едет на conn от того же
    шва, где `sniff_guard` формирует рукопожатие. Рукопожатие, переданное движку `go`,
    спрашивает guard один раз — на внешнем шве; внутренний вызов идёт без попытки guard'а.
15. Счётчики трафика для отчёта об энергопотреблении оборачивают сокет на прямом пути.
    По чтению кода обёртка не прозрачна для поиска TCP-сокета в разрезе ClientHello, и
    тогда разрез спит по 500 мс и без туннеля. Не воспроизведено; проверить, и если так —
    это отдельный баг, не эта задача. Проверка С2 обязана обходить эти счётчики.
16. Связи, которые не меняются (SPEC §2.4): сетевые опции узла при `detour` не
    применяются апстримом; QUIC над туннелем закрыт выравниванием MTU и усечением
    датаграмм (задачи 120/144/150); `sniff_guard` решает по пути. Тесты перезаписи
    проверяют, что хопы попадают в оба графа — выравнивания и носителей guard'а.

## 8. Решения владельца

Приняты 2026-11-25/26:

- цепочка перехватывает `detour` любого узла на позиции ≥ 1, собственный `detour`
  перекрывается без ошибки;
- двое не могут перехватить один узел — ошибка при старте;
- хоп — обычный исходящий в конфиге, внутренний тип, клиенты фильтруют по типу;
- `strip` и `mtu_align` — внутри `lx.detour`, один `except_outbounds` на уровне
  `lx.detour`; `filters` вложенные; объект — полное перетирание;
- значение по умолчанию — `"detour": true`: выравнивание MTU и весь каталог `strip`;
  `false` — всё выключено, поведение апстрима;
- ручки `GetRunningConfig`, `GetEffectiveConfig`, `GetOutboundConfig`; в ответе
  `original`, `effective`, `changes`; `by` — объект с `type`;
- `GetChainCloneConfig` удаляется целиком;
- новая задача вместо правок по старым, со ссылками из старых.
- `idle_timeout`, `strip_evasion`, `strip` цепочки — ошибка загрузки с объяснением (П7);
  клиентам изменения доносятся issue на бамп пина после релиза (SPEC §5);
- решение `sniff_guard` сильнее фильтра `strip` (С3, И7);
- каталог `strip`: `tls.fragment`, `tls.spoof`, `tls.kernel`, `tls.engine`; отдельного
  ключа для механизмов, которым нужен сокет ядра, нет — это те же фильтры; uTLS и оба
  padding убраны: за туннелем их видят релей и сеть до сервера;
- `direct` в группе на позиции ≥ 1 — хоп ниже через метку в контексте дозвона (Х8); от
  метки цепочки остаётся только это;
- К5: фиксированный локальный порт узла на позиции ≥ 1 — ошибка загрузки; поля соединения,
  которые апстрим под `detour` тихо игнорирует, — свойство `detour`, видимое в `changes`
  у любого узла (Д1–Д4), не ошибка и не правило цепочки;
- статус цепочки — унарный по тегу, как статусы endpoint'ов: позиции, выбранный узел на
  каждой, выключение, счётчики ошибок; общий список `GetChains` уходит.

## 9. Константы

Новых нет. Режимы `mtu_align` прежние; каталог `strip` — `tls.fragment`, `tls.spoof`, `tls.kernel`, `tls.engine`.
