Здесь — проблема, что меняется и критерии приёмки.

## 1. Проблема

Цепочка на позиции ≥ 1 создаёт копию выбранного узла с `detour` через позицию ниже,
а оригинал остаётся жить со своим `detour`. У узла два экземпляра на двух путях.

В LxBox#233 это сломало WireGuard: группа `o-proton` на позиции 1 цепочки
`c-proton = [o-direct, o-proton]` проверяет своих членов, то есть оригиналы через
`o-ru`. Проверки держат живой сессию оригинала, копия в цепочке с тем же ключом не
проходит handshake, соединения через цепочку падают по таймауту, а группа остаётся
зелёной, потому что меряет не тот путь. Ручная диагностика из UI тоже ходит через
оригинал.

Для stateless-узлов то же раздвоение тише: группа на позиции ранжирует узлы по пути,
по которому трафик не идёт, а штрафы и sticky делятся между двумя ролями узла.

## 2. Что меняется

1. **Цепочка перехватывает `detour`.** Каждому узлу, до которого цепочка доходит на
   позиции ≥ 1 (включая всех членов групп любой вложенности, выбранных и нет), при
   загрузке конфига ставится `detour` на хоп позиции ниже. Собственный `detour` узла
   перекрывается. Копий нет: у узла один экземпляр и один путь.
2. **Хоп — внутренний исходящий `chain-hop`** с тегом `<цепочка>#<i>`. Его вставляет
   перезапись в общий список исходящих. В пользовательском конфиге тип запрещён.
3. **Колец нет.** Кольцо после перезаписи — обычный цикл `detour`; его ловит апстримная
   проверка порядка запуска (`circular outbound dependency`, с тегами хопов). Ядро само
   проверяет только конфликт перезаписи: узел или группа в двух цепочках или на двух
   позициях ≥ 1 одной цепочки, повтор тега (ALGORITHM К1).
4. **`strip` уходит из цепочки в `lx.detour.strip`** и действует на любой узел с
   `detour`: на каждом рукопожатии, если под соединением нет настоящего сокета ядра,
   включённые фильтры не дают узлу применить механизм. Фильтры: разрез ClientHello (в
   туннеле стоит 0,5–1,5 с на рукопожатие), `tls.spoof`, kTLS и движок `apple` (без
   сокета ядра роняют рукопожатие). Решение `sniff_guard` сильнее фильтра. uTLS и оба
   padding из каталога убраны.
5. **`lx.mtu_align` переезжает в `lx.detour.mtu_align`.** Исключения у обоих механизмов
   общие: `lx.detour.except_outbounds`.
6. **Ручки конфига:** `GetRunningConfig` (как есть), новые `GetEffectiveConfig` и
   `GetOutboundConfig(tag)` с `original` / `effective` / `changes`.
   `GetChainCloneConfig` удаляется.

### 2.1 Блок `lx.detour`

```json
"lx": {
  "detour": {
    "mtu_align": "clamp",
    "strip": {
      "filters": {
        "tls": { "fragment": true, "spoof": true, "kernel": true, "engine": true }
      }
    },
    "except_outbounds": ["foreign-node"]
  }
}
```

По умолчанию — `"detour": true`: ключа нет — то же, что `true`.

| Запись | `mtu_align` | `strip` |
|--------|-------------|---------|
| ключа `detour` нет / `true` | `clamp` | каталог ядра: все четыре фильтра |
| `"detour": false` | `off` | выключен — поведение апстрима |
| объект | что написано; без ключа — `clamp` | что написано; без ключа — каталог ядра |

`strip` и `filters` принимают `true` / `false` / объект. Объект — полное перетирание:
не указанный фильтр выключен. Неизвестный ключ на любом уровне, неизвестный тег в
`except_outbounds` — ошибки при старте с полным путём ключа. `lx.mtu_align`,
`strip_evasion` и `strip` в конфиге цепочки — ошибки при старте с указанием нового
места; `idle_timeout` цепочки — ошибка с текстом, что звеньев больше нет.

### 2.2 Ручка `GetOutboundConfig(tag)`

```json
{
  "tag": "NL-FREE#114",
  "original":  { "type": "wireguard", "tag": "NL-FREE#114", "detour": "o-ru" },
  "effective": { "type": "wireguard", "tag": "NL-FREE#114", "detour": "c-proton#0" },
  "changes": [
    { "field": "detour", "from": "o-ru", "to": "c-proton#0",
      "by": { "type": "chain", "chain": "c-proton", "position": 1 } }
  ]
}
```

Принимает теги исходящих, endpoint'ов, хопов и групп. У хопа нет `original` и `changes`.
`by.type` — закрытый список: `chain`, `chain_rewrite`, `lx.detour` (поля, которые апстрим под `detour` не применяет, ALGORITHM Д1), `mtu_align`.

### 2.3 Фильтры `strip`

| Фильтр | Что не применяется без сокета ядра | Почему |
|--------|------------------------------------|--------|
| `tls.fragment` | разрез ClientHello на пакеты из конфига узла; `record_fragment` не трогается | без сокета ядра разрез не может дождаться подтверждения кусков и спит 500 мс между ними |
| `tls.spoof` | поддельный ClientHello сырым TCP-пакетом | через ws, grpc, xhttp, httpupgrade, mux, QUIC, WireGuard роняет каждое рукопожатие; через vless/trojan поверх TLS вбрасывает обманку в поток релея |
| `tls.kernel` | kTLS (`kernel_tx`, `kernel_rx`) | роняет каждое рукопожатие |
| `tls.engine` | `apple` заменяется на `go`; отпечаток меняется на отпечаток Go | системный TLS macOS/iOS требует сокет и роняет рукопожатие |

На участке от релея до сервера ни у одного из механизмов пользы, которую снимал бы
фильтр, нет: релей пересылает только настоящие байты. В лог — одна строка на снятое.

### 2.4 Что под `detour` уже работает и не меняется

- **Сетевые опции узла.** Апстрим при заданном `detour` не строит собственный dialer
  узла, поэтому `tcp_fast_open`, `tcp_multi_path`, keepalive, `bind_interface`,
  `routing_mark`, `reuse_addr`, `udp_fragment`, `connect_timeout`, `netns`,
  `protect_path` молча не применяются, а параллельный дозвон по адресам выключен. После
  перехвата это касается и узлов на позициях ≥ 1; `GetOutboundConfig` показывает такие
  поля в `changes` с `by.type: lx.detour` (ALGORITHM Д1). Фиксированный локальный порт — ошибка
  загрузки (К5). Решения владельца 2026-11-26.
- **QUIC поверх туннеля.** `initial_packet_size` и выключение PMTUD для узлов над
  IP-туннелем выставляет выравнивание MTU (`lx.detour.mtu_align`, бывший
  `lx.mtu_align`, задачи 120/144); датаграммы больше, чем пропускает потоковый
  `detour`, усекаются (задача 150). Хопы цепочки входят в тот же граф `detour`.
- **`sniff_guard`.** Защита от сниффинга на релее уже решает по пути соединения
  (сокет ядра или носитель) и сильнее фильтра `strip`: фильтр не отменяет форму
  рукопожатия, выбранную guard'ом. Граф носителей guard строит по `detour` из опций,
  поэтому перезапись цепочек идёт до его сборки.
- **Отклонено при разборе** как не имеющее цены в туннеле или как договор с сервером:
  мусорные пакеты AWG, паузы padding в VLESS-шифровании, `record_fragment`, padding
  anytls и мультиплексора, смена портов hysteria2, keepalive транспортов, `flow`,
  `obfs`, ECH, REALITY, параметры заголовков AWG.

## 3. Что уходит из кода

- механизм звеньев: создание на лету, учёт соединений, вытеснение по `idle_timeout`,
  прогрев позиций, ошибки прогрева;
- своя MTU-логика цепочки (её покрывает общее выравнивание по `detour`);
- подмена выбранного узла его звеном в пяти точках дозвона групп, из них две — lx-вставки
  в апстримном селекторе; запись носителя соединения в этих точках остаётся;
- метка цепочки в контексте дозвона — кроме одного: хоп позиции ≥ 1 кладёт в контекст
  «`direct` = хоп ниже», и точки выбора групп подменяют выбранный `direct` этим хопом
  (ALGORITHM Х8, решение владельца 2026-11-26);
- отдельный обход WG-звеньев в роутере (смена сети, доступность);
- `GetChainCloneConfig` в protobuf, демоне и `libbox`.

## 4. Критерии приёмки

1. Конфиг LxBox#233 на стенде: группа на позиции 1 меряет путь через позицию 0; мёртвый
   по этому пути узел выводится из пула; сессия WG одна.
2. Каждое правило ALGORITHM.md покрыто тестом с номером правила в имени.
3. Для каждого узла каждого тестового конфига `changes`, применённые к `original`,
   дают `effective`.
4. Сборка под `LX_TAGS` и без тегов; тесты затронутых пакетов зелёные; стенд цепочки
   `lx-test/chain` зелёный.
5. FEATURE 015 переписана под новую модель; FEATURE 004 и задачи 073/075/120/144
   ссылаются на эту задачу там, где их поведение изменилось; модель звеньев и причина
   отказа от неё — в HISTORY.md задачи 073.
6. После релиза в LxBox и singbox-launcher заводится по issue на бамп пина с
   инструкцией, что поменялось (§5). Сами клиенты правят генераторы и документацию
   вместе с бампом; ядро в их репозитории не коммитит.

## 5. Что донести клиентам

Текст для issue в LxBox и singbox-launcher после релиза:

- **Ошибки загрузки, которые надо убрать из генераторов:** `strip_evasion`, `strip` и
  `idle_timeout` в конфиге цепочки; `lx.mtu_align` (переехал в `lx.detour.mtu_align`,
  `except` → `lx.detour.except_outbounds`). Лаунчер сейчас пишет `idle_timeout` цепочки
  из редактора цепочки.
- **Поведение по умолчанию:** без ключа `lx.detour` ядро снимает фильтры `strip` с любого
  узла, чьё соединение пришло из туннеля, а не только со звеньев цепочек. Чтобы вернуть
  поведение апстрима — `"detour": false`.
- **Новая ошибка загрузки у узлов на позициях ≥ 1:** фиксированный локальный порт
  (WireGuard `listen_port`, Tailscale `listen_port` / `relay_server_port`, OpenConnect
  `dtls_local_port`). Поля сокета, которые апстрим под `detour` тихо не применяет
  (`bind_interface`, `routing_mark`, `tcp_fast_open` и др., ALGORITHM Д1), ошибкой не
  становятся: у любого узла с `detour` они видны в `changes` с `by.type: lx.detour`.
- **Поведение:** узлы на позициях ≥ 1 цепочки ходят путём цепочки везде, включая прямые
  маршруты и ручную диагностику; собственный `detour` такого узла перекрывается.
- **Колец и конфликтов нет:** клиент не собирает их сам. Ядро отвечает техническими
  ошибками: апстримной `circular outbound dependency` с тегами хопов `<цепочка>#<i>`
  (`[A, Dir{A, X}]` — кольцо) и ошибкой конфликта перезаписи «`<тег>` is needed on chain
  … and on chain …» (узел или Направление в двух цепочках, на двух позициях ≥ 1 одной
  цепочки, повтор тега). Генератор: для верхней позиции — копия Направления без узлов,
  стоящих ниже; узел или Направление в двух цепочках — копии под своими тегами
  (WireGuard — разные ключи).
- **Списки исходящих:** появляются хопы типа `chain-hop` с тегами `<цепочка>#<i>`;
  UI скрывает их по типу.
- **Ручки:** `GetChainCloneConfig` и `GetChains` удалены; новые `GetEffectiveConfig`,
  `GetOutboundConfig(tag)` (JSON-объект `tag` / `original` / `effective` / `changes`) и
  `GetChainStatus(tag)`; в позиции статуса нет полей звеньев (`clone`, `clonesCreated`,
  `clonesEvicted`, `liveClones`). `SetChainPositionEnabled` больше не отдаёт `warmupError`,
  в `libbox` возвращает только ошибку.
- **Документация LxBox:** `docs/KERNEL.md`, FEATURE 006 (обе языковые версии).
