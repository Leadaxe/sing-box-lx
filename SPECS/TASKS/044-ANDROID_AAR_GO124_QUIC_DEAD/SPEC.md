# SPEC: 044 — ANDROID_AAR_GO124_QUIC_DEAD

| Поле | Значение |
|------|----------|
| Тип | B (bug) — среда сборки AAR, не код форка |
| Статус | C (complete) — корень изолирован на железе, фикс девайс-верифицирован; ждёт среза релиза (lx.19-rc.2+) |
| Жалоба | 4pda, 2026-08-01: «hysteria2 не работает в LxBox v2.19.0», личный сервер жив в v2raytun/v2rayng на том же телефоне/провайдере |

AAR, собранный тулчейном **Go 1.24.x** (как делал CI через `go-version-file: go.mod`), убивает **все quic-go-аутбаунды** (hysteria2, tuic, masque-h3) на части вендорских Android-ядер: каждый dial внутри VPN-процесса виснет до `context deadline exceeded`. Тот же исходник, собранный **Go 1.25.x**, на том же устройстве работает. Фикс — явный пин `go-version: '1.25.x'` во всех трёх AAR-джобах (`lx-release.yml` `build_android`, `lx-build.yml` `android-aar`, `lx-ci.yml` `android`).

---

## 1. Симптом и матрица воспроизведения

Симптом на устройстве (OnePlus Nord CE 2 / CPH2411, MTK Dimensity 900, Android 15, ColorOS): в LxBox все Hysteria-узлы и MASQUE h3 — `-1` в тесте пинга, соединения не поднимаются вовсе; TCP-протоколы (VLESS/Trojan/gRPC/XHTTP), WARP AWG (wireguard-go UDP) и MASQUE h2 — живы. В логах ядра только `open connection … context deadline exceeded`, ни одной сетевой ошибки.

Матрица (личный hy2-сервер репортёра, 2026-08-02):

| Стенд | Сборка | hy2 |
|---|---|---|
| macOS desktop-ядро (HEAD и v1.14.0-lx.17-rc.5), go1.25.5 | CLI | ✅ |
| Эмулятор API 34 (generic kernel), голый android-бинарь go1.25.5 | CLI | ✅ |
| Эмулятор, LxBox v2.19.0 release (AAR lx.17-rc.5 из CI) | AAR go1.24 | ✅ (!) |
| Эмулятор, LxBox 2.19.1-dev.9 (AAR lx.19-rc.1 из CI) | AAR go1.24 | ✅ (!) |
| **CPH2411**, LxBox dev.9 (AAR lx.19-rc.1 из CI) | AAR go1.24 | ❌ −1 ×3 |
| **CPH2411**, голый android-бинарь ядра, VPN выключен | go1.25.5 | ✅ 0.37s |
| **CPH2411**, LxBox + AAR, собранный локально | **go1.25.5** | ✅ 124–208ms ×7 |

Ключевая пара — две последние строки: единственная переменная — версия Go-тулчейна. Эмулятор с generic-ядром дефект не показывает ни на одной сборке — нужен вендорский кернел.

## 2. Что исключено по пути

- **Конфиг/клиент**: LxBox-пайплайн эмитит hy2-аутбаунд байт-в-байт как рабочий ручной конфиг; минимальный конфиг (tun + один hy2, без правил) мёртв так же; socks-inbound в том же VPN-процессе мёртв так же (tun/gvisor вне пути).
- **Сеть/оператор**: параллельно жив второй канал (сотовая off — без изменений), голый бинарь с того же телефона по тому же Wi-Fi работает.
- **UDP GSO / ECN** (главные исходные подозреваемые по аналогии со SPEC 010): на воспроизводящей go1.24-сборке диагностические ручки (см. §4) `QUIC_GO_DISABLE_GSO` / `QUIC_GO_DISABLE_ECN` — по одной и обе разом — **не лечат**. Offload-пути quic-go невиновны.
- **badtls/badlinkname**: констрейнт `go1.25 && badlinkname` — на go1.24 badtls и так заглушка; активный badtls (go1.25) совпадает с *рабочей* сборкой.
- **Источник**: между релизным тегом и HEAD только docs/CI-коммиты; локальные AAR собирались из идентичного дерева.

## 3. Корень и фикс

Корень — взаимодействие **stdlib/runtime Go 1.24** с вендорским ядром в VPN-процессе (протектнутый UDP-сокет). До конкретного изменения stdlib не доводили: бинарный дифф тулчейнов однозначен, Go 1.25 дефект устраняет, дальнейшая археология не окупается (при желании — bisect по go1.24.x→1.25.0 на стенде из §5).

Фикс: во всех AAR-джобах явный `go-version: '1.26.x'` вместо `go-version-file: go.mod` (go.mod остаётся `go 1.24.x` ради паритета с upstream — из-за этого go-version-file молча откатывал тулчейн). Порог дефекта — «>= 1.25»; пин держим на последней стабильной минорке, девайс-верифицированы обе: go1.25.5 (124/208/159 ms) и go1.26.5 (140/155/180 ms). Десктоп/CLI-джобы не тронуты: дефект специфичен для android-вендорских ядер. Правило на будущее: минорку в пине поднимать только после прогона AAR на реальном устройстве (эмулятор дефект этого класса не показывает).

## 4. Диагностические ручки (остаются в ядре)

`experimental/libbox/quic_env_knobs_lx.go` — статические экспорты `SetQuicGSODisabled(bool)` / `SetQuicECNDisabled(bool)` (Go-side `os.Setenv` родных ручек quic-go; читаются на каждом новом сокете → применяются на следующем реконнекте, рестарт процесса не нужен). Потребитель — LxBox Debug API `POST /action/quic-knobs?gso=on|off&ecn=on|off` (задача §341 LxBox). Именно они закрыли GSO/ECN-ветку за два HTTP-вызова без пересборок; оставлены для будущих полевых диагнозов offload-класса.

## 5. Верификация

Финальная сборка (AAR go1.25.5 + ручки, LxBox dev.10) на CPH2411: hy2-узел репортёра 124/208/159 ms тремя прогонами подряд, Chrome через туннель ходит. Регрессий по остальным узлам нет (TCP/AWG/MASQUE h2 живы как были). Repro-стенд: Debug API LxBox (`/action/urltest` + `/state`) + `adb forward`; полный сценарий — в дневнике задачи LxBox §341.

## NB

- Мёртвые hy2-узлы **подписки** (11 шт.) и MASQUE h3 этим фиксом не оживают — у них свои причины (см. память/реестр «мёртвые узлы подписки»); проверка после фикса это подтвердила: личный сервер жив, подписочные hy2 — нет.
- `badlinkname` на go1.25 снова линкуется (badtls теперь `go1.25 && badlinkname`); заметка памяти «badlinkname needs go1.24.x» устарела в этой части.
