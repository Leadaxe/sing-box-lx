# TEST_PLAN 062 — конфиг masque к стандарту, с алиасами

Задача меняет **только разбор конфига**, поэтому основной вес — на юнит-тестах декода.
Живые прогоны нужны лишь чтобы подтвердить: то, что работало вчера, работает и сегодня.

## Правило, без которого прогон бессмысленен

Схему проверять **живым декодом через registry** (`box.New` / `include`-путь), а не
чтением структуры и не `json.Unmarshal` в изолированный тип. Прецедент известен: badjson
схлопывает пустые значения, и «поле есть» на глаз ≠ «поле дошло до кода»
([SPEC 060](../060-TLS_FRAGMENT_AUTO_ON_DETOUR/SPEC.md) §3.3,
[SPEC 021](../021-MASQUE_CONNECT_IP_OUTBOUND/SPEC.md)).

---

## A. Совместимость: старые конфиги (главное)

Эталон — реальный конфиг из LxBox-генератора, целиком на старых именах.

| # | конфиг | ожидание |
|---|---|---|
| A1 | `network: h3` + `sni` + `mtu` (боевой) | поднимается, `warp=on`; в логе ровно **одна** deprecation-строка |
| A2 | `network: h2` + `sni` + `skip_cert_verify: true` | поднимается, pinning отключён |
| A3 | `record_fragment: true` (плоский) | фрагментация включена — проверять фактом, не только успехом дайла |
| A4 | `fragment_fallback_delay: "20ms"` (плоский) | значение доехало до `tf.NewConn` |
| A5 | старый конфиг под `detour` | авто-`record_fragment` из SPEC 060 по-прежнему срабатывает |

A1 — обязательный: это ровно то, что сейчас у пользователей в подписках.

## B. Новая схема

| # | конфиг | ожидание |
|---|---|---|
| B1 | `transport: h3` + `tls.server_name` | поднимается, `warp=on` |
| B2 | `tls.insecure: true` | pinning отключён (эквивалент A2) |
| B3 | `tls.record_fragment: true` | эквивалент A3 |
| B4 | `tls: {}` (пустой блок) | валиден; ведёт себя как «tls не задан» — проверять живым декодом |
| B5 | `tls` отсутствует вовсе | дефолты профиля, как сегодня |
| B6 | **`tls.disable_sni: true`** | ClientHello **без** SNI (§8 шаг 6); проверять на проводе, а не по успеху |

B6 — новая возможность, которой сегодня нет; на части путей endpoint отвечает только без
SNI, поэтому проверять отдельно.

## C. Разрешение старое/новое (§2)

| # | вход | ожидание |
|---|---|---|
| C1 | только новое | новое, **без** deprecation-строки |
| C2 | только старое | старое + ровно одна deprecation-строка |
| C3 | оба, значения совпадают | принято, молча |
| C4 | оба, значения различаются (`sni` vs `tls.server_name`) | **fail-fast**, в тексте оба имени |
| C5 | `network: h3` + `transport: h2` | fail-fast |
| C6 | `skip_cert_verify: true` + `tls.insecure: false` | fail-fast (старое `true` против нового `false`) |
| C7 | `skip_cert_verify: false` + `tls.insecure: true` | принято, `insecure` = true, **без** ошибки |

C6/C7 — ловушка `bool` из §8 шага 2: «не задано» и «`false`» неразличимы, поэтому
конфликтом считается только `старое == true && новое == false`. C7 обязателен — он
проверяет, что мы не объявили конфликтом обычный случай.

## D. Предупреждения (§1.3)

| # | вход | ожидание |
|---|---|---|
| D1 | `tls.alpn: ["h3"]` | warning, поле проигнорировано, узел работает |
| D2 | `tls.ech.enabled: true` | warning, игнор |
| D3 | `tls.reality.enabled: true` | warning, игнор |
| D4 | `transport: h3` + `tls.record_fragment: true` | warning «на QUIC резать нечего», узел работает |
| D5 | `transport: h2` + `tls.record_fragment: true` | **без** warning |

Во всех случаях — именно `logger.Warn`, а не ошибка: конфиг остаётся валидным.

## F. Статика и сборка

- `make -f Makefile.lx lx-build` — полный набор тегов;
- сборка **без** `with_quic` (stub-путь) — masque не должен ломать её;
- `go vet`, `gofmt -l` по lx-owned файлам;
- `go test -race ./protocol/masque/ ./transport/masque/... ./option/`;
- `staticcheck` (если доступен) — увидит `// Deprecated:` и не должен ругаться на наши
  же внутренние обращения к legacy-полям: там нужен `//nolint:staticcheck`, как в
  `common/dialer/dialer.go:90`.

## G. Что проверить руками до релиза

1. **Один узел, старый конфиг** — реальная подписка, ничего не меняя: работает + одна
   строка в логе.
2. **Тот же узел, переписанный на новую схему** — тот же результат, без строки.
3. **Лог не зашумлён**: N masque-узлов на старых именах дают N строк (по одной на узел),
   а не N×5 (по одной на поле) — см. §8 шаг 5.

Пункт 3 стоит проверить на боевом конфиге с несколькими masque-узлами: это то, что
пользователь увидит первым после обновления.
