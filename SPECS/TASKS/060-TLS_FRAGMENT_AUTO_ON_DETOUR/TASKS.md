# TASKS — SPEC 060 `lx.sniff_guard`

Контракты и волны — [PLAN.md](PLAN.md). Отметка `[x]` ставится по факту, после ревью.

## Волна 1 — фундамент (параллельно)

- [x] **A. `option`** — `lx.sniff_guard`: структуры, строгий разбор, ошибки с именем ключа
      (`outbound_type` — `true`, `[]`, неизвестный тип; неизвестное значение и группа в карте;
      `delay` ≤ 0; неизвестный ключ), канонизация (нет метода у обеих секций = нет блока),
      resolved-типы из PLAN §2, схема; тесты, в том числе `[]` на сыром JSON.
- [x] **B. `common/lxsniffguard`** — метки, стартовые состояния, ожидающая пара (10 мин, один
      дайл), проба на спуск (окно 10 мин на ключ), право двигать метку только у узла с
      несовпадающим SNI, личный отказ (симметричный, окно 10 мин на узел), отметка рукопожатия,
      `Node.Dial` с быстрым повтором, `Peek`/`Report`, смена сети, `persist` через интерфейс
      `Cache` с отпечатком, info-строки переходов; функция несовпадения SNI по таблице FEATURE;
      юнит-тесты SPEC §6 «метка» и «жизнь метки».
- [x] **D. Документация** — `docs-lx/lx-config.md` и `.ru.md` §13 под `lx.sniff_guard`; запись
      в `docs-lx/lx-changelog.md` про снятый дефолт под `detour` с готовым блоком на замену.
