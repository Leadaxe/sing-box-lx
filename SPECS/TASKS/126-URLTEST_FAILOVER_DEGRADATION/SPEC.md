`failover` переезжает с удерживаемого узла, если тот отвечает больше чем вдвое медленнее
лучшего из остальных, это подтвердила повторная проба, и свежий полный прогон нашёл узел
больше чем в 1,5 раза быстрее. Ключа нет.

## 1. Проблема

116 держит узел, пока он отвечает на пробу. Узел, перегруженный так, что проба проходит
за 2–3 с вместо 300 мс, формально жив, и группа не уходит с него, пока он не умрёт
совсем. Пользователь лечит это перезапуском клиента.

Отвергнуто:

- **Норма узла по скользящему окну** (`baseline_window`, `tolerance`, `degradation_confirmations`) —
  норма ползёт: стабильно деградировавший узел через окно становится «нормой» и перестаёт
  триггерить; много ручек ради выключенной функции.
- **`max_rtt` в мс** — абсолютный порог одинаково срабатывает на перегрузку узла и на
  смену Wi-Fi → LTE; когда медленно всем, каждый тик давал бы подтверждение и полный
  прогон. Число в форме — догадка пользователя, не измерение.

## 2. Поведение

Только `mode: failover`. `least_test` и `round_robin` не меняются.

1. **Триггер.** После пробы тика удерживаемый узел, который ответил, сравнивается с
   лучшей задержкой среди остальных узлов группы, у которых есть history и которые
   поддерживают сеть, за которую узел держится (TCP-выбор — с TCP-узлами, UDP-выбор —
   с UDP-узлами). Задержка больше **2×** лучшей — подозрение. History соседей может быть
   старой (в `failover` их пробует только полный прогон): это повод посмотреть, а не
   решение. Нет соседей с history — триггера нет.
2. **Подтверждение.** Сразу вторая проба того же узла, независимо от свежести history.
   Не ответил — отказ (116 §2.3). Снова больше 2× — узел «медленный». Иначе — выброс,
   тик заканчивается.
3. **Эскалация.** Как при отказе: полный прогон по остальным узлам (медленный и
   отказавший не пробуются повторно).
4. **Переезд.** Сеть, чей удерживаемый узел медленный, переезжает на самый быстрый узел
   прогона, только если его задержка меньше удерживаемой больше чем в **1,5** раза. Иначе
   остаётся. Сеть, чей узел не медленный и жив, держит его (116). Аварийный режим
   SPEC 054 стоит первым, как раньше. `interrupt_exist_connections` действует при
   переезде, как при отказе.
5. **Все медленные.** Если просела сеть, а не узел, полный прогон обновляет задержки
   соседей, и на следующем тике узел уже не вдвое медленнее их — триггер молчит. На одну
   смену условий сети — не больше одного полного прогона.
6. **Без флапа.** Триггер строже переезда (2× против 1,5×). После переезда новый узел
   сравнивается с только что измеренными соседями, обратного переезда по оживлению
   бывшего нет (116).

Пороги — константы в lx-файле, без ключей конфига (решение владельца 2026-10-11).
Протокол и конфиг не меняются. Порядок полей формы LxBox — без изменений.

**Энергия.** Обычный тик — одна проба удерживаемого узла, как раньше. Подозрение — плюс
одна проба; подтверждённое — плюс полный прогон по всем (как при отказе).

## 3. Критерии приёмки

- Узел стал больше 2× медленнее соседа: две пробы удерживаемого, полный прогон, переезд
  на узел больше 1,5× быстрее (TCP и UDP).
- Медленнее, но меньше 2×: одна проба, без переезда.
- Разовый выброс: вторая проба быстрая — без полного прогона, без переезда.
- Медленно всем: триггер по старой history соседей, полный прогон, никто не быстрее в
  1,5 раза — остаёмся; следующий тик — одна проба.
- UDP-выбор сравнивается только с UDP-узлами (тест 116 `udpHeldSeparately` зелёный).
- `slowerBy`: границы 2× и 1,5× строгие.
- Существующие тесты `protocol/group` зелёные.
