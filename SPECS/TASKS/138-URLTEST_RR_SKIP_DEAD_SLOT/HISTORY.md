# HISTORY — SPEC 138: самовосстановление пула `round_robin`

Хронология [SPEC 138](SPEC.md): как задача менялась и что отвергнуто. Актуальное состояние — в
SPEC.md и [ALGORITHM.md](ALGORITHM.md).

## 2026-10-22 — обход мёртвого слота

Полевой отчёт ([#53](https://github.com/Leadaxe/sing-box-lx/issues/53)): роутер OpenWrt, группа
`round_robin` из четырёх узлов на двух физических серверах, пул 3 из 4. Сервер моргает на
10–20 с, оба его узла умирают разом, а живой замены вне пула нет: мёртвый узел остаётся в слоте
и получает свою долю соединений — половину при пуле 4 из 4, треть при пуле 3 из 4.

Решение — пропуск в выборе: слот без history обходится, пока в пуле есть живые; ключи пропущенных
слотов расходятся по живым поровну по остатку хеша, а не «в первый живой по кругу» (два мёртвых
подряд отдали бы соседу 3/4 ключей). Сигнал — общая history, пропуск начинается с провала
плановой пробы.

A/B на роутере на бэкпорте `v1.14.2-lx.11`: стоковое ядро роняло около трети новых соединений
весь простой, с обходом — ни одного отказа после первых 15–20 с. Отказ сервера RST вместо чёрной
дыры окно обнаружения не сократил, причина не разбиралась. Влито 2026-10-23 (PR #54), в релизах
с `v1.14.3-lx.23`.

## 2026-11-24 — первая версия самовосстановления по отказам

Issue [#76](https://github.com/Leadaxe/sing-box-lx/issues/76) и
[LxBox#191](https://github.com/Leadaxe/LxBox/issues/191): узел убит вручную, `interval` 10 мин —
обход начинается только после плановой пробы. Первая версия реагировала на отказ соединения
шестью этапами: повтор через следующий слот; проверка пары «узел и сосед» пробами без записи,
третий узел, если молчат оба, и вердикт «своя сеть» с заморозкой, если молчат все; отказ ждал
вердикта «жив» по своему узлу до 60 с и тогда сдвигал ключ; обёртка первого байта; счётчики и
карантин по медиане; UDP; поля `GetPool`; слот под подозрением по соединению, висящему дольше
5 с; вердиктная проба одного узла по отказу, «указывающему на сайт».

Стенд на NanoPi (пять серверов socks и vless на loopback, пул 3 из 5): один убитый узел — 30
запросов из 30 прошли, замена через 0,13 с, `v1.14.4-lx.36` на том же сценарии — 10 отказов из
30; убиты все пять — никто не вычеркнут. Узел, убитый через секунду после плановой пробы, с
сокращением «history моложе 30 с — жив» заменялся через 32 с, без него — через 0,84 с. Обёртка
первого байта на пути записи отнимала у отдачи 18–20 % скорости и 77–85 % процессора на байт;
после ухода с пути записи отдача вернулась к уровню без обёртки. Зависший узел под параллельной
нагрузкой заменялся через ~21 с, 23 соединения успели уйти в него — отсюда обход слота под
подозрением. Круг ключа по пулу без постороннего трафика занимал 31 с.

Попутно: отказ в подключении и сброс при открытии через прокси-узел в `least_test`/`failover`
стали «путь мёртв» (SPEC 054); рукопожатия socks, httpupgrade и ShadowTLS v3 ограничены 15 с
(SPEC 161).

## 2026-11-25 — формальный алгоритм и переписанный код

Ревью первой версии показало, что выводы делались из признаков, которые их не доказывают: обрыв
сети выглядел как смерть узла, молчание проб — как «своя сеть», единичный отказ на живом узле
сдвигал ключ. Написан [ALGORITHM.md](ALGORITHM.md): модель, наблюдения, аксиомы, правила вывода,
инварианты, сценарии. Несколько раундов формального ревью и решений владельца; сверка кода с
документом (вопросы V1–V11) внесена в правила. Код переписан под алгоритм: `630d081a6`,
`1f960c2e9`, `176c18538`, `8ab84cbef`, `1acc12a38`, `0fddeff77`, `94122a533`, `f965d6020`.

Что ушло из прежней версии: сосед и третий узел (проверка судит весь пул, кандидаты — от курсора,
не больше двух пачек); вердикт «своя сеть» и заморозка по молчанию проб (заморозка — только по
сигналу платформы); вывод «сеть вернулась» по зависаниям; ожидание вердикта отказом до 60 с;
сдвиг ключа по одному мягкому признаку (теперь — явный отказ или второй признак при живом узле);
сроки 5 с «клиент ушёл», 30 с «молчание сайта», 60 с между проверками по зависанию TCP; критерий
«быстрого ответа» контроля; замена по свежей history без пробы.

Тот же день, решение владельца: во время 15-секундной заморозки повтор открытия через другой слот
разрешён (прежде заморозка отключала и его), запрещены выводы и записи в состояние группы; исход
повтора никуда не идёт (`c0349345a`, `78eacdb71`).

## Отвергнуто — не возвращаться

- Сжимать пул при смерти узла: `hash % pool` меняется у всех ключей, массовые переезды sticky.
- Fallback `Select(network)` вместо соседнего слота: весь трафик в один узел, возможно вне пула.
- Перебирать соседние слоты, когда узел не поддерживает сеть соединения.
- Считать узел живым по свежей history без пробы.
- «Жив» по байту соединения, начатого до отказа, или по моменту чтения байта из буфера.
- Обёртка первого байта на пути записи всё время соединения.
- Вердикт по исходу повтора («открылось через соседа — виноват первый»).
- Случайный сосед для повтора.
- Список запрещённых узлов на ключ и срок жизни сдвига.
- Порог карантина константой и окно по времени вместо медианы пула.
- Штатный дотест пула для замены: проба с записью стирает history всех при моргании сети.
- Придерживать соединение до появления замены.
- Буфер первой посылки для повтора после закрытия без байта.
- «Нет данных от узла N секунд — мёртв»: простаивающее соединение тоже молчит.
- Вывод «своя сеть лежит» по молчанию проб и заморозка по нему.
- Сдвиг ключа по одному мягкому признаку.
- Обход слота сразу по быстрому отказу: слот рвущего долю соединений узла мигал бы.
- Молчание, неявный отказ, короткий обрыв без кода и отказ `detour` вне счёта узла.
- Ленивый пул с порогом качества ([#56](https://github.com/Leadaxe/sing-box-lx/issues/56)) — спроса нет.
