# ALGORITHM: 138 — самовосстановление пула `round_robin`

**Фича:** [007-URLTEST_BALANCE](../../FEATURES/007-URLTEST_BALANCE/FEATURE.md) · контракт — [SPEC.md](SPEC.md)

Формальное описание алгоритма: что группа наблюдает, что из этого вправе вывести и что делает.
Реализация сюда не входит. Документ — основание для проверки кода: каждое действие кода должно
быть применением одного правила из §4, каждое правило — следовать из аксиом §3.

Статус: черновик после формальной проверки правил (soundness, живучесть, минимальность).
Правила §4 расходятся с кодом и с SPEC.md; перечень расхождений — §8. Решения владельца, внесённые в правила: мягкие
признаки по одному не дают выводов (A0); уход клиента — `CANCEL`, молчание назначения меряется порогом
группы `T_site`; повтор по мягкому признаку остаётся; слот оценивается целиком, как маршрут (П);
ключ сдвигается по второму мягкому признаку при доказанно живом узле между попытками (K2); явный
отказ и `LOCAL` на подключении к узлу запускают пробу жизни; обход слота — сразу только по
медленному признаку (S1, S2); заморозку включает только сигнал платформы (N3), опрос кандидатов
ограничен `k` пачками на проверку; молчание, неявный отказ и отказ `detour` идут в счёт узла (Q1);
ключ с пометкой K5 сохраняет повтор по `FAIL_NODE`. Открытый вопрос — §9.

## 1. Скрытое состояние мира

Группа его не видит и восстанавливает по наблюдениям.

- `Net(t) ∈ {up, down}` — своя сеть устройства.
- `Node(n, t) ∈ {alive, dead}` — узел `n` обслуживает соединения. Узел — весь маршрут слота:
  сервер, его `detour`, транспортная сессия (принцип П, §3). Зависший узел (принимает
  соединение и молчит) — `dead`.
- `Path(n, t) ≡ Net(t) = up ∧ Node(n, t) = alive` — путь через узел работает.
- `Site(d, n) ∈ {ok, refuse, silent}` — как назначение `d` отвечает через узел `n`.
- `Flaky(n) ∈ [0, 1]` — доля соединений, которые живой узел `n` не обслужил, а другой узел пула
  обслужил.

Обозначения: `P` — узлы пула, `C` — узлы группы вне пула, `T` = 15 с — таймаут пробы,
`H` = 5 с — порог ожидания, `ρ` = 1 с — начальный таймаут повторной передачи транспорта,
`k` = 2 — предел пачек кандидатов на одну проверку, `c` — курсор по `C` (позиция, с которой
следующая проверка продолжает опрос кандидатов; идёт по кругу),
`key(c)` — sticky-ключ соединения с адресатом (нет ключа — правила сдвига не применяются).

## 2. Наблюдения

Единственный источник знаний — **обмен**: запрос через узел и его исход.

```
X = (n, target, a, w, b, res)
  n       узел
  target  URL пробы | назначение d
  a       момент начала (выбор узла)
  w       момент первой отправки клиента (для пробы w = a)
  b       момент исхода
  res     ∈ {ANSWER, REFUSE_DST, FAIL_NODE, SILENT, LOCAL, CANCEL}
```

Исходы обмена «соединение приложения через `n` к `d`»:

| res | Вид | Что наблюдается |
|-----|-----|-----------------|
| `ANSWER` | жёсткий | пришёл первый байт от `d` |
| `REFUSE_DST` явный | жёсткий | ответ протокола листа `n` с отказом по назначению (код SOCKS, статус HTTP CONNECT), выставленный **самим листом**; либо отказ в подключении или сброс от `d` на открытии у листа, который сам ходит до `d` (`direct`, endpoint, MASQUE) |
| `REFUSE_DST` неявный | мягкий | соединение открыто, клиент отправил данные и свою сторону не закрывал, удалённая сторона закрыла этот поток без единого байта и без кода; обрыв транспортной сессии узла (таймаут простоя QUIC, обрыв mux-сессии) у открытого соединения наблюдается так же |
| `FAIL_NODE` | мягкий | открытие не удалось: активный отказ (отказ в подключении, сброс, EOF, ошибка рукопожатия, ошибка транспортной сессии узла) либо таймаут открытия; отказ промежуточного `detour`, в том числе с кодом |
| `SILENT` | мягкий | открыто, клиент отправил в `w`, соединение ещё ждёт, первого байта нет дольше `T_site`, и путь через `n` подтверждён в первой половине ожидания: в момент осмотра `t` выполнено `t − w ≥ T_site` и `Live` (§3) |
| `LOCAL` | — | ошибка без ответа удалённой стороны по этому обмену: нет маршрута, сеть или узел сети недоступны (в том числе по ICMP), интерфейс выключен, ошибка привязки адреса |
| `CANCEL` | мягкий | клиент отменил открытие или ушёл без байта — в любой момент, раньше или позже `T_site`; соединение закрыла сама группа (вердикт D1, прерывание группы, закрытие группы) |

Исходы обмена «проба через `n`»: `ANSWER` · `FAIL_NODE` (активный отказ) · `SILENT` (`b − a = T`) · `LOCAL`.
Исход пробы сам по себе — тоже мягкий признак; жёстким он становится в сравнении с контролем (D1).

**Уход клиента ничего не доказывает.** Клиент вправе ждать сколько хочет и рвать соединение когда
хочет. `SILENT` определяется только порогом группы `T_site` и только пока соединение ждёт; ушедший
раньше клиент даёт `CANCEL`, из которого ничего не выводится и который никуда не считается.
`LOCAL` получает повтор (§5) и выводов не даёт: причина может быть в своей сети, в чужом
маршрутизаторе по дороге к `d`, в самом узле, и по ошибке они не различаются. `LOCAL` на открытии к
адресу прокси-узла (не у листа, который сам ходит до `d`) ещё запускает пробу жизни узла (S1):
выключенный сервер у многих хостеров отвечает быстрой ошибкой «узел недоступен», а не тишиной, а
провайдер при блокировке адреса подставляет «сеть недоступна».

`T_site = T` = 15 с. Основания: правило половины (§3) при пробе жизни, начатой на `H`, требует
`T_site ≥ 2·(H + D) + ρ` — 11,6 с при ответе пробы за 0,3 с и 15 с при ответе за 2 с; за 15 с узел
делает три повторные передачи SYN к сайту (1, 3, 7 с); новой константы не появляется. Меньшее
значение (10 с) оставляет пробе жизни меньше 2 с на ответ и на медленной сети `SILENT` не
наступает вовсе.

**Моменты применения.** Таймеров на соединение нет. Возраст ожидания и условие `SILENT` читаются
при осмотре слота на выборе узла и при ответе пробы. Пока группа никого не выбирает и проб нет,
ничего не выводится; зависшее соединение при этом ждёт своего клиента.

`SILENT`, после которого по тому же обмену пришёл `ANSWER`, отменяется: его счёт снимается (Q1),
сдвиг, опиравшийся на него, возвращается (K2).

Момент доказательства. `ANSWER` пробы пришёл в момент `b`. Первый байт соединения приложения
мог ждать в буфере (ядро, mux, QUIC), поэтому момент его доказательства — где-то на `[a, b]`.

## 3. Аксиомы

- **A0 (мягкие признаки).** `SILENT`, `FAIL_NODE`, `CANCEL` и неявный `REFUSE_DST` на трафике
  приложения ничего не различают: каждый мог дать перерыв сети, мёртвый узел, молчащий сайт или
  узел, клиент, который рвёт соединения. Единичный мягкий признак не даёт ни одного вывода о
  `Net`, `Node`, `Site`, `Flaky`. Он вправе вызвать только безвредное: повтор открытия через другой
  слот, пробу, приращение счётчика, временный обход слота (§4.3), запись в память K2. Вывод из
  мягких признаков возможен тремя путями и никаким четвёртым:
  - **статистика** — доля признаков узла против медианы пула (Q2);
  - **управляемое сравнение** — собственная проба узла против контроля в том же окне (D1);
  - **повтор наблюдения при доказанно живом узле между попытками** (K2) — третий путь, принят
    владельцем. Два мягких признака одного ключа на одном узле, между началами которых узел дал
    `ANSWER` другому, а этому ключу — нет. Единичный признак совместим с любой причиной A0.
    Повтор исключает общую причину обоих признаков — перерыв сети или смерть узла: каждая
    понадобилась бы дважды, с доказанным путём между ними. Остаются `Site(d, n) ≠ ok` либо два
    независимых сбоя подряд у одного ключа (на узле с `Flaky = p` — вероятность `≈ p²`). Это
    сравнение без контроля в одном окне: вывод вероятностный, его единственное действие — сдвиг
    ключа, вывода о `Node` и `Flaky` из него нет.

  Жёсткие наблюдения — `ANSWER`, явный `REFUSE_DST`, проба в сравнении с контролем — дают вывод сами.
- **П (слот — маршрут).** Слот оценивается целиком, как маршрут, без детализации внутрь. Группа
  не выясняет, какое звено цепочки — сам узел, его `detour`, транспортная сессия — дало отказ:
  если через слот падает заметная доля соединений, слот плох и заменяется. Различается одно: к
  чему относится явный отказ — к назначению `d` (`REFUSE_DST`, сдвиг ключа) или к следующему звену
  маршрута (`FAIL_NODE`), потому что от этого зависит действие, а не вина.
- **A1 (ответ доказывает путь).** `res(X) = ANSWER ⇒ ∃ t ∈ [a, b]: Path(n, t)`; для пробы `t = b`.
  Для соединения ещё `Site(d, n) = ok`. О состоянии в момент `a` ответ ничего не говорит: запрос,
  отправленный при `Net = down`, доходит повторной передачей.
- **A2 (явный отказ — ответ сервера, не доказательство пути).** `res(X) = REFUSE_DST явный ⇒ Net(b) = up ∧ Site(d, n) = refuse`.
  `Node(n, b) = alive` отсюда не следует: явный отказ доказывает только, что сервер узла ответил.
  Сервер со сломанным собственным выходом или DNS, с истёкшей подпиской или квотой отказывает с
  кодом на всё подряд. Явный отказ не служит доказательством `Path(n)` ни в одном правиле.
- **A3 (неявный отказ двусмыслен, частный случай A0).** `res(X) = REFUSE_DST неявный ⇒ Site(d, n) = refuse ∨ Node(n, b) = dead ∨ Path(n)` прерывался на `[w, b]`
  (умерший процесс узла закрывает свои соединения; после перерыва пути соединение сбрасывается
  первой же повторной передачей).
- **A4 (молчание двусмысленно, частный случай A0).** `res(X) ∈ {SILENT, FAIL_NODE} ⇒ Net = down где-то на [a, b] ∨ Node(n) = dead ∨ Site(d, n) = silent ∨ Flaky(n) > 0`.
  Само по себе молчание не выделяет ни одну из причин.
- **A5 (повторная передача).** Если запрос отправлен в `w`, а `Path(n)` работает непрерывно с
  момента `r ≥ w`, то запрос доставлен, а потерянный ответ передан заново, не позже `2r − w + ρ`
  (таймаут повторной передачи TCP и QUIC удваивается с каждой попыткой, RFC 6298).
- **A6 (нет перерыва между доказательствами).** Если `Path(n)` доказан в моменты `t1 < t2`,
  `t2 − t1 ≤ 2T`, то `Path(n)` не прерывался на `[t1, t2]`. То же для `Net`.
  Нарушение — перерыв, целиком уместившийся между двумя доказательствами; ущерб от него ограничен §6.

**Правило половины** (следствие A1 и A5). Для обмена `X` через `n` с отправкой в `w` и исходом
в `b` говорим, что путь подтверждён узлами `M` — `Live(X; M)`, — если есть `ANSWER` через узел из
`M` на `[a', b']` с `a' ≥ w` и

```
b − b' ≥ (b' − w) + ρ
```

Для ещё ждущего обмена вместо `b` берётся момент осмотра `t`. Смысл: путь доказан не позже `b'`;
что бы ни было на `[w, b']`, запрос `X` к моменту `b` доставлен. Молчание и закрытие, не прошедшие
правило половины, совместимы с перерывом пути любой длины; такое молчание не становится `SILENT`.

## 4. Правила вывода

Запись: `посылки ⊢ вывод → действие`. Действие совершается только по правилу.

### 4.1 Сеть и эпоха

Одна переменная `E` — конец последней заморозки. Событие ставит `E := now + T`. Событие даёт
только N3; молчание проб события не даёт (D5).

- **N0 (эпоха).** Пока `now < E`, не выводится и не делается ничего: ни повторов, ни проб, ни
  §4.2–4.5; идущая проверка обрывается без вердикта. Обмен с `a < E` не участвует ни в одном
  правиле: ни начатый до события, ни начатый в заморозке.
- **N3 (сигнал платформы).** Сигнал пробуждения; сигнал смены сети; расхождение настенных и
  монотонных часов больше 10 с ⊢ состояние сети неизвестно → событие. Часы сверяются при
  обработке каждого исхода, до применения правил; после события базис сверки переустанавливается.
  Сигнал в заморозке продлевает её от своего момента.

**Обрыв сети без сигнала платформы** событием не становится. Пока сеть лежит, каждое соединение
повторяется один раз через другой слот (§5) и падает; вычёркиваний, сдвигов и счёта нет (I1).
Проверки кончаются без вердикта (D5), проб не больше `|P|·(k + 1)` на проверку (L3).

### 4.2 Узел мёртв

**Проверка** (одна на группу одновременно; следующая — не раньше чем через `T` после конца
прошлой) судит весь пул:

1. В момент `x` начинаются пробы всех узлов пула.
2. Если за `H` не ответил никто, начинается опрос кандидатов `C` с курсора `c`: пачками размером с
   пул, по кругу в порядке конфига, новая пачка — через `H` после предыдущей либо сразу, когда
   предыдущая вся завершилась без ответа; до первого `ANSWER` или до `k`-й пачки этой проверки.
   Курсор встаёт за последним опрошенным кандидатом и сохраняется между проверками.
3. Первый `ANSWER` пробы — контроль, момент `b0`. Каждому узлу пула, ещё не ответившему, в `b0`
   начинается **решающая проба**.
4. Когда решающая проба узла кончилась без `ANSWER` (момент `y`), начинается проба «контроль
   после» через любой узел, уже ответивший в этой проверке.

Правила:

D1 — управляемое сравнение по A0: пробы узла и контроля в одном окне; мягкие признаки трафика в
его посылки не входят, они только запускают проверку.

- **D1 (мёртв).** В этой проверке ни одна проба `n` не дала `ANSWER`; решающая проба `n` начата
  в `x1 ≥ b0` и кончилась в `y` без `ANSWER` (`FAIL_NODE`, `SILENT` или `LOCAL`); «контроль после»
  дал `ANSWER` с началом `≥ y`; нет `ANSWER` через `n` с началом `≥ x`
  ⊢ (A1, A6: сеть работала на всём `[b0, y]`, узел не обслужил пробу) `Node(n) = dead` → вычеркнуть `n`
  (стереть history), отменить его открытия в полёте (они идут в повтор), закрыть его соединения,
  ждущие первого байта (`CANCEL`), отбросить его признаки, ждущие Q1, стереть его записи в памяти
  K2, заменить слот (§5).
- **D3 (жив).** Проба `n`: `ANSWER` ⊢ `Node(n) = alive` → записать history, снять подозрение.
- **D4 (вердикта нет).** «Контроль после» не ответил ⊢ ничего → проверка кончается без вердикта
  о молчавших узлах; подозрение остаётся и запускает следующую проверку.
- **D5 (нет контроля).** Ни пул, ни `k` пачек кандидатов не дали `ANSWER` ⊢ ничего: ни о сети, ни
  об узлах → проверка кончается без вердикта и без события; курсор остаётся там, где остановился
  опрос; подозрение остаётся. Сюда попадают и лежащая сеть, и недоступный URL пробы при живой
  сети, и пул вместе с `k` пачками кандидатов на мёртвых серверах: по пробам они не различаются, и
  различать их не нужно — ни одно правило вердикта без контроля не срабатывает. Трафик
  приложения при этом обрабатывается как обычно: повторы, подозрение, K1, K2, Q1.

**Проба жизни** — проба одного узла `n` без контроля, вне проверки и её паузы: не больше одной в
полёте на узел, не чаще раза в 3 с на узел и четырёх за 15 с на группу. `ANSWER` — D3 и
доказательство пути для `SILENT`, Q1 и K2. Исход без `ANSWER` ставит подозрение (если его ещё нет)
и запускает проверку.

Что запускает пробу жизни: признак трафика по S1 или S2 (в том числе явный отказ, K1). Проверку
запускает только проба жизни без `ANSWER`.

### 4.3 Подозрение на слот

Подозрение — не вывод о `Node(n)`, а временный обход слота при выборе (мягко: если обходить нечем —
выбор как обычно). Признаки трафика делятся по цене ожидания.

- **S1 (быстрый отказ).** Обмен через `n` с `a ≥ E` кончился быстрым отказом: `FAIL_NODE` с
  активным отказом (отказ в подключении, сброс, EOF, ошибка рукопожатия), `LOCAL` на открытии к
  адресу прокси-узла (§2), явный `REFUSE_DST` → проба жизни `n`; слот **не обходится**, пока проба
  жизни не кончилась без `ANSWER`; после неё — подозрение (обход) и проверка. Соединения в это
  время спасает повтор (§5).
- **S2 (медленный признак).** Обмен через `n` с `a ≥ E`: таймаут открытия, либо при осмотре слота
  не завершён дольше `H` (открытие в полёте; TCP-ожидание первого байта), и нет `ANSWER` через `n`
  с началом `≥ a` → проба жизни `n` и подозрение (обход) **сразу**; если проба жизни кончилась без
  `ANSWER` — проверка.
- **S3 (снятие).** Подозрение снимают: `ANSWER` через `n` с началом `≥ a`; вердикт D1 или D3; уход
  узла из слота; событие (N0); плановый прогон; срок `2T` от последнего мягкого признака узла.
  Конец зависшего обмена подозрения не снимает.

Обоснование деления. Медленный признак уже стоил `H` ожидания, и каждое следующее соединение в
узел стоит столько же — обход окупается сразу. Быстрый отказ спасается повтором мгновенно (цена —
один RTT). Обход по быстрому отказу на узле, рвущем долю соединений, заставлял бы слот мигать и
ломал бы sticky до карантина; такой узел уводит статистика (Q2).

Подозрение не меняет history, ключи и счётчики. Безвредность: соединение, обошедшее слот, идёт
через другой узел пула, ключ остаётся на своём слоте — та же цена, что у повтора (§5). Снимается
само: у живого узла после медленного признака — ответом пробы жизни, не позже `3 с + D`; по
быстрому отказу у живого узла обхода не бывает вовсе; у мёртвого — вердиктом D1; без вердикта
(D5, нет контроля) — по сроку `2T`, после чего следующий признак ставит его заново. UDP-ожидание
(«отправил, ответа нет») подозрения не создаёт: только проба жизни узла, не чаще раза в 60 с на
группу.

Цена быстрого правила на убитом узле. До отказа пробы жизни (≈ один RTT до сервера узла, `≤ d`) в
узел уходят все соединения, выбранные на его слот: ещё не увидевшие первого отказа и выбранные
за время пробы. При потоке `λ` соединений в секунду это `≈ λ·2·RTT/|P|`; при 100 параллельных
соединениях, открытых разом после убийства, — `≈ 100/|P|` (33 при пуле 3), все они начаты раньше
первого отказа и ушли бы в узел при любом правиле обхода. Каждое получает отказ и спасается
повтором ценой одного RTT; пробу жизни делает одна (не больше одной в полёте на узел).

### 4.4 Назначение недоступно через узел

- **K1 (явный отказ).** `res(X) = REFUSE_DST явный`, `a ≥ E` ⊢ (A2) `Site(d, n) = refuse` →
  сдвиг `key` на следующий слот; проба жизни `n` по S1 (в пределах её лимитов частоты): узел,
  отказывающий во всём (A2), не отвечает и пробе и уходит по D1.
- **K2 (второй мягкий признак).** Обмены `X1`, `X2` через `n`, оба с `a ≥ E`, одного `key`, оба
  выбраны на слоте ключа при одном и том же сдвиге `s` (не повтор и не обход); `res ∈ {FAIL_NODE,
  REFUSE_DST неявный, SILENT}` у обоих (`CANCEL` и `LOCAL` не считаются); `X2` начат после исхода
  `X1` (параллельные соединения ключа — одна попытка); есть `ANSWER` `Y` через `n` другому ключу
  или пробе с `a(Y) ≥ a1`, `b(Y) ≤ a2` (узел и сеть доказанно работали между попытками); нет
  `ANSWER` соединения с этим `key` через `n` с началом `≥ a1`
  ⊢ (A0, третий путь) `Site(d, n) ≠ ok` либо два независимых сбоя ключа → сдвиг `key` на следующий
  слот.
  Первый признак — только повтор (§5) и память «один признак у ключа на `n`»: запись
  `(key, n, s, a1, b1)`. Память — таблица фиксированного размера на группу, при переполнении
  вытесняется самая старая запись. Запись стирают: событие (N0), плановый прогон, уход `n` из
  слота (D1, Q2), `ANSWER` этому ключу через `n`, сдвиг ключа. Отменённый `SILENT` (§2), на который
  опирался сдвиг, возвращает ключ, пока текущий сдвиг тот, что дал K2.
- **K4 (единичный мягкий признак).** `res(X)` — `FAIL_NODE`, неявный `REFUSE_DST`, `SILENT`, `CANCEL`,
  и посылки K2 не выполнены ⊢ (A0) о назначении ничего → сдвига нет; `FAIL_NODE`, неявный
  `REFUSE_DST`, `SILENT` пишут память K2.
- **K5 (круг).** `key` сдвинут (K1, K2) через все узлы пула, и между этими сдвигами не было `ANSWER`
  соединения с этим ключом ⊢ `Site(d, ·) ≠ ok` везде → пометка «проблема в адресе»: ключ
  возвращается на свой слот; сдвиги K1 и K2, повтор по явному отказу и по `LOCAL` для него
  выключены до планового прогона, ручного прогона или сигнала смены сети. Повтор по `FAIL_NODE`
  сохраняется: смерть узла не даёт ошибку соединениям помеченного ключа (цена — повтор и для
  адреса, недоступного везде, если он виден как `FAIL_NODE`). `ANSWER` соединения с ключом
  начинает счёт круга заново.

Сдвиг: слот ключа `= (hash(key) + shift) mod |P|`; одно соединение сдвигает ключ не более одного
раза; соединение, выбранное при сдвиге `s`, сдвигает ключ только если текущий сдвиг всё ещё `s`;
отказ на слоте обхода (§4.3) и на слоте повтора ключ не сдвигает и в память K2 не пишется. UDP
ключ не сдвигает.

### 4.5 Статистика узла

Путь от мягких признаков трафика к выводу о `Flaky` (A0). Признак идёт в счёт узла, вывод даёт
только сравнение с медианой пула. По принципу П отказы узла, его `detour` и транспортной сессии в
счёте не различаются.

- **Q1 (счёт).** Мягкий признак `X` через `n`, `a ≥ E`, даёт `fails(n) += 1`, не более одного раза
  на `key`, если после него путь через `n` подтверждён — `ANSWER` через `n` с началом `≥ b`,
  полученный не позже `b + 2T`, D1 для `n` не сработал (признаки мёртвого узла не считаются) — и:
  - `FAIL_NODE` (в том числе отказ `detour`): повтор того же соединения через `m ≠ n` дал `ANSWER`;
    отказ активный либо `Live(X; P \ {n})` (при таймауте открытия сеть доказана в первой половине
    ожидания);
  - неявный `REFUSE_DST` при `b − w < H`: дополнительных условий нет, счёт по общим условиям
    (выбор чтения — §9, V6);
  - неявный `REFUSE_DST` при `b − w ≥ H`: ещё `Live(X; {n})`;
  - `SILENT`: по определению (§2); пришедший позже `ANSWER` того же обмена счёт снимает.

  `CANCEL` и `LOCAL` в счёт не идут. Явный `REFUSE_DST` (K1) даёт `fails(n) += 1` раз на ключ, когда
  ключ получил `ANSWER` на другом слоте.
- **Q2 (карантин).** `conns(n) ≥ 8 ∧ fails(n) ≥ 3 ∧ fails(n)/conns(n) ≥ 5 % ∧ fails(n)/conns(n) > 2·median{fails(m)/conns(m) : m ∈ P, m ≠ n, conns(m) ≥ 8}`,
  множество под медианой не пусто
  ⊢ `Flaky(n)` велика → карантин: слот обходится и получает замену; history не стирается; счётчики
  `n` обнуляются; записи `n` в памяти K2 стираются.
- **Q3.** `conns(n) = 256` → оба счётчика `n` делятся пополам. D1 и уход `n` из слота обнуляют счётчики.
  UDP в счётчиках не участвует.

Карантин и пометка K5 снимаются плановым прогоном, ручным прогоном, сигналом смены сети.

## 5. Действия

- **Повтор.** Соединение, чьё открытие не удалось (`FAIL_NODE`, `REFUSE_DST` на открытии, `LOCAL`),
  вне заморозки — один раз открывается через следующий слот `≠ n` без подозрения, чей лист не
  вложенный `urltest`; для ключа с пометкой K5 — только по `FAIL_NODE`. Повтор — действие над одним
  соединением, не вывод: ключ остаётся на прежнем узле, в том числе закреплённый (sticky).
  Принятая цена: при разовом сбое живого узла один запрос уходит с другого адреса — риск для сайтов
  с привязкой сессии к адресу. На правила §4 исход повтора влияет только как посылка Q1.
- **Замена.** В слот вычеркнутого или карантинного узла встаёт первый ответивший на пробу узел из `C`,
  не карантинный; опрос — как в шаге 2 проверки: от курсора `c`, пачки через `H`, не больше `k`
  пачек за попытку. Попытка без ответа оставляет слот пустым (выбор его пропускает); следующая
  попытка — со следующей проверкой, пауза и курсор общие с проверкой. Кандидат, послуживший
  контролем, занимает первый освободившийся слот. Пишет слоты только один исполнитель одновременно
  (общий флаг с плановым прогоном).
- **Заполнение при прогоне.** Во время планового или стартового прогона узел из `C`, ответивший на
  пробу, сразу встаёт в слот, чей узел без history.
- **Вне самовосстановления:** тест соединения, замер задержки через группу, режимы `least_test` и `failover`.

## 6. Что обязано выполняться

Безопасность (при A0–A6):

- **I0.** Каждый вывод о `Node`, `Site`, `Flaky` получен одним из четырёх путей: жёсткое
  наблюдение (D3, K1), управляемое сравнение (D1), статистика против медианы (Q2), повтор
  наблюдения при доказанно живом узле (K2 — только о `Site`, только сдвиг). Мягкий признак сам
  вызывает только повтор, пробу жизни, счёт (Q1), запись в память K2 и временный обход слота (S1
  после неудачной пробы, S2 сразу).
- **I1 (обрыв без сигнала).** `Net = down` на всём интервале наблюдений ⇒ ни вычёркивания, ни
  сдвига, ни карантина, ни счёта, ни события. Вывод из правил: у D1 в посылках контроль `ANSWER`,
  у Q1 — `ANSWER` через `n` после признака, у K1 — явный отказ (A2: `Net(b) = up`), у K2 — `ANSWER`
  между попытками, у Q2 — счёт Q1, у событий — только N3; ни одной из этих посылок при лежащей сети
  нет. Каждое соединение повторяется один раз через другой слот без подозрения (если такой есть) и
  падает.
- **I1′.** Один перерыв сети любой длины без сигнала (при A6) ⇒ ни вычёркивания, ни счёта по
  обменам, начатым до его конца (кроме неявного отказа с `b − w < H`: один счёт, сценарий 31), и не
  больше одного из двух признаков K2 на ключ: `Y` в K2 доказывает путь на `[a1, a2]`, так что оба
  признака в одном перерыве не помещаются. Ложный сдвиг от перерыва возможен только у ключа,
  чей первый признак был до перерыва при ответившем после него узле.
- **I2.** `n` вычеркнут ⇒ существовал интервал, на котором `n` не отвечал, а контроль отвечал до и после.
- **I3.** `key` сдвинут с `n` ⇒ был явный отказ `d` через `n` (K1) либо два мягких признака ключа на
  `n` с `ANSWER` через `n` другому между их началами и без `ANSWER` ключу (K2). Пометка K5 ⇒ `|P|`
  сдвигов подряд без единого ответа ключу.
- **I4.** Ни одно наблюдение с `a < E` не участвует в выводах.
- **I5.** Один узел занимает не больше одного слота; живой слот не теряет узел иначе как по D1/Q2.
- **I6.** Заморозка включается только событием N3 (сигнал платформы или расхождение часов).
- **I7.** Память K2 — не вывод: пишется по K4, стирается по K2 (N0, плановый прогон, уход узла,
  ответ ключу, сдвиг). Вытеснение из переполненной таблицы приводит только к пропуску сдвига,
  ложного сдвига не даёт.
- **I8.** Курсор `c` меняет только опрос кандидатов (шаг 2 проверки, замена); проба кандидата не
  меняет ни history, ни слотов иначе как через D3, контроль D1 и замену.

Живучесть. `D` — время ответа пробы живого узла (`≤ T`), `G` — остаток паузы между проверками (`≤ T`).

- **L1.** `Node(n) = dead`, `Net = up`, через `n` идёт трафик, URL пробы доступен, в пуле есть живой
  узел ⇒ `n` вычеркнут не позже `t0 + G + D + T + D`, где `t0` — конец пробы жизни без ответа,
  начатой по первому быстрому отказу (S1) либо по медленному признаку (S2: таймаут открытия,
  осмотр зависшего обмена старше `H`); при отказе в подключении и при `LOCAL` — `t0 + G + 2D`.
  Обход слота начинается при S2 с первого признака, при S1 — с `t0`, то есть через один RTT до
  сервера узла после первого отказа; до `t0` соединения в узел спасает повтор. Если в пуле живых
  нет — плюс `H·(j − 1) + D` при `j ≤ k`, `j` — номер пачки кандидатов от курсора, первой с живым
  узлом; при `j > k` — ещё до `⌈j/k⌉ − 1` проверок без вердикта (D5), каждая `≤ k·H + T` и пауза
  `T`. Проверка судит весь пул, так что поводы от одного узла не откладывают вердикт другому.
- **L2.** `Site(d, n) = refuse` с кодом ⇒ ключ сдвинут после первого явного отказа (K1).
  Отказ без кода ⇒ ключ сдвинут вторым закрытием (K2), если между попытками через `n` ответили
  другому ключу или пробе. Молчание назначения ⇒ ключ сдвинут вторым ожиданием, дожившим до
  `T_site` и осмотренным (K2); клиент, уходящий раньше `T_site`, даёт `CANCEL` — сдвига нет, ключ
  остаётся на узле. Без ответа через `n` между попытками сдвига нет; узел уходит в карантин, когда
  таких ключей набирается на Q2.
- **L3.** Заморозка конечна: `T` от последнего события N3; после неё первая же причина запускает
  проверку без остаточных пауз. Проверки заморозку не включают, цикла «проверка → заморозка» нет.
  Число проб ограничено независимо от `|C|`: проверка делает не больше `|P|·(k + 1)` проб пула и
  кандидатов (решающие пробы и «контроль после» — только при контроле), следующая — не раньше `T`
  после конца прошлой, так что проверок не больше 4 в минуту; проб жизни — не больше 4 за 15 с на
  группу. Худший случай при лежащей сети, группе 500 и пуле 3 — все пробы кончаются мгновенно
  (`LOCAL`): `4 · 9 + 16 = 52` пробы в минуту; при пробах, молчащих до `T`, проверка длится
  `2H + T` = 25 с, цикл 40 с — `13,5 + 12 ≈ 26` проб в минуту. Полный обход курсором 497 кандидатов
  — 83 проверки, не меньше 21 мин.
- **L4.** Подозрение конечно: снимается по S3, не позже `2T` от последнего мягкого признака.

Ограниченность ущерба при нарушении аксиом:

- ложный счёт — один на ключ; до вывода нужно не меньше трёх ключей, доля 5 % и вдвое выше медианы;
- ложный карантин — до планового прогона, слот занят другим узлом;
- ложное вычёркивание — узел возвращается кандидатом на следующей замене или плановом прогоне;
  ложное вычёркивание после быстрой смены сети без сигнала (перерыв уместился между контролем до и
  после, нарушение A6) видят все группы через общую history;
- ложный сдвиг (K2) — ключ уходит на соседний слот, то есть на другой адрес для сайта; на узле с
  `Flaky = p` до карантина ложно сдвигается доля `≈ p²` ключей, через узел трафик которых идёт;
- ложная заморозка — `T` без повторов и выводов, только по N3;
- ложное подозрение — обход слота до ответа пробы жизни, не дольше `2T`; по быстрому отказу живого
  узла обхода нет.

Цепочки. Сдвиг K2 и счёт Q1 идут от одних признаков независимо: счёт — раз на ключ, сдвиг счёта
не добавляет, поэтому цепочки «сдвиг → счёт → карантин» нет; остаётся «счёт → карантин»
(сценарий 30). Ложное вычёркивание обнуляет счётчики и не трогает ключи: ключи привязаны к слоту.
Ложная заморозка новых событий не порождает. Пометка K5 требует `|P|` сдвигов подряд без единого
ответа ключу.

## 8. Что проверить в коде по этому документу

Правила §4 изменены относительно кода; ниже — что привести в соответствие и что установить.

1. **Сдвиг по мягким признакам (A0, K2, K4).** Код сдвигает ключ по закрытию без байта, по отказу
   открытия и по брошенному ожиданию после вердикта «жив». По этому документу сдвигает явный
   отказ (K1) и второй мягкий признак ключа на узле при `ANSWER` через узел другому между
   попытками (K2), с памятью фиксированного размера и её стиранием; `CANCEL` и `LOCAL` в K2 не
   идут; отменённый `SILENT` возвращает сдвиг.
2. **`SILENT` (§2).** Порог `T_site`, уход клиента — `CANCEL`; сроков 5 с и 30 с нет. Применение —
   при осмотре слота и при ответе пробы; отмена счёта пришедшим ответом.
3. **Классы исходов (§2).** `LOCAL`: «сеть недоступна», «узел сети недоступен», ошибки интерфейса и
   привязки — без выводов. Ошибка транспортной сессии узла (mux, QUIC) — отказ маршрута слота
   (`FAIL_NODE` на открытии, как закрытие без байта после него), не `LOCAL`. Явный отказ у листа,
   который сам ходит до сайта, — только отказ в подключении и сброс. Установить, отличает ли код
   явный отказ по назначению `d` от отказа следующему звену маршрута (`detour`): от этого зависит
   действие — сдвиг ключа (K1) или `FAIL_NODE`. Закрытие самой группой — `CANCEL`, не неявный отказ.
4. **Протоколы с отказом назначения на открытии.** SSH (отказ открытия канала), hysteria2 (ответ с
   ошибкой на запрос потока): если код видит причину, это явный `REFUSE_DST` (K1), а не `FAIL_NODE`.
   Чем раньше протокол даёт код, тем раньше сдвиг: K1 с первого отказа, K2 — со второго.
5. **Проверка (§4.2).** Опрос всего пула; опрос кандидатов от курсора, не больше `k` пачек за
   проверку, курсор сохраняется между проверками; без ответа — D5: без вердикта и без заморозки;
   решающая проба после ответа контроля, `LOCAL` решающей пробы — посылка D1; контроль после.
   Убрать: соседа и «третьего», второй круг, критерий быстрого ответа (`≤ 1 с и ≤ T/4`), вердикт
   «своя сеть» и заморозку по молчанию проб.
6. **N2 и N4 убраны.** «Сеть вернулась» по зависаниям на двух узлах и заморозка по локальной
   ошибке не должны оставаться в коде.
7. **Правило половины.** `SILENT`, счёт неявного отказа при `b − w ≥ H` и счёт таймаута открытия
   требуют `Live`. Срок ожидания доказательства «после» — `2T`, не 60 с.
8. **S1–S3.** Быстрый отказ (активный `FAIL_NODE`, `LOCAL` на открытии к адресу прокси-узла, явный
   отказ) — проба жизни без обхода, обход и проверка — после её неудачи. Медленный признак —
   проба жизни и обход сразу. Срок `2T`; конец зависшего обмена подозрения не снимает; плановый
   прогон снимает.
9. **K5.** Счёт круга обнуляется ответом ключу; помеченный ключ сохраняет повтор по `FAIL_NODE`.
10. **Слепая группа убрана.** Сейчас, по описанию, — «своя сеть» и заморозка по кругу. Молчание
    всех проб — D5; заморозку включает только N3.
11. **N0.** `E` — конец заморозки; обмены, начатые в заморозке, не участвуют. Сверка часов — при
    каждом исходе, с переустановкой базиса.
12. **D1 и гонка с ответом.** `ANSWER` через `n`, пришедший после вычёркивания, вердикт не отменяет.
    Проверить, что посылка «нет `ANSWER` с началом `≥ x`» читается в момент вердикта.
13. **I5 при заполнении во время прогона.** Остаточная гонка: кандидат занимает слот узла, чья проба
    ещё идёт.
14. **Полузакрытие под mux и в цепочке.** Обёртка не узнаёт о конце потока клиента; закрытие после
    него считается неявным отказом и идёт в счёт.
15. **Явный отказ и проба жизни (A2, K1).** Явный отказ нигде не служит доказательством пути
    (снятие подозрения, `Live`, посылки Q1 и K2); K1 запускает пробу жизни.
16. **Соответствие в целом.** Для каждого места в коде, которое стирает history, пишет слот, сдвигает
    ключ, меняет счётчик, пишет память K2, двигает курсор или включает заморозку, указать правило из
    §4 и путь по I0. Место без правила — ошибка либо пробел этого документа.

## 9. Варианты на решение владельца

Принятое и вариантом не являющееся: повтор по мягкому признаку (§5); уход клиента — `CANCEL`;
`T_site = T`; сдвиг по второму мягкому признаку при доказанно живом узле (K2); повтор по
`FAIL_NODE` для ключа с пометкой K5; обход слота по быстрому отказу — только после неудачной пробы
жизни, по медленному признаку — сразу (S1, S2); слот оценивается как маршрут (П).

Отклонено:

- молчание и неявный отказ вне счёта Q1 — почти весь трафик идёт поверх TLS и первый байт приходит
  сразу; молчание или обрыв без байта при живом узле — обычно сайт, режущий адрес узла;
- отказ промежуточного `detour` вне счёта Q1 — карантин оценивает пригодность слота, а не вину:
  узел за ненадёжным `detour` — ненадёжный слот; полностью мёртвый `detour` ловит D1, рвущий часть
  соединений — только статистика.

## 10. Константы

| Константа | Вердикт | Основание или от чего защищает |
|-----------|---------|--------------------------------|
| `T` = 15 с | внешняя | таймаут пробы и рукопожатия в ядре |
| `T_site` = `T` | слита с `T` | порог молчания назначения; основания — §2 |
| `H` = 5 с | произвольна | возраст ожидания, с которого осмотр запускает пробу жизни и обход (S2); покрывает две повторные передачи SYN узла к сайту (1 с, 3 с); меньше — лишние пробы и обходы, больше — дольше трафик идёт в зависший узел и позже доказательство для `SILENT` |
| `ρ` = 1 с | обоснована | начальный таймаут повторной передачи, RFC 6298 |
| заморозка 15 с | слита с `T` | к концу заморозки завершилась любая проба и любое рукопожатие, начатые до события (N3) |
| пауза проверок 15 с | слита с `T`; произвольна | защищает от шторма проб при `Flaky`-узле и при лежащей сети: не больше 4 проверок в минуту |
| `k` = 2 пачки кандидатов на проверку | произвольна | цена каждой пачки — `|P|` проб на проверку при лежащей сети (при пуле 3 — `+12` в минуту к худшим 52); выгода — контроль в той же проверке, когда весь пул и первая пачка от курсора на мёртвых серверах. При `k = 2` опрос кандидатов `k·H = 10 с` укладывается в таймаут пробы пула `T`; дальнейший поиск контроля идёт следующими проверками по курсору |
| память K2 — 256 записей на группу | произвольна | один признак на пару «ключ, узел»; вытеснение старых — пропуск сдвига, не ложный сдвиг (I7) |
| срок подозрения и доказательства «после» | `2T` | горизонт A6; прежние 60 с убраны |
| порог A7 (`max(1 с, 3·delay)`; в коде `≤ 1 с и ≤ T/4`) | убрана | решающая проба начинается после ответа контроля |
| 5 с — «клиент ушёл» | убрана | уход клиента — `CANCEL` |
| 30 с — `SILENT` по сроку | убрана | один порог `T_site` |
| 60 с — проверка по зависанию | убрана для TCP | проба жизни дешевле; осталась как предел проб жизни по UDP-ожиданию: произвольна, защищает от постоянных проб при законном одностороннем UDP |
| 3 с на узел — проба жизни | произвольна | защищает от шторма проб |
| 4 за 15 с на группу | произвольна, избыточна при пуле до 4 узлов | общий потолок проб жизни на большом пуле и при лежащей сети (16 в минуту) |
| 8 — `conns` | произвольна | для соседей под медианой: доля по малой выборке — шум. Для самого узла избыточна при `fails ≥ 3` |
| 3 — `fails` | произвольна | один и два признака — совпадение |
| 5 % | произвольна | нижняя граница при медиане 0 |
| 2 × медиана | произвольна | «сильно хуже медианы»: общая для пула причина (сеть, общий `detour`) не ведёт к карантину |
| 256 — `conns` | произвольна | длина памяти счётчиков |
| 10 с расхождения часов | произвольна | выше подстроек NTP, ниже любого сна, после которого узел успел закрыть соединения |
