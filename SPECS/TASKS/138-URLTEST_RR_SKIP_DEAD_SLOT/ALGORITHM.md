# ALGORITHM: 138 — самовосстановление пула `round_robin`

**Фича:** [007-URLTEST_BALANCE](../../FEATURES/007-URLTEST_BALANCE/FEATURE.md) · контракт — [SPEC.md](SPEC.md)

Формальное описание алгоритма: что группа наблюдает, что из этого вправе вывести и что делает.
Реализация сюда не входит. Документ — основание для проверки кода: каждое действие кода должно
быть применением одного правила из §4, каждое правило — следовать из аксиом §3.

Статус: черновик на проверку владельцем. Код сверен с ним не полностью (§8).

## 1. Скрытое состояние мира

Группа его не видит и восстанавливает по наблюдениям.

- `Net(t) ∈ {up, down}` — своя сеть устройства.
- `Node(n, t) ∈ {alive, dead}` — узел `n` обслуживает соединения. Зависший узел (принимает
  соединение и молчит) — `dead`.
- `Site(d, n) ∈ {ok, refuse, silent}` — как назначение `d` отвечает через узел `n`.
- `Flaky(n) ∈ [0, 1]` — доля соединений, которые живой узел `n` рвёт на открытии.

Обозначения: `P` — узлы пула, `C` — узлы группы вне пула, `T` = 15 с — таймаут пробы,
`H` = 5 с — порог ожидания, `key(c)` — sticky-ключ соединения с адресатом (нет ключа —
правила сдвига не применяются).

## 2. Наблюдения

Единственный источник знаний — **обмен**: запрос через узел и его исход.

```
X = (n, target, a, b, res)
  n       узел
  target  URL пробы | назначение d
  a       момент начала
  b       момент исхода
  res     ∈ {ANSWER, REFUSE_DST, FAIL_NODE, SILENT, LOCAL, CANCEL}
```

Исходы обмена «соединение приложения через `n` к `d`»:

| res | Что наблюдается |
|-----|-----------------|
| `ANSWER` | пришёл первый байт от `d` |
| `REFUSE_DST` явный | отказ, названный отказом назначения: ответ прокси с кодом отказа по назначению (SOCKS, HTTP CONNECT), выставленный **самим листом** `n`; либо отказ/сброс на открытии у листа, который сам ходит до `d` (`direct`, endpoint, MASQUE) |
| `REFUSE_DST` неявный | соединение открыто, клиент отправил данные, удалённая сторона закрыла без единого байта |
| `FAIL_NODE` | открытие через прокси-лист не удалось по любой другой причине (отказ, сброс, EOF, таймаут рукопожатия, отказ промежуточного `detour`) |
| `SILENT` | открыто, клиент отправил, байта нет, и: клиент ушёл при `b − a_write ≥ H`, либо ожидание длится `> 30 с`; либо таймаут открытия у листа, который сам ходит до `d` |
| `LOCAL` | ошибка, порождённая локально без обращения к сети (нет маршрута, сеть недоступна, интерфейс выключен) |
| `CANCEL` | клиент отменил раньше, чем выполнено условие `SILENT` |

Исходы обмена «проба через `n`»: `ANSWER` · `FAIL_NODE` (активный отказ) · `SILENT` (`b − a = T`) · `LOCAL`.

`CANCEL` — не наблюдение: из него ничего не выводится.

## 3. Аксиомы

- **A1 (ответ доказывает путь).** `res(X) = ANSWER ⇒ Net(a) = Net(b) = up ∧ Node(n, a) = Node(n, b) = alive`.
  Для соединения ещё `Site(d, n) = ok`.
- **A2 (явный отказ — тоже ответ).** `res(X) = REFUSE_DST явный ⇒ Net(b) = up ∧ Node(n, b) = alive ∧ Site(d, n) = refuse`.
- **A3 (неявный отказ двусмыслен).** `res(X) = REFUSE_DST неявный ⇒ Site(d, n) = refuse ∨ Node(n, b) = dead`
  (умерший процесс узла закрывает все свои соединения).
- **A4 (молчание двусмысленно).** `res(X) ∈ {SILENT, FAIL_NODE} ⇒ Net = down где-то на [a, b] ∨ Node(n) = dead ∨ Site(d, n) = silent ∨ Flaky(n) > 0`.
  Само по себе молчание не выделяет ни одну из причин.
- **A5 (локальная ошибка).** `res(X) = LOCAL ⇒ Net(b) = down`. О узле и назначении — ничего.
- **A6 (устойчивость).** На интервале длиной `2T` `Net` и `Node(n)` меняют состояние не более
  одного раза каждый. Нарушение A6 может дать неверный вывод; ущерб от него ограничен §6.
- **A7 (обычная задержка).** У узла `m` с известной задержкой `delay(m)` обмен пробы,
  завершившийся `ANSWER` за `b − a ≤ max(1 с, 3·delay(m))`, шёл по сети, которая была `up` на всём `[a, b]`.
  Более долгий ответ совместим с `Net = down` в начале интервала (повторные передачи TCP).
- **A8 (эпоха).** Если в момент `e` состояние сети менялось (§4.1), то обмен с `a ≤ e` не несёт
  информации об узлах и назначениях.

## 4. Правила вывода

Запись: `посылки ⊢ вывод → действие`. Действие совершается только по правилу.

### 4.1 Сеть

Момент последнего события сети — `E`. Событие сдвигает `E := now`.

- **N1 (сеть лежит).** Проверка (§4.2) опросила `n` и все доступные контрольные узлы, все обмены,
  начатые в `[x, x+ε]`, кончились `SILENT`/`LOCAL`, и за `[x, x+T]` в группе нет ни одного `ANSWER`
  ⊢ `Net = down` → событие; заморозка `F` = 15 с.
- **N2 (сеть вернулась).** За `[t − H, t]` в группе нет `ANSWER`; не меньше двух узлов пула имеют
  незавершённый обмен старше `H` без `ANSWER` через себя с начала этого обмена; в момент `t` приходит
  `ANSWER` через один из этих узлов ⊢ `Net` была `down` и стала `up` → событие; заморозка.
- **N3 (сигнал платформы).** Сигнал пробуждения, сигнал смены сети, расхождение настенных и
  монотонных часов больше 10 с ⊢ состояние сети неизвестно → событие; заморозка.
- **N4 (локальная ошибка).** `res(X) = LOCAL` ⊢ `Net = down` → событие; заморозка `(?)`.
- **N5 (URL пробы недоступен).** Все пробы проверки кончились `SILENT`, но за `[x, x+T]` в группе
  есть `ANSWER` соединений приложения ⊢ `Net = up`, пробам верить нельзя → события нет, заморозки
  нет, вердиктов о узлах нет; повторы продолжаются `(?)`.

Во время заморозки не выводится и не делается ничего: ни повторов, ни проб, ни §4.2–4.5.

### 4.2 Узел мёртв

Проверка узла `n`: одновременно, в момент `x`, начинаются пробы `n` и контрольного `m ≠ n`
(сосед по пулу; если его нет или он не отвечает — следующий слот; если слотов нет — кандидаты из `C`
пачками, контролем служит первый ответивший).

- **D1.** проба `n`: `FAIL_NODE` или `SILENT` на `[x, y]`;
  проба `m`: `ANSWER` на `[x, b1]`, `b1 − x` в пределах A7;
  повторная проба `m`, начатая в `a2 ≥ y`: `ANSWER`;
  нет `ANSWER` через `n` с началом `≥ x`
  ⊢ `Node(n) = dead` → вычеркнуть `n` (стереть history), отменить его открытия в полёте (они идут в
  повтор), закрыть его соединения, ждущие первого байта, заменить слот (§5).
- **D2 (поздний контроль).** Как D1, но `b1 − x` вне A7 ⊢ ничего → второй круг: в `x2 ≥ y` заново
  пробуются `n` и `m` вместе; к нему применяется D1 с `x := x2` и без условия A7 (по A6 сеть уже
  менялась один раз).
- **D3.** проба `n`: `ANSWER` ⊢ `Node(n) = alive` → записать history, снять подозрение.
- **D4.** все опрошенные молчат ⊢ N1 либо N5.

Что запускает проверку `n`:
`FAIL_NODE` соединения через `n`; подозрение на слот (§4.3); молчание вердиктной пробы (§4.4).
Пределы: одна проверка на группу одновременно; не чаще одной в 15 с; проверка «по зависанию» — не
чаще одной в 60 с.

### 4.3 Подозрение на слот

- **S1.** Обмен через `n` с началом `a > E`: `FAIL_NODE`, либо не завершён дольше `H`
  (открытие в полёте; TCP-ожидание первого байта), и нет `ANSWER` через `n` с началом `≥ a`
  ⊢ `Node(n)` под вопросом → слот обходится при выборе (мягко: если обходить нечем — выбор как
  обычно); запускается проверка (§4.2).
- **S2.** `ANSWER` через `n` с началом `≥ a`, либо вердикт D1/D3 ⊢ подозрение снято.

Подозрение не меняет history, ключи и счётчики. UDP-ожидание («отправил, ответа нет») подозрения
не создаёт: только повод для проверки не чаще раза в 60 с.

### 4.4 Назначение недоступно через узел

- **K1 (явный отказ).** `res(X) = REFUSE_DST явный`, `a > E` ⊢ (A2) `Site(d, n) = refuse` →
  сдвиг `key` на следующий слот.
- **K2 (неявный отказ).** `res(X) = REFUSE_DST неявный` на `[a, b]`, `a > E`; затем `ANSWER` через
  `n` с началом `≥ b` (другое соединение или вердиктная проба одного узла `n`), полученный не позже
  `b + 60 с` ⊢ (A3, A1) `Site(d, n) = refuse` → сдвиг `key`.
  Если вместо этого сработал D1 — отказ отбрасывается.
- **K3 (молчание).** `res(X) = SILENT` на `[a, b]`, `a > E`; `ANSWER` через `n` на `[a', b']`,
  `a ≤ a'` и `b' ≤ b` ⊢ (A1) сеть и узел работали, пока `d` молчал → `Site(d, n) = silent` → сдвиг `key`.
  Ложная посылка возможна: медленный сайт при нетерпеливом клиенте. Поэтому K3 не участвует в §4.5.
- **K4.** `res(X) = FAIL_NODE` ⊢ о назначении ничего → сдвига нет.
- **K5 (круг).** `key` сдвинут через все узлы пула ⊢ `Site(d, ·) ≠ ok` везде → пометка «проблема в
  адресе»: ключ возвращается на свой слот, правила K1–K3 и повтор для него выключены до планового
  прогона, ручного прогона или события N3 «смена сети».

Вердиктная проба одного узла (для K2, K3 на простаивающем узле): не больше одной в полёте и четырёх
за 15 с на группу, не чаще раза в 3 с на узел. Её `SILENT` запускает проверку §4.2.

Сдвиг: слот ключа `= (hash(key) + shift) mod |P|`; одно соединение сдвигает ключ не более одного
раза; соединение, выбранное при сдвиге `s`, сдвигает ключ только если текущий сдвиг всё ещё `s`;
отказ на слоте обхода (§4.3) ключ не сдвигает.

### 4.5 Узел рвёт соединения

- **Q1 (подтверждённый отказ).** `res(X) = FAIL_NODE` через `n` на `[a, b]`, `a > E`; повтор того же
  соединения через `m ≠ n`: `ANSWER`; D1 для `n` не сработал ⊢ сеть работала, отказ — на счёт `n` →
  `fails(n) += 1`, но не более одного раза на `key`.
  K1/K2 при `ANSWER` того же ключа на другом слоте дают `fails(n) += 1` на тех же условиях. K3 — нет.
- **Q2 (карантин).** `conns(n) ≥ 8 ∧ fails(n) ≥ 3 ∧ fails(n)/conns(n) ≥ 5 % ∧ fails(n)/conns(n) > 2·median{fails(m)/conns(m) : m ∈ P, m ≠ n, conns(m) ≥ 8}`
  ⊢ `Flaky(n)` велика → карантин: слот обходится и получает замену; history не стирается; счётчики
  `n` обнуляются.
- **Q3.** `conns(n) = 256` → оба счётчика `n` делятся пополам. D1 и уход `n` из слота обнуляют счётчики.
  UDP в счётчиках не участвует.

Карантин и пометка K5 снимаются плановым прогоном, ручным прогоном, сменой сети.

## 5. Действия

- **Повтор.** Соединение с исходом открытия ≠ `ANSWER`, ≠ `CANCEL`, вне заморозки, для ключа без
  пометки K5 — один раз открывается через следующий живой слот без подозрения, чей лист не вложенный
  `urltest`. Повтор не зависит от правил §4: он не вывод, а услуга приложению.
- **Замена.** В слот вычеркнутого или карантинного узла встаёт первый ответивший на пробу узел из `C`
  (пачками, по порядку конфига), не карантинный. Пишет слоты только один исполнитель одновременно
  (общий флаг с плановым прогоном).
- **Заполнение при прогоне.** Во время планового или стартового прогона узел из `C`, ответивший на
  пробу, сразу встаёт в слот, чей узел без history.
- **Вне самовосстановления:** тест соединения, замер задержки через группу, режимы `least_test` и `failover`.

## 6. Что обязано выполняться

Безопасность (при A1–A8):

- **I1.** `Net = down` на всём интервале наблюдений ⇒ ни вычёркивания, ни сдвига, ни карантина.
- **I2.** `n` вычеркнут ⇒ существовал интервал, на котором `n` не отвечал, а контроль отвечал до и после.
- **I3.** `key` сдвинут с `n` ⇒ было наблюдение о `d` через `n` (`REFUSE_DST` или `SILENT`) и `ANSWER`
  через `n`, совместимые по времени с K1–K3.
- **I4.** Ни одно наблюдение с `a ≤ E` не участвует в выводах.
- **I5.** Один узел занимает не больше одного слота; живой слот не теряет узел иначе как по D1/Q2.

Живучесть:

- **L1.** `Node(n) = dead`, `Net = up`, через `n` идёт трафик ⇒ `n` вычеркнут не позже `H + T + ε`
  (при позднем контроле — `H + 2T + ε`).
- **L2.** `Site(d, n) = refuse` ⇒ ключ сдвинут после первого отказа (K1) или первого доказательства
  жизни `n` (K2). `Site(d, n) = silent` ⇒ после первого ожидания, которое клиент бросил (K3).
- **L3.** Заморозка конечна: после неё первая же причина запускает проверку без остаточных пауз.
- **L4.** Подозрение конечно: снимается первым `ANSWER` через узел, вердиктом, сменой узла в слоте.

Ограниченность ущерба при нарушении аксиом:

- ложный сдвиг — ключ живёт на другом узле пула; узлу не засчитывается (K3) или засчитывается раз на ключ;
- ложный карантин — до планового прогона, слот занят другим узлом;
- ложное вычёркивание — узел возвращается кандидатом на следующей замене;
- ложная заморозка — 15 с без повторов и выводов.

## 7. Проверка по сценариям

Столбец «вывод» — какое правило срабатывает; «верно» — совпадает ли вывод со скрытым состоянием.

| № | Скрытое состояние | Наблюдения | Вывод | Верно |
|---|-------------------|------------|-------|-------|
| 1 | `n` убит (порт закрыт), сеть up | соединение: `FAIL_NODE`; проба `n`: `FAIL_NODE`; контроль: `ANSWER` быстро, повторно `ANSWER` | D1 | да |
| 2 | `n`: машина выключена | то же, проба `n`: `SILENT` | D1 через `T` | да |
| 3 | `n` завис (принимает, молчит) | ожидание `> H` → S1; проба `n`: `SILENT`; контроль дважды `ANSWER` | S1, D1 | да, за `H + T` |
| 4 | сеть down | все обмены `SILENT`/`LOCAL` | N1 (или N4) | да |
| 5 | сеть down, вернулась в середине пробы | контроль `ANSWER` позже A7 | D2: второй круг, `n` отвечает → D3 | да |
| 6 | медленная сеть, `n` мёртв | контроль `ANSWER` в пределах `3·delay` — D1; без `delay` — D2, во втором круге `n` молчит | D1/D2 | да, до `2T` |
| 7 | сеть down 20 с под нагрузкой, вернулась | зависания на ≥2 узлах, затем `ANSWER` через застрявший | N2; обмены до `E` отброшены (A8) | да |
| 8 | сеть down, трафик только через один узел | зависание на одном узле, затем `ANSWER` через него | N2 не срабатывает; для `SILENT` этого соединения K3 требует `ANSWER` внутри ожидания: `a ≤ a'` выполнено, если проба начата после начала соединения | **нет: ложный сдвиг одного ключа**; ущерб по §6 |
| 9 | `Site(d, n) = refuse`, прокси сообщает кодом | `REFUSE_DST` явный | K1 | да |
| 10 | `Site(d, n) = refuse`, VLESS закрывает без байта | `REFUSE_DST` неявный, затем `ANSWER` через `n` | K2 | да |
| 11 | `n` умер, его соединения закрыты разом | много `REFUSE_DST` неявных; `ANSWER` через `n` после — нет; D1 | K2 не срабатывает, D1 | да |
| 12 | `Site(d, n) = silent`, узел загружен | `SILENT` (клиент ушёл через 8 с), внутри ожидания `ANSWER` через `n` | K3 | да |
| 13 | то же, узел простаивает | ожидание `> H` → S1 → проба `n`: `ANSWER` внутри ожидания | D3, затем K3 при уходе клиента | да |
| 14 | сайт медленный (ответ через 6–20 с) | `ANSWER` | ничего | да |
| 15 | сайт ответил бы через 10 с, клиент ушёл через 8 с | `SILENT`, `ANSWER` через `n` внутри | K3 | **нет: ложный сдвиг**; узлу не засчитан |
| 16 | `Flaky(n) = 20 %` | `FAIL_NODE` + повтор `ANSWER`, разные ключи | Q1, Q2 | да |
| 17 | `n` рвёт открытия только к одному `d` (SSH-канал) | `FAIL_NODE` + повтор `ANSWER`, один ключ | Q1 один раз | да: карантина нет; **но ключ не сдвигается** (K4) — каждое соединение к `d` идёт через повтор |
| 18 | весь пул на одном упавшем сервере | `n1`, `n2`: `FAIL`/`SILENT`; кандидат из `C`: `ANSWER` дважды | D1 для обоих; N2 не срабатывает (ответил не застрявший) | да |
| 19 | пул из одного узла, узел мёртв, первый кандидат мёртв | контроль — первый ответивший из `C` | D1 | да |
| 20 | пул из одного узла, сеть down | молчат все | N1 | да |
| 21 | URL пробы недоступен, сеть и узлы живы | все пробы `SILENT`, соединения приложения дают `ANSWER` | N5 | да — **если N5 реализовано** |
| 22 | URL пробы недоступен только через `n` | проба `n`: `SILENT`, контроль `ANSWER`; есть трафик через `n` → `ANSWER` с началом `≥ x` | D1 не срабатывает | да; без трафика — `n` вычеркнут, как и плановой проверкой |

## 8. Что проверить в коде по этому документу

Открытые расхождения — места, где правило сформулировано здесь, а соответствие кода не установлено.

1. **Класс `LOCAL` (A5, N4, сценарий 26).** Различает ли код локальную ошибку и отказ назначения у
   листа, который сам ходит до сайта. Если нет — «сеть недоступна» трактуется как K1.
2. **N5 (сценарий 21).** Что делает код, когда молчат все пробы, а соединения приложения получают
   байты: должен не замораживать и не выносить вердиктов. Сейчас, по описанию, — «своя сеть» и заморозка,
   то есть 15 с без повторов при живой сети, по кругу.
3. **A7 (D1/D2).** Критерий «быстрого ответа» контроля в коде — `≤ 1 с и ≤ T/4`; здесь —
   `max(1 с, 3·delay(m))`. На медленной сети код всегда уходит во второй круг.
4. **K2: срок 60 с и порядок.** Проверить, что неявный отказ разрешается только `ANSWER` с началом
   после отказа и отбрасывается при D1.
5. **K3 и A8 вместе (сценарий 8).** Остаточный ложный сдвиг признан; проверить, что он один на
   соединение и не даёт счёта.
6. **Сценарий 17.** Решить, нужен ли сдвиг ключа, когда один и тот же ключ повторно даёт `FAIL_NODE`
   на одном узле при успешных повторах (сейчас — нет).
7. **I5 при заполнении во время прогона.** Остаточная гонка: кандидат занимает слот узла, чья проба
   ещё идёт.
8. **L3.** После заморозки паузы сброшены; проверить отсутствие цикла «проверка → заморозка» при
   живой сети во всех ветках N1.
9. **Соответствие в целом.** Для каждого места в коде, которое стирает history, пишет слот, сдвигает
   ключ, меняет счётчик или включает заморозку, указать правило из §4. Место без правила — ошибка
   либо пробел этого документа.
