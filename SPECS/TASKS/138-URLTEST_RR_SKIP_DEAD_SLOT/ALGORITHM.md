# ALGORITHM: 138 — самовосстановление пула `round_robin`

**Фича:** [007-URLTEST_BALANCE](../../FEATURES/007-URLTEST_BALANCE/FEATURE.md) · контракт — [SPEC.md](SPEC.md)

Формальное описание алгоритма: что группа наблюдает, что из этого вправе вывести и что делает.
Реализация сюда не входит. Документ — основание для проверки кода: каждое действие кода должно
быть применением одного правила из §4, каждое правило — следовать из аксиом §3.

Статус: утверждён владельцем вместе с ответами на вопросы сверки кода (V1–V11, 2026-11-25), ответы
внесены в правила. Перечень расхождений с прежним кодом — §8. Решения владельца, внесённые в правила: мягкие
признаки по одному не дают выводов (A0); уход клиента — `CANCEL`, молчание назначения меряется порогом
группы `T_site`; повтор по мягкому признаку остаётся; слот оценивается целиком, как маршрут (П);
ключ сдвигается по второму мягкому признаку при доказанно живом узле между попытками (K2); явный
отказ и `LOCAL` на подключении к узлу запускают пробу жизни; обход слота — сразу только по
медленному признаку (S1, S2); заморозку включает только сигнал платформы (N3), опрос кандидатов
ограничен `k` пачками на проверку; молчание, неявный отказ и отказ `detour` идут в счёт узла (Q1);
ключ с пометкой K5 сохраняет повтор по `FAIL_NODE`; кандидат встаёт в слот только по ответу своей пробы
(§5); в заморозке повтор открытия работает, а выводов и записи состояния группы нет (N0, 2026-11-25).
Решения раунда 9 (R1–R8, §9) внесены в правила: вычеркнутый узел покидает слот сразу, пустой слот
запускает только поиск замены, не проверку пула (§4.2, §5); единая нарастающая пауза раундов
(W, §4.6); решающая проба и общий на ядро потолок проб в полёте (§4.7, L3); второе вычёркивание — карантин
(Q4); `code=1` SOCKS и уход клиента (§2); повтор только во внешней rr-группе (§5).
Решения ревью 9 (2026-11-25, §9) внесены в правила: живая history кандидата (§5), повтор при
вложенном `urltest`-члене (§5), флаг прогона только на запись слота (§5), раунд без проб (W1),
исключение собственной первой пробы из U3 (§4.7), прогон и вычеркнутый узел (§5).
Решения по стенду 10 и стенду `impair` (2026-11-25, §9) внесены в правила: прогон без ответа ничего
не меняет (§5), прогон не ставит в слот узел, вычеркнутый во время этого прогона, и раскладка
отдаёт дыру следующему живому (§5), молчащий узел в стартовом пуле — ограничение (§6), живой
медленный узел, вычеркнутый по D1, — ограничение (§6).
Решения по стенду `impair` v2 (2026-11-26, §9): жизнь узла определяет адрес пробы, как у апстрима
(§1, сценарий 22); одна остановка узла — несколько признаков Q2 (§6).

## 1. Скрытое состояние мира

Группа его не видит и восстанавливает по наблюдениям.

- `Net(t) ∈ {up, down}` — своя сеть устройства.
- `Node(n, t) ∈ {alive, dead}` — узел `n` обслуживает соединения. Узел — весь маршрут слота:
  сервер, его `detour`, транспортная сессия (принцип П, §3). Зависший узел (принимает
  соединение и молчит) — `dead`. Жизнь узла группа судит по адресу пробы (`url` группы), как
  апстримный urltest: узел, не пропускающий адрес пробы — отказом или молчанием, — для группы
  мёртв, даже если через него ходит другой трафик; `ANSWER` трафика только откладывает D1
  (сценарий 22, решение владельца 2026-11-26).
- `Path(n, t) ≡ Net(t) = up ∧ Node(n, t) = alive` — путь через узел работает.
- `Site(d, n) ∈ {ok, refuse, silent}` — как назначение `d` отвечает через узел `n`.
- `Flaky(n) ∈ [0, 1]` — доля соединений, которые живой узел `n` не обслужил, а другой узел пула
  обслужил.

Обозначения: `P` — узлы пула, `C` — узлы группы вне пула, `T` = 15 с — таймаут пробы,
`H` = 5 с — порог ожидания, `ρ` = 1 с — начальный таймаут повторной передачи транспорта,
`k` = 2 — предел пачек кандидатов на одну проверку, `c` — курсор по `C` (позиция, с которой
следующий раунд продолжает опрос кандидатов; идёт по кругу), `U` = 16 — потолок проб
самовосстановления в полёте на экземпляр ядра (§4.7), `g` — ступень паузы раундов группы (§4.6),
`key(c)` — sticky-ключ соединения с адресатом (нет ключа — K1, K2, K5 не применяются, а Q1 считает
каждый признак без ограничения «раз на ключ»).

## 2. Наблюдения

Единственный источник знаний — **обмен**: запрос через узел и его исход.

```
X = (n, target, a, w, b, res)
  n       узел
  target  URL пробы | назначение d
  a       момент начала (выбор узла)
  w       момент первой отправки клиента (для пробы w = a)
  b       момент исхода
  res     ∈ {ANSWER, REFUSE_DST, FAIL_NODE, SILENT, LOCAL, CANCEL}
```

Исходы обмена «соединение приложения через `n` к `d`»:

| res | Вид | Что наблюдается |
|-----|-----|-----------------|
| `ANSWER` | жёсткий | пришёл первый байт от `d` |
| `REFUSE_DST` явный | жёсткий | ответ протокола листа `n` с отказом по назначению (код SOCKS, кроме `code=1`; статус HTTP CONNECT), выставленный **самим листом**; либо отказ в подключении или сброс от `d` на открытии у листа, который сам ходит до `d` (`direct`, endpoint, MASQUE) |
| `REFUSE_DST` неявный | мягкий | соединение открыто, клиент отправил данные и свою сторону не закрывал, удалённая сторона закрыла этот поток без единого байта и без кода; обрыв транспортной сессии узла (таймаут простоя QUIC, обрыв mux-сессии) у открытого соединения наблюдается так же |
| `FAIL_NODE` | мягкий | открытие не удалось: активный отказ (отказ в подключении, сброс, EOF, ошибка рукопожатия, ошибка транспортной сессии узла) либо таймаут открытия; отказ промежуточного `detour`, в том числе с кодом; ответ SOCKS `code=1` (general failure) — отказ узла, не назначения |
| `SILENT` | мягкий | открыто, клиент отправил в `w`, соединение ещё ждёт, первого байта нет дольше `T_site`, и путь через `n` подтверждён в первой половине ожидания: в момент осмотра `t` выполнено `t − w ≥ T_site` и `Live` (§3) |
| `LOCAL` | — | ошибка без ответа удалённой стороны по этому обмену: нет маршрута, сеть или узел сети недоступны (в том числе по ICMP), интерфейс выключен, ошибка привязки адреса |
| `CANCEL` | мягкий | клиент отменил открытие или ушёл без байта — в любой момент, раньше или позже `T_site`; чтение со стороны клиента кончилось (EOF, закрытие входящей стороны) до первого байта от узла; соединение закрыла сама группа (вердикт D1, прерывание группы, закрытие группы) |

Исходы обмена «проба через `n`»: `ANSWER` · `FAIL_NODE` (активный отказ) · `SILENT` (`b − a = T`) · `LOCAL`.
Исход пробы сам по себе — тоже мягкий признак; жёстким он становится в сравнении с контролем (D1).

**Распознавание по платформам.** Ошибка открытия относится к классу по любому звену своей цепочки
обёрток; строки сравниваются целиком с текстом звена, у которого нет вложенной ошибки.

| Класс | unix, android, darwin | Windows (`syscall.Errno` числом) | строки |
|-------|-----------------------|----------------------------------|--------|
| `LOCAL` | `ENETUNREACH`, `EHOSTUNREACH`, `ENETDOWN`, `EHOSTDOWN`, `EADDRNOTAVAIL` | 10051, 10065, 10050, 10064, 10049 (`WSAENETUNREACH`, `WSAEHOSTUNREACH`, `WSAENETDOWN`, `WSAEHOSTDOWN`, `WSAEADDRNOTAVAIL`) | `tun.ErrNoRoute` («no route to internet», нет маршрута по умолчанию при `auto_detect_interface`); «no available network interface» (параллельный dialer без интерфейса); gVisor: «network is unreachable», «no route to host», «host is down», «machine is not on the network», «bad local address» |
| активный отказ | `ECONNREFUSED`, `ECONNRESET` | 10061, 10054 (`WSAECONNREFUSED`, `WSAECONNRESET`) | gVisor: «connection was refused», «connection reset by peer» |
| таймаут открытия | ошибка с `Timeout()`, истёкший срок контекста или дедлайна | 10060 (`WSAETIMEDOUT`) | gVisor: «operation timed out» |

Строки gVisor приходят от стека WireGuard и AWG: он отдаёт ошибку `tcpip` текстом
(`errors.New(err.String())`), а не кодом. Активный отказ — явный `REFUSE_DST` только у листа,
который сам ходит до `d` (§2, таблица), у остальных — `FAIL_NODE`. Остальные ошибки открытия —
`FAIL_NODE` с активным отказом.

**Уход клиента ничего не доказывает.** Клиент вправе ждать сколько хочет и рвать соединение когда
хочет. `SILENT` определяется только порогом группы `T_site` и только пока соединение ждёт; ушедший
раньше клиент даёт `CANCEL`, из которого ничего не выводится и который никуда не считается.
Клиент, закрывший свою сторону до первого байта от узла, — тоже `CANCEL`: такой обмен выходит из
учёта `SILENT`, счёта Q1, памяти K2 и обхода слота (S2). Законное полузакрытие (клиент дописал
запрос и ждёт ответа) при этом теряет мягкий признак — безопасная сторона.
`LOCAL` получает повтор (§5) и выводов не даёт: причина может быть в своей сети, в чужом
маршрутизаторе по дороге к `d`, в самом узле, и по ошибке они не различаются. `LOCAL` на открытии к
адресу прокси-узла (не у листа, который сам ходит до `d`) ещё запускает пробу жизни узла (S1):
выключенный сервер у многих хостеров отвечает быстрой ошибкой «узел недоступен», а не тишиной, а
провайдер при блокировке адреса подставляет «сеть недоступна».

`T_site = T` = 15 с. Основания: правило половины (§3) при пробе жизни, начатой на `H`, требует
`T_site ≥ 2·(H + D) + ρ` — 11,6 с при ответе пробы за 0,3 с и 15 с при ответе за 2 с; за 15 с узел
делает три повторные передачи SYN к сайту (1, 3, 7 с); новой константы не появляется. Меньшее
значение (10 с) оставляет пробе жизни меньше 2 с на ответ и на медленной сети `SILENT` не
наступает вовсе.

**Моменты применения.** Таймеров на соединение нет. Возраст ожидания и условие `SILENT` читаются
при осмотре слота на выборе узла и при ответе пробы. Пока группа никого не выбирает и проб нет,
ничего не выводится; зависшее соединение при этом ждёт своего клиента.

`SILENT`, после которого по тому же обмену пришёл `ANSWER`, отменяется: его счёт снимается (Q1),
сдвиг, опиравшийся на него, возвращается (K2).

Момент доказательства. `ANSWER` пробы пришёл в момент `b`. Первый байт соединения приложения
мог ждать в буфере (ядро, mux, QUIC), поэтому момент его доказательства — где-то на `[a, b]`.

## 3. Аксиомы

- **A0 (мягкие признаки).** `SILENT`, `FAIL_NODE`, `CANCEL` и неявный `REFUSE_DST` на трафике
  приложения ничего не различают: каждый мог дать перерыв сети, мёртвый узел, молчащий сайт или
  узел, клиент, который рвёт соединения. Единичный мягкий признак не даёт ни одного вывода о
  `Net`, `Node`, `Site`, `Flaky`. Он вправе вызвать только безвредное: повтор открытия через другой
  слот, пробу, приращение счётчика, временный обход слота (§4.3), запись в память K2. Вывод из
  мягких признаков возможен тремя путями и никаким четвёртым:
  - **статистика** — доля признаков узла против медианы пула (Q2);
  - **управляемое сравнение** — собственная проба узла против контроля в том же окне (D1);
  - **повтор наблюдения при доказанно живом узле между попытками** (K2) — третий путь, принят
    владельцем. Два мягких признака одного ключа на одном узле, между началами которых узел дал
    `ANSWER` другому, а этому ключу — нет. Единичный признак совместим с любой причиной A0.
    Повтор исключает общую причину обоих признаков — перерыв сети или смерть узла: каждая
    понадобилась бы дважды, с доказанным путём между ними. Остаются `Site(d, n) ≠ ok` либо два
    независимых сбоя подряд у одного ключа (на узле с `Flaky = p` — вероятность `≈ p²`). Это
    сравнение без контроля в одном окне: вывод вероятностный, его единственное действие — сдвиг
    ключа, вывода о `Node` и `Flaky` из него нет.

  Жёсткие наблюдения — `ANSWER`, явный `REFUSE_DST`, проба в сравнении с контролем — дают вывод сами.
- **П (слот — маршрут).** Слот оценивается целиком, как маршрут, без детализации внутрь. Группа
  не выясняет, какое звено цепочки — сам узел, его `detour`, транспортная сессия — дало отказ:
  если через слот падает заметная доля соединений, слот плох и заменяется. Различается одно: к
  чему относится явный отказ — к назначению `d` (`REFUSE_DST`, сдвиг ключа) или к следующему звену
  маршрута (`FAIL_NODE`), потому что от этого зависит действие, а не вина.
- **A1 (ответ доказывает путь).** `res(X) = ANSWER ⇒ ∃ t ∈ [a, b]: Path(n, t)`; для пробы `t = b`.
  Для соединения ещё `Site(d, n) = ok`. О состоянии в момент `a` ответ ничего не говорит: запрос,
  отправленный при `Net = down`, доходит повторной передачей.
- **A2 (явный отказ — ответ сервера, не доказательство пути).** `res(X) = REFUSE_DST явный ⇒ Net(b) = up ∧ Site(d, n) = refuse`.
  `Node(n, b) = alive` отсюда не следует: явный отказ доказывает только, что сервер узла ответил.
  Сервер со сломанным собственным выходом или DNS, с истёкшей подпиской или квотой отказывает с
  кодом на всё подряд. Явный отказ не служит доказательством `Path(n)` ни в одном правиле.
- **A3 (неявный отказ двусмыслен, частный случай A0).** `res(X) = REFUSE_DST неявный ⇒ Site(d, n) = refuse ∨ Node(n, b) = dead ∨ Path(n)` прерывался на `[w, b]`
  (умерший процесс узла закрывает свои соединения; после перерыва пути соединение сбрасывается
  первой же повторной передачей).
- **A4 (молчание двусмысленно, частный случай A0).** `res(X) ∈ {SILENT, FAIL_NODE} ⇒ Net = down где-то на [a, b] ∨ Node(n) = dead ∨ Site(d, n) = silent ∨ Flaky(n) > 0`.
  Само по себе молчание не выделяет ни одну из причин.
- **A5 (повторная передача).** Если запрос отправлен в `w`, а `Path(n)` работает непрерывно с
  момента `r ≥ w`, то запрос доставлен, а потерянный ответ передан заново, не позже `2r − w + ρ`
  (таймаут повторной передачи TCP и QUIC удваивается с каждой попыткой, RFC 6298).
- **A6 (нет перерыва между доказательствами).** Если `Path(n)` доказан в моменты `t1 < t2`,
  `t2 − t1 ≤ 2T`, то `Path(n)` не прерывался на `[t1, t2]`. То же для `Net`.
  Нарушение — перерыв, целиком уместившийся между двумя доказательствами; ущерб от него ограничен §6.

**Правило половины** (следствие A1 и A5). Для обмена `X` через `n` с отправкой в `w` и исходом
в `b` говорим, что путь подтверждён узлами `M` — `Live(X; M)`, — если есть `ANSWER` через узел из
`M` на `[a', b']` с `a' ≥ w` и

```
b − b' ≥ (b' − w) + ρ
```

Для ещё ждущего обмена вместо `b` берётся момент осмотра `t`. Смысл: путь доказан не позже `b'`;
что бы ни было на `[w, b']`, запрос `X` к моменту `b` доставлен. Молчание и закрытие, не прошедшие
правило половины, совместимы с перерывом пути любой длины; такое молчание не становится `SILENT`.

## 4. Правила вывода

Запись: `посылки ⊢ вывод → действие`. Действие совершается только по правилу.

### 4.1 Сеть и эпоха

Одна переменная `E` — конец последней заморозки. Событие ставит `E := now + T`. Событие даёт
только N3; молчание проб события не даёт (D5).

- **N0 (эпоха).** Пока `now < E`, ничего не выводится и состояние группы не меняется: ни проб
  (проверки, поиска замены, жизни), ни §4.2–4.5 — вычёркивания, сдвига ключа, счёта и карантина, записи памяти
  K2, подозрения и обхода, пометки K5; идущая проверка обрывается без вердикта. Работает только
  повтор открытия (§5): действие над одним соединением, которое в состояние группы ничего не пишет.
  Обмен с `a < E` не участвует ни в одном правиле: ни начатый до события, ни начатый в заморозке,
  в том числе сам повтор — его исход, ответ или отказ, никуда не идёт.
- **N3 (сигнал платформы).** Сигнал пробуждения; сигнал смены сети; расхождение настенных и
  монотонных часов больше 10 с ⊢ состояние сети неизвестно → событие. Часы сверяются при
  обработке каждого исхода, до применения правил, — каждой группой, которая этот исход берёт, в том
  числе исход общей пробы (U3); после события базис сверки переустанавливается.
  Сигнал в заморозке продлевает её от своего момента. Событие сбрасывает паузу раундов (W3).

**Обрыв сети без сигнала платформы** событием не становится. Пока сеть лежит, каждое соединение
повторяется один раз через другой слот (§5) и падает; вычёркиваний, сдвигов и счёта нет (I1).
Проверки кончаются без вердикта (D5), проб не больше `|P|·(k + 1)` на проверку; после полного круга
курсора пауза нарастает (W2, L3).

### 4.2 Узел мёртв

**Раунд** — проверка пула или поиск замены (§5). Раунд у группы один одновременно; следующий
начинается не раньше конца паузы (W1, §4.6). Пробы раундов и пробы жизни проходят общую на ядро
очередь с потолком `U` (§4.7); проба, ждущая места, правил не меняет: её начало — момент выхода в
полёт.

**Проверка** судит весь пул. Узлы пула — все узлы в слотах, кроме карантинных и узлов без history
(такой слот — пустой, §5 «Заполнение при прогоне»). Непроверенный узел (§5 «Прогон без ответа»)
history не имеет, но он узел пула: проверка судит его наравне с остальными. Вычеркнутый узел
слот покидает сразу (D1), поэтому в пуле его нет: он — кандидат из `C` на общих основаниях (§5);
вложенный `urltest` и `direct` в слоте — обычные узлы для проверки и проб.

1. В момент `x` начинаются пробы всех узлов пула.
2. Если за `H` не ответил никто, начинается опрос кандидатов `C` (порядок — §5 «Замена»): пачками
   размером с пул, новая пачка — через `H` после предыдущей либо сразу, когда предыдущая вся
   завершилась без ответа; до первого `ANSWER` или до `k`-й пачки этой проверки. Предел `k` общий
   для шага 2 и замены этой же проверки (§5): пачки, опрошенные на шаге 2, замене не возвращаются.
   Курсор встаёт за последним опрошенным по курсору кандидатом и сохраняется между проверками.
3. Первый `ANSWER` пробы — контроль, момент `b0`. Каждому узлу пула, ещё не ответившему,
   начинается **решающая проба**: в `b0`, если его первая проба кончилась или летит не меньше `H`;
   иначе — в момент, когда первая проба кончилась без `ANSWER` или пролетела `H`, что раньше;
   ответившему к этому моменту узлу решающая проба не посылается. Начало решающей пробы всегда
   `≥ b0`. Решающая проба узла, чья первая проба ещё летит, летит параллельно с ней и её исход не
   берёт (исключение из U3, §4.7). `ANSWER` любой из двух — D3.
4. Решающие пробы идут частями (§4.7): часть — до `U − 1` узлов и место под её «контроль после».
   Когда все решающие пробы части кончились, а у некоторых без `ANSWER` (момент `y` — конец
   последней), начинается одна проба «контроль после» этой части через любой узел, уже
   ответивший в этой проверке. D1 для узла выводится только из его решающей пробы и «контроля
   после» его части.

Правила:

D1 — управляемое сравнение по A0: пробы узла и контроля в одном окне; мягкие признаки трафика в
его посылки не входят, они только запускают проверку.

- **D1 (мёртв).** В этой проверке ни одна проба `n` не дала `ANSWER`; решающая проба `n` начата
  в `x1 ≥ b0` и кончилась в `y` без `ANSWER` (`FAIL_NODE`, `SILENT` или `LOCAL`; отменённая проба —
  не исход, §4.7); «контроль после»
  дал `ANSWER` с началом `≥ y`; нет `ANSWER` через `n` с началом `≥ x`
  ⊢ (A1, A6: сеть работала на всём `[b0, y]`, узел не обслужил пробу) `Node(n) = dead` → вычеркнуть `n`
  (стереть history), убрать `n` из слота — слот пуст, даже если замены нет; отменить его открытия в
  полёте (они идут в повтор), закрыть его соединения, ждущие первого байта (`CANCEL`), отбросить
  его признаки, ждущие Q1, стереть его записи в памяти K2, `strikes(n) += 1` (Q4), заменить слот (§5).
- **D3 (жив).** Проба `n`: `ANSWER` ⊢ `Node(n) = alive` → записать history, снять подозрение.
- **D4 (вердикта нет).** «Контроль после» не ответил ⊢ ничего → проверка кончается без вердикта
  о молчавших узлах; подозрение остаётся и запускает следующую проверку.
- **D5 (нет контроля).** Ни пул, ни `k` пачек кандидатов не дали `ANSWER` ⊢ ничего: ни о сети, ни
  об узлах → проверка кончается без вердикта и без события; курсор остаётся там, где остановился
  опрос; подозрение остаётся. Сюда попадают и лежащая сеть, и недоступный URL пробы при живой
  сети, и пул вместе с `k` пачками кандидатов на мёртвых серверах: по пробам они не различаются, и
  различать их не нужно — ни одно правило вердикта без контроля не срабатывает. Трафик
  приложения при этом обрабатывается как обычно: повторы, подозрение, K1, K2, Q1.

**Проба жизни** — проба одного узла `n` без контроля, вне проверки: не больше одной в полёте на
узел, не чаще раза в 3 с на узел и четырёх за 15 с на группу; пока ступень паузы выше базы и пауза
идёт, проб жизни нет (W4). `ANSWER` — D3 и
доказательство пути для `SILENT`, Q1 и K2. Исход без `ANSWER` ставит подозрение (если его ещё нет)
и запускает проверку; проба жизни по UDP-ожиданию подозрения не ставит (§4.3), проверку запускает
как обычно.

Что запускает пробу жизни: признак трафика по S1 или S2 (в том числе явный отказ, K1),
UDP-ожидание (§4.3). Если пробу не дали лимиты частоты или пауза (W4), признак ничего не
запускает: по медленному признаку обход слота всё равно ставится (S2) и истекает по сроку `2T`, по
быстрому — ничего.

Что запускает проверку: только мягкий признак на узле пула — через пробу жизни без `ANSWER` или
оставшееся подозрение (D4). Что запускает поиск замены: пустой слот (в том числе слот с узлом без
history, §5), а также слот карантинного узла без замены, — при выборе узла, если пауза истекла
(W1), есть хотя бы один кандидат и флаг прогона свободен; проверку пула он не запускает, контроль
для замены не нужен (§5). Таймеров нет — только на выборе. Выбор узла для чужой пробы (проба
другой группы или замер задержки, идущие через эту группу) ни проверки, ни поиска, ни осмотра не
запускает.

### 4.3 Подозрение на слот

Подозрение — не вывод о `Node(n)`, а временный обход слота при выборе (мягко: если обходить нечем —
выбор как обычно). Признаки трафика делятся по цене ожидания.

- **S1 (быстрый отказ).** Обмен через `n` с `a ≥ E` кончился быстрым отказом: `FAIL_NODE` с
  активным отказом (отказ в подключении, сброс, EOF, ошибка рукопожатия), `LOCAL` на открытии к
  адресу прокси-узла (§2), явный `REFUSE_DST` → проба жизни `n`; слот **не обходится**, пока проба
  жизни не кончилась без `ANSWER`; после неё — подозрение (обход) и проверка. Соединения в это
  время спасает повтор (§5).
- **S2 (медленный признак).** Обмен через `n` с `a ≥ E`: таймаут открытия, либо при осмотре слота
  не завершён дольше `H` (открытие в полёте; TCP-ожидание первого байта, если клиент свою сторону
  не закрыл — иначе это `CANCEL`, §2), и нет `ANSWER` через `n`
  с началом `≥ a` → проба жизни `n` и подозрение (обход) **сразу**; если проба жизни кончилась без
  `ANSWER` — проверка.
- **S3 (снятие).** Подозрение снимают: `ANSWER` через `n` с началом `≥ a`; вердикт D1 или D3; уход
  узла из слота; событие (N0); плановый прогон; срок `2T` от последнего мягкого признака узла.
  Конец зависшего обмена подозрения не снимает.

Обоснование деления. Медленный признак уже стоил `H` ожидания, и каждое следующее соединение в
узел стоит столько же — обход окупается сразу. Быстрый отказ спасается повтором мгновенно (цена —
один RTT). Обход по быстрому отказу на узле, рвущем долю соединений, заставлял бы слот мигать и
ломал бы sticky до карантина; такой узел уводит статистика (Q2).

Подозрение не меняет history, ключи и счётчики. Безвредность: соединение, обошедшее слот, идёт
через другой узел пула, ключ остаётся на своём слоте — та же цена, что у повтора (§5). Снимается
само: у живого узла после медленного признака — ответом пробы жизни, не позже `3 с + D`; по
быстрому отказу у живого узла обхода не бывает вовсе; у мёртвого — вердиктом D1; без вердикта
(D5, нет контроля) — по сроку `2T`, после чего следующий признак ставит его заново. UDP-ожидание
(«отправил, ответа нет» дольше `H`) подозрения не создаёт, ни сразу, ни после неудачной пробы:
зависшие UDP-обмены не делают слот подозрительным для TCP. Оно запускает только пробу жизни узла
(общие лимиты и не чаще раза в 60 с на группу); её неудача запускает проверку, вердикт D1 законен.

Цена быстрого правила на убитом узле. До отказа пробы жизни (≈ один RTT до сервера узла, `≤ d`) в
узел уходят все соединения, выбранные на его слот: ещё не увидевшие первого отказа и выбранные
за время пробы. При потоке `λ` соединений в секунду это `≈ λ·2·RTT/|P|`; при 100 параллельных
соединениях, открытых разом после убийства, — `≈ 100/|P|` (33 при пуле 3), все они начаты раньше
первого отказа и ушли бы в узел при любом правиле обхода. Каждое получает отказ и спасается
повтором ценой одного RTT; пробу жизни делает одна (не больше одной в полёте на узел).

### 4.4 Назначение недоступно через узел

- **K1 (явный отказ).** `res(X) = REFUSE_DST явный`, `a ≥ E` ⊢ (A2) `Site(d, n) = refuse` →
  сдвиг `key` на следующий слот; проба жизни `n` по S1 (в пределах её лимитов частоты): узел,
  отказывающий во всём (A2), не отвечает и пробе и уходит по D1.
- **K2 (второй мягкий признак).** Обмены `X1`, `X2` через `n`, оба с `a ≥ E`, одного `key`, оба
  выбраны на слоте ключа при одном и том же сдвиге `s` (не повтор и не обход); `res ∈ {FAIL_NODE,
  REFUSE_DST неявный, SILENT}` у обоих (`CANCEL` и `LOCAL` не считаются); `X2` начат после исхода
  `X1` (параллельные соединения ключа — одна попытка); есть `ANSWER` `Y` через `n` другому ключу
  или пробе с `a(Y) ≥ a1`, `b(Y) ≤ a2` (узел и сеть доказанно работали между попытками); нет
  `ANSWER` соединения с этим `key` через `n` с началом `≥ a1`
  ⊢ (A0, третий путь) `Site(d, n) ≠ ok` либо два независимых сбоя ключа → сдвиг `key` на следующий
  слот.
  Первый признак — только повтор (§5) и память «один признак у ключа на `n`»: запись
  `(key, n, s, a1, b1)`. Память — таблица фиксированного размера на группу, при переполнении
  вытесняется самая старая запись. Запись стирают: событие (N0), плановый прогон, уход `n` из
  слота (D1, Q2), `ANSWER` этому ключу через `n`, сдвиг ключа. Отменённый `SILENT` (§2), на который
  опирался сдвиг, возвращает ключ, пока текущий сдвиг тот, что дал K2; `ANSWER` ключу с началом
  `≥ a1`, пришедший, пока сдвиг совершался, тоже возвращает его.
  Посылки проверяются по тому, что группа помнит: `ANSWER` ключу с началом `≥ a1` ищется и среди
  пришедших до `b1`. Если нужного свидетельства нет — запись вытеснена, доказательство пути выпало
  из памяти узла, ответ ключу не отличим от ответа другому ключу, — вывода нет, сдвига нет.
- **K4 (единичный мягкий признак).** `res(X)` — `FAIL_NODE`, неявный `REFUSE_DST`, `SILENT`, `CANCEL`,
  и посылки K2 не выполнены ⊢ (A0) о назначении ничего → сдвига нет; `FAIL_NODE`, неявный
  `REFUSE_DST`, `SILENT` пишут память K2.
- **K5 (круг).** Счётчик ключа — число подряд идущих сдвигов (K1 или K2) без `ANSWER` соединению с
  этим ключом; `ANSWER` ключу обнуляет его. Счётчик достиг `|P|` (число слотов пула, не число живых
  слотов) ⊢ `Site(d, ·) ≠ ok` везде → пометка «проблема в адресе»: ключ
  возвращается на свой слот; сдвиги K1 и K2, повтор по явному отказу и по `LOCAL` для него
  выключены до планового прогона, ручного прогона или сигнала смены сети. Повтор по `FAIL_NODE`
  сохраняется: смерть узла не даёт ошибку соединениям помеченного ключа (цена — повтор и для
  адреса, недоступного везде, если он виден как `FAIL_NODE`).

Сдвиг: слот ключа `= (hash(key) + shift) mod |P|`; одно соединение сдвигает ключ не более одного
раза; соединение, выбранное при сдвиге `s`, сдвигает ключ только если текущий сдвиг всё ещё `s`;
отказ на слоте обхода (§4.3) и на слоте повтора ключ не сдвигает и в память K2 не пишется. UDP
ключ не сдвигает.

### 4.5 Статистика узла

Путь от мягких признаков трафика к выводу о `Flaky` (A0). Признак идёт в счёт узла, вывод даёт
только сравнение с медианой пула. По принципу П отказы узла, его `detour` и транспортной сессии в
счёте не различаются.

- **Q1 (счёт).** Мягкий признак `X` через `n`, `a ≥ E`, даёт `fails(n) += 1`, не более одного раза
  на `key` среди последних 16 засчитанных ключей узла (без ключа — каждый признак), если после него
  путь через `n` подтверждён — `ANSWER` через `n` с началом `≥ b`, полученный не позже `b + 2T`, D1
  для `n` не сработал (признаки мёртвого узла не считаются) — и:
  - `FAIL_NODE` (в том числе отказ `detour`): повтор того же соединения через `m ≠ n` дал `ANSWER`;
    отказ активный либо `Live(X; P \ {n})` (при таймауте открытия сеть доказана в первой половине
    ожидания);
  - неявный `REFUSE_DST` при `b − w < H`: дополнительных условий нет, счёт по общим условиям
    (короткий обрыв без кода; цена — сценарий 31);
  - неявный `REFUSE_DST` при `b − w ≥ H`: ещё `Live(X; {n})`;
  - `SILENT`: `b` — момент осмотра, на котором выполнено определение (§2, вместе с `Live`); общее
    условие «`ANSWER` через `n` после `b`» для него не требуется — `Live` его уже содержит. Счёт —
    сразу на этом осмотре, один `SILENT` на обмен; пришедший позже `ANSWER` того же обмена счёт
    снимает. Карантин Q2, наступивший на этом счёте, ответ не снимает (§6).

  `CANCEL` и `LOCAL` в счёт не идут. Явный `REFUSE_DST` (K1) даёт `fails(n) += 1` раз на ключ в
  момент, когда повтор того же соединения через другой слот дал `ANSWER`; отложенного ожидания и
  срока нет: повтора не было или он не ответил — счёта нет.
- **Q2 (карантин).** `conns(n) ≥ 8 ∧ fails(n) ≥ 3 ∧ fails(n)/conns(n) ≥ 5 % ∧ fails(n)/conns(n) > 2·median{fails(m)/conns(m) : m ∈ P, m ≠ n, conns(m) ≥ 8}`,
  множество под медианой не пусто
  ⊢ `Flaky(n)` велика → карантин: слот обходится и получает замену; history не стирается; счётчики
  `n` обнуляются; записи `n` в памяти K2 стираются.
- **Q3.** `conns(n) = 256` → оба счётчика `n` делятся пополам. D1 и уход `n` из слота обнуляют счётчики.
  UDP в счётчиках не участвует.
- **Q4 (мигалка).** `strikes(n)` — число вычёркиваний D1 узла с последнего планового прогона;
  плановый прогон его обнуляет первым ответом своей пробы, а не стартом: вычёркивания во время
  прогона идут уже в новый интервал, прогон без ответа интервал не начинает (§5). D1 для `n` при `strikes(n) = 1` (второе вычёркивание за интервал
  прогона), и в пуле, кроме `n`, есть другой узел (то же условие непустого множества, что у Q2)
  ⊢ `n` то умирает, то оживает → статус карантина Q2: узел не кандидат до планового прогона;
  выход, защита малого пула и поведение при сигнале платформы — те же, что у Q2. Действия D1
  (вычёркивание, пустой слот, замена) совершаются как обычно.

Карантин (Q2, Q4) и пометка K5 снимаются плановым прогоном, ручным прогоном (оба — только получив
ответ хотя бы одной пробы, §5), сигналом смены сети.

### 4.6 Пауза раундов

Одна пауза на группу для проверок пула, поиска замены и проб жизни. Мягкие признаки и молчание
проб ни о чём не говорят (A0, D5), поэтому пауза — только ограничение темпа, вывода в ней нет.

Состояние:

- `g ∈ {15, 30, 60, 120}` с — ступень; база 15 с (`T`), потолок 120 с;
- `o` — множество кандидатов, опрошенных с последнего ответа пробы группы (W3), как бы их ни
  опросили: от курсора или первыми по живой history (§5); узел в нём один раз, сколько бы проб ни
  получил. `lap ≡ C ⊆ o` — полный круг: с последнего ответа опрошен каждый кандидат `C` (у группы
  без кандидатов вне пула круг пройден сразу). Кандидат с живой history, опрошенный первым, курсор
  не двигает (I8), но в `o` идёт: его проба без ответа — такой же опрос, как от курсора;
- `xr` — право на один внеочередной раунд в текущей паузе: выдаётся по W5, тратится раундом,
  пропадает с концом паузы.

Правила:

- **W1 (пауза).** Раунд кончился в момент `e` ⊢ следующий раунд начинается не раньше `e + g`
  (кроме внеочередного, W5). Пауза идёт на `[e, e + g)`. Раунд, не запустивший ни одной пробы
  (нечего пробовать: кандидатов нет или все в карантине; поиск, начатый при занятом флаге прогона),
  — не раунд: паузы не начинает, ступень не меняет (W2), право `xr` не тратит.
- **W2 (рост).** Раунд, запустивший хотя бы одну пробу, кончился, ни одна его проба не дала
  `ANSWER`, и в момент конца выполнено `lap` ⊢ `g := min(2g, 120)`. До полного круга ступень не растёт: поиск кандидата в большой
  группе идёт с базовой паузой. Внеочередной раунд ступень не меняет.
- **W3 (сброс).** `ANSWER` любой пробы группы — проверки, кандидата, жизни, планового или ручного
  прогона ⊢ `g := 15`, `o := ∅`. Событие N3 ⊢ `g := 15`, текущая пауза снята (L3: после заморозки
  без остаточных пауз); `o` событие не трогает. Первый байт соединения приложения ступень **не**
  сбрасывает (W5).
- **W4 (пробы жизни).** Пока `g > 15` и пауза идёт, проба жизни не начинается; признак, который её
  запустил бы, ничего не запускает (§4.2). Повтор открытия (§5) и уже стоящий обход слота от паузы
  не зависят; обход по медленному признаку ставится как обычно (S2). При `g = 15` проба жизни
  ограничена только своими лимитами (§4.2).
- **W5 (первый байт).** `ANSWER` соединения приложения через группу, выбранного в этой паузе (выбор
  не раньше `e`), пока `g > 15` и пауза идёт, и в этой паузе внеочередного раунда ещё не было ⊢
  `xr`. Соединение, выбранное до `e`, шло во время раунда, и его ответ — не новость о времени после
  раунда: выбор, запустивший поиск, иначе давал внеочередной поиск сразу за ним — вторую пробу тех же
  кандидатов в ту же секунду. Право `xr` — один раунд сразу: проверка, если её ждёт оставшееся
  подозрение (D4), иначе поиск замены, если есть пустой слот; без повода право ждёт
  повода до конца паузы. Раунд ответил — W3; не ответил никто — ступень и конец паузы прежние.
  При `g = 15` права нет: следующий раунд и так через 15 с.

Пауза своя у каждой группы: свидетельства у каждой группы свои.

### 4.7 Очередь проб ядра

Одна очередь на экземпляр ядра, общая для всех rr-групп; в полёте не больше `U` = 16 проб
самовосстановления (проверок, поиска, жизни). Плановый прогон (SPEC 019 и апстримный) в неё не
входит, у него свой предел. Очередь — только порядок и темп: выводов в ней нет, паузы (W),
карантин и счёт остаются на группе.

- **U1 (пачка).** Группа ставит в очередь пачки: первые пробы пула, пачку кандидатов, пробу жизни,
  часть решающих проб вместе с её «контролем после» (§4.2, шаг 4). Пачка допускается целиком, когда
  для неё есть места; пачка больше `U` делится на части по `U` (часть решающих — по `U − 1` узлов и
  своя проба «контроль после»).
- **U2 (справедливость).** Ждущие группы обслуживаются по кругу: в свою очередь группа получает
  одну пачку; следующая пачка той же группы — после того, как свою пачку получила каждая ждущая.
- **U3 (один узел — одна проба).** Узлу в полёте одна проба на ядро (тот же URL пробы). Группа,
  которой нужна проба узла с уже летящей пробой, ждёт её исход и берёт его, если начало этой пробы
  удовлетворяет границе её правила (первая проба `≥ x`, решающая `≥ b0`, «контроль после» `≥ y`,
  проба жизни — любая); иначе после её конца ставит свою. `ANSWER` пишет общую history — его видят
  все ждавшие группы, каждая применяет к нему свои правила.
  Исключение — собственная первая проба этого же узла этой же группы: решающая проба (§4.2, шаг 3)
  её не ждёт и не берёт, а летит параллельно с ней с момента по шагу 3 (`x + H` для зависшей
  первой). Отменённую пробу никто не берёт: когда у полёта не осталось ждущих, он снимается из
  очереди сразу, и новая проба того же узла ставится заново. Отменённая проба — не исход: ни
  `ANSWER`, ни «без `ANSWER`» ни для одного правила (D1, проба жизни, живость history, §5).

Ожидание в очереди сдвигает начала проб позже, но не раньше их нижних границ, поэтому ни одна
посылка D1, D3, Q1, K2 от него не ломается; удлиняются только сроки (L1).

## 5. Действия

- **Повтор.** Соединение, чьё открытие не удалось (`FAIL_NODE`, `REFUSE_DST` на открытии, `LOCAL`),
  один раз открывается через другой слот пула `≠ n`, чей лист не вложенный `urltest`; для ключа с
  пометкой K5 — только по `FAIL_NODE`. В заморозке так же: слот выбирается тем же порядком, а исход
  и исходного открытия, и повтора в правила не идёт (N0, I4). Подозрение для повтора мягкое, как
  для выбора (§4.3): сначала следующий по кругу слот без подозрения; если таких нет — следующий по
  кругу слот под подозрением. Слот, который выбор пропускает (пустой, мёртвый, карантинный), повтор
  не берёт. Повтор — действие над одним соединением, не вывод: ключ остаётся на прежнем узле, в том
  числе закреплённый (sticky).
  Повтор делает только самая внешняя rr-группа в цепочке одного открытия: она помечает контекст
  открытия, и внутренняя rr-группа (как `detour` узла или член `least_test`/`urltest`) при этой
  пометке не повторяет. Если член, выбранный внешней группой, — сам вложенная группа `urltest`
  (напрямую или через селектор), внешняя его не повторяет (выше) и контекст не помечает: повторяет
  внутренняя. В цепочке одного открытия повторяет ровно одна rr-группа. Неудачный повтор пишется в
  лог на уровне Debug.
  Принятая цена: при разовом сбое живого узла один запрос уходит с другого адреса — риск для сайтов
  с привязкой сессии к адресу. На правила §4 исход повтора влияет только как посылка Q1.
- **Замена.** В пустой слот (узел вычеркнут D1) или слот карантинного узла встаёт первый узел из
  `C`, ответивший на свою пробу в текущей проверке или поиске замены; по history без пробы —
  никогда, при любом `pool_tolerance` (смена узла живого слота по скорости при `pool_tolerance > 0`
  — дело прогона группы, I5). Карантинный узел (Q2, Q4) кандидатом не является до
  планового прогона. Вычеркнутый узел — кандидат на общих основаниях: ответив на свою пробу, он
  получает history (D3) и может занять пустой слот, как любой кандидат. Порядок опроса кандидатов
  (общий для шага 2 проверки и поиска): сначала кандидаты с живой history по возрастанию задержки,
  затем остальные от курсора `c` по кругу в порядке конфига.
  **Живая history** узла — history, записанная после последней неудачной пробы самовосстановления
  этого узла (проверки, поиска, жизни; отменённая проба не в счёт). Неудачная проба кандидата
  history не стирает — это был бы вывод без контроля (A0); она только лишает history живости, и
  кандидат идёт в порядок курсора, пока его history не перезапишут (ответ любой пробы, прогон).
  - *Замена в проверке* (после D1 или Q2 в ней): пачки размером с пул через `H`; предел `k` пачек —
    один на проверку, общий для шага 2 и замены и для обеих частей порядка; замена опрашивает только
    пачки, которые шаг 2 не израсходовал. Кандидат, послуживший контролем, занимает первый
    освободившийся слот.
  - *Поиск замены* — отдельный раунд (§4.2), его запускает пустой слот на выборе после паузы (W1)
    или право W5. Узлы пула он не пробует и контроля не ждёт: встаёт кандидат, ответивший на свою
    пробу. Слот непроверенного узла (§5 «Прогон без ответа») поиск не заполняет и не запускается
    из-за него: такой слот проверяет проверка. Пачки размером с пул через `H`, не больше `k` за раунд; после полного круга курсора без
    ответа пауза нарастает (W2). Без кандидатов поиск не запускается; поиск, начатый при занятом
    флаге прогона, ничего не пробует (во время прогона слот заполняет прогон) — в обоих случаях
    раунда нет (W1).
    Раунд без ответа оставляет слот пустым (выбор его пропускает); следующий — после паузы, курсор
    общий с проверкой.

  Пишет слоты только один исполнитель одновременно (общий флаг с прогоном группы). Флаг берётся
  только на запись слота: пробы раунда его не держат, и плановый или ручной прогон во время раунда
  не пропускается. Если в момент записи флаг занят прогоном, раунд запись пропускает — слот
  заполняет прогон.
- **Заполнение при прогоне.** Во время любого прогона группы — планового, стартового, после
  сигнала сети, ручного теста — узел из `C`, ответивший на пробу, сразу встаёт в пустой слот или
  слот, чей узел без history. Во время прогона слот заполняет сам прогон. История пачки проб
  пишется в конце пачки (апстрим `37fffa325`, синк [166](../166-UPSTREAM_SYNC_1_14_4_PLUS_146/SPEC.md)):
  слот узла, не ответившего в той же пачке, до её конца не пуст, его закрывает итоговая раскладка
  или заполнение следующей пачки. Итоговая раскладка
  прогона узел из слота в слот не переносит: узел, стоящий в слоте, — в том числе вставший во время
  этого прогона, — остаётся в своём слоте, а раскладка заполняет только пустые слоты и слоты без
  history, каждый по его индексу (I5). При `pool_tolerance > 0` живой слот меняет узел только по
  оговорке I5. Ленивый плановый и
  стартовый прогон (SPEC 019) идёт до `|P| + r` живых, `r = max(⌈|P|/2⌉, 1)` — запас: узлы запаса в
  слот не встают и трафик не несут, их свежая history ставит их первыми в порядке опроса замены;
  живых меньше — прогон идёт до конца списка. Узлы, снятые прогоном с карантина (Q2, Q4), прогон
  пробует всегда, и при набранных пуле и запасе.
  Плановый прогон не ставит в слот узел, вычеркнутый (D1) этой группой во время самого прогона, —
  ни заполнением, ни итоговой раскладкой: раскладка отдаёт такой слот следующему живому узлу обхода,
  а если живых больше нет, слот после прогона пуст. Узел, вычеркнутый раньше (в прошлом интервале),
  — обычный кандидат: ответив на пробу прогона, он может встать в пустой слот (прогон снимает
  карантин Q4, узел ответил). Слот, в котором после
  прогона (или после того, как D1 другой группы стёр общую history листа) стоит узел без history, —
  пустой слот: выбор его пропускает, в пул проверки он не входит, он запускает поиск замены и не
  запускает проверку пула (I9). Исключение — слот непроверенного узла (ниже, «Прогон без ответа»):
  выбор его пропускает, но заполнение при прогоне его не берёт.
- **Прогон без ответа.** Пачка проб прогона, в которой не ответила ни одна проба, пока в прогоне
  не ответил никто (узлы пула, очередная пачка обхода, узлы из карантина; у ручного прогона и при
  `pool_tolerance > 0` — весь список одной пачкой), — наблюдение без контроля (A0): мёртвый узел от
  лежащей сети она не отличает. Такая пачка history не стирает: history, стёртая её неудачными
  пробами, возвращается, кроме узла, вычеркнутого (D1) за это время; history, которую за это время
  стёрла другая группа ядра (history общая на ядро), не возвращается. После первого ответа прогона
  контроль есть: неудачная проба стирает history как обычно. Прогон, в котором не ответил никто, не меняет
  состояние группы: ни раскладку, ни пустоту слотов, ни счёт, ни `strikes(n)`, ни карантин и пометки
  K5. Плановый прогон снимает их своим первым ответом (до заполнения по этому ответу), ручной — в
  раскладке; узлы, бывшие в карантине на старте, плановый прогон пробует и до ответа. Если узлы
  пула не ответили в пачке без ответа, а позже в прогоне ответил другой узел, плановый прогон
  пробует эти узлы пула ещё раз — уже с контролем: ответивший остаётся в слоте (обрыв в начале
  прогона), не ответивший теряет history, и его слот заполняется как пустой (пул из одного узла,
  пул, умерший целиком).
  Исключение — ручной тест (SPEC 019, решения владельца 2026-11-26): history неответивших он стирает
  и без единого ответа, как апстрим, чтобы интерфейс показал их ошибкой; раскладку, счёт и карантин
  не меняет. Если в ручном тесте не ответил никто, узлы пула, чью history он стёр, — **непроверенные**
  (кроме карантинных): контроля не было, и мёртвыми их считать нельзя (A0). Слот непроверенного
  узла не пустой: выбор его обходит, как слот без history, — трафик в неответивший узел не идёт; если
  обойти нечем (непроверенные все слоты), выбор, как и при пуле без history, остаётся на своём слоте.
  Ни поиск замены, ни заполнение при прогоне такой слот не берут. Проверяет его первый раунд после
  теста: непроверенный узел на выборе после паузы (W1) запускает проверку пула (§4.2), а не поиск, и
  проверка судит непроверенные узлы вместе с живыми: ответивший получает history (D3) и остаётся в
  слоте, не ответивший при ответившем контроле вычеркнут (D1), его слот заполняет замена. Проверка
  без ответа (D5) пометки не снимает. Прогон с ответом снимает пометки после того, как пробовал узлы
  с контролем: ручной тест и прогон после смены сети пробуют весь список одной пачкой, плановый
  пробует непроверенные узлы пула ещё раз после первого ответа, как узлы пачки без ответа. Пометка
  уходит и тогда, когда узел снова получил history или покинул слот. Второй ручной тест в том же
  обрыве пометки сохраняет. Прогон без ответа и сигнал смены сети их не снимают. Если в ручном
  тесте кто-то ответил, контроль был: неответившие теряют history без пометки, их слоты пустые, как
  после любого прогона с ответом. Прогон после сигнала смены сети — под общим правилом.
- **Вне самовосстановления:** тест соединения, замер задержки через группу (выбор узла для него
  ничего в группе не запускает, §4.2), режимы `least_test` и `failover`.

## 6. Что обязано выполняться

Безопасность (при A0–A6):

- **I0.** Каждый вывод о `Node`, `Site`, `Flaky` получен одним из четырёх путей: жёсткое
  наблюдение (D3, K1), управляемое сравнение (D1), статистика против медианы (Q2), повтор
  наблюдения при доказанно живом узле (K2 — только о `Site`, только сдвиг); Q4 опирается на два
  вывода D1. Мягкий признак сам
  вызывает только повтор, пробу жизни, счёт (Q1), запись в память K2 и временный обход слота (S1
  после неудачной пробы, S2 сразу).
- **I1 (обрыв без сигнала).** `Net = down` на всём интервале наблюдений ⇒ ни вычёркивания, ни
  сдвига, ни карантина, ни счёта, ни события. Вывод из правил: у D1 в посылках контроль `ANSWER`,
  у Q1 — `ANSWER` через `n` после признака, у K1 — явный отказ (A2: `Net(b) = up`), у K2 — `ANSWER`
  между попытками, у Q2 — счёт Q1, у событий — только N3; ни одной из этих посылок при лежащей сети
  нет. Каждое соединение повторяется один раз через другой слот (сначала без подозрения, §5) и
  падает.
- **I1′.** Один перерыв сети любой длины без сигнала (при A6) ⇒ ни вычёркивания, ни счёта по
  обменам, начатым до его конца (кроме неявного отказа с `b − w < H`: один счёт, сценарий 31), и не
  больше одного из двух признаков K2 на ключ: `Y` в K2 доказывает путь на `[a1, a2]`, так что оба
  признака в одном перерыве не помещаются. Ложный сдвиг от перерыва возможен только у ключа,
  чей первый признак был до перерыва при ответившем после него узле.
- **I2.** `n` вычеркнут ⇒ существовал интервал, на котором `n` не отвечал, а контроль отвечал до и после.
- **I3.** `key` сдвинут с `n` ⇒ был явный отказ `d` через `n` (K1) либо два мягких признака ключа на
  `n` с `ANSWER` через `n` другому между их началами и без `ANSWER` ключу (K2). Пометка K5 ⇒ `|P|`
  сдвигов подряд без единого ответа ключу.
- **I3′.** Кандидат встаёт в слот только по `ANSWER` своей пробы (замена, заполнение при прогоне).
- **I4.** Ни одно наблюдение с `a < E` не участвует в выводах.
- **I5.** Один узел занимает не больше одного слота; живой слот не теряет узел иначе как по D1/Q2.
  Плановый прогон с ответом снимает со слота узел, не ответивший на его пробу (§6), в том числе
  узел с заблокированным адресом пробы (сценарий 22): по §1 такой слот не живой.
  Оговорка для `pool_tolerance > 0`: в этом режиме группа держит в пуле самых быстрых с гистерезисом,
  и прогон группы (плановый или ручной, SPEC 019) может сменить узел живого слота, если узел снаружи
  быстрее больше чем на `pool_tolerance`; ключи этого слота переходят к новому узлу.
  Самовосстановление по скорости слот не меняет.
- **I6.** Заморозка включается только событием N3 (сигнал платформы или расхождение часов).
- **I7.** Память K2 — не вывод: пишется по K4, стирается по K2 (N0, плановый прогон, уход узла,
  ответ ключу, сдвиг). Вытеснение из переполненной таблицы, выпавшее доказательство пути и
  совпадение ячеек памяти ответов ключей приводят только к пропуску сдвига, ложного сдвига не дают.
- **I8.** Курсор `c` меняет только опрос кандидатов (шаг 2 проверки, замена, поиск замены); проба
  кандидата не меняет ни history, ни слотов иначе как через D3, контроль D1 и замену.
- **I9.** Пустой слот не запускает проб узлов пула; проверку пула запускает только мягкий признак
  на узле пула (§4.2) или непроверенный узел в слоте (§5 «Прогон без ответа»). Вычеркнутый узел в слоте не остаётся, и плановый прогон, во время которого
  его вычеркнули, в слот его не ставит (§5).
- **I10.** Пауза раундов не растёт, пока курсор не прошёл полный круг с последнего ответа (W2), и
  не сбрасывается ничем, кроме ответа пробы группы и N3 (W3).
- **I11.** Непроверенный узел (ручной тест без единого ответа стёр его history) теряет слот только
  по D1 проверки или по неудачной пробе прогона, у которого был ответ (контроль); поиск замены и
  заполнение при прогоне его слот не берут, выбор его слот обходит (§5 «Прогон без ответа»).

Живучесть. `D` — время ответа пробы живого узла (`≤ T`), `G` — остаток паузы раундов (`≤ g`, W1).

- **L1.** `Node(n) = dead`, `Net = up`, через `n` идёт трафик, URL пробы доступен, в пуле есть живой
  узел ⇒ `n` вычеркнут не позже `t0 + G + max(D, H) + T + D`, где `t0` — конец пробы жизни без
  ответа, начатой по первому быстрому отказу (S1) либо по медленному признаку (S2: таймаут
  открытия, осмотр зависшего обмена старше `H`); при отказе в подключении и при `LOCAL` —
  `t0 + G + 2D`. Обход слота начинается при S2 с первого признака, при S1 — с `t0`, то есть через
  один RTT до сервера узла после первого отказа; до `t0` соединения в узел спасает повтор. Для
  зависшего узла это ≈ 41 с (осмотр на 5-й с, проба жизни молчит до 20, решающая проба — с 25 до
  40, контроль после — `40 + d`); принято владельцем: обход идёт с 5-й секунды, соединения в слот
  до вычёркивания не уходят. При `g > 15` проба жизни ждёт конца паузы (W4): `t0` сдвигается до
  `G ≤ g` (на потолке до 120 с), по быстрому отказу обхода до неё нет, соединения спасает повтор;
  внеочередной раунд по первому байту (W5) проверку запускает, только если подозрение уже стоит.
  Если в пуле живых нет — плюс `H·(j − 1) + D` при `j ≤ k`, `j` — номер пачки кандидатов от
  курсора, первой с живым узлом; при `j > k` — ещё до `⌈j/k⌉ − 1` проверок без вердикта (D5),
  каждая `≤ k·H + T`, и пауза `T` между ними, пока курсор не прошёл полный круг (W2). Проверка
  судит весь пул, так что поводы от одного узла не откладывают вердикт другому. Очередь ядра
  (§4.7) добавляет к каждой пачке ожидание не дольше одного оборота очереди (U2): при `w` ждущих
  группах — до `w − 1` чужих пачек, каждая освобождает места не позже `T`.
- **L1′ (пустой слот).** Слот пуст, в `C` есть живой кандидат, URL пробы доступен через него ⇒
  слот заполнен не позже, чем курсор дойдёт до этого кандидата: `⌈i/(k·|P|)⌉` раундов поиска с
  паузой `T` (ступень до полного круга не растёт), `i` — место кандидата от курсора; кандидат с
  живой history — в первом раунде. На большой группе с малым пулом это долго — ограничение §6.
- **L2.** `Site(d, n) = refuse` с кодом ⇒ ключ сдвинут после первого явного отказа (K1).
  Отказ без кода ⇒ ключ сдвинут вторым закрытием (K2), если между попытками через `n` ответили
  другому ключу или пробе. Молчание назначения ⇒ ключ сдвинут вторым ожиданием, дожившим до
  `T_site` и осмотренным (K2); клиент, уходящий раньше `T_site`, даёт `CANCEL` — сдвига нет, ключ
  остаётся на узле. Без ответа через `n` между попытками сдвига нет; узел уходит в карантин, когда
  таких ключей набирается на Q2.
- **L3.** Заморозка конечна: `T` от последнего события N3; после неё первая же причина запускает
  проверку без остаточных пауз. Проверки заморозку не включают, цикла «проверка → заморозка» нет.
  Все пробы группы — проверок, поиска, жизни — в одном счёте. Проб в одном раунде, независимо от
  `|C|`: проверка без ответа (D5) — `|P|·(k + 1)` (пул и `k` пачек); проверка с контролем и
  заменой — `|P|·(k + 2) + ⌈|P|/(U − 1)⌉` (плюс решающие и по одному «контролю после» на часть);
  поиск замены — `k·|P|`.

  Раундов на ступени `g` — не больше одного за `g` после конца прошлого плюс один внеочередной
  (W5, только при `g > 15`); проб жизни — не больше 4 за 15 с на группу и ни одной, пока идёт
  пауза при `g > 15` (W4). Отсюда в минуту при мгновенных исходах (худший темп):
  - **база 15 с:** `4·(|P|(k + 2) + ⌈|P|/(U − 1)⌉) + 16`; без ответов (сеть лежит)
    `4·|P|(k + 1) + 16`; при пуле 3 — 68 и 52;
  - **потолок 120 с** (только без ответов, W3): за цикл `2·|P|(k + 1)` проб раундов и не больше 4
    проб жизни в окне вне паузы — при пуле 3 22 за 2 мин, 11 в минуту; без трафика приложения
    внеочередного раунда нет — 13 за 2 мин.

  При пробах, молчащих до `T`, проверка длится `2H + T` = 25 с и темп ниже: на базе цикл 40 с —
  `13,5 + 12 ≈ 26` проб в минуту при пуле 3. Полный обход курсором 497 кандидатов — 83 раунда на
  базовой паузе, не меньше 21 мин, затем ступени 30, 60, 120 с.

  Граница ядра (§4.7): при любом числе групп в полёте не больше `U` = 16 проб. Проба, молчащая до
  `T` = 15 с, держит место весь `T`, поэтому при лежащей сети без ICMP на всё ядро не больше
  `U·60/T` = 64 проб в минуту. При мгновенных исходах (`LOCAL`) место освобождается сразу и граница
  ядра темп не ограничивает: темп — сумма групповых границ выше.
- **L4.** Подозрение конечно: снимается по S3, не позже `2T` от последнего мягкого признака.
- **L5.** Пауза конечна: не больше 120 с; первый ответ любой пробы группы или N3 возвращает её к
  15 с (W3), первый байт приложения даёт раунд сразу (W5).

Ограниченность ущерба при нарушении аксиом:

- ложный счёт — один на ключ, пока ключ среди последних 16 засчитанных ключей узла (§10): ключ,
  вытесненный из этого кольца, может быть засчитан снова — на узле, где сбоят больше 16 ключей,
  граница «один на ключ» не держится, держится только порог доли; до вывода нужно не меньше трёх
  счётов, доля 5 % и вдвое выше медианы;
- ложный карантин — до планового прогона, слот занят другим узлом;
- карантин Q2, наступивший на счёте `SILENT`, который позже снят ответом того же обмена (§2, Q1),
  не отменяется: признанный ущерб, держится до планового прогона, history узла не стирается;
- ложное вычёркивание — узел возвращается кандидатом на следующей замене или плановом прогоне;
  второе за интервал планового прогона — карантин до прогона (Q4); ложное вычёркивание после
  быстрой смены сети без сигнала (перерыв уместился между контролем до и после, нарушение A6;
  в том числе Windows Modern Standby) видят все группы через общую history; это ограничение
  принято владельцем (§9, сценарий 34): разовое вычёркивание живого узла, возврат сам, защиты нет;
- ложный сдвиг (K2) — ключ уходит на соседний слот, то есть на другой адрес для сайта; на узле с
  `Flaky = p` до карантина ложно сдвигается доля `≈ p²` ключей, через узел трафик которых идёт;
- ложная заморозка — `T` без выводов и проб, только по N3; повтор открытия работает;
- ложное подозрение — обход слота до ответа пробы жизни, не дольше `2T`; по быстрому отказу живого
  узла обхода нет.

Принятые ограничения (без правки, §9):

- медленный поиск замены в большой группе с малым пулом: пачка `k·|P|` за раунд, группа 300 с пятью
  живыми, пул 3 — на стенде в среднем ≈ 4 мин, полный круг курсора ≈ 12 мин; огромные группы —
  вопрос конфига. Запас прогона (§5) снимает случай «живые есть, но прогон до них не дошёл»: до
  `r` живых вне пула с последнего прогона опрашиваются первыми; медленным поиск остаётся, когда
  запас вычеркнут или пуст;
- вложенный `urltest` как член: D1 внешней группы стирает общую history листа, последним выбранного
  внутренней. Внутренняя rr-группа видит в слоте узел без history как пустой слот: выбор его
  пропускает, на выборе после паузы запускается поиск замены, проверки пула нет; внутренняя группа
  других режимов действует по своим правилам выбора. Волна одна;
- до D1 повтор и обход берут следующий по кругу слот, и сосед несёт двойную долю трафика (при двух
  подряд мёртвых — тройную);
- плановый прогон SPEC 019 при лежащей сети с молчащими пробами может долго держать флаг прогона, и
  на это время поиск замены не начинается, а замена проверки слот не пишет — вне этого документа;
- клиент, закрывший свою сторону после засчитанного `SILENT` (позже `T_site`), счёт Q1 и запись K2
  не снимает: «выходит из учёта» §2 относится к закрытию до засчитанного `SILENT`; снимает их только
  пришедший `ANSWER` того же обмена (§2, Q1);
- смена сети без сигнала платформы (сценарий 34) — разовое вычёркивание живого узла, возврат сам;
- ложные сдвиги на узлах, где назначения массово закрываются без байта, — цена `≈ p²` выше (K2);
  стенд 9 на живой подписке: три неподтверждённых сдвига такого рода, без правки;
- плановый прогон SPEC 019 заменяет узел пула, не ответивший на его пробу, когда в той же пачке
  ответил другой узел, в том числе живой узел, чей путь лежал в момент пробы (стенд 9: стоп
  ретранслятора во время прогона) — раскладка прогона. Обрыв сети, в который попала вся пачка,
  пул не меняет (прогон без ответа, §5);
- молчащий узел среди первых `|P|` узлов конфига задерживает стартовый прогон до `T` = 15 с:
  стартовый пул — первые `|P|` узлов, прогон сначала ждёт пробы всего пула и только потом идёт
  обходом, и всё это время в группе нет живого слота (стенд 10, 3a: 15 с ошибок). Молчащий узел в
  обходе живых не задерживает: они встают в слоты за секунды. Порядок стартового прогона SPEC 019,
  без правки;
- живой, но очень медленный или нестабильный узел, который примерно в половине проб не отвечает
  за `T` = 15 с, вычёркивается по D1: в проверке, где обе его пробы промолчали, а контроль до и после
  ответил, он неотличим от мёртвого, и вывод верен по правилу (стенды 9 и 10 на живой подписке).
  Дальше — как при любом вычёркивании: узел возвращается кандидатом, ответив на пробу, второе
  вычёркивание за интервал прогона — карантин Q4. Принято владельцем (§9).
- узел, который блокирует адрес пробы, а другой трафик пропускает, для группы мёртв (§1,
  сценарий 22), как у апстрима. Быстрый отказ пробы при ответившем контроле — D1 в первой
  проверке; молчащая проба — узел держится, пока трафик даёт `ANSWER` в окне проверки, и уходит
  по плановому прогону (пункт о прогоне выше). Это не ложное вычёркивание: кандидатом узел не
  вернётся, пока адрес пробы через него закрыт. Лечится адресом пробы, который узлы не блокируют.
  Решение владельца 2026-11-26;
- одна длинная остановка узла может сорвать несколько соединений разных ключей сразу, и каждое
  засчитывается отдельным признаком Q1: на малой выборке при медиане 0 это карантин Q2 до
  планового прогона (стенд `impair` v2, 4c: одна остановка 6 с — три признака из 40 соединений).
  Решение владельца 2026-11-26.

Цепочки. Сдвиг K2 и счёт Q1 идут от одних признаков независимо: счёт — раз на ключ (в пределах
кольца 16 ключей), сдвиг счёта не добавляет, поэтому цепочки «сдвиг → счёт → карантин» нет;
остаётся «счёт → карантин» (сценарий 30). Ложное вычёркивание обнуляет счётчики и не трогает ключи: ключи привязаны к слоту; второе за
интервал прогона даёт карантин Q4 до прогона, третьего вычёркивания за интервал нет.
Ложная заморозка новых событий не порождает. Пометка K5 требует `|P|` сдвигов подряд без единого
ответа ключу.

## 8. Что проверить в коде по этому документу

Правила §4 изменены относительно кода; ниже — что привести в соответствие и что установить.

1. **Сдвиг по мягким признакам (A0, K2, K4).** Код сдвигает ключ по закрытию без байта, по отказу
   открытия и по брошенному ожиданию после вердикта «жив». По этому документу сдвигает явный
   отказ (K1) и второй мягкий признак ключа на узле при `ANSWER` через узел другому между
   попытками (K2), с памятью фиксированного размера и её стиранием; `CANCEL` и `LOCAL` в K2 не
   идут; отменённый `SILENT` возвращает сдвиг.
2. **`SILENT` (§2).** Порог `T_site`, уход клиента — `CANCEL`; сроков 5 с и 30 с нет. Применение —
   при осмотре слота и при ответе пробы; отмена счёта пришедшим ответом.
3. **Классы исходов (§2).** `LOCAL`: «сеть недоступна», «узел сети недоступен», ошибки интерфейса и
   привязки — без выводов. Ошибка транспортной сессии узла (mux, QUIC) — отказ маршрута слота
   (`FAIL_NODE` на открытии, как закрытие без байта после него), не `LOCAL`. Явный отказ у листа,
   который сам ходит до сайта, — только отказ в подключении и сброс. Установить, отличает ли код
   явный отказ по назначению `d` от отказа следующему звену маршрута (`detour`): от этого зависит
   действие — сдвиг ключа (K1) или `FAIL_NODE`. Закрытие самой группой — `CANCEL`, не неявный отказ.
4. **Протоколы с отказом назначения на открытии.** SSH (отказ открытия канала), hysteria2 (ответ с
   ошибкой на запрос потока): если код видит причину, это явный `REFUSE_DST` (K1), а не `FAIL_NODE`.
   Чем раньше протокол даёт код, тем раньше сдвиг: K1 с первого отказа, K2 — со второго.
5. **Проверка (§4.2).** Опрос всего пула; опрос кандидатов от курсора, не больше `k` пачек за
   проверку, курсор сохраняется между проверками; без ответа — D5: без вердикта и без заморозки;
   решающая проба после ответа контроля, `LOCAL` решающей пробы — посылка D1; контроль после.
   Убрать: соседа и «третьего», второй круг, критерий быстрого ответа (`≤ 1 с и ≤ T/4`), вердикт
   «своя сеть» и заморозку по молчанию проб.
6. **N2 и N4 убраны.** «Сеть вернулась» по зависаниям на двух узлах и заморозка по локальной
   ошибке не должны оставаться в коде.
7. **Правило половины.** `SILENT`, счёт неявного отказа при `b − w ≥ H` и счёт таймаута открытия
   требуют `Live`. Срок ожидания доказательства «после» — `2T`, не 60 с.
8. **S1–S3.** Быстрый отказ (активный `FAIL_NODE`, `LOCAL` на открытии к адресу прокси-узла, явный
   отказ) — проба жизни без обхода, обход и проверка — после её неудачи. Медленный признак —
   проба жизни и обход сразу. Срок `2T`; конец зависшего обмена подозрения не снимает; плановый
   прогон снимает.
9. **K5.** Счёт круга обнуляется ответом ключу; помеченный ключ сохраняет повтор по `FAIL_NODE`.
10. **Слепая группа убрана.** Сейчас, по описанию, — «своя сеть» и заморозка по кругу. Молчание
    всех проб — D5; заморозку включает только N3.
11. **N0.** `E` — конец заморозки; обмены, начатые в заморозке, не участвуют. Повтор открытия в
    заморозке есть, состояние группы он не меняет. Сверка часов — при каждом исходе, с
    переустановкой базиса.
12. **D1 и гонка с ответом.** `ANSWER` через `n`, пришедший после вычёркивания, вердикт не отменяет.
    Проверить, что посылка «нет `ANSWER` с началом `≥ x`» читается в момент вердикта.
13. **I5 при заполнении во время прогона.** Остаточная гонка: кандидат занимает слот узла, чья проба
    ещё идёт; с R7 (пункт 22) к прогону добавляется замена по контролю — один исполнитель слотов.
    Стенд 9: итоговая раскладка ленивого прогона строилась по слотам, снятым до его проб, и
    переносила узел, вставший во время прогона, в запас, а его слот отдавала другому (лог «takes the
    dead slot» расходился со слотами) — раскладка строится по слотам на конец прогона (§5).
14. **Полузакрытие и уход клиента (§2, R5).** Конец чтения со стороны клиента (EOF, закрытие
    входящей стороны) до первого байта от узла — `CANCEL`: обмен выходит из учёта `SILENT`, счёта
    Q1, памяти K2 и обхода S2. На стенде не распознавалось для HTTP CONNECT и SOCKS5. Под mux и в
    цепочке обёртка может не узнать о конце потока клиента — установить и закрыть.
15. **Явный отказ и проба жизни (A2, K1).** Явный отказ нигде не служит доказательством пути
    (снятие подозрения, `Live`, посылки Q1 и K2); K1 запускает пробу жизни.
16. **R1 — пустой слот.** D1 убирает узел из слота сразу, даже без замены (на стенде узел
    оставался и вычёркивался заново; `rrHealCheck` собирает пул из всех непустых слотов). Пустой
    слот и слот карантинного узла без замены запускают только поиск замены — пробы кандидатов, без
    проб пула и без контроля (`rrPoolLook`, `rrRefill`); проверку пула — только мягкий признак на
    узле пула (I9).
17. **R2 — пауза раундов (§4.6, W1–W5).** Одно состояние на группу: ступень `g`, счёт `o` курсора с
    последнего ответа и `lap`, право `xr`. Рост — только после раунда без ответа при `lap`; сброс —
    ответ любой пробы группы (в том числе планового и ручного прогона) и N3; первый байт не
    сбрасывает, а даёт один внеочередной раунд на паузу; пробы жизни при `g > 15` ждут конца паузы;
    повтор и обход от паузы не зависят. `o` — множество разных кандидатов, опрошенных с последнего
    ответа, в том числе первыми по живой history: без них (прежняя формулировка) на стенде 9 ступень
    при молчащей сети росла на раунд позже — первый раунд опрашивал кандидатов с history стартового
    прогона, и круг не засчитывался. Внеочередной раунд даёт только соединение, выбранное в паузе
    (W5): выбор, запустивший поиск, давал вторую пробу тех же кандидатов в ту же секунду.
18. **R3 — решающая проба и очередь ядра (§4.2, §4.7).** Решающая проба не посылается узлу, который
    ответил или чья первая проба летит меньше `H`; «контроль после» — один на часть решающих проб.
    Очередь на экземпляр ядра с потолком `U` = 16, пачки целиком, круг между группами (U2), одна
    проба на узел в полёте с учётом нижних границ правил (U3; ключ дедупликации — узел и URL пробы);
    плановый прогон вне очереди. Пробы замены и поиска в общем счёте группы. Формулы L3 — требование
    к коду: в минуту на базе не больше `4·(|P|(k + 2) + ⌈|P|/(U − 1)⌉) + 16` (68 при пуле 3), без
    ответов `4·|P|(k + 1) + 16` (52), на потолке 120 с — `2·|P|(k + 1)` проб раундов и ≤ 4 пробы
    жизни за цикл; на ядро — ≤ 16 в полёте. Стенд 8 мерил 76 и 72 при 52 по формуле — пробы замены
    шли мимо бюджета; повторить замер после правок.
19. **R4 — Q4.** Счётчик `strikes(n)` вычёркиваний D1 с последнего планового прогона; второе D1 —
    статус карантина Q2 до прогона, с теми же выходом, защитой малого пула и поведением при сигнале.
    Проверить, что плановый прогон пробует карантинные узлы и при ленивых проверках SPEC 019; если
    нет — ошибка, чинить.
20. **R5 — классы.** SOCKS `code=1` — `FAIL_NODE`, не `REFUSE_DST` (`protocol/socks/destination_refused_lx.go`).
    Уход клиента — пункт 14.
21. **R6 — вложенные rr-группы.** Повтор только во внешней rr-группе цепочки одного открытия (пометка
    в контексте); внутренняя при пометке не повторяет. Строка лога неудачного повтора — Debug, не
    Error. `onPoolLook` (`urltest_balance_lx.go`) выходит при чужой пробе или замере через группу
    (`rrUnwatched(ctx)`), как `rrOnPick`.
22. **R7 — холодный старт.** Кандидат-контроль проверки занимает освободившийся слот и во время
    стартового прогона (на стенде замену пропускал флаг прогона, слот заполнил прогон на 12 с
    позже). Если правка не простая — оставить код и заменить в §5 последнее предложение «Заполнения
    при прогоне» на «во время прогона слот заполняет сам прогон».
23. **R8 — заполнение и остатки заморозки.** Заполнение пустого слота идёт на любом прогоне группы,
    включая ручной тест (§5). Убрать остатки старой заморозки: комментарий `frozen` в
    `daemon/started_service.proto` («own network down», «frozenSeconds 0 на время прогона») и
    недостижимую ветку «until the network change run ends» в `cmd_api_group_pool_lx.go`.

24. **Ревью 9 (2026-11-25).** Живая history кандидата — по времени последней неудачной пробы узла,
    history по неудачной пробе кандидата не стирается (§5). Пометка контекста R6 не ставится, когда
    выбранный член — вложенный `urltest` (§5). Флаг прогона — только на запись слота, ручной тест и
    тик прогона во время раунда не пропускаются (§5). Раунд без проб и поиск при занятом флаге —
    без паузы и без роста ступени; поиск без кандидатов не запускается (W1, §5). Решающая проба не
    ждёт собственную первую пробу (U3), D1 зависшего узла — по L1 (≈ 41 с). Прогон не возвращает
    вычеркнутый узел; слот с узлом без history — пустой (§5). Полёт без ждущих снимается из очереди
    сразу, отменённая проба — не исход (U3). Часы сверяет каждая группа, взявшая исход (N3).
    Пачки кандидатов при пуле больше `U`: первая проба, получившая место после старта пачки
    кандидатов, остаток этой пачки не уменьшает.
25. **Непроверенные узлы (SPEC 019, 2026-11-26).** Пометку ставит только пачка ручного теста без
    ответа, на узлы пула, чью history она стёрла; набор только растёт. Слот с пометкой не пустой для
    поиска, замены и заполнения при прогоне и не исключён из проверки; выбор и повтор его обходят
    по отсутствию history. Пометку снимают ответ узла (history), уход из слота, D1, прогон с ответом
    после проб с контролем (плановый — после повторной пробы узлов пула).
26. **Соответствие в целом.** Для каждого места в коде, которое стирает history, пишет слот, сдвигает
    ключ, меняет счётчик, пишет память K2, двигает курсор, меняет ступень паузы или включает заморозку, указать правило из
    §4 и путь по I0. Место без правила — ошибка либо пробел этого документа.

## 9. Решения владельца

Принятое и вариантом не являющееся: повтор по мягкому признаку (§5); уход клиента — `CANCEL`;
`T_site = T`; сдвиг по второму мягкому признаку при доказанно живом узле (K2); повтор по
`FAIL_NODE` для ключа с пометкой K5; обход слота по быстрому отказу — только после неудачной пробы
жизни, по медленному признаку — сразу (S1, S2); слот оценивается как маршрут (П); повтор открытия
в заморозке разрешён, запрет заморозки — только на выводы и запись состояния группы (N0,
2026-11-25).

  стенду 10, Ж); слот с узлом без history — пустой слот, поиск замены (§5, §6);
- полёт без ждущих снимается из очереди сразу; отменённая проба не засчитывается как «нет ответа»
  (U3, D1);
- клиент, закрывший сторону после засчитанного `SILENT`, — ограничение без правки (§6); вынос
  обхода R10 из апстримного файла отложен до раунда упрощения.

Не чинить: задержка 7–14 с в history после простоя; единичный `SILENT` пропадает при делении Q3.

Отклонено:

- молчание и неявный отказ вне счёта Q1 — почти весь трафик идёт поверх TLS и первый байт приходит
  сразу; молчание или обрыв без байта при живом узле — обычно сайт, режущий адрес узла;
- отказ промежуточного `detour` вне счёта Q1 — карантин оценивает пригодность слота, а не вину:
  узел за ненадёжным `detour` — ненадёжный слот; полностью мёртвый `detour` ловит D1, рвущий часть
  соединений — только статистика.
- короткий обрыв без кода (`b − w < H`) вне счёта Q1 — теряется основной случай гео-блокировки
  без кода: VLESS и Trojan закрывают поток сразу; ключ всё равно сдвигается K2, но узел с такими
  сайтами в карантин не уходит. Принятая цена — ложный счёт раз на ключ (сценарий 31).

Открытых вопросов нет.
