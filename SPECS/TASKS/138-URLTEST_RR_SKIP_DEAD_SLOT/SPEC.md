При выборе узла `round_robin` пропускает слот, чей узел известно мёртв (последняя проба
провалилась и стёрла его history), и берёт живой слот того же пула. Состав пула и
раскладка слотов не меняются. Если живых слотов в пуле нет — выбор как раньше.

Отказ боевого соединения запускает самовосстановление (§3, дополнение 2026-11-24, не
реализовано). Соединение, которое не открылось, повторяется через следующий слот пула, а группа
фоном пробует отказавший узел и соседа. Узел не ответил, сосед ответил — узел мёртв: слот
обходится и сразу получает замену, не дожидаясь плановой проверки. Узел ответил — он жив, а сайт
через него недоступен: ключ закрепления сдвигается на следующий слот. Не ответил никто — моргнула
своя сеть, ничего не трогается. Узел, который отвечает на пробу, но рвёт соединения заметно чаще
соседей, выводится из пула до следующей плановой проверки. Это не `failover`: пул остаётся пулом.

## 1. Проблема

Конфиг из отчёта:

```json
{
  "type": "urltest",
  "tag": "auto",
  "outbounds": ["ru-7f6da9614", "shadowtls-shadowsocks-inf6da9614", "wh", "shadowtls-shadowsocks-inee53d308"],
  "interval": "3667ms",
  "mode": "round_robin",
  "balancer": { "pool": 3, "pool_tolerance": 700, "sticky_hash": ["none"] }
}
```

Физически серверов два: `ru-7f6da9614` (vless без mux) и `shadowtls-shadowsocks-inf6da9614`
(ss + shadowtls, h2mux) стоят на одном IP, `wh` и `shadowtls-shadowsocks-inee53d308` — на
другом. Сервер моргает на 10–20 с, и оба его узла умирают разом.

Пул по SPEC 019 меняет жильца слота только на живой узел вне пула; живого кандидата нет —
мёртвый остаётся в слоте («пул не пустеет»). Выбор узла берёт жильца слота без проверки
живости, а ошибка дайла пул не трогает. Пока простой длится, мёртвый слот получает свою
долю новых соединений:

| Пул | Раскладка при простое сервера 1 | Доля новых соединений в мёртвый сервер |
|-----|--------------------------------|------------------------------------------|
| 4 из 4 | оба узла сервера 1 в пуле, запасных нет | 1/2 |
| 3 из 4, оба узла сервера 1 в пуле | один слот получает запасной узел сервера 2, второй остаётся мёртвым | 1/3 |
| 3 из 4, в пуле один узел сервера 1 | запасной — второй узел сервера 1, тоже мёртвый | 1/3 |

При этом живые узлы в пуле есть всегда, пока жив хотя бы один сервер.

## 2. Поведение

Только `mode: round_robin`. `least_test` и `failover` не меняются.

**Мёртвый слот** — тег слота резолвится в узел, и в history URL-тестов нет записи под его
реальным тегом (`RealTag`: для вложенной группы — её текущий лист; так же history читает
`GetPool`). Нерезолвимый тег считается мёртвым. Остальные слоты — живые.

1. **Номер слота** считается как сейчас: счётчик (`sticky_hash: ["none"]`) или
   `hash(key) % pool`. Счётчик растёт на 1 за соединение, как сейчас.
2. **В пуле нет живых слотов** → выбор как сейчас, `slot[номер]`. Это холодный старт
   (истории нет ни у кого) и тотальный простой (SPEC 019: ротация по последним известным,
   дайлы падают, восстановление само).
3. **С закреплением.** Живой `slot[номер]` → его узел: ключи живого слота не двигаются
   никогда, строгий ноль переездов SPEC 019 сохраняется. Мёртвый `slot[номер]` → `j`-й
   живой слот в порядке слотов, `j = (hash / pool) % число живых`: ключи мёртвых слотов
   расходятся по живым поровну, по остатку хеша, независимому от номера слота. «Первый
   живой по кругу» не годится: при `[живой, мёртвый, мёртвый, живой]` последний получал бы
   3/4 ключей. При неизменном наборе живых слотов один ключ всегда попадает на один узел.
   Узел ожил → его ключи возвращаются на него со следующего нового соединения, без
   переходного состояния.
4. **Без закрепления.** Ротация идёт только по живым слотам в порядке слотов: `k`-й живой,
   `k = счётчик % число живых`. Все слоты живы → последовательность совпадает с нынешней.
   «Следующий живой» здесь не годится: при пуле из 4 с двумя мёртвыми подряд соседний
   живой получал бы 3/4 соединений.
5. **Пул не меняется.** Выбор слота не трогает раскладку, `onChange` (кэш достижимости
   SPEC 020), References (SPEC 109), `ActiveTags`. Состав пула меняют только
   плановый дотест и замена мёртвого или карантинного узла (§3.4), под одним флагом `checking`.
6. **Сеть.** Узел выбранного слота не поддерживает сеть соединения → fallback
   `Select(network)`, как сейчас (SPEC 019 «Узел слота не поддерживает network»). Проверка
   живости от сети не зависит, как и планирование пула.
7. **Наблюдаемость.** `Now()` показывает фактически выбранный узел. `GetPool` не меняется:
   у мёртвого слота `delay = 0`, то есть слот с нулём в UI пропускается, пока в пуле есть
   живые.
8. **Ошибка дайла** в `round_robin` сама по себе не трогает ни пул, ни history. Меняет их только
   вердикт проверки узлов, которую отказ запускает (§3.3).

### 2.1 Источник сигнала

Своего состояния нет, читается общая history:

- **Дотест пула** каждый тик пробует членов пула с `force` (`pool_tolerance: 0` — членов
  пула, при нехватке живых ещё и кандидатов; `> 0` — все узлы). Запись стирается в момент
  провала конкретной пробы, а не в конце прогона, поэтому пропуск начинается раньше, чем
  дотест перепишет слоты.
- **Ручные тесты** — тест группы, clash API `/proxies/{name}/delay` и `/group/{name}/delay`,
  RPC демона `URLTestOutbound` и `URLTest` — пишут и стирают ту же запись. Успешный
  оживляет узел.
- **Другие группы с тем же узлом** — их пробы; дайл-ошибка в `least_test` стирает запись
  (апстрим); провал fallback-дайла SPEC 054 тоже.
- **Цена общего сигнала.** Ручной тест задержки с коротким `timeout` (clash API
  `/proxies/{name}/delay`, RPC `URLTestOutbound`), который не успел, или отказ дайла /
  fallback-дайла `least_test`-группы с тем же узлом стирает запись и выводит узел из
  ротации `round_robin` до ближайшего дотеста пула — не дольше `interval` плюс время пробы:
  члены пула пробуются каждый тик. Это осознанный компромисс: свой сигнал живости ради
  этого потребовал бы состояния. Пользовательская документация говорит об этом явно.
- **Проверка по отказу соединения** (§3) стирает запись узла, который не ответил на пробу при
  ответившем контрольном узле.
- **Отменённая проба** (закрытие группы) запись не стирает.
- **Штрафы SPEC 054** к `round_robin` не применяются и сигналом не служат. Обход (§2) новых
  счётчиков и таймеров не вводит; счётчики §3.6 влияют на него только через карантин.
- **Возраст записи** не учитывается. У членов пула при работающем тикере запись не старше
  одного прогона; при остановленном (`idle_timeout`, гейт SPEC 020) — последняя известная.

### 2.2 Холодный старт и первый прогон

- До первого ответа пробы истории нет → п. 2 → как сейчас: слоты — первые `pool` по
  конфигу.
- Тёплая история (процесс не выгружался) → пул засеян по ней, узлы живы → пп. 3–4 с первого
  соединения.
- **Первый прогон.** Пробы отвечают не одновременно. Пока ответила часть пула, слоты без
  ответа (ещё не измерены, а не мертвы) тоже пропускаются, и их доля уходит на ответивших —
  до конца их проб, не дольше таймаута пробы 15 с. Это перекос распределения, не отказ;
  отличать «не измерен» от «мёртв» потребовало бы нового состояния.

### 2.3 Задержка реакции

Пропуск начинается, когда проба мёртвого узла провалилась: до ближайшего тика (не больше
`interval`, в отчёте 3,667 с) плюс время провала пробы:

- RST или недостижимость — ожидается быстрее остальных; на устройстве не подтвердилось:
  с `reject with tcp reset` окно было те же ~15–20 с, что с `drop` (не разбиралось);
- чёрная дыра без mux — TCP connect timeout узла, 5 с по умолчанию (`connect_timeout`);
- mux-сессия на внешне живом TCP — до таймаута пробы, 15 с.

На роутере (пул 3 из 4, `interval` 3,667 с) обход начинался через ~15–20 с простоя. Для
простоя в 10–20 с фикс закрывает хвост окна или не успевает вовсе. Узел
возвращается в ротацию в пределах одного прогона после возврата сервера: прогон с мёртвым
узлом длится до таймаута, а буферизованный тик стартует сразу за ним. Пауза SPEC 125
(`tickTooSoon`) этому не мешает: она читает `lastTickRunEnd`, который пишет только
`testNodesTick`, а пути пула зовут `testNodes(…, true)` и отметку не ставят.

Более быстрый сигнал — по боевому соединению — даёт §3: пропуск начинается, как только
проба после отказа соединения подтвердила, что узел не отвечает, а контрольный отвечает.

**Энергия.** Обход проб не прибавляет. Проверка живости — чтение history в памяти, не больше
двух проходов по слотам за соединение. Пробы добавляет только §3, по отказам и в пределах §3.7.

### 2.4 Отвергнуто

- **Сжимать пул в планировании** — убирать мёртвого жильца без замены в `planTolerantPool`,
  `planFirstLivePool` и `balancePoolFirstLive`. Число слотов перестаёт быть постоянным,
  `hash(key) % pool` меняется у всех ключей при каждом сжатии и обратном росте: массовые
  переезды закрепления дважды за простой. Нарушаются инварианты SPEC 019 «пул не пустеет» и
  «живой жилец не меняет индекс слота»; без этого остаётся дырявый слот, а это тот же
  пропуск в выборе. Каждое изменение — `setSlots` → инвалидация кэша достижимости SPEC 020,
  выпавший узел теряет References SPEC 109 и его простаивающие соединения закрываются.
  Срабатывает только в конце прогона, после всех проб и добора, — позже, чем стирается
  history.
- **Fallback `Select(network)` вместо соседнего слота.** Весь перенаправленный трафик уходит
  в один узел, и он может быть вне пула: не в References (SPEC 109) и не в `ActiveTags`
  (SPEC 020, может спать). На холодном старте свёл бы весь трафик в первый узел конфига.
- **Перебор соседей при несовместимости по сети** — нет, правило SPEC 019 не меняется.

## 3. Самовосстановление по отказу соединения

Дополнение 2026-11-24, не реализовано. Только `mode: round_robin`.

Сейчас `round_robin` узнаёт о смерти узла только на плановой проверке. Пока её не было, слот
считается живым, §2 его не обходит, и закреплённые ключи слота и его доля ротации падают — с
`interval` 10 минут до 10 минут.

Группа различает три причины отказа и на каждую отвечает по-своему:

| Причина | Как распознаётся | Что делает группа |
|---------|------------------|-------------------|
| Сайт недоступен через этот узел (гео-ограничение, блокировка адреса) | узел отвечает на пробу | ключ закрепления сдвигается на следующий слот (§3.5) |
| Узел мёртв | узел на пробу молчит, контрольный отвечает | слот обходится и получает замену (§3.4) |
| Легла своя сеть | молчат все опрошенные | ничего не трогается, группа замирает на 15 с (§3.7) |

Исход боевого соединения сам вердиктом не служит: одна ошибка не отличает мёртвый узел от
недоступного сайта. Отказ только запускает пробу, а решает проба по URL, который выбран для
проверки группы.

### 3.1 Что считается отказом

1. **Соединение не открылось.** Любая ошибка открытия, кроме отмены клиентом. Отказ в подключении
   и сброс входят: у прокси-узла при открытии отвечает его собственный сервер, и отказ на этом
   шаге даёт остановленный процесс на живой машине. Сортировать ошибки незачем — причину
   определяет проба.
2. **Соединение закрылось без единого принятого байта**, хотя клиент что-то отправил. VLESS,
   VMess, Trojan и Shadowsocks отдают соединение, достучавшись только до своего сервера, а mux с
   живой сессией, HTTP/2-транспорт, hysteria2 и TUIC — вообще без похода в сеть; отказ у них виден
   только так. Таймером «нет байта» не меряется: соединение может молчать законно.
3. **Успех** — первый байт, пришедший от назначения. Открытое соединение успехом не считается.
4. **Отмена клиентом** — не отказ: ни повтора, ни пробы.

Первый байт ловит обёртка на соединении группы. Путь перекачки данных выбирается один раз, в
начале копирования. Обёртка отдаёт ускоренный читатель нижнего соединения, а после первого байта
сигналит о завершении рукопожатия (`NeedHandshakeForRead`): копирование перестраивает путь, и
чтение идёт мимо обёртки. Запись идёт через обёртку всё время соединения. Узлы `direct` не
оборачиваются: для них недоступный сайт виден на открытии, а обёртка отключила бы перекачку в
ядре системы.

### 3.2 Повтор через следующий слот

Повтор нужен приложению: оно не теряет соединение. На вердикт о узле он не влияет.

1. **Когда.** Только если соединение не открылось (§3.1.1). При закрытии без байта повтора нет:
   приложение уже отправило данные в первый узел; оно повторит запрос само, а ключ к тому
   моменту сдвинется.
2. **Куда.** В следующий по кругу живой слот пула, считая от слота, через который соединение
   реально шло (после обхода §2 это может быть не слот ключа). Узлы вне пула для повтора не
   берутся.
3. **Один повтор**, не больше двух попыток на один вызов группы. Для назначения с несколькими
   адресами роутер зовёт группу на каждый адрес отдельно (`DialSerialNetwork`), и предел
   действует на каждый вызов. Повтор не открылся — приложение получает ошибку первого узла.
4. **Следующего слота нет** (пул из одного узла, остальные мертвы) — повтора нет, приложение
   получает ошибку. Соединение не придерживается до появления замены: таймаут пробы при поиске
   замены — 15 с (`C.TCPTimeout`), быстрая ошибка лучше зависания.
5. **Вложенные группы.** Узел слота разворачивается через `selector` (`Selected()`) до первого
   узла, который не `selector`. Если это `urltest` в любом режиме — повтор не делается: у
   `least_test` и `failover` есть свой (SPEC 054), у `round_robin` — этот. Обычный узел, `chain`,
   `selector` над обычным узлом — повтор делается.
6. **Цепочки.** Повтор идёт через звено узла (`ResolveChainLeaf`), как и первая попытка.
7. **Наблюдаемость.** Список соединений показывает узел, через который соединение реально
   пошло, в том числе после повтора и сдвига (§3.9).
8. **Контекст соединения истёк по дедлайну** — повтора нет, проверка узлов запускается.
9. **Отказ узла вне пула** (fallback `Select(network)` на холодном старте) — ни повтора, ни
   проверки.

### 3.3 Проверка узлов и вердикт

1. **Что пробуется.** Отказавший узел A и сосед B — слот, в который шёл или пошёл бы повтор.
2. **Как.** Тем же URL и таймаутом, что плановая проверка (`g.link`, `C.TCPTimeout`), **без
   записи**: прямой вызов `urltest.URLTest`, history меняется только по вердикту. Штатная проба
   при провале сама стирает history, и моргание своей сети вычеркнуло бы всех.
3. **Свежий узел не пробуется.** Узел с history моложе 30 с считается живым без пробы.
4. **Узел — группа.** Пробуется её текущий лист (`RealTag`), не сама группа. Проба листа делается
   и тогда, когда повтор не делался из-за вложенного `urltest` (§3.2.5).
5. **Вердикт.**
   - **A молчит, B ответил** — A мёртв: его history стирается, ответ B записывается, §2 обходит
     слот, дальше §3.4.
   - **A ответил** — A жив, дело в сайте: history A записывается свежей, ключ сдвигается (§3.5).
     Если не открылся и повтор через B, а B ответил на пробу — ключ сдвигается на два слота.
   - **Молчат оба** — пробуется третий: следующий слот пула, а если слотов больше нет — первый
     кандидат вне пула. Третий ответил — мертвы оба, вычёркиваются оба, ответ третьего
     записывается. Молчит и он или третьего взять негде — своя сеть: ничего не трогается, группа
     замирает (§3.7).
6. **Соседа в пуле нет.** Контролем служит поиск замены (§3.4): кандидат вне пула ответил — A
   мёртв, и этот кандидат его заменяет; не ответил никто — своя сеть.

### 3.4 Замена мёртвого узла

Короткая процедура под тем же флагом `checking`, что плановая проверка: второго писателя слотов
не появляется. Если `checking` занят, ничего не запускается — прогон уже делает ту же работу.

- **`pool_tolerance: 0`** — узлы вне пула пробуются пачками размером с пул, параллельно; в слот
  мёртвого встаёт первый ответивший в порядке конфига. Ответы всех ответивших пишутся в history,
  молчание — нет. Кандидат с history моложе 30 с считается ответившим без пробы. Остальной пул
  не пробуется и не двигается.
- **`pool_tolerance > 0`** — в слот встаёт самый быстрый по history живой узел вне пула, без
  проб; history нет (тесты выключены) — пробами, как выше. Пересортировку по задержке
  делает ближайший тик.
- **Поиск замены как контроль** (соседа в пуле нет, §3.3.6) — кандидаты пробуются всегда, в том
  числе при `pool_tolerance > 0`: выбор по history без проб не говорит, отвечает ли сеть сейчас.
  Если в этот момент идёт плановый прогон (`checking` занят), вердикта нет — решит прогон.
- **Замены нет** — мёртвый узел остаётся в слоте, §2 его обходит.
- **Закрепление.** Ключи заменённого слота переходят на новый узел, ключи остальных слотов не
  двигаются.
- **Оживший узел** в свой слот не возвращается: он кандидат на следующую замену.

### 3.5 Сдвиг ключа закрепления

Сайт может быть недоступен через один живой узел и доступен через другой. Группа запоминает это
одним числом на ключ — сдвигом.

1. **Ключ** — ключ закрепления (`sticky_hash`) плюс адресат: домен, а если его нет — IP
   назначения. Адресат добавляется, если его в ключе закрепления ещё нет, в том числе когда в
   `sticky_hash` нет компонента `domain`: иначе сдвиг уводил бы с узла всё приложение из-за
   одного адреса. Слот по-прежнему считается от ключа закрепления.
2. **Сдвиг** прибавляется к слоту ключа: `(hash + сдвиг) % pool`. Он растёт на 1, когда отказ
   пришёлся на узел, который жив по пробе или по свежей history.
3. **Круг пройден** — сайт недоступен через все узлы пула: ключ получает пометку «проблема в
   адресе», возвращается на свой слот и в подбор больше не играет — ни повторов, ни сдвигов, ни
   проб по его отказам.
4. **Сброс пометки** — плановый тик, ручной прогон, смена сети. Сдвиги без пометки живут до
   рестарта.
5. **Таблица** — 1024 записи (хеш ключа, сдвиг, пометка, признак «отказ пройденным узлам уже
   засчитан» для §3.6.2); при переполнении вытесняется самая
   старая. Сдвиг привязан к слоту, не к узлу: после замены узла в слоте он продолжает действовать.
6. **Без закрепления** (`sticky_hash: ["none"]`) сдвигов нет: ключа нет, защищать адресат от
   слота незачем.

### 3.6 Узел, который рвёт соединения

Узел может отвечать на пробу и при этом не обслуживать заметную долю соединений (перегружен,
стоит в стране с ограничениями). Такой узел выводится из пула по сравнению с соседями.

1. **Счётчики слота** — соединения и подтверждённые отказы, с момента попадания узла в пул.
2. **Подтверждённый отказ** — отказ на узле, после которого то же соединение или тот же ключ
   получили первый байт через другой слот. Повтор получил байт — отказ засчитан первому узлу.
   Ключ после сдвигов получил байт — отказ засчитан узлам, которые он прошёл, каждому один раз.
   Ключ с пометкой «проблема в адресе» никому отказ не засчитывает: виноват сайт.
3. **Порог.** Отказов не меньше 3, и их доля больше удвоенной медианы долей по пулу.
4. **Забывание.** Когда счётчик соединений доходит до 256, оба счётчика делятся пополам. Окна по
   времени нет: память — последние несколько сотен соединений, на нагруженном роутере она
   короткая по времени, на тихом телефоне длинная.
5. **Вывод из пула.** Узел уходит в карантин: слот обходится (как мёртвый по §2) и получает
   замену (§3.4), кандидатом узел не считается. History не стирается — на пробу он отвечает, и
   другим группам он виден живым.
6. **Снятие карантина** — плановый тик, ручной прогон, смена сети.
7. **Без закрепления** счёт работает внутри соединения: не открылось через A, повтор получил
   первый байт — отказ узлу A.

### 3.7 Пределы и заморозка

Константы, без ключей конфига.

- **Одна проверка в полёте на группу.** Свой флаг (CAS), не `checking`.
- **Пауза между проверками — 15 с от конца прошлой.** Ограничивает только пробы. Повторы
  делаются, сдвиги и подтверждённые отказы записываются: узел с history моложе 30 с считается
  живым, новой пробы для этого не нужно.
- **Заморозка — 15 с.** В неё не делается ничего: ни повторов, ни проб, ни сдвигов, ни счёта
  отказов. Сеть ещё не встала, отказ ничего не говорит об узлах, а повтор только удваивает
  ожидание. Включается:
  - вердиктом «своя сеть» (§3.3.5);
  - сигналом пробуждения устройства — он есть на Android, iOS и Windows;
  - сигналом смены сети (`InterfaceUpdated`) — на 15 с, и дольше, пока идёт запущенный им полный
    прогон.
- **Где сигнала сна нет** (macOS, Linux) — защищает сама схема: пока сеть не поднялась, молчат
  все опрошенные, и первая же проверка включает заморозку.

### 3.8 UDP

- **Общий пул.** UDP выбирает узел из тех же слотов: мёртвый и карантинный узел обходится и для
  UDP.
- **Ошибка открытия.** VLESS, Trojan, hysteria2, TUIC при открытии UDP идут к своему серверу, и
  ошибка видна. Обрабатывается как в TCP: повтор через следующий слот и проверка узлов.
- **Пакеты ушли, ответа нет** — запускает проверку узлов, и вердикт о жизни узла выносит она.
  Повтора, сдвига ключа и счёта отказов нет: односторонний UDP бывает законным.

### 3.9 Тест соединения и наблюдаемость

- Тест соединения (SPEC 139) делает повтор, обе попытки видны в трассе, стадия повтора несёт
  `fallback_for`; проб не запускает, history, пул, сдвиги и счётчики не трогает.
- Список соединений показывает узел, через который соединение реально пошло. Запись списка
  создаётся до выбора узла, поэтому в данных соединения есть общая ячейка, которую делят все
  копии этих данных. Группа пишет в неё свой выбор после выбора и после повтора; каждая группа —
  свой, по тегу, так что вложенные группы не затирают друг друга. Список соединений и демон
  читают ячейку; пока она пуста, узел группы берётся как раньше («последний выбранный»). Демон,
  увидев выбор, повторно отправляет для этого соединения событие «новое соединение».
- Лог: `Info` — вычёркивание мёртвого узла (узел, контрольный, результаты проб), вывод узла в
  карантин (отказы, доля, медиана), пометка «проблема в адресе»; `Debug` — сдвиг ключа, вердикт
  «своя сеть».
- `GetPool` показывает нового жильца слота; новых полей нет.

### 3.10 Порядок реализации

1. Отказ открытия, повтор через следующий слот, проверка узлов, вычёркивание, замена, пределы и
   заморозка; реальный узел в списке соединений (§3.9). Закрывает issue #76.
2. Первый байт, сдвиг ключа, счётчики и карантин. Обёртка стоит на каждом соединении группы —
   её цена меряется на роутере до включения.
3. UDP: ошибки открытия и «пакеты без ответа».

### 3.11 Ограничения

- **Вложенный `round_robin`.** Его «текущий лист» — последний выбранный узел, он меняется с
  каждым соединением; проба может попасть не в тот узел, что отказал.
- **Закрытие без байта не повторяется** — приложение видит одну ошибку на ключ и слот.
- **Предел попыток — на вызов группы** (§3.2.3): назначение с несколькими адресами роутер
  открывает по адресам последовательно (`DialSerialNetwork`), и каждый вызов может дать свой
  повтор.
- **Потоки мимо `DialContext` группы** — те, что роутер ведёт сам (pre-match flow,
  `RoutedFlow`), — не получают ни обхода, ни повтора.
- **Проверка без соседа во время планового прогона** вердикта не выносит (§3.4): решает прогон.
- **Задержка соединения.** Приложение ждёт отказ первой попытки (до 5 с подключения узла, до 15 с
  через mux) и затем повтор. Для `direct` и WireGuard к недоступному сайту это два таймаута
  подряд, пока ключ не сдвинется или не получит пометку.
- **Узел в стране с ограничениями** может уйти в карантин по подтверждённым гео-отказам, хотя для
  остальных сайтов он годен. Принято: если есть узлы удачнее, берутся они.
- **Пул из двух узлов.** Медиана считается по одному соседу, сравнение грубое; решает нижний
  порог.
- **Сигнал общий** (§2.1): вычеркнутый мёртвый узел видят мёртвым и другие группы.
- **Плановая проверка при недоступном URL проверки** по-прежнему стирает history всех узлов;
  состав пула при этом не меняется, выбор идёт без обхода.

### 3.12 Отвергнуто

- **Вердикт по исходу повтора** («открылось через соседа — виноват первый»). Открытое соединение
  не значит, что сайт ответил (§3.1.2).
- **Случайный сосед для повтора.** Нужен был, чтобы развести два мёртвых узла подряд; это делает
  проба третьего, а последовательный обход даёт сдвигу по кругу естественный конец.
- **Список запрещённых узлов на ключ** и **срок жизни сдвига** — одно число без срока проще, а
  цена ошибки мала: ключ живёт на другом узле пула.
- **Подтверждение сдвига первым байтом через соседа.** Не нужно: если сайт лежит у всех, ключ
  проходит круг и получает пометку, узлы при этом не наказаны.
- **Порог карантина константой** («5 отказов в минуту») и **окно по времени** — не подгоняются под
  объём трафика; сравнение с медианой пула и забывание по числу соединений подгоняются сами.
- **Штатный дотест пула для замены** (`CheckOutbounds(ctx, false)`). Он заново
  пробует весь пул с записью, и моргание сети в этот момент стирает всех.
- **Придержать соединение до появления замены** — приложение висит на время проб.
- **Буфер первой посылки для повтора после закрытия без байта** — заметное усложнение ради одного
  соединения.
- **Заморозка всего в паузе между проверками** — группа училась бы по одному ключу за 15–30 с.
- **Тиковый прогон, в котором не ответил никто, ничего не стирает** — показывал бы ложный
  результат; отложено.
- **Вторая подтверждающая проба через паузу**, **ранняя проба по счётчику ошибок без контроля**,
  **«нет данных от узла N секунд — мёртв»** (простаивающее соединение тоже молчит).
- **Ленивый пул с порогом качества** ([issue #56](https://github.com/Leadaxe/sing-box-lx/issues/56))
  — спроса нет.

## 4. Критерии приёмки

### 4.1 Обход мёртвого слота (§2)

- Без закрепления, пул `[a,b,c,d]`, `b` и `d` мертвы: соединения только на `a` и `c`,
  поровну.
- Без закрепления, все живы: последовательность выбора совпадает с выбором без проверки
  живости.
- С закреплением, пул `[a,b,c,d]`, `b` и `c` мертвы (подряд): ключи живых слотов — на тех
  же узлах; ключи мёртвых — на `a` и `d` примерно поровну, каждый ключ одинаково при
  повторах; раскладка слотов не изменилась.
- Узел снова жив: его ключи на нём со следующего соединения, ключи живых слотов не
  двигались.
- Все мертвы: выбор совпадает с нынешним, с закреплением и без.
- Холодный старт (пустая history): выбор как сейчас; пустой пул — fallback.
- Узел слота, выбранного пропуском, не поддерживает сеть — fallback.
- `balancePoolFirstLive` на httptest-фикстуре SPEC 019: мёртвый член без запасного остаётся в
  своём слоте, `selectBalanced` его не выбирает; внешние `DeleteURLTestHistory` /
  `StoreURLTestHistory` (как у clash API) включают и снимают пропуск.
- Существующие тесты `protocol/group` зелёные, `go vet` и `gofmt` чисто.

### 4.2 Самовосстановление (§3)

Мёртвый узел:

- Пул `[a,b,c]`, `a` не открывает соединения, проба `a` молчит, проба `b` отвечает: соединение
  открыто через `b`; history `a` стёрта; слот `a` занят первым ответившим узлом вне пула; слоты
  `b` и `c` не менялись, замена их не пробует.
- Отказ в подключении (сервер узла отвечает RST) обрабатывается так же, как таймаут.
- Контекст соединения истёк по дедлайну: повтора нет, проверка запущена. Отказ узла вне пула
  (fallback на холодном старте): ни повтора, ни проверки.
- Соединение ключа пошло в обход мёртвого слота (§2) и не открылось: повтор — в следующий слот
  после фактического, а не после слота ключа.
- `a` молчит, `b` отвечает: history `b` записана. Молчат `a` и `b`, третий `c` отвечает:
  вычеркнуты оба, history `c` записана. Молчит и `c` или третьего взять негде: history и слоты не
  менялись, включена заморозка.
- `pool_tolerance: 0`: кандидаты пробуются пачками размером с пул, в слот встаёт первый
  ответивший в порядке конфига, ответы всех ответивших записаны; кандидат с history моложе 30 с
  не пробуется.
- Соседа нет, `pool_tolerance > 0`: кандидаты пробуются. Идёт плановый прогон: вердикта нет,
  слоты и history не менялись.
- Пул из одного узла: повтора нет; узел молчит, кандидат вне пула отвечает — кандидат в слоте;
  кандидаты молчат — ничего не менялось.
- Оживший вычеркнутый узел в свой слот не возвращается.
- `pool_tolerance > 0`: замена взята по history без проб; без history — пробами.
- Тик идёт во время проверки: слоты не перемешаны, один узел не попадает в два слота (`-race`).

Сайт недоступен через узел:

- `a` отвечает на пробу, соединение ключа через `a` не открылось: ключ сдвинут на 1, следующее
  соединение ключа идёт в следующий слот; ключи других сайтов на `a` не двигались.
- Не открылись `a` и повтор через `b`, оба отвечают на пробу: сдвиг 2.
- Сайт недоступен через все узлы: после круга ключ помечен, идёт в свой слот, повторов и проб по
  нему нет; тик снимает пометку.
- Соединение по IP без домена: сдвиг ведётся по ключу с IP назначения, второй адрес того же
  процесса не сдвинут.
- Узел «открылся» без похода в сеть (фейковый ленивый узел) и закрыл соединение без байта: это
  отказ, повтора нет, ключ сдвинут.
- Таблица сдвигов не растёт выше 1024 записей.
- `sticky_hash: ["none"]`: сдвигов нет.

Узел рвёт соединения:

- У `a` 3 подтверждённых отказа, у соседей 0: `a` в карантине, слот получил замену, history `a` не
  стёрта; тик снимает карантин.
- Подтверждённые отказы у всех узлов поровну: никто не выведен.
- Ключ с пометкой «проблема в адресе» отказ никому не засчитал.
- После 256 соединений счётчики узла уменьшены вдвое.

Пределы:

- Сто одновременных отказов через `a`: одна проверка; в паузе 15 с — повторы и сдвиги есть, новых
  проб нет.
- Узел с history моложе 30 с не пробуется, сдвиг делается без пробы.
- Заморозка (вердикт «своя сеть», сигнал пробуждения, смена сети): ни повторов, ни проб, ни
  сдвигов, ни счёта отказов.
- Смена сети: заморозка 15 с от сигнала; прогон дольше 15 с — заморозка до его конца.

Прочее:

- Отмена клиентом: ни повтора, ни пробы.
- Слот — `urltest` в `least_test`: нашего повтора нет, проба листа есть; слот — `selector` над
  обычным узлом: повтор есть.
- Тест соединения (SPEC 139): повтор есть; проб, изменений history, сдвигов и счётчиков нет.
- Два одновременных соединения группы через разные слоты: список соединений показывает у
  каждого свой узел; при повторе — узел повтора.
- UDP: ошибка открытия даёт повтор и проверку; «пакеты без ответа» — только проверку.
- Тесты `protocol/group` зелёные, в том числе под `-race`; `go vet` и `gofmt` чисто.
