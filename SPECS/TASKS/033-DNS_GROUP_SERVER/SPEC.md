## 2. Архитектура реализации

Пакет `dns/transport/group`, регистрация/зависимости/валидации состава —
как в v1 (реестр, `Dependencies()` = участники, резолв в
`Start(StartStateStart)`, отказ `fakeip`/`hosts`, циклы ловит менеджер).

### Модель данных

```go
type memberRecord struct {           // на участника, под общим мьютексом
    errors   []time.Time             // живые ошибки (лениво отсекаются по error_ttl)
    wins     []time.Time             // живые победы (лениво по win_ttl); только fastest
    lastRTT  time.Duration           // последняя успешная проба (для наблюдаемости)
}
```

- Срезы отсекаются лениво при чтении; рост ограничен (кап на длину —
  счёт выше капа не различим и не нужен).
- «Успех стирает ошибки» / «ошибка стирает победы» — операции над этими
  же срезами.
- `Reset()` (смена сети) очищает записи, текущего и флаг выборов.

### Выбор цели

- Снапшот под мьютексом: чистые (0 живых ошибок), счёт побед, текущий.
- `stable`: текущий чистый → он; иначе случайный чистый → становится
  текущим (лог info).
- `fastest`: среди чистых max живых побед; ничья → липкость, потом
  случайность; побед нет ни у кого → выборы (см. веер); конкуренты
  при `electionRunning` → случайный чистый.
- `parallel`: цели нет — сразу веер по чистым.
- Чистых нет: наименее грязный (min живых ошибок; ничья — самая давняя
  последняя ошибка; полная ничья — случайно), одна попытка, **без веера**;
  результат помечается в трассе как «режим выживания».

### Бюджет и веер

- Бюджет запроса = `ctx.Deadline()` (клиент всегда ставит; фолбэк
  `C.DNSTimeout`). Одиночная цель получает под-дедлайн = **половина
  остатка**; вееру гарантирован остаток.
- Веер: по чистым минус сбойнувшая цель, **под ctx запроса** (без
  детача — «опоздавший» = после первого успеха, до дедлайна). Первый
  успех → ответ + победа (кроме `parallel`); опоздавшие ответы
  отбрасываются, но стирают ошибки своего сервера.
- Guard: сбой участника веера при `ctx.Err() != nil` ошибкой **не
  записывается** (травится только цель). Сбой самой цели пишется всегда —
  её под-дедлайн был честным.
- Выборы `fastest` — тот же веер (по всем чистым), под CAS-флагом
  `electionRunning`.

### Конфиг

`option.GroupDNSServerOptions{Servers, Mode, ErrorTTL, WinTTL}` —
поля `interval`/`down_time` **удаляются** (старый конфиг падает на
unknown field: потребителей нет, совместимость не поддерживается);
`mode: failover|race` → ошибка «unknown mode». Валидации v1 (непустой
`servers`, дубликаты, самовключение) остаются.

Поле `servers` несёт тег `reference:"dns_server"` — апстрим ввёл генерацию
JSON-схемы (`Add JSON schema support`, мерж 2026-07-30) и по этому тегу
связывает поле со списком тегов DNS-серверов. Прецедент — `dns.final` в том же
файле. Без тега схема отдавала бы `servers` простым списком строк: на рантайм
это не влияет, но подсказки в редакторах конфига теряются.

## 3. Зона касания upstream

Не меняется против v1: `constant/dns.go`, `option/dns.go`,
`include/registry.go` — те же три маркированных шва (в option меняется
состав полей структуры внутри существующего блока).

## 4. Критерии приёмки

- Юниты (фейки, `-race`):
  - stable: липкость на здоровой сети (текущий не меняется); сбой
    текущего → случайные перевыборы среди чистых; выздоровевший
    экс-текущий трафика не возвращает;
  - fastest: холодный старт = выборы-веер; повтор до истечения `win_ttl`
    идёт победителю; истечение → новые выборы; ошибка победителя стирает
    его победы (флап-бэка нет); ничья побед → липкость;
    single-flight: конкурентный бёрст → ровно один веер;
  - parallel: каждый запрос веером по чистым, побед нет; чистых нет →
    одна попытка;
  - единый поток: сбой цели → веер по чистым без цели; первый успех =
    ответ; все сбойнули → ошибка; чистых после сбоя нет → ошибка без
    веера;
  - бюджет: цель-blackhole получает ≤ половины остатка, веер успевает
    ответить в оставшемся; guard — при исчерпанном бюджете участники
    веера не получают ошибок;
  - записи: успех стирает ошибки, ошибка стирает победы, TTL истекают,
    Reset — амнистия;
  - выживание: все грязные → наименее грязный, одна попытка; успех
    в выживании очищает сервер и возвращает штатный путь;
  - NXDOMAIN/пустой — валидный ответ и победа в веере;
  - вложенная группа — один участник/один исход для внешней.
- Живой `box.New`: конфиг v2 принимается; `mode: failover` и
  `down_time` отвергаются; трасса гонки (см. 035) на медленном участнике.
- DoD: build ± теги, vet, gofmt, `sing-box check` со всеми тремя
  режимами.

## 5. Вне скоупа

Hedged-веер по порогу; режим per-query-ротации; приоритет порядком
списка; фильтрация «быстрых лжецов».
