# HISTORY 033

## v1 — failover + down_time (033) и race + interval (034) как отдельные задачи (2026-07-26, день)

Первая архитектура: у сервера было **состояние** — метка сбоя выводила его
в down на фиксированный `down_time`; режимы были отдельными механизмами:

- `failover` (033): обход списка по порядку, 1 сбой = down, при полном
  исчерпании — «одна попытка к самому давнему»;
- `race` (034): ленивая гонка по `interval` на реальном запросе, победитель
  закреплялся до следующей гонки, порядок прихода давал рейтинг-фолбэк.

Отгружена в `v1.14.0-lx.16-rc.1` (конфиг `mode: failover|race`,
`interval`, `down_time`).

## v2 — TTL-модель, режимы как грани одного механизма (2026-07-26, вечер)

Переосмысление (внешняя проработка + адверсариальная панель, 5 линз):
состояние down, `down_time`, `interval`, периодическая гонка, спецправило
исчерпания и сами режимы `failover`/`race`/`round_robin` заменены **двумя
TTL-записями (ошибка/победа) + одним правилом веера**. Ключевые причины:

- `failover` растворяется в `stable` (липкость прежде случайности), `race` —
  в `fastest` (победы только соревновательные, ритм — `win_ttl`), отдельный
  `round_robin` отвергнут (per-query-ротация ломает обещание стабильности);
- порядок списка перестал быть значимым — вместе с ним умерла семантика
  «первый = основной»;
- панель нашла и в дизайн внесены обязательные поправки: под-дедлайн цели
  (половина остатка бюджета — иначе цель-blackhole оставляет веер с мёртвым
  ctx), guard записей ошибок при исчерпанном бюджете (иначе один таймаут
  травит всю группу), веер только по чистым, симметрия «успех стирает
  ошибки / ошибка стирает победы» (лечит флап-бэк `win_ttl > error_ttl`
  и дренаж восстановления), single-flight выборов (иначе стадо вееров
  на каждом истечении `win_ttl`), парная случайность тай-брейков.

Раз режимы стали гранями одного механизма выбора, держать 034 отдельной
задачей стало нарушением §3.2 (одна зона — одна задача): 034 слита сюда,
номер освобождён. Обратная совместимость с конфигом rc.1 сознательно
не поддерживается — потребителей нет.
