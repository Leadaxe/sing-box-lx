Узел, стоящий над IP-туннелем (через `detour` или как звено `chain`), получает размер пакета,
который в этот туннель влезает: `mtu` — у туннелей, `initial_packet_size` — у QUIC-прокси.
Считается один раз на старте по конфигу, управляется одним ключом `lx.mtu_align`, явные значения
по умолчанию только понижаются, всё дописанное видно в логе с причиной.

Scope: **client-only** (outbound/endpoint).

---

## 1. Проблема

### 1.1 Issue #37

hysteria2 с `detour` на masque (WARP, `mtu` 1280 по умолчанию) работает на IPv4-сервер и не
работает на IPv6-сервер. quic-go внутри hysteria2 шлёт пакеты с UDP-payload 1280 байт; по IPv4 это
IP-пакет 1308 байт, по IPv6 — 1328. Оба не влезают в MTU 1280, gvisor режет их на фрагменты.
IPv4-фрагменты WARP пропускает, IPv6-фрагменты теряет.

Замер на чистом канале (GL, Амстердам, 2026-10-09; WARP h3, наш ключ):

| masque `mtu` | UDP по IPv6 через туннель | QUIC Initial по IPv6 (google, facebook) |
|---|---|---|
| 1280 | проходит до 1232 байт payload, с 1240 — 0/3 | 1200, 1232 — OK; 1252, 1280 — TIMEOUT |
| 1340 | проходит до 1280, с 1300 — 0/3 | OK на всех размерах |

UDP по IPv4 проходит на всех размерах до 1350 в обоих случаях (фрагменты пропускаются).
Порог ровно там, где IPv6-пакет перестаёт помещаться в MTU туннеля.

### 1.2 Та же задача у `chain`, но только у `chain`

`chain` (073 §3.5) уже понижает `mtu` туннельного звена на накладные туннеля под ним. Обычный
`detour` — которым собран конфиг репортёра и большинство многохоповых конфигов — не делает
ничего. QUIC-прокси (hysteria2, tuic, hysteria) не выравниваются ни там, ни там.

### 1.3 Внешний QUIC masque стартует с 1242

`InitialPacketSize` внешнего QUIC к WARP — константа 1242 (взята у usque). quic-go считает бюджет
датаграммы консервативно: `InitialPacketSize − 37` = 1205 байт, а внутренний пакет 1280 с байтом
context-id требует 1281. Бюджет растёт только по PMTUD: старт после подтверждения хендшейка, первая
проба через 5 RTT (1347 → бюджет 1310). Итог: **окно ≈ 6 RTT после подъёма туннеля**, в котором
каждый внутренний пакет 1205…1280 байт отбивается `DatagramTooLarge` → ICMP «too big» c MTU 1280
(для стека это ничего не меняет, пакет уже ≤ 1280) → молча пропадает. Апстримный masque-client
ставит `mtu + 51`.

ICMP Packet Too Big при этом всегда называет 1280 (`connectip.minMTU`), а не фактический бюджет —
дефект из 107.

## 2. Модель

### 2.1 Ёмкость узла

`capacity(tag)` — сколько байт IP-пакета пронесёт узел для узла над собой:

| Тип | Ёмкость |
|---|---|
| `masque`, `wireguard` (endpoint и legacy outbound), `openvpn-client`, `openconnect` | его **эффективный** `mtu` (после собственного выравнивания, рекурсивно вниз) |
| `tailscale` endpoint | `system_interface_mtu`, иначе 1280 (дефолт TUN tailscale) |
| `selector`, `urltest` | min по всем достижимым узлам, рекурсивно |
| любой другой узел с `detour` | транзитивно `capacity(detour)` — сам он поверх IP ничего не добавляет |
| `direct`, TCP-прокси, прокси с UDP-релеем (ss, socks, vless, trojan, …) без `detour` | ∞ (уровня IP нет) |
| `tuic` в `udp_relay_mode: native` | ∞ + предупреждение (как в 073) |
| `chain` как цель `detour` | ∞ + предупреждение («цепочка выравнивает себя сама») |
| цикл `detour` | ∞; цикл отвергает штатная проверка зависимостей на старте |

### 2.2 Потребность узла

`fam` — семейство адреса `server` узла (для WG endpoint — `peers[0].address`, для legacy WG —
`server`); домен или не разобрано → IPv6 (консервативно, как в 073). `ipudp(v4)` = 28,
`ipudp(v6)` = 48.

| Тип верхнего узла | Поле | Предел `limit` | Накладные | Комментарий |
|---|---|---|---|---|
| `wireguard` | `mtu` | `cap − 32 − ipudp` | 60 / 80 | как в 073 |
| `masque` | `mtu` | `cap − 51 − ipudp` | 79 / 99 | вместо оценки 90; 51 = заголовок QUIC + тег AEAD + кадр DATAGRAM + context-id (как `mtu + 51` апстрима) |
| `hysteria2`, `tuic`, `hysteria` | `initial_packet_size` | `cap − ipudp`, кламп [1200, 1452] | — | вместе с полем ставится `disable_path_mtu_discovery: true` (§2.4) |
| `openvpn-client`, `openconnect` | — | — | неизвестны | не трогаются; одно предупреждение, если под ними есть ёмкость |

Для WARP по умолчанию (masque 1280): hysteria2 по IPv6 → 1232, по IPv4 → 1252 — ровно значения,
проверенные в §1.1.

Если `limit < 1200` для QUIC-узла (туннель `mtu` < 1248 под IPv6-сервером), QUIC-минимум не
даёт влезть: ставится 1200 и пишется предупреждение «не поместится, минимум QUIC».

### 2.3 Режимы `lx.mtu_align`

Один ключ в корневом блоке `lx` (098), общий для `chain` и `detour`:

```jsonc
"lx": { "mtu_align": "clamp" }                      // строка — режим
"lx": { "mtu_align": { "mode": "clamp", "except": ["my-wg"] } }  // объект — режим + исключения
```

| Режим | Поле не задано | Задано явно и **больше** `limit` | Задано явно и влезает |
|---|---|---|---|
| `off` | не трогаем | не трогаем | не трогаем |
| `fill` | дописываем `limit` | не трогаем; предупреждение «не влезет под <tag>» | не трогаем |
| `clamp` **(дефолт)** | дописываем `limit` | **понижаем** до `limit`; в лог: configured → effective, причина | не трогаем |

Ни один режим не повышает значения. `except` — теги, которые не трогаются ни в одном режиме
(без per-node ключей в апстрим-структурах опций). Дефолт `clamp` сохраняет уже выпущенный
контракт `chain` (073: «`mtu` в конфиге = как самостоятельного, цепочка только понижает»).

### 2.4 PMTUD у QUIC-узла

quic-go не умеет «потолок», только «стартовый размер + поиск вверх до 1452». Под туннелем:
по IPv6 поиск сам упирается (фрагменты теряются, пробы проваливаются); по IPv4 пробы «проходят»
через фрагментацию, и каждый пакет едет двумя. Поэтому вместе с **выведенным**
`initial_packet_size` ставится `disable_path_mtu_discovery: true`. Если `initial_packet_size`
задан явно — узел не трогается целиком, включая PMTUD (bool не отличает «явный false» от
«не задан»).

### 2.5 Группы и динамика

Берётся min по всем членам группы на старте; при переключении селектора/urltest значение не
меняется (как в 073). Размер QUIC-пакета фиксируется при создании клиента в sing-quic и живёт
до его пересоздания; MTU устройства WG — при создании устройства. Переключение детура не
переезжает живое QUIC-соединение hy2 на новый путь. Min — единственный вариант, при котором узел
работает в любом состоянии группы без пересоздания. Цена на широком члене группы: до 200 байт на
пакет (1452 → 1252) и отсутствие PMTUD. Выход для тех, кому это критично: явное значение в
`fill`, тег в `except`, `off`.

### 2.6 Внешний QUIC masque

`InitialPacketSize` внешнего QUIC = `mtu + 51`, кламп [1200, 1452]. Берётся уже выровненный
`mtu`, поэтому masque под WG получает согласованное значение автоматически. ICMP Packet Too Big
называет фактический бюджет датаграммы минус context-id (не константу 1280); если бюджет меньше
1280, ICMP всё равно называет 1280 — ниже минимума IPv6 стек не опустится, а честное число
только зациклит повтор.

## 3. Где считается

- **`detour`:** пре-пасс в `box_lx.go` рядом с `applyLXOptions`, **до** создания узлов: обход
  `options.Endpoints` + `options.Outbounds` по тегам, правка типизированных опций на месте
  (`*option.Hysteria2OutboundOptions` и т.д.). Порядок узлов в конфиге не важен; апстрим-файлы
  конструкторов hysteria2/tuic/hysteria не трогаются — они читают `QUICOptions` как есть.
- **`chain`:** тот же пакет расчёта вместо собственного `mtu.go`; звенья-QUIC на позициях ≥ 1
  получают `initial_packet_size`/PMTUD по той же таблице; накладные masque — по семейству.
- **masque:** `InitialPacketSize` и ICMP — внутри outbound'а, от итогового `mtu`.

Общий код — новый пакет без build-tag (`common/lxmtu`): таблицы §2.1–2.2, режимы §2.3,
обход графа, результат `Decision{Tag, Field, Configured, Effective, Reason, Warning}`.

## 4. Наблюдаемость

- На старте — одна Info-строка на изменённое поле:
  `mtu_align: hy2-us initial_packet_size → 1232 (detour warp[masque] mtu 1280 − 48 ipv6; pmtud off)`,
  `mtu_align: wg-exit mtu 1420 → 1200 clamped (limited by warp[masque] mtu 1280 via sel −80 ipv6)`.
  Предупреждения (`fill` с явным значением больше предела, `native` tuic, неизвестные накладные,
  QUIC-минимум) — Warn.
- `chain` сохраняет `mtu_configured/mtu_effective/mtu_reason` в `ChainInfo`; причина получает
  префикс режима (`clamped:` / `filled:` / `kept (explicit, fill)`). Выдача решений по `detour`
  в lx RPC — вне этой задачи (кандидат в OBSERVABILITY).

## 5. Требования

1. hysteria2/tuic/hysteria без явного `initial_packet_size` над IP-туннелем (через `detour`,
   группу под `detour`, транзитивный `detour`, звено `chain`) получают `cap − ipudp(fam)` и
   `disable_path_mtu_discovery: true`.
2. Туннель без явного `mtu` над IP-туннелем получает `cap − overhead(type, fam)`; masque — 79/99.
3. Режимы `off` / `fill` / `clamp` и `except` работают по таблице §2.3 одинаково для `detour`
   и `chain`; дефолт `clamp`; неизвестный режим или тег в `except` — ошибка старта.
4. Явно заданное поле, которое влезает, не меняется ни в одном режиме. Поле, которое не влезает:
   `fill` — предупреждение, `clamp` — понижение с записью configured → effective.
5. Ёмкость считается рекурсивно по §2.1; группа — min; цикл не зацикливает расчёт.
6. Поведение `chain` для `mtu` при дефолтном режиме не меняется (существующие тесты
   `TestChainMTU` и стенд `lx-test/chain` зелёные), кроме накладных masque 90 → 79/99.
7. `InitialPacketSize` внешнего QUIC masque = `mtu + 51` (кламп); ICMP Packet Too Big называет
   фактический бюджет (≥ 1280).
8. Без `lx.mtu_align` в конфиге поведение = `clamp`; `sing-box check` принимает все формы ключа.

## 6. Критерии приёмки

1. Юниты пакета: таблица формул по типам и семействам; selector/urltest под detour → min;
   транзитивный detour; цикл; явные значения в трёх режимах; `except`; QUIC-минимум; tuic native
   и chain как цель → ∞ + предупреждение; openvpn над туннелем → предупреждение.
2. Юниты box-пре-пасса: конфиг репортёра (#37) без правок → у hysteria2 `initial_packet_size`
   1232 (IPv6-сервер) и PMTUD off; тот же конфиг с IPv4-сервером → 1252; с явным 1300 в `clamp`
   → 1232, в `fill` → 1300 + предупреждение.
3. `TestChainMTU` и `lx-test/chain` зелёные; chain-звено hysteria2 над WG получает размер.
4. masque: юнит на `InitialPacketSize` от `mtu` (1280 → 1331, 1420 → 1452 кламп); ICMP-юнит.
5. Стенд GL: конфиг репортёра (с нашим WARP-ключом) против живого hysteria2-сервера — через
   masque по умолчанию; если IPv6-сервера hy2 нет — QUIC-проба к IPv6-хосту через masque с
   выведенным размером (как в §1.1) плюс hy2 по IPv4 на штатность.
6. Замер §1.3 до/после: первый пакет 1280 байт сразу после подъёма туннеля при 1242 теряется,
   при `mtu + 51` проходит.
7. `make -f Makefile.lx lx-build`; `go vet`/`go test` затронутых пакетов (`common/lxmtu`,
   `protocol/chain`, `protocol/masque`, `transport/masque/connectip`, корень `box_lx_test.go`).

## 7. Границы

- Направление «сервер → клиент» не управляется с нашей стороны; на практике оно само
  ограничивается потерей проб (видно в §1.1).
- xhttp по h3 и naive (cronet) не выравниваются: свой QUIC-транспорт, под туннелем редкость.
- Рантайм-адаптация (пересоздание QUIC-клиента по переключению селектора, когда у него нет живых
  соединений) — отдельная версия, не здесь.
- `openvpn`/`openconnect` как верхние узлы: накладные не выводятся, только предупреждение.
- Серверная сторона.
- Выдача решений по `detour` в lx RPC / Clash API — кандидат в OBSERVABILITY.

## 8. Риски

- `clamp` понижает явный `mtu` под обычным `detour`, чего раньше не было: пользователь с
  заведомо нерабочим `mtu: 1420` у WG под masque увидит в логе понижение, а не молчаливую
  поломку. Для тех, кто хотел именно 1420, — `except`/`fill`/`off`.
- Выведенное `disable_path_mtu_discovery: true` у hy2 на широком члене группы — потеря до 14 %
  полезной нагрузки на пакет против 1452. Для brutal CC пропускная способность задана конфигом.
- Поднятый `InitialPacketSize` внешнего QUIC masque (1331 при 1280) паддит Initial-пакеты
  хендшейка до 1331: снаружи 1359 (IPv4) / 1379 (IPv6). С DF, снятым в 028, узкий путь
  дофрагментирует, отказа нет. Вопрос №8 из 110 закрывается замером §6.6.

## 9. Хвост #37: `mtu` 1280 с выведенным 1232 не работает, 1340 работает

Разбор 2026-11-02 по комментарию репортёра от 2026-10-10 (lx.14, без ответа; issue закрыт
2026-10-09). Строки `mtu_align` у него есть, hy2 на IPv6-сервер получил `initial_packet_size
→ 1232`, и всё равно `dial quic: timeout: no recent network activity`; `mtu: 1340` у masque
лечит. Это **не** SPEC 150: над IP-туннелем читатели (сокет ядра, netstack) усекают молча,
потокового `detour` в его конфиге нет.

Что известно по коду:

- Выравнивание действует только на путь клиент → сервер. Сервер hysteria2 стартует с
  `InitialPacketSize = 1280` (apernet/quic-go `a10df75c`, которым собран hysteria core, и
  sagernet/quic-go 0.61 — одна константа) и **не опускает** стартовый размер по
  `max_udp_payload_size` партнёра: параметр задаёт только потолок PMTUD
  (`newMTUDiscoverer(start = config.InitialPacketSize, max = min(1452, peer))`,
  `connection.go`). Сам параметр у quic-go-клиента зашит как 1452 (`MaxPacketBufferSize`),
  конфигом не меняется. Значит с первого Handshake-пакета сервер шлёт по IPv6 пакеты
  **1328 байт**, и фраза §7 «направление сервер → клиент само ограничивается потерей проб»
  для стартового размера неверна: 1280 не проба, ниже сервер не уйдёт.
- На нашей стороне приём не ограничен `mtu`: `connectip.ReadPacket` отдаёт датаграмму целиком,
  `stackDevice.Write` вызывает `DeliverNetworkPacket` без проверки размера, в gvisor проверка
  MTU только на отправке (`ipv6.go`, `packetMustBeFragmented`). Пакет 1328 байт, дошедший до
  нас, стек принял бы.
- Что меняется для Cloudflare при `mtu: 1340`: только размер наших внешних пакетов
  (`InitialPacketSize` 1391 против 1331, §2.6). Гипотеза «edge ограничивает датаграмму к нам
  размером наших пакетов, и при 1331 внутренний 1328 не помещается» **опровергнута замером**
  (ниже).

**Замер 2026-11-02** (Mac владельца за роутером `home`, выход через собственный Xray в NL с
`routeOnly: true`; masque h3 `mtu: 1280` и `mtu: 1340` без detour; DNS по UDP через SOCKS5
UDP-ASSOCIATE к `2001:4860:4860::8888`, EDNS 4096 + DO, стенд `h2t/dns-mtu.json`, `dnsq.py`):

| Запрос | Payload ответа | IPv6-пакет внутри туннеля | `mtu` 1280 | `mtu` 1340 |
|---|---|---|---|---|
| `. DNSKEY` | 1139 | 1187 | 4/5 (первый — таймаут на подъёме туннеля) | туннель не поднялся |
| `org DNSKEY` | 1319 | **1367** | **5/5**, 60–70 мс | туннель не поднялся |
| `cloudflare.com TXT` | 2649 → TC 43 | — | резолвер сам усёк | туннель не поднялся |

Нисходящий внутренний IPv6-пакет 1367 байт, крупнее и 1328 (серверный пакет hy2), и самого
`mtu` 1280, доходит до стека целиком. Значит направление сервер → клиент при `mtu` 1280 через
WARP **не ограничено**, и стартовые 1280-байтные пакеты сервера hysteria2 репортёра должны были
доходить. Причина его отказа при 1280 остаётся неизвестной; кандидаты вне размера пакета:
`detour` на группу `warp-masque-auto` (в его логе рядом с таймаутами hy2 идут `lx penalty:
selection moved` / `failover` между членами masque — QUIC-сокет hy2 живёт на сессии одного
члена, переключение группы его не переносит) и port hopping `server_ports`. Нужен его debug-лог
на актуальном ядре.

При `mtu: 1340` с этого пути внешний QUIC не поднимается (`dial quic: timeout: no recent network
activity`): Initial 1391 + 28 = 1419 байт на проводе, а path MTU с Mac за роутером ≈ 1390
([mac-awg-mtu-behind-home-masque]); фрагменты до WARP не доходят. У репортёра путь шире, у него
1340 работало. Это и есть цена пути 2 ниже.

Пути, рассматривавшиеся до замера (после него путь 1 не нужен — приём и так не ограничен; решения владельца нет):

1. Внешний `InitialPacketSize` masque считать не от `mtu`, а от `max(mtu, 1328) + 51`, чтобы
   стартовые серверные пакеты IPv6 (1280 payload) входили при `mtu` по умолчанию. Цена —
   Initial-пакеты хендшейка 1379 на проводе (IPv4), на узком пути фрагментация (DF снят в 028).
2. Поднимать `mtu` masque до 1340 через `mtu_align`, когда над ним QUIC-прокси с IPv6-сервером
   (WARP принимает внутренние пакеты до ≥ 1328, §1.1). Цена — внешний путь ≈ 1440 байт.
3. Только документация и предупреждение в логе: QUIC-прокси над туннелем `mtu < 1328` с
   IPv6-сервером → Warn с советом `mtu: 1340`.

Итог замера: причина у репортёра не в размере нисходящих пакетов. Ответ дан 2026-11-02
([#37, комментарий](https://github.com/Leadaxe/sing-box-lx/issues/37#issuecomment-6583791451)):
просьба о debug-логе на актуальном ядре с `mtu: 1280` и о прогоне с `detour` на одиночный узел
masque вместо группы; issue переоткроется, когда будет за что зацепиться.
