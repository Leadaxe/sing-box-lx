## Why

Tailscale-клиент открывает канал к координатору (`controlplane.tailscale.com`) сначала по голому
HTTP на **порт 80** и переводит соединение на Noise заголовком `Upgrade`. Порт 443 (Noise внутри
TLS) — только запасной: он пробуется, если 80 не ответил быстро, или если предыдущее соединение
было недавно (`controlhttp.Dialer.forceNoise443`, эвристика против tailscale/tailscale#13597).

На сети с DPI, который замораживает поток на порту 80 после смены протокола, получается тупик:

1. Соединение на 80 устанавливается мгновенно, регистрация и первая карта сети проходят.
2. Дальше поток замерзает: исходящие данные не подтверждаются, входящие не приходят, но сокет не
   закрыт.
3. Сторож долгого опроса (120 с) отменяет **запрос**, а не соединение; следующий запрос уходит в тот
   же мёртвый сокет. До новой попытки соединения, а значит и до перехода на 443, дело не доходит.
4. Восстановление наступает, только когда ядро ОС закрывает сокет по исчерпанию перепосылок
   (`tcp_retries2`, ~15 минут); после этого tailscale открывает канал на 443.

Каждый перезапуск ядра (deploy конфига, рестарт службы) повторяет цикл: узел ~15 минут не
синхронизируется с координатором. Трафик через exit node при этом идёт по старой карте сети через
DERP, консоль Tailscale показывает узел отключённым.

### Полевые факты (2026-09-29)

- Лог endpoint'а: `control: map response long-poll timed out!` ровно через 120 с после последней
  карты, повторно через каждые 120 с; `PollNetMap: Post "https://controlplane.tailscale.com/machine/map": context canceled`;
  новых `creating new noise client` нет. Повторилось после двух перезапусков подряд.
- Сокет на роутере: `93.100.173.230:36090 → 192.200.0.107:80 ESTABLISHED`, `Send-Q 5186`,
  `Recv-Q 0`; в `/proc/net/tcp` — таймер перепосылки активен, `retr 0x0A`.
- Спустя время канал восстановился сам — на `192.200.0.113:443`.
- Трафик роутера в сторону координатора идёт напрямую (у endpoint'а нет `detour`), мимо
  `route.rules`: к правке маршрутизации лаунчера (issue #139) не относится.

### Почему не конфигом

- В опциях endpoint'а (`option/tailscale.go`) рычага для порта нет.
- `control_url` с явным `:443` не помогает: `ts2021.NewClient` ставит пустой `httpPort`, но
  `controlhttp.Dialer.dialHostOpt` строит адрес через `strDef(a.HTTPPort, "80")` и всё равно
  пробует 80 первым. К тому же пользователь официального Tailscale этот URL не знает — в формах
  лаунчера и LxBox есть только ключ.
- `detour` на endpoint'е работает, но гоняет координатор и DERP через VPN без необходимости и
  требует от пользователя диагноза.

## What

Ядро lx по умолчанию ходит к координатору Tailscale только по Noise поверх HTTPS (443) —
штатным рычагом tailscale `TS_FORCE_NOISE_443`.

- Если переменная окружения `TS_FORCE_NOISE_443` не задана, при инициализации пакета
  `protocol/tailscale` выставляется `envknob.Setenv("TS_FORCE_NOISE_443", "true")`.
  `envknob.Setenv` обновляет и уже зарегистрированное значение, которое читает `controlhttp`.
- Явно заданная переменная (в том числе `false`) не переписывается — ручка отключения остаётся у
  пользователя.
- Действует на весь процесс, на все tailscale-endpoint'ы. Прямой UDP между узлами, DERP и
  маршрутизация не меняются — только транспорт канала к координатору.

**Цена.** Канал к координатору шифруется дважды (Noise внутри TLS); авторы tailscale оценивают
затраты как крошечные, трафик там служебный. Первый дайл больше не ждёт гонки 80/443.

**Инвариант §3.2.** Поведение по умолчанию меняется без build-tag — это хотфикс по §3.1
(воспроизведён в поле, есть тест и условие снятия), как остальные записи реестра HOTFIXES.

## Тест

`protocol/tailscale/control_https_lx_test.go` — `TestForceNoise443Default`:
после инициализации пакета зарегистрированный `TS_FORCE_NOISE_443` (тот же указатель, что читает
`controlhttp`) равен `true`; явное `false` не переписывается; незаданная переменная получает `true`.

```
go test -tags with_gvisor,with_tailscale -ldflags=-checklinkname=0 ./protocol/tailscale -run TestForceNoise443Default -count=1
```

Полевая проверка: после выката на роутер `netstat -tnp` показывает канал sing-box к
`controlplane.tailscale.com` на `:443` сразу после старта, консоль Tailscale держит «Connected»
дольше 2 минут после рестарта.

## Условие снятия

Любое из:

- tailscale при таймауте долгого опроса закрывает соединение и дайлит заново (тогда эвристика
  «недавний дайл → 443» срабатывает за ~2 минуты, а не за ~15);
- tailscale переходит на 443 по умолчанию или `control_url` с явным `https://…:443` перестаёт
  пробовать порт 80;
- sing-box даёт опцию endpoint'а для транспорта канала к координатору.

Проверять при бампе `github.com/sagernet/tailscale` (`control/controlhttp/client.go`,
`control/controlclient/direct.go`).
