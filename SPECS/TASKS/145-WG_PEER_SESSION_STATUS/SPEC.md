## 1. Проблема

`device.Down()` в wireguard-go зовёт `peer.Stop()` → `ZeroAndFlushAll()`: ключевые пары и
состояние хендшейка стираются. `peer.lastHandshakeNano`, `rxBytes` и `txBytes` при этом не
трогаются. `PeerStatuses()` (SPEC 114) читал их из UAPI-дампа как есть, поэтому после
следующего `Up()` пир в состоянии `up` показывал хендшейк прошлой сессии. Пока тот моложе
`reject_after_time`, потребитель по правилу CONSUMERS §2 считает пира «на связи», хотя
ключей у него нет и новый хендшейк ещё не прошёл.

`Down` → `Up` бывает в трёх местах:

- тумблер SPEC 106: `SetEnabled(false)` → `Suspend`, `SetEnabled(true)` → `Resume`;
- сон по простою SPEC 020 и пробуждение по dial — те же `Suspend`/`Resume`; так же
  работает AWG-guard;
- пауза сети (`applyPauseEvent`, на Android — выключение экрана) и пробуждение сети.

## 2. Контракт

Сессия начинается при сборке устройства и заново при каждом `Up` после `Down`.

| Поле `PeerStatus` | Было | Стало |
|---|---|---|
| `lastHandshakeUnix` | последний хендшейк устройства | последний хендшейк **текущей сессии**; хендшейк старше её начала отдаётся как `0` |
| `rxBytes` / `txBytes` | счётчики устройства | без изменений: всего с момента сборки устройства |
| `sessionRxBytes` / `sessionTxBytes` (6, 7) | — | с начала текущей сессии |

Пока устройство лежит (`asleep`, `disabled` поверх живого устройства), ответ не
меняется: хендшейк и счётчики прошлой сессии видны как раньше. Новая сессия начинается
в момент `Up`, а не `Down`, поэтому спящий узел по-прежнему может показать «последняя
связь N мин назад».

Пересборка устройства (`torn_down` → сборка, ленивая сборка SPEC 097) начинает сессию с
нулевых счётчиков, у неё `session* == rx/tx`.

`Up` уже поднятого устройства (пробуждение сети без паузы перед ним) сессию не
начинает.

Форма ответа расширяется, а не меняется: в proto два новых поля, в libbox `PeerStatus` —
`SessionRxBytes`, `SessionTxBytes`. Клиенты, не знающие новых полей, получают правильный
`lastHandshakeUnix` без доработки.

CLI `sing-box api peers`: колонки `RX (TOTAL)` / `TX (TOTAL)` — байты сессии, в скобках
всего.

## 3. Реализация

Апстримный код wireguard-go/amneziawg-go не меняется: правка в нашем слое
`transport/wireguard`.

- `transport/wireguard/peer_session_lx.go`: `peerSession` (флаг `down` и снимок
  `base`: момент начала и rx/tx по каждому пиру).
  - `markSessionDown` ставит флаг после `Down` живого устройства.
  - `markSessionUp` перед `Up` забирает флаг и, если он был, снимает счётчики из
    UAPI и запоминает время. Устройство в этот момент лежит, счётчики стоят, хендшейк
    до `Up` пройти не может.
  - `resetSession` при `Teardown`.
  - `applySession` в `PeerStatuses` обнуляет хендшейк старше начала сессии и считает
    `session* = total − снимок`; итог меньше снимка (без пересборки невозможен) считается
    новым началом, а не уходит в переполнение.
- `transport/wireguard/endpoint.go`: вызовы `// lx: SPEC 145` в `Suspend`, `Resume`,
  `Teardown` и обеих ветках `applyPauseEvent`; поле `session` в `Endpoint`.
- `adapter.PeerStatus`: `SessionRxBytes`, `SessionTxBytes`.
- `daemon/started_service.proto` (lx-блок `PeerStatus`): поля 6 и 7, `.pb.go`
  перегенерирован; конверсия в `daemon/started_service_wireguard_lx.go`.
- libbox `command_types_wireguard_lx.go`, CLI `cmd_api_peers_lx.go`.

`TransferTotals()` (тик простоя SPEC 020) читает сырые счётчики и не затронут.

Если `Up` упал, снимок остаётся: устройство лежит, хендшейка нет, `0` верен. Повтор
`Resume` сессию заново не начинает, флаг уже снят, а снимок по-прежнему верен.

## 4. Критерии приёмки

1. Юниты `applySession`: без снимка сессия = всё время устройства; хендшейк до начала
   сессии → 0, после — как есть; вычитание по ключу пира; пир без снимка — с нуля; итог
   меньше снимка — с нуля.
2. Юнит `markSession*`: `Up` без `Down` сессию не начинает; после `Down` — начинает;
   `resetSession` всё забывает.
3. Живой юнит на паре endpoint'ов через loopback (`TestPeerStatuses_serverLearnsEndpoint`):
   после хендшейка `Suspend` — хендшейк прошлой сессии виден; `Resume` — хендшейк `0`,
   `sessionRxBytes == 0`, всего не меньше прежнего; после трафика — новый хендшейк не
   раньше `Resume`, `0 < sessionRx < rx`.
4. На устройстве (LxBox): тумблер выкл/вкл в пределах минуты — сразу после включения
   `lastHandshakeUnix == 0`, сессия около нуля; после хендшейка время новое. То же для сна
   по простою и пробуждения по dial.
