# SPEC: 098 — LX_ROOT_CONFIG_BLOCK

**Фича:** [ENERGY](../../FEATURES/008-ENERGY/FEATURE.md) (ключи `wg`, `naive`); `masque` — [MASQUE_WARP](../../FEATURES/009-MASQUE_WARP/FEATURE.md)

| Поле | Значение |
|------|----------|
| Тип | R (refactor) — корневой блок `lx` конфига: все глобальные ручки форка в одном месте, сгруппированные по подсистеме |
| Статус | N (new) — решение владельца 2026-09-24: «оптом делаем компактизацию, потом реализуем, потом релиз»; порядок: 098 (блок + переезд) → 097 (ключи ленивой сборки WG) → релиз; 096 добавит `naive` после замера; решение владельца 2026-09-24: отложена до релиза после lx.10 (lx.10 = синк 095 + фикс 099) |
| Ветка | `lx` |
| Build-tag | нет для самого блока; ключи `wg.idle_*`, `wg.lazy_build`, `wg.build_max` действуют под `with_lx_idle_suspend` (как сегодня `route.lx_idle_suspend`) |
| Связано | [020](../020-MULTI_WG_IDLE_BUFFER_HEAT/SPEC.md) (семантика ключей сна), [097](../097-LAZY_WG_DEVICE_BUILD/SPEC.md), [096](../096-NAIVE_ENGINE_POOL/SPEC.md), [021](../021-MASQUE_CONNECT_IP_OUTBOUND/SPEC.md) (`idle_timeout` узла masque), [062](../062-MASQUE_CONFIG_SCHEMA_MIGRATION/SPEC.md) (образец миграции с алиасами), [037](../037-RUNNING_CONFIG_RPC/SPEC.md) (running-config отдаёт блок как есть) |

## 1. Зачем

Глобальные ручки форка сегодня лежат в `route` (`lx_idle_suspend`, `lx_idle_suspend_reachable`, `lx_idle_teardown`) только потому, что тик усыпления живёт в роутере. Впереди новые семьи: ленивая сборка и потолок WG-устройств (097), глобальный дефолт простоя MASQUE, движки naive (096). Складывать их в `route` значит копить в блоке маршрутизации ручки ресурсов с префиксом в имени вместо структуры. Клиенты (LxBox, лаунчер) наши, поэтому переезд стоит один релиз алиасов, а не годы совместимости.

Что в блок **не** идёт: всё, что описывает конкретный узел, остаётся в его объекте, как в апстриме — поля AWG в endpoint'е, `xhttp`/`xmux` в transport, типы `masque`/`chain`/dns-`group`, `tls.reality.key_share`, `idle_timeout` узла masque.

## 2. Схема

```json
"lx": {
  "wg": {
    "idle_suspend": "30s",
    "idle_suspend_reachable": "5m",
    "idle_teardown": "10m",
    "lazy_build": true,
    "build_max": 4,
    "build_overflow": "wait"
  },
  "masque": {
    "idle_timeout": "5m"
  },
  "naive": {
    "single_engine": true,
    "lazy_start": true
  }
}
```

Все подблоки и ключи опциональны; пустой `lx` и отсутствующий `lx` равнозначны.

### 2.1 `lx.wg` — WG/AWG-endpoint'ы

| Ключ | Тип | Дефолт | Значение | Откуда |
|---|---|---|---|---|
| `idle_suspend` | длительность | выкл | Порог простоя endpoint'а, которого нет в активном дереве маршрутизации: после него устройство уводится в Down (сокеты закрыты, приёмные буферы свободны), следующий дайл будит. `0`/отсутствие выключает механизм, тик не стартует | `route.lx_idle_suspend` |
| `idle_suspend_reachable` | длительность | выкл | Второй, более длинный порог для endpoint'ов в дереве (член urltest-пула, выбранный узел, final); по умолчанию они не спят. Обязан быть ≥ `idle_suspend`, требует его | `route.lx_idle_suspend_reachable` |
| `idle_teardown` | длительность, явный `"0"` допустим | наследует `idle_suspend_reachable` | Третий уровень: сколько уже спящий endpoint спит до полной разборки устройства и netstack'а; считается от засыпания. Явный `"0"` запрещает разборку. Требует `idle_suspend` | `route.lx_idle_teardown` |
| `lazy_build` | bool | `false` | Старт ядра не собирает устройство: endpoint начинает в состоянии третьего уровня, устройство собирается при первом дайле (097 §2.1). Требует `idle_suspend` | новый, 097 |
| `build_max` | целое ≥ 0 | `0` = без потолка | Не больше N собранных устройств одновременно; (N+1)-я сборка сначала разбирает самое давно неиспользуемое спящее (097 §2.2) | новый, 097 |
| `build_overflow` | `wait` \| `build` | `wait` | Когда все N держат живые соединения: ждать освобождения в пределах дедлайна дайла или собрать сверх потолка с предупреждением. Открытое решение 097 §5; при выборе одного поведения ключ снимается | новый, 097 |

Семантика трёх ключей сна — SPEC 020 без изменений; дефолт ядра остаётся «выключено», включают приложения.

### 2.2 `lx.masque` — MASQUE-outbound'ы

| Ключ | Тип | Дефолт | Значение |
|---|---|---|---|
| `idle_timeout` | длительность | выкл (как сегодня) | Глобальный дефолт окна простоя для всех masque-узлов: после него сессия (netstack, насосы, QUIC keepalive) разбирается, следующий дайл собирает заново (SPEC 021 B1). `outbounds[].idle_timeout` узла сильнее; явный `"0"` в узле выключает усыпление даже при глобальном значении |

Сборка сессии у MASQUE и так ленивая, потолок не нужен: узлов WARP в конфиге единицы.

### 2.3 `lx.naive` — зарезервировано (096)

`single_engine` (один движок Cronet на узел при `insecure_concurrency`, приём iOS) и `lazy_start` (движок при первом дайле). Парсер 098 подблок **не** заводит: ключи появятся вместе с реализацией 096, до этого неизвестный подблок отвергается как любой неизвестный ключ. Имена закреплены здесь, чтобы не переезжать второй раз.

## 3. Правила

- **Валидация на загрузке**, тексты ошибок называют полный путь ключа (`lx.wg.idle_suspend_reachable must be >= lx.wg.idle_suspend`). Опечатка в имени ключа — ошибка, не тихий дефолт (принцип 089/091).
- **Гейт сборки** прежний: ключи `lx.wg.*` в сборке без `with_lx_idle_suspend` — ошибка старта с тем же текстом, что сегодня у `route.lx_idle_suspend` (dесктоп-сборки его не несут; мобильные AAR несут).
- **Приоритет** для masque: ключ узла > `lx.masque.idle_timeout` > дефолт ядра (выкл).
- **Алиасы** на один релиз: `route.lx_idle_suspend`, `route.lx_idle_suspend_reachable`, `route.lx_idle_teardown` принимаются с предупреждением на каждый ключ (`route.lx_idle_suspend is deprecated, use lx.wg.idle_suspend`); значение, заданное в обоих местах, — ошибка старта, если различается, и предупреждение, если совпадает (образец SPEC 062). Снятие алиасов — в релизе, следующем за тем, где LxBox и лаунчер перешли на `lx`; дата снятия записывается в changelog при вводе.
- **Running-config** (SPEC 037) отдаёт блок `lx` в канонической форме — уже после разрешения алиасов, то есть приложение видит `lx.wg.*`, даже если конфиг пришёл со старыми ключами.
- **Провод, дефолты и поведение** ни одного узла не меняются: 098 только переносит и группирует ключи; новые ключи `wg.lazy_build`/`build_max`/`build_overflow` парсятся и валидируются здесь, действуют с 097.

## 4. Реализация (границы для PLAN)

- Новый lx-файл `option/lx.go`: `LXOptions{WG *LXWGOptions; MASQUE *LXMASQUEOptions}` с валидацией; в апстримном `option/options.go` одна строка `LX *LXOptions json:"lx,omitempty"` под маркером; алиасы остаются в `option/route.go` внутри существующего блока `lx:begin idle-suspend` до снятия.
- Точки чтения: `route/router.go` (три поля idle-suspend) переходят на разрешённые значения `lx.wg`; `protocol/masque.NewOutbound` получает глобальный дефолт из контекста (`service.FromContext[*option.LXOptions]`, регистрируется в `box.New`), а не через сигнатуру.
- Тесты: парсинг блока, валидация каждого правила, алиасы (оба места, конфликт, совпадение), приоритет masque, гейт сборки; `sing-box check` на всех `lx-test/config/*.json` плюс новый `lx_block.json`; running-config отдаёт канонический блок.
- Доки: `docs-lx/lx-config.md`/`.ru.md` (раздел «Блок `lx`» + пометка deprecated у старых ключей), `docs-lx/lx-energy.md`/`.ru.md` (пути ключей), changelog; контракт LxBox/лаунчера — по их регламенту, синхронно.

## 5. Критерии приёмки

1. Конфиг с блоком `lx` и конфиг со старыми `route.lx_idle_*` дают одинаковое поведение тика (юнит на резолв + `check`); конфликт значений — ошибка с полным путём ключа.
2. `lx.masque.idle_timeout` действует на узел без своего ключа и не действует на узел с явным `"0"`.
3. Новые ключи `wg.lazy_build`/`build_max`/`build_overflow` принимаются и валидируются; до 097 они инертны и об этом сказано в доке.
4. `option/` меняется только этой задачей и по её списку; `go build` без тегов и с полным `LX_TAGS`; стенды `lx-test`.
5. LxBox и лаунчер пишут `lx.*` до релиза, снимающего алиасы.
