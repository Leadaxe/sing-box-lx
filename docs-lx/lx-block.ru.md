# sing-box-lx — корневой блок `lx`

> EN: [lx-block.md](lx-block.md)

Глобальные настройки форка собраны в одном корневом блоке `lx`, по подсистемам. Всё, что
относится к конкретному узлу, остаётся в его объекте, как в апстриме: поля AWG — в endpoint'е,
`xhttp` — в `transport`, свой `idle_timeout` masque-узла — в узле. Все ключи необязательны, пустой
`lx` равен отсутствующему. Опечатка в имени ключа — ошибка загрузки, а не тихое значение по
умолчанию. `GetRunningConfig` отдаёт блок без пустых подблоков и без явно записанных значений по
умолчанию.

```jsonc
"lx": {
  "wg": {
    "idle": {
      "suspend": "30s",
      "suspend_reachable": "5m",
      "teardown": "10m",
      "lazy_build": true,
      "build_max": 4,
      "build_overflow": "wait"
    },
    "buffers": {
      "read_datagram_count": 8,
      "send_by_mtu": true
    },
    "connected_socket": true
  },
  "masque": {
    "idle_timeout": "5m"
  },
  "trusttunnel": {
    "idle_timeout": "5m"
  },
  "detour": {
    "mtu_align": "clamp",
    "strip": true
  },
  "sniff_guard": {
    "tls": { "method": "record_fragment" },
    "quic": { "method": "decoy_first_byte" }
  }
}
```

## `lx.wg` — endpoint'ы WireGuard / AmneziaWG

Подблок `idle` работает только в мобильной сборке (`with_lx_idle_suspend`). Десктопный бинарь
отказывается стартовать, если в `idle` задано хоть что-то действующее: окно простоя, явный
`teardown` (включая `"0"`), `lazy_build`, ненулевой `build_max` или `build_overflow: "build"`.
`sing-box check` роутер не запускает и на десктопе такие ключи принимает. `buffers` и
`connected_socket` работают в любой сборке.

| Ключ | Тип | По умолчанию | Что задаёт |
|---|---|---|---|
| `idle.suspend` | длительность | выкл | Порог простоя endpoint'а вне активного дерева маршрутизации: после него устройство уводится в Down (сокеты закрыты, приёмные буферы свободны), следующий дайл будит. Отсутствие или `0` выключает механизм |
| `idle.suspend_reachable` | длительность | выкл | Второй, более длинный порог для endpoint'ов в дереве (член urltest-пула, выбранный узел, final); без него они не спят. Не меньше `idle.suspend`, требует его |
| `idle.teardown` | длительность, явный `"0"` допустим | как `idle.suspend_reachable` | Сколько уже спящий endpoint спит до разборки устройства и netstack'а; считается от засыпания. `"0"` запрещает разборку. Требует `idle.suspend` |
| `idle.lazy_build` | bool | `false` | Endpoint'ы стартуют разобранными, устройство собирается при первом дайле. Требует `idle.suspend` |
| `idle.build_max` | целое ≥ 0 | `0` = без потолка | Не больше N собранных устройств одновременно |
| `idle.build_overflow` | `wait` \| `build` | `wait` | Когда все `build_max` устройств держат живые соединения: ждать в пределах дедлайна дайла или собрать сверх потолка с предупреждением |
| `buffers.read_datagram_count` | целое 1–128 | `128`, как в апстриме | Сколько датаграмм резервируется на одно чтение из сокета. Linux и Android, туннели без `detour` |
| `buffers.send_by_mtu` | bool | `true` | Брать буфер чтения из стека по MTU туннеля, а не 64 КБ. `false` — для диагностики |
| `connected_socket` | bool | `false` | Подключать сокет туннеля к адресу сервера в режиме одного пира. Linux и Android |

**Сон и сборка устройств.** Таймлайны ключей сна и рекомендованный мобильный конфиг — в
[lx-energy.ru.md](lx-energy.ru.md), порядок выбора жертвы для `build_max` — в
[lx-energy.ru.md §11](lx-energy.ru.md#11-ленивая-сборка-и-бюджет-не-дают-собирать-устройства-впустую).

- `lazy_build` не действует на endpoint с `listen_port`: его никто не дайлит.
- `build_max` без `lazy_build` допустим: устройства собираются на старте, потолок действует с
  первой пересборки после `idle.teardown`.
- `wait` из `build_overflow` длится до дедлайна дайла, не дольше 15 с.
- `build_max` меньше числа одновременно используемых узлов заставляет их разбирать друг друга при
  каждом переключении, и каждый дайл платит сборку устройства. Это ключ для сессий с массовыми
  пробами, а не общая экономия памяти.

**Сокет туннеля.** `buffers` и `connected_socket` действуют только на туннель без `detour`: у
туннеля через `detour` своего сокета нет.

- `buffers.read_datagram_count`. Туннель держит буфер на 64 KiB на каждую датаграмму, которую
  может прочитать за раз, в каждой из двух приёмных рутин (IPv4 и IPv6), пока жив: 16,4 MiB при
  128, около 1 MiB при 8. Простаивающий туннель физической памяти почти не занимает, но куча Go
  растёт: она входит в лимит памяти рантайма, отодвигает сборку мусора, а с первым трафиком
  буферы становятся физическими. Чем больше туннелей, тем меньше значение: `8` для одного-двух
  туннелей на слабой машине, `1` или `2` для десятков и сотен; скорость при `1` на релизной сборке
  не мерилась. При значении меньше 128 сокет
  создаётся без склейки на приём (UDP GRO), склейка на отправку (UDP GSO) остаётся. На быстрых
  каналах и настоящей сетевой карте пачки и GRO могут давать выигрыш, поэтому по умолчанию
  оставлено апстримное значение. На macOS и Windows ключ принимается и ничего не меняет.
  [Замеры](../SPECS/TASKS/158-WG_QUEUED_PACKET_BUFFERS/SPEC.ru.md).
- `buffers.send_by_mtu: false` возвращает буферы чтения из стека по 64 КБ. Нужен при разборе
  проблемы, чтобы исключить буферы по MTU из подозреваемых.
- `connected_socket` действует на туннель с одним пиром, фиксированным адресом сервера и без
  `listen_port`. Сокет подключается к серверу, и система хранит маршрут, а не ищет его на каждую
  датаграмму; на слабой плате это несколько процентов отдачи
  ([замеры](../SPECS/TASKS/160-WG_DIRECT_SEND_COST/SPEC.ru.md)). Цена: подключённый сокет слышит
  только адрес сервера, а его исходный адрес фиксируется при подключении. Ядро переподключает
  сокет при ошибке отправки и при рукопожатии без ответа, поэтому сервер, ответивший с нового
  адреса, будет услышан после ближайшего повтора рукопожатия, а не сразу. Ключ выключен по
  умолчанию: на телефоне, который меняет сеть, он не проверен. На macOS сокет в этом режиме
  подключён всегда.

**Ошибки загрузки.**

| Сообщение | Причина |
|---|---|
| `lx.wg.idle.* is set but this build lacks idle-suspend support; rebuild with -tags with_lx_idle_suspend (mobile-only feature)` | Действующий ключ `idle` в десктопной сборке |
| `lx.wg.idle.suspend_reachable must be >= lx.wg.idle.suspend` | `suspend_reachable` меньше `suspend` |
| `lx.wg.idle.<ключ> requires lx.wg.idle.suspend` | `suspend_reachable`, `teardown` или `lazy_build` без `suspend` |
| `lx.wg.idle.<ключ> must be >= 0` | Отрицательная длительность или `build_max` |
| `lx.wg.idle.build_overflow must be "wait" or "build"` | Неизвестное значение |
| `lx.wg.buffers.read_datagram_count must be between 1 and 128` | `0`, отрицательное значение или больше 128 |
| `lx.wg.<старый ключ> is moved to lx.wg.idle.<новый ключ>` | Плоский ключ прежней раскладки, см. [Удалённые ключи](#удалённые-ключи) |

## `lx.masque` — MASQUE-outbound'ы

| Ключ | Тип | По умолчанию | Что задаёт |
|---|---|---|---|
| `idle_timeout` | длительность ≥ 0 | выкл | Окно простоя для всех `masque`-узлов без своего `idle_timeout`: после него сессия (netstack, насосы, QUIC keepalive) разбирается, следующий дайл собирает её заново |

```json
"lx": { "masque": { "idle_timeout": "5m" } }
```

Приоритет: `idle_timeout` узла, затем `lx.masque.idle_timeout`, иначе выключено. Явный `"0"` в
узле держит его туннель поднятым при любом глобальном значении. Сессия MASQUE и так собирается
лениво, потолка здесь нет.

**Ошибка загрузки:** `lx.masque.idle_timeout must be >= 0` — отрицательная длительность.

## `lx.trusttunnel` — TrustTunnel-outbound'ы

| Ключ | Тип | По умолчанию | Что задаёт |
|---|---|---|---|
| `idle_timeout` | длительность ≥ 0 | `5m` | Окно простоя для всех `trusttunnel`-узлов без своего `idle_timeout`: после него сессия закрывается локально, следующий дайл открывает её заново. Отсутствие ключа или `0` — 5 минут |

```json
"lx": { "trusttunnel": { "idle_timeout": "10m" } }
```

Приоритет: `idle_timeout` узла, затем `lx.trusttunnel.idle_timeout`, иначе 5 минут. Явный `"0"` в
узле отключает разборку его сессии. В отличие от `lx.masque`, глобальный `0` здесь значит «не
задано», а не «выключено»: выключить разборку можно только в узле. Поля самого outbound'а — в
[protocols-transports.ru.md §6.2](protocols-transports.ru.md#62-поля-outbound).

**Ошибка загрузки:** `lx.trusttunnel.idle_timeout must be >= 0` — отрицательная длительность.

## `lx.detour` — что ядро делает с узлом под `detour`

Узел, который дозванивается через `detour` — напрямую, через группу под `detour` или как узел,
перехваченный позицией [`chain`](lx-chain.ru.md), — получает от ядра две вещи: размер пакета
подгоняется под туннель снизу (`mtu_align`), а механизмы, которым нужен сокет ядра, фильтруются,
когда его под узлом нет (`strip`). Один список `except_outbounds` исключает узлы из обоих
([SPEC 165](../SPECS/TASKS/165-CHAIN_DETOUR_REWRITE/SPEC.md)).

```jsonc
"lx": {
  "detour": {
    "mtu_align": "clamp",
    "strip": {
      "filters": {
        "tls": { "fragment": true, "spoof": true, "kernel": true, "engine": true }
      }
    },
    "except_outbounds": ["foreign-node"]
  }
}
```

По умолчанию блок — `true`: ключа `detour` нет — то же, что `"detour": true`.

| Запись | `mtu_align` | `strip` |
|---|---|---|
| ключа нет / `true` | `clamp` | весь каталог: все четыре фильтра |
| `false` | `off` | ничего — поведение апстрима |
| объект | что написано; без ключа — `clamp` | что написано; без ключа — весь каталог |

| Ключ | Значения | Без ключа | Смысл |
|---|---|---|---|
| `mtu_align` | `off`, `fill`, `clamp` | `clamp` | Режим выравнивания ([ниже](#lxdetourmtu_align--выравнивание-mtu-и-размера-пакета-по-пути)) |
| `strip` | `true`, `false`, объект `{filters}` | каталог | `true` — каталог; `false` — ничего; объект без `filters` — каталог |
| `strip.filters` | `true`, `false`, объект `{tls: {fragment, spoof, kernel, engine}}` | каталог | `true` — каталог; `false` — ничего; объект целиком заменяет каталог: не названный фильтр выключен, `{}` не фильтрует ничего |
| `except_outbounds` | список тегов | нет | Узлы, которые не выравниваются и не фильтруются |

`GetEffectiveConfig` пишет блок развёрнутым, все ключи и все фильтры явно; `GetRunningConfig`
отдаёт его как написан.

### `lx.detour.mtu_align` — выравнивание MTU и размера пакета по пути

Узел может стоять прямо над IP-туннелем: через `detour`, через группу под `detour` или как узел на
позиции [`chain`](lx-chain.ru.md). Такой узел получает размер пакета, который влезает в туннель: `mtu` у
туннелей (`wireguard`, `masque`), `initial_packet_size` плюс `disable_path_mtu_discovery: true` у
QUIC-прокси (`hysteria2`, `tuic`, `hysteria`). Без этого, например, hysteria2 через WARP работает
с IPv4-сервером и молчит с IPv6-сервером. Размер считается один раз на старте по конфигу, до
создания узлов. Значения только понижаются; каждое изменённое поле видно в логе старта вместе с
причиной.

```jsonc
"lx": { "detour": { "mtu_align": "clamp", "except_outbounds": ["my-wg"] } }
```

| Режим | Поле не задано | Задано явно и больше предела | Задано явно и влезает |
|---|---|---|---|
| `off` | не трогается | не трогается | не трогается |
| `fill` | дописывается предел | не трогается; предупреждение «не влезет под `<tag>`» | не трогается |
| `clamp` (по умолчанию) | дописывается предел | понижается до предела; в лог: configured → effective и причина | не трогается |

Ни один режим не повышает значения. Узел из `except_outbounds` не трогается ни в одном режиме. Без
ключа действует `clamp`, и на позициях цепочек, и под обычным `detour`.

**Ёмкость узла** — сколько байт IP-пакета он пронесёт для узла над собой:

| Узел снизу | Ёмкость |
|---|---|
| `masque`, `wireguard` (endpoint и legacy outbound), `openvpn-client`, `openconnect` | его эффективный `mtu` (после собственного выравнивания, рекурсивно вниз) |
| `tailscale` endpoint | `system_interface_mtu`, иначе 1280 |
| `selector`, `urltest` | min по всем достижимым членам, рекурсивно |
| `chain-hop` `<цепочка>#<i>` | min из своей позиции и хопа ниже: позиция может быть выключена или выбрать `direct`, и узел сверху должен влезать в любом состоянии; хоп 0 — его позиция |
| `chain` как цель `detour` | то же, что её верхний хоп |
| любой другой узел — `direct` и любой прокси (vless, trojan, ss, socks, hysteria2, tuic, …), с `detour` или без | без предела: прокси доставляет пакет узла над собой целиком (потоком TCP или своей нарезкой), и то, что лежит под его `detour`, верхний узел не ограничивает |

Ёмкость наверх несут только туннели, группы и хопы цепочек. Исключение правило не покрывает:
туннель над `shadowsocks` или `socks` по UDP, у которых свой `detour` на туннель. Они пропускают
датаграммы как есть, и ограничение под ними действует; верхнему туннелю там `mtu` задаётся руками.

**Что получает узел сверху** (`ipudp` = 28 для IPv4-сервера, 48 для IPv6; домен или неразобранный
адрес считаются IPv6; у WG-endpoint семейство берётся из `peers[0].address`):

| Узел сверху | Поле | Предел | Накладные v4 / v6 |
|---|---|---|---|
| `wireguard` | `mtu` | `ёмкость − 32 − s4 − ipudp` (`s4` — транспортный паддинг AmneziaWG, 0 у обычного WG) | 60 / 80 (+ `s4`) |
| `masque` | `mtu` | `ёмкость − 51 − ipudp` | 79 / 99 |
| `hysteria2`, `tuic`, `hysteria` | `initial_packet_size` (+ `disable_path_mtu_discovery: true`) | `ёмкость − ipudp`, кламп 1200…1452 | — |
| `openvpn-client`, `openconnect` | — | не выводится; одно предупреждение, если под узлом есть ёмкость | неизвестны |

**Пол IPv6.** Туннель, который несёт IPv6 внутри, никогда не выравнивается ниже 1280: это
`wireguard`-endpoint с IPv6-префиксом в `address` и `masque` всегда. gvisor молча не поднимает
IPv6 на канале с меньшим MTU, а мёртвый IPv6 внутри туннеля хуже фрагментов. Если путь оставляет
меньше 1280, туннель получает 1280 и строку Warn (`… is above the path: … leaves 1220 bytes, below
the IPv6 minimum 1280; outer packets will be fragmented`). Туннель только с IPv4 внутри
выравнивается и ниже 1280; явный `mtu` ниже 1280 никогда не повышается.

Если предел QUIC-узла ниже 1200 (туннель с `mtu` < 1248 под IPv6-сервером), ставится 1200 с
предупреждением: ниже минимума QUIC опуститься нельзя. PMTUD выключается вместе с выведенным
`initial_packet_size`: quic-go ищет размер только вверх до 1452, по IPv6 пробы теряются вместе с
фрагментами, по IPv4 «проходят» фрагментацией, и каждый пакет едет двумя. Узел с явным
`initial_packet_size` не трогается целиком, включая PMTUD.

**Пример — WARP по умолчанию** (`masque` с `mtu` 1280) и hysteria2 с `detour` на него:

```jsonc
{ "type": "masque", "tag": "warp", "mtu": 1280, /* … */ },
{ "type": "hysteria2", "tag": "hy2", "server": "2001:db8::1", "detour": "warp", /* … */ }
```

`hy2` получает `initial_packet_size: 1232` (1280 − 48) и `disable_path_mtu_discovery: true`; с
IPv4-сервером — 1252 (1280 − 28). Без выравнивания quic-go шлёт пакеты с payload 1280, по IPv6 это
1328 байт. Туннель режет их на фрагменты, и WARP их теряет ([masque-explained.ru.md §4](masque-explained.ru.md#4-размер-пакета)).

**Группы.** Под группой берётся min по всем членам на старте; при переключении селектора или
urltest значение не пересчитывается. Размер QUIC-пакета фиксируется при создании клиента, MTU
WG-устройства — при создании устройства, и живое соединение на новый путь не переезжает. Цена на
широком члене группы: до 200 байт на пакет (1452 → 1252) и выключенный PMTUD. Если эта цена
мешает, есть три выхода: явное значение в режиме `fill`, тег в `except_outbounds` или режим `off`.

**Лог старта** — одна Info-строка на изменённое поле, предупреждения — Warn:

```
mtu_align: hy2 initial_packet_size → 1232 (detour warp[masque] mtu 1280 − 48 ipv6; pmtud off)
mtu_align: wg-exit mtu 1420 → 1200 clamped (limited by warp[masque] mtu 1280 via sel −80 ipv6)
```

Каждое изменённое поле — ещё и запись изменения в `GetOutboundConfig(tag)`: `by.type` —
`mtu_align`, с режимом, узлом снизу, накладными и той же причиной, что в строке лога. У QUIC-узла
две записи: `initial_packet_size` и `disable_path_mtu_discovery`
([lx-observability.ru.md](lx-observability.ru.md)).

**Не выравниваются:**

- xhttp по h3 и naive (cronet) — у них свой QUIC-транспорт;
- `openvpn-client` и `openconnect` как верхние узлы — только предупреждение;
- направление «сервер → клиент» — им управляет сервер.

Чем masque отвечает на это снизу (внешний `InitialPacketSize` = `mtu + 51`, ICMP Packet Too Big с
фактическим бюджетом) — в [masque-explained.ru.md §4](masque-explained.ru.md#4-размер-пакета).

### `lx.detour.strip` — фильтры для узла без сокета ядра

Части TLS-механизмов узла нужен собственный TCP-сокет устройства под рукопожатием. Через туннель
или прокси под рукопожатием лежит поток внутри другого соединения, и там эти механизмы стоят
времени или роняют рукопожатие. Фильтр не даёт узлу применить свой механизм на таком рукопожатии.
На участке от релея до сервера ни один из них не делает ничего, что фильтр бы отнимал: релей
пересылает только настоящие байты.

| Фильтр | Что не применяется без сокета ядра | Почему |
|---|---|---|
| `tls.fragment` | собственный разрез ClientHello узла (`fragment`, `fragment_fallback_delay`); `record_fragment` остаётся | разрез не может дождаться подтверждения кусков и спит `fragment_fallback_delay` (500 мс) между ними: 0,5–1,5 с на рукопожатие |
| `tls.spoof` | поддельный ClientHello сырым TCP-пакетом | через ws, grpc, xhttp, httpupgrade, mux, QUIC или WireGuard роняет каждое рукопожатие; через vless/trojan поверх TLS вбрасывает обманку в поток релея |
| `tls.kernel` | kTLS (`kernel_tx`, `kernel_rx`): TLS остаётся в пространстве пользователя | роняет каждое рукопожатие |
| `tls.engine` | движок `apple`: рукопожатие идёт через `go`, отпечаток становится отпечатком Go | системному TLS macOS/iOS нужен сокет, без него рукопожатие падает |

- **Какие узлы.** Любой узел с `detour`, включая перехваченные узлы цепочек, которого нет в
  `except_outbounds`. Узел без `detour` не фильтруется никогда.
- **На каждом рукопожатии.** Если соединение от `detour` — сокет ядра (`detour` на `direct` или на
  группу, которая сейчас выбрала `direct`), механизмы узла работают как в конфиге. Узел с
  `fragment` и `detour: S`, `S = [direct, wg-relay]`: пока `S` выбирает `direct`, ClientHello
  режется; после переключения на `wg-relay` следующее рукопожатие идёт без разреза и без пауз по
  500 мс.
- **`lx.sniff_guard` сильнее.** Если guard сам формирует это рукопожатие, применяется его форма, и
  фильтр её не отменяет. Разрез, снятый фильтром, для guard'а — не выбор узла: узел без явного
  `record_fragment` всё равно может получить форму guard'а.
- **Что видно.** Опции узла не меняются, в `changes` фильтров нет. Применённый фильтр пишет одну
  Info-строку на узел и фильтр
  (`lx.detour: <tag>: strip tls.fragment: no kernel socket under detour`) и этап `detour_strip` с
  именем фильтра в трассе проверки соединения.
- **Фильтр выключен или `"detour": false`** — поведение апстрима: механизм пробуется на соединении
  без сокета ядра и, кроме разреза, падает.

Оставить разрез узла под `detour`, а остальное фильтровать:

```jsonc
"lx": { "detour": { "strip": { "filters": { "tls": { "spoof": true, "kernel": true, "engine": true } } } } }
```

### Что `detour` не применяет

С `detour` апстрим строит dialer узла ниже и не строит собственный dialer узла
(`common/dialer/dialer.go`, `NewWithOptions`), а поля сокета читает только собственный.
Поэтому под `detour` эти поля не действуют и ошибок не дают. Ядро это поведение не меняет, а
показывает: `GetOutboundConfig` отдаёт каждое поле в `changes` с `by.type: "lx.detour"` без `to`,
и в представлении итогового конфига его нет; в апстрим опции узла уходят как написаны.

`bind_interface`, `inet4_bind_address`, `inet6_bind_address`, `bind_address_no_port`,
`protect_path`, `routing_mark`, `reuse_addr`, `netns`, `connect_timeout`, `tcp_fast_open`,
`tcp_multi_path`, `disable_tcp_keep_alive`, `tcp_keep_alive`, `tcp_keep_alive_interval`,
`udp_fragment`, `network_strategy`, `network_type`, `fallback_network_type`, `fallback_delay`.

`domain_resolver` под `detour` действует. Два исключения остаются как в апстриме: anytls с
`tcp_fast_open` не загружается, openconnect применяет свои keepalive-поля сам. Ключа для этого
нет: ни `"detour": false`, ни `except_outbounds` эти поля не включают.

### Ошибки загрузки

Все их ловит и `sing-box check`.

| Сообщение | Причина |
|---|---|
| `lx.detour.mtu_align must be "off", "fill" or "clamp"` | Неизвестный режим |
| `lx.detour: unknown key <key>`; так же с `lx.detour.strip`, `lx.detour.strip.filters`, `lx.detour.strip.filters.tls` | Неизвестный ключ на этом уровне. Ключи прежнего каталога цепочки (`tls.utls`, `multiplex.padding`, `xhttp.padding`) — тоже неизвестные ключи |
| `<key> must be true, false or an object` | `lx.detour`, `strip`, `strip.filters` или `strip.filters.tls` другого типа |
| `lx.detour.strip.filters.tls.<filter> must be true or false` | Значение фильтра — не bool |
| `lx.detour.except_outbounds must be a list of tags` | Ни список, ни один тег |
| `lx.detour.except_outbounds: empty tag` | Пустая строка в `except_outbounds` |
| `lx.detour.except_outbounds: unknown outbound/endpoint tag: <tags>` | Тег — ни outbound, ни endpoint |
| `lx.mtu_align is moved to lx.detour.mtu_align (lx.mtu_align.except is lx.detour.except_outbounds)` | Прежний корневой ключ `lx.mtu_align` |

## `lx.sniff_guard` — защита от перенаправления по SNI

Между клиентом и сервером может стоять узел, который читает имя из первого пакета рукопожатия и
отправляет соединение на это имя, а не на набранный адрес. Так работает Xray-инбаунд с
`sniffing.destOverride` без `routeOnly`. Он встречается на релее под `detour` и на роутере с VPN
или прозрачным прокси в локальной сети. Пока SNI — собственное имя сервера, подмена приводит туда
же. Когда SNI — маскировка (REALITY, WARP, hysteria2 или tuic с подставным SNI, QUIC-маскировка
AmneziaWG), соединение уходит на чужой хост, и узел выглядит мёртвым: рукопожатие висит и падает
через 12–17 с или приходит чужой ключ. Блок делает первый пакет рукопожатия нечитаемым для
сниффера и не меняет того, что получает сервер. По исходам подключений блок учится, на каких путях
это нужно.

Без блока, как и без `method` в секции, защиты нет: рукопожатие уходит как в апстриме. Блок, в
котором ни у одной секции нет метода, равнозначен отсутствию блока. Сам себя блок не включает:
защиту по умолчанию выставляет приложение, которое пишет конфиг.

```jsonc
"lx": {
  "sniff_guard": {
    "nodes": {
      "sni_mismatch": true,                 // нет ключа = true; false — фильтра нет
      "outbound_type": ["vless", "masque"]  // false | нет ключа — фильтра нет
    },
    "detour_type": {                        // нет detour = "direct"
      "direct": "clean",
      "ssh":    "clean",
      "socks":  "clean",
      "*":      "suspect"
    },
    "override": false,
    "tls": {
      "method": "record_fragment",          // record_fragment | fragment | delay | off
      "delay": "300ms",
      "persist": true
    },
    "quic": {
      "method": "decoy_first_byte",         // decoy_first_byte | delay | off
      "detour_type": { "socks": "never" },
      "persist": true
    }
  }
}
```

**Кого защищать — `nodes`.** Два фильтра; узел защищается, если проходит оба. Узел, не прошедший
фильтры, работает как без блока. Без блока `nodes` действует `sni_mismatch: true`: узел с
собственным именем проходит сниффящий релей и без защиты. Защиту всем узлам, которые её умеют,
даёт `sni_mismatch: false`.

| Ключ | Значения | Без ключа | Смысл |
|---|---|---|---|
| `sni_mismatch` | `true`, `false` | `true` | `true` — только узлы, у которых SNI не совпадает с адресом `server`; `false` — фильтра нет |
| `outbound_type` | список типов, `false` | фильтра нет | Только узлы перечисленных типов. Известный тип, который защиту не умеет, допустим и пропускается |

Совпадение SNI с `server` проверяется при загрузке сравнением строк, без DNS: без учёта регистра
и завершающей точки, поддомен — другое имя. Сравнивается имя, которое фактически уйдёт в ClientHello
или Initial; при ECH — внешнее, публичное. Внешнее имя берётся только из конфига ECH, заданного
в самом узле (`ech.config`); при `ech.config_path` и ECH из DNS сравнивается обычный
`server_name`.

| `server` | SNI | Результат |
|---|---|---|
| домен | не задан или тот же домен | совпадает |
| домен | другое имя | не совпадает |
| IP | имя | не совпадает |
| IP | не задан | совпадает — снифферу нечего читать |
| любой | SNI не отправляется (`disable_sni`) | совпадает |
| hysteria2 с обфускацией Salamander | любое | совпадает — Initial снифферу не прочитать |
| REALITY, masque (WARP), QUIC-маскировка AWG | любое | не совпадает всегда |

Узел за CDN (`server` — IP CDN, SNI — свой домен) попадает под фильтр без нужды, защита ему не
мешает. Узел, для имени которого DNS релея отдаёт другой адрес, фильтр `sni_mismatch` не
пройдёт. Для него ставят `sni_mismatch: false`, при нужде вместе с `outbound_type`.

**Стартовое состояние пути — `detour_type`.** Карта «тип носителя → состояние, с которого путь
начинает». Носитель — ближайший не-групповой outbound, через который фактически идёт
подключение: группа (`selector`, `urltest`) разворачивается в выбранного участника. Узел без
`detour`, с `detour` в `direct` или в группу, где сейчас выбран `direct`, идёт по пути типа
`direct`. Если носитель определить не удалось, защиты нет и лейбл не ведётся.

| Значение | Смысл |
|---|---|
| `never` | На этом пути защиты нет никогда: лейбл не ведётся, повторов нет, узловые ключи работают как в апстриме |
| `clean` | Старт без защиты |
| `suspect` | Старт с защитой |

Ключ `"*"` — все типы, которых нет в карте. Группы ключами быть не могут. Карта по умолчанию:
`direct`, `ssh`, `socks` — `clean`; `"*"` — `suspect`. Своя карта накладывается поверх этой,
перечислять нужно только то, что меняется. Секция `tls` или `quic` может перекрыть отдельные
типы своей картой `detour_type`. `"socks": "never"` в секции `quic` примера взят из полевого
случая: через `socks` с UDP-over-TCP байт-приманка ломала туннель, хотя сниффера на пути не было.

**Секции `tls` и `quic`, `override`.**

| Ключ | Значения | Без ключа | Смысл |
|---|---|---|---|
| `tls.method` | `record_fragment`, `fragment`, `delay`, `off` | `off` | Метод для TLS поверх TCP (таблица ниже) |
| `quic.method` | `decoy_first_byte`, `delay`, `off` | `off` | Метод для QUIC |
| `delay` (в секции) | положительная длительность | `300ms` | Пауза метода `delay` этой секции. Против Xray нужна больше 200 мс; меньшее значение допустимо для сниффера с более коротким ожиданием |
| `persist` (в секции) | `true`, `false` | `false` | Сохранять лейблы зашифрованных релеев в `experimental.cache_file`; требует включённого `cache_file` |
| `detour_type` (в секции) | карта, как выше | общая карта | Перекрытие стартовых состояний для протокола |
| `override` (общий) | `true`, `false` | `false` | `false` — узловые `fragment` / `record_fragment` сильнее блока. `true` — для узла, прошедшего `nodes`, форму ClientHello определяет лейбл пути, даже если узел просил другое. Подробнее — в [Узловые ключи TLS и блок](#узловые-ключи-tls-и-блок) |

**Методы.** Сервер в каждом случае получает корректное рукопожатие. После рукопожатия трафик не
трогается.

| Метод | Что уходит в сеть | Против сниффера Xray | Цена |
|---|---|---|---|
| `tls.record_fragment` | ClientHello разрезан на несколько TLS-записей, точки разреза внутри имени SNI | Сниффер разбирает только первую запись, она обрывается посреди расширений — «не ClientHello» с первой попытки | Нет |
| `tls.fragment` | ClientHello одной записью, кусками по TCP-сегментам с ожиданием ACK (на сокете устройства) или паузой (через релей) | Защищает, пока пауза между кусками больше 200 мс: через релей это `fragment_fallback_delay` (500 мс), на прямом пути за прозрачным прокси ядро выдерживает ту же паузу | Пауза `fragment_fallback_delay` через релей и на прямом пути за прозрачным прокси |
| `tls.delay` | ClientHello одной записью, двумя кусками с разрезом внутри SNI и паузой `delay` между ними | Первый кусок неполон, сниффер ждёт продолжения 200 мс и сдаётся | Пауза `delay` на каждом защищённом рукопожатии |
| `quic.decoy_first_byte` | Датаграмма из одного байта `0x00` перед первым Initial; сервер её отбрасывает | QUIC-сниффер решает по первой датаграмме: «не QUIC» | Нет |
| `quic.delay` | Второй Initial задерживается на `delay` | Сниффер собирает ClientHello из Initial-пакетов в пределах 200 мс и не успевает | Пауза `delay` на каждом защищённом рукопожатии |

**Какие узлы умеют защиту.** TLS поверх TCP: vless, trojan, vmess, anytls, shadowtls, http с TLS,
masque `h2`, trusttunnel `h2`, XHTTP на `h2`. QUIC: masque `h3`, hysteria2, tuic, trusttunnel с
QUIC, XHTTP на `h3`, wireguard с QUIC-образной маскировкой AmneziaWG. Не умеют и пропускаются
молча: naive и узлы с системным TLS-движком (`engine: apple`, `windows`).

| Метод | Применим | Не применим |
|---|---|---|
| `tls.record_fragment`, `tls.fragment`, `tls.delay` | все TLS-узлы из списка выше | naive, системные TLS-движки |
| `quic.decoy_first_byte` | все QUIC-узлы из списка, включая AmneziaWG | — |
| `quic.delay` | QUIC-узлы, у которых ClientHello занимает два Initial-пакета | AmneziaWG; узел, чей ClientHello уместился в один Initial; hysteria2 с обфускацией Salamander. На таком узле метод ничего не делает |

Узел, к которому метод секции не применим, идёт как без блока и лейбл пути не двигает.

**Как учится лейбл пути.** Лейбл ведётся на пару «путь + протокол»: путь — `direct` или тег
ближайшего релея, протокол — `tls` или `quic`. Два релея одного типа с разной настройкой
сниффинга различаются по тегу. На `clean` узлы этого пути идут без защиты, на `suspect` — с ней.

Лейбл меняет только пара исходов на одном узле:

- упал без защиты, затем прошёл с ней → путь становится `suspect`;
- упал с защитой, затем прошёл без неё → путь становится `clean`;
- остальное лейбл не трогает. Мёртвый узел падает в обоих случаях и ничего не меняет, поэтому
  массовая проверка узлов защиту с пути не снимает.

Быстрая ошибка повторяется в том же дайле с противоположным решением. После таймаута
противоположное решение достаётся следующему дайлу этого узла на этом пути, если он будет в
течение 10 минут. На пути `suspect` попытка без защиты после неудачи допускается не чаще раза в
10 минут на путь.

В пару идут только настоящие рукопожатия, к которым применено решение блока. Не идут: дайл,
севший на уже поднятую сессию (mux, пул anytls, XHTTP, долгая QUIC-сессия masque, hysteria2, tuic,
trusttunnel), и узел со своими `fragment` / `record_fragment` при `override: false`. `fragment`,
снятый фильтром `lx.detour.strip`, своим для узла не считается.

Двигают лейбл только узлы, у которых SNI не совпадает с `server`, даже если фильтр
`sni_mismatch` выключен: узел с собственным именем проходит сниффящий релей и так, и о сниффере
ничего не говорит. Такой узел защищается по лейблу только при `sni_mismatch: false`. На пути `clean` он повторов не делает. Если на пути
`suspect` он упал с защитой и прошёл без неё, он запоминает личный отказ и дальше идёт на этом
пути без защиты; лейбл пути и другие узлы не меняются. Обратная пара отказ снимает. Повтор для
такого узла — не чаще раза в 10 минут. Личный отказ живёт, пока жив экземпляр ядра, и не
сохраняется.

Особенности протоколов:

- **hysteria2, tuic** — рукопожатие идёт внутри библиотеки QUIC, поэтому исход оценивается по
  сроку жизни соединения: закрытое раньше 30 с — неудача, прожившее дольше — успех. Успех засчитывается, как
  только соединение прожило 30 с, неудача — при следующем новом соединении узла. Повтора в
  том же дайле нет, пара складывается через следующий дайл. Сокеты следующих хопов при
  порт-хопе hysteria2 рукопожатия не несут и не защищаются; режим realm у hysteria2 не
  защищается.
- **masque `auto`** — h3 живёт по лейблу `quic`, h2 по лейблу `tls`. Быстро упавший h3
  повторяется с противоположным решением до отката на h2. Молчащий h3 через 3 с уступает h2, а
  противоположное решение достаётся следующей попытке h3.
- **AmneziaWG** — endpoint `wireguard` под блок попадает, если его маскировка `ip: "quic"` или у
  него непустой `i1`; байт уходит только перед QUIC-образной пачкой. Решение берётся из лейбла
  при создании сокета, а исход рукопожатия лейбл не двигает. Поэтому на пути со стартом `clean`
  (прямой, `socks`) защиту для AWG задают явно: `suspect` для этого типа носителя в
  `quic.detour_type`.

Каждая смена лейбла и каждый личный отказ пишут строку в лог на уровне info: путь, протокол,
старое и новое состояние, узел и исходы обеих попыток. Отдельного API нет.

**Цена обучения.**

- Первая неудача на пути `clean` — таймаут: сниффер уводит соединение туда, где никто не
  отвечает. Первый дайл узла висит до дедлайна, первый URL-тест падает, защита приходит со
  второго дайла.
- Узел с быстрым отказом стоит двух рукопожатий вместо одного.
- Случайный сбой на чистом пути (неудача без защиты, следом успех с ней) ставит `suspect`, и
  снять его может только обратная пара. Для `record_fragment` и `decoy_first_byte` это
  бесплатно; для `delay` и `fragment` — пауза на каждом рукопожатии, с `persist` и после
  перезапуска.

**Смена сети и `persist`.** Смена сети сбрасывает в стартовое состояние лейблы пути `direct` и
незашифрованных носителей (`socks`, `http` без TLS) вместе с личными отказами и ожидающими
повторами на них. Лейблы зашифрованных релеев смену сети переживают. Если под тем же тегом
оказался другой релей (тип, адрес или порт), его лейблы и отказы сбрасываются. Без `persist` лейблы
живут, пока жив экземпляр ядра: перезапуск и применение нового конфига начинают со стартовых
состояний. С `persist` лейблы зашифрованных релеев пишутся в `experimental.cache_file` и
поднимаются при старте, если под тем же тегом тот же релей. Запись для пути, который карта в
текущем конфиге объявляет `never`, не применяется. Лейблы `direct` и незашифрованных носителей не
сохраняются.

**Границы.**

- Сниффер напрямую не обнаруживается и от других причин отказа не отличается. Признак один —
  пара исходов на одном узле, и случайный сбой может сложиться в ложную пару.
- Рукопожатие, которое без ошибки завершилось не там, успехом и считается: `tuic` с `insecure` и
  SNI, который резолвится в живой QUIC-хост. masque защищён пином ключа, hysteria2 —
  аутентификацией, TLS-узлы — проверкой сертификата (без `insecure`).
- Полный gRPC-транспорт (`grpc`, не lite) не защищается: его рукопожатие идёт вне дайла узла.
  Такой узел идёт как без блока.
- На прямом пути не защищаются shadowtls v2/v3 и любой узел с `tcp_fast_open`: путь для них
  определить нельзя. Через `detour` они защищаются как все.
- shadowtls v3 без uTLS не защищается ни на каком пути: его рукопожатие идёт мимо TLS-слоя ядра.
  С uTLS — как остальные.
- Релей блок не лечит; на стороне релея лечение — `"routeOnly": true` в `sniffing`.
- Против снифферов, кроме Xray, не проверено. sing-box как релей назначение по сниффингу не
  подменяет, защита через него не нужна. Ожидание 200 мс — константа Xray; для другого сниффера
  `delay` подбирается ключом.
- DPI, который дропает защищённое рукопожатие (разрез на записи как сигнатура), блок не обходит:
  лейбл такого пути по паре уходит в `clean`.

**Ошибки загрузки.** Все их ловит `sing-box check`. `<key>` — полный путь ключа, например
`lx.sniff_guard.quic.detour_type`.

| Сообщение | Причина |
|---|---|
| `lx.sniff_guard.tls.method must be one of "record_fragment", "fragment", "delay", "off"`; то же для `quic` со своими методами | Неизвестный метод |
| `lx.sniff_guard.nodes.outbound_type: true is not a filter; list the types, or use false for no filter` | `nodes.outbound_type: true` |
| `lx.sniff_guard.nodes.outbound_type: empty list; list the types, or use false for no filter` | `nodes.outbound_type: []` |
| `<key>: unknown outbound type "<t>"` | Тип, которого не знает ни один outbound или endpoint этой сборки, в `nodes.outbound_type` или ключом `detour_type` |
| `lx.sniff_guard.nodes.outbound_type: "<t>" is a group; a group is never dialled itself, name the member types` | Группа в `nodes.outbound_type` |
| `<key>: "<t>" is a group; name the member types, a group is resolved to the member it picks` | Группа ключом `detour_type` |
| `<key>.<type> must be "never", "clean" or "suspect"` | Неизвестное значение в карте `detour_type` |
| `<key>.delay must be > 0` (`<key>` — `lx.sniff_guard.tls` или `lx.sniff_guard.quic`) | `delay` ноль или отрицательный |
| `lx.sniff_guard.tls.persist: requires experimental.cache_file to be enabled`; то же с `.quic` | `persist: true` без включённого `experimental.cache_file` |
| начинается с ключа: `lx.sniff_guard`, `lx.sniff_guard.nodes`, `lx.sniff_guard.tls`, `lx.sniff_guard.quic` | Неизвестный ключ или значение, которое не объект |
| `lx.quic_sniff_decoy is removed: the QUIC sniff decoy is configured by lx.sniff_guard.quic` | Удалённый ключ `lx.quic_sniff_decoy` |

Проверки неизвестного типа и `persist` выполняются, только если хотя бы у одной секции задан
метод; `persist` проверяется у секции, у которой метод есть.

### Узловые ключи TLS и блок

Минимальный блок защиты TLS-узлов:

```json
"lx": { "sniff_guard": { "tls": { "method": "record_fragment" } } }
```

С ним путь через любой релей, кроме `ssh` и `socks`, стартует с разрезом; прямой путь и путь
через `ssh` или `socks` — без, пока узел на нём не упадёт без разреза и не пройдёт с ним. Чтобы с
разрезом стартовали все релеи, добавьте `"detour_type": {"ssh": "suspect", "socks": "suspect"}`.
Чтобы резать и узлы, у которых SNI совпадает с `server`, — `"nodes": {"sni_mismatch": false}`.

Узловые ключи апстрима работают при любом состоянии блока:

- **`fragment` / `record_fragment` / `fragment_fallback_delay`** у узла действуют как в
  апстриме, с блоком и без него. Под `detour` без сокета ядра снизу фильтр `tls.fragment` из
  [`lx.detour.strip`](#lxdetourstrip--фильтры-для-узла-без-сокета-ядра) по умолчанию снимает
  `fragment` узла; `record_fragment` остаётся, а узел без явного `record_fragment` блок тогда
  формирует так, будто разреза у него нет. В остальном блок перекрывает их только при
  `"override": true`: тогда для узла, прошедшего `nodes`, на `suspect` идёт метод блока, на
  `clean` — ClientHello без разреза. На пути `never` блок не действует. У QUIC узловых ключей
  нет, там `override` ни на что не влияет.
- **`"record_fragment": false`** — узел просит ClientHello одной записью. Под блоком без
  `override` такой узел идёт без разреза на любом пути.
- **REALITY-узлы** — `fragment` / `record_fragment` действуют и на них. В апстриме
  REALITY-клиент строит uTLS-соединение на голом сокете, и эти ключи там молча не
  действуют. Гибридный ClientHello занимает 1,5–1,9 КБ, это два TCP-сегмента. Поможет ли
  разрез в сети, которая теряет такой первый пакет, — свойство той сети. Второй способ —
  `key_share` ([protocols-transports.ru.md §5.2](protocols-transports.ru.md#52-отпечатки-и-гибридный-key-share)).

## Удалённые ключи

Конфиг с любым из этих ключей не загружается.

| Ключ | Что вместо |
|---|---|
| `lx.quic_sniff_decoy` | `lx.sniff_guard.quic` с `"method": "decoy_first_byte"` |
| `lx.awg_masquerade` | ничего: пачка AmneziaWG идёт на любом пути |
| `lx.wg.idle_suspend`, `idle_suspend_reachable`, `idle_teardown`, `lazy_build`, `build_max`, `build_overflow` | тот же ключ в `lx.wg.idle`: `idle_suspend` → `idle.suspend`, `lazy_build` → `idle.lazy_build` |
| `route.lx_idle_suspend`, `lx_idle_suspend_reachable`, `lx_idle_teardown` | `lx.wg.idle.suspend`, `suspend_reachable`, `teardown` |
| `network` в `masque`-узле | `vhttp` |
| `lx.mtu_align` | `lx.detour.mtu_align`; `except` → `lx.detour.except_outbounds` |
| `idle_timeout` в `chain` | ничего: цепочка не создаёт звеньев, узел на позиции ≥ 1 сам дозванивается через хоп ниже |
| `strip_evasion`, `strip` в `chain` | `lx.detour.strip` |
