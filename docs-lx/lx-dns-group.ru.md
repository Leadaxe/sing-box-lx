# sing-box-lx — группа DNS-серверов

> EN: [lx-dns-group.md](lx-dns-group.md) · Фича: [DNS_GROUP](../SPECS/FEATURES/013-DNS_GROUP/FEATURE.md)

Тип `group` в `dns.servers[]` объединяет несколько DNS-серверов под одним тегом: если один сервер
не отвечает, запрос уходит к другим. В апстриме такого резерва нет. `dns.final` там — сервер по
умолчанию, а не запасной, и запрос, который правило направило в сервер, при сетевой ошибке,
таймауте или `SERVFAIL` падает без повтора. Build-тег не нужен; конфиг без `group` работает как в
апстриме.

## Поля

```jsonc
{
  "type": "group",
  "tag": "public",
  "hosts": ["local"],               // необязательное: теги серверов типа hosts,
                                    //   опрашиваются первыми, в этом порядке
  "servers": ["google", "cloudflare", "quad9"], // обязательное, хотя бы один тег;
                                    //   порядок не важен ни в одном режиме
  "mode": "stable",                 // stable (по умолчанию) | fastest | parallel
  "error_ttl": "2m",                // по умолчанию 2m: сколько помнится ошибка сервера
  "win_ttl": "5m"                   // по умолчанию 5m: сколько помнится победа сервера;
                                    //   только для fastest, в других режимах — предупреждение
}
```

Тег группы принимается везде, где принимается тег DNS-сервера: `dns.final`, правила,
`domain_resolver` у узла и `route.default_domain_resolver`.

Ключи `mode: failover` и `race`, `interval` и `down_time` из первой версии группы удалены: конфиг с
ними не загружается.

## Как группа выбирает сервер

Сбой — это транспортная ошибка, таймаут или `SERVFAIL`. `NXDOMAIN` и пустой ответ — нормальные
ответы.

Группа помнит ошибки и победы серверов, каждую запись — своё время. Ошибка помнится `error_ttl` и
стирает победы этого сервера. Победа помнится `win_ttl`; её получает только сервер, ответивший
первым, когда запрос ушёл сразу к нескольким, и любой успех стирает ошибки сервера. Чистый сервер —
сервер без ошибок в памяти. Смена сети стирает всю память.

Три режима выбирают среди чистых серверов:

- `stable` — группа держится за текущий сервер, пока он чист. Только когда текущий получил ошибку,
  она выбирает случайный чистый. На выздоровевший прежний сервер она не возвращается.
- `fastest` — чистый сервер с наибольшим числом побед. Когда побед нет ни у кого, запрос уходит
  сразу ко всем чистым, и кто ответит первым, получает победу. Такие выборы идут по одному за
  раз; запросы в это время идут к случайному чистому. Выборы повторяются, когда победы истекают.
- `parallel` — каждый запрос уходит сразу ко всем чистым серверам, побед группа не считает.
  Запросов к серверам в N раз больше.

Когда выбранный сервер не ответил, запрос уходит сразу ко всем остальным чистым. На первую попытку
отводится половина оставшегося времени запроса, вторая половина остаётся на этот запасной ход.
Первый успех отвечает и становится текущим. Остальные ответы в кеш не идут, но снимают ошибки
своих серверов.

Если чистых серверов нет, группа делает одну попытку к серверу с наименьшим числом ошибок и
не опрашивает остальные. Так шквал запросов не множится на число серверов.

> ⚠️ При сбое любой режим отправляет имя запроса всем чистым серверам, `parallel` — с каждым
> запросом. Не смешивайте внутренние и публичные резолверы в одной группе.

## Локальные имена первыми: `hosts`

Ключ `hosts` перечисляет серверы типа `hosts`, которые группа опрашивает до выбора сервера, в
порядке ключа:

- **Попадание** — запрос A или AAAA, сервер `hosts` знает имя и отвечает NOERROR. Этот ответ
  уходит как есть, сеть не опрашивается. Попадание и тогда, когда у имени есть адрес только
  другого семейства: имя только с IPv4 на запрос AAAA получает пустой ответ, и в сеть запрос не
  уходит. Поэтому `strategy: ipv6_only` на таком имени адреса не даёт — так же, как `hosts`-файл
  ОС.
- **Промах** — имя неизвестно, другой тип запроса или ответ не NOERROR. Запрос уходит в
  `servers` по режиму группы.
- Серверы из `hosts` не попадают в память ошибок и побед, в запасной ход и в одиночную попытку,
  не становятся текущими и не показываются в `GetDNSGroups`.
- `servers` остаётся обязательным и непустым. Сервер `hosts` или `fakeip` внутри `servers` —
  ошибка загрузки с подсказкой про ключ `hosts`. В `hosts` — только теги серверов типа `hosts`,
  без повторов и без пересечения с `servers`.

Ключ нужен для адресов самих серверов: outbound и endpoint разрешают свой адрес через
`domain_resolver`, а этот резолвер обращается к серверу напрямую, мимо DNS-правил. Поэтому до
таких адресов не доходят ни действие `predefined`, ни правило `server: hosts`. Сам сервер `hosts`
резолвером быть не может: на любое другое имя он отвечает NXDOMAIN.

## Что видно снаружи

Поток DNS-запросов показывает сервер, который ответил; при ответе из кеша и при полном сбое —
тег группы. У каждого запроса есть трасса проб: путь через группы, исход каждой пробы
(`answered`, `timeout`, `network_error`, `servfail`) и её время, а также флаги `fanned` (запрос
ушёл ко всем) и `survival` (чистых не было).

`GetDNSGroups` (сборка с `with_lx_command`,
[lx-config §8](lx-observability.ru.md)) отдаёт по каждому
серверу группы: чист ли он, сколько ошибок помнится и когда была последняя, сколько побед, время
последнего ответа и текущий ли он.

## Пример — отказоустойчивый публичный DNS по умолчанию

```jsonc
{
  "dns": {
    "servers": [
      { "type": "udp", "tag": "google",     "server": "8.8.8.8" },
      { "type": "udp", "tag": "cloudflare", "server": "1.1.1.1" },
      { "type": "group", "tag": "public",
        "servers": ["google", "cloudflare"],
        "mode": "fastest", "error_ttl": "2m", "win_ttl": "5m" }
    ],
    "final": "public"
  }
}
```

## Пример — одно локальное имя для WireGuard-сервера с IPv4 и IPv6

Свой WireGuard-сервер (или WARP), доступный по IPv4 и IPv6 под одним локальным именем
(issue #60):

```jsonc
{
  "dns": {
    "servers": [
      { "type": "hosts", "tag": "local",
        "predefined": { "wg.home": ["203.0.113.10", "2001:db8::10"] } },
      { "type": "udp", "tag": "google",     "server": "8.8.8.8" },
      { "type": "udp", "tag": "cloudflare", "server": "1.1.1.1" },
      { "type": "group", "tag": "resolver",
        "hosts": ["local"],
        "servers": ["google", "cloudflare"],
        "mode": "stable" }
    ],
    "final": "resolver"
  },
  "route": { "default_domain_resolver": { "server": "resolver", "strategy": "prefer_ipv6" } }
}
```

`wg.home` в адресе сервера endpoint'а получает оба адреса из `local`, семейство выбирает
`strategy`. Любое другое имя идёт в `google` или `cloudflare` по режиму `stable`.
