# sing-box-lx — энергооптимизация на мобильных (idle-suspend × urltest)

> 🌐 English version: **[lx-energy.md](lx-energy.md)**.
>
> Фичи: [ENERGY](../SPECS/FEATURES/008-ENERGY/FEATURE.md) (idle-suspend), [URLTEST_BALANCE](../SPECS/FEATURES/007-URLTEST_BALANCE/FEATURE.md) (round_robin/пул/failover), [AWG](../SPECS/FEATURES/003-AWG/FEATURE.md). Конфиг-ключи всех lx-фич: [lx-config.ru.md](lx-config.ru.md).

Документ объясняет, почему форк экономит батарею на Android и как этим управлять. Апстримный sing-box держит каждый WireGuard/AmneziaWG-эндпоинт живым 24/7 независимо от трафика. Recv-воркеры держат буферы: ~8 МБ на воркера при мобильном `BatchSize=128`. Эти буферы — главный источник GC-нагрева: на устройстве 8 усыплённых узлов освободили 134 МБ. Таймеры keepalive и handshake будят радио. Форк выборочно усыпляет простаивающие эндпоинты и ограничивает пробы health-check, чтобы те не будили спящих.

## 1. Экономию дают три слоя: достижимость, тик, эндпоинт

```
┌─────────────────────────────────────────────────────────────────┐
│ СЛОЙ 1 · ДОСТИЖИМОСТЬ (Router)                                  │
│ «Куда трафик может попасть прямо сейчас?»                       │
│ event-driven кэш: пересчёт только при смене активного дерева    │
└───────────────┬─────────────────────────────────────────────────┘
                │ reachable[tag] → bool
┌───────────────▼─────────────────────────────────────────────────┐
│ СЛОЙ 2 · ТИК (Router, каждые max(порог/2, 5s), pause-aware)     │
│ по всем WG/AWG-эндпоинтам: SuspendIfIdle(reachable, T1, T2)     │
└───────────────┬─────────────────────────────────────────────────┘
                │ решение по цепочке гейтов (§4)
┌───────────────▼─────────────────────────────────────────────────┐
│ СЛОЙ 3 · ЭНДПОИНТ (device Down/Up + Close/Rebuild)              │
│ Down: воркеры выходят, буферы свободны, таймеры молчат          │
│ Close (проспал lx.wg.idle.teardown): уходит и netstack          │
│ Пробуждение — только по дайлу: +1 RTT / rebuild ~0.5-1 с        │
└─────────────────────────────────────────────────────────────────┘
```

Health-check urltest (пробы) в эти слои не входит. Каждая проба — обычный дайл, поэтому она будит спящие эндпоинты. Половина оптимизаций ограничивает пробы теми случаями, когда они нужны (§6).

## 2. Достижим эндпоинт, куда может попасть новое соединение

Эндпоинт достижим, если новое соединение может попасть на него прямо сейчас. Обход начинается с трёх точек входа (сидов):

- `route.final` (default outbound);
- цель каждого route/bypass-правила;
- detour каждого DNS-сервера. DNS дайлится при каждом резолве, поэтому узел только для DNS всегда достижим. Иначе он флапал бы Down/Up вокруг каждой паузы и добавлял handshake к первому DNS-запросу.

Вниз обход идёт так, транзитивно, с отсечением циклов:

- селектор → только текущий выбор (`Now()`);
- round_robin-urltest → весь текущий пул;
- legacy-urltest → текущий выбранный узел;
- обычный outbound → его detour-цепочка.

Множество кэшируется и пересчитывается только по событиям: переключение селектора, авто-переключение urltest (включая самый первый выбор), перестройка пула, перезагрузка конфига. Между событиями тик читает готовую map: один map-lookup и пара атомиков на эндпоинт.

## 3. Недостижимые и достижимые узлы засыпают по разным порогам

```jsonc
"lx": {
  "wg": {
    "idle": {
      "suspend": "30s",                // порог для НЕДОСТИЖИМЫХ (выключатель фичи)
      "suspend_reachable": "5m",       // опционально: порог для ДОСТИЖИМЫХ
      "teardown": "5m"                 // опционально: сколько СПАТЬ до полного сноса;
                                       //   дефолт = suspend_reachable, "0" = выкл
    }
  }
}
```

Ключи лежат в блоке `lx.wg.idle` корневого блока `lx` ([lx-block.ru.md](lx-block.ru.md)).
Плоский `lx.wg.idle_suspend` и остальные ключи старой раскладки не загружаются, ошибка называет новое имя.
Ключи `route.lx_idle_suspend` / `route.lx_idle_suspend_reachable` / `route.lx_idle_teardown`
удалены 2026-11-02: конфиг с ними не загружается, как с неизвестными ключами.

| | Недостижимый узел | Достижимый узел | Любой спящий узел |
|---|---|---|---|
| Порог | `lx.wg.idle.suspend` (30s простоя) | `lx.wg.idle.suspend_reachable` (5m простоя); `0`/нет — не гасится | `lx.wg.idle.teardown` (5m сна, отсчёт от засыпания); явный `0` — не сносить, нет ключа — взять окно достижимых |
| Что происходит | `Down()` — заморозка | `Down()` — заморозка | `Close()` — полный снос: уходит и gVisor netstack (~6 МБ/узел) |
| Пробуждение | дайл, +1 RTT | дайл, +1 RTT | дайл, rebuild ~0.5–1 с на первом запросе |

Третий уровень — глубокий сон. Заморозка (`Down`) освобождает recv-буферы и таймеры, но netstack остаётся. Узел, проспавший ещё одно окно, сносится целиком, от него остаётся только конфиг. Окно сна считается от момента засыпания, а не от последнего дайла, поэтому не зависит от того, каким порогом узел уснул. Живые соединения снос не затрагивает: узел с потоками не засыпает (§4), а сносятся только спящие.

Ядро проверяет, что `reachable`-порог задан вместе с `lx.wg.idle.suspend` и не меньше него. Рекомендация: `>= idle_timeout` urltest-групп, почему — в §7.

Простой — время с последнего дайла через эндпоинт, то есть с создания нового соединения. Данные установленных соединений идут мимо дайл-пути, их защищают гейты §4.5–4.6.

## 4. Тик проверяет шесть условий, прежде чем усыпить эндпоинт

На каждом тике каждый эндпоинт проходит цепочку от дешёвых проверок к дорогим:

1. **listen-mode** (`listen_port` задан) → никогда не гасим: входящие пиры не могут его разбудить.
2. **Выбор окна**: недостижим → `lx.wg.idle.suspend`; достижим → `lx.wg.idle.suspend_reachable` (или выход, если та не задана).
3. **Часы простоя**: `IdleSince() < окна` → рано.
4. **Уже погашен** (остановлен или закрыт) → чужое состояние не трогаем.
5. **Живые TCP-потоки**: gauge `CurrentEstablished` gVisor-стека устройства > 0 → есть установленные соединения (закачка, push-сокет) → не гасим. Гейт точный, и keepalive на него не влияет: keepalive — не TCP-поток.
6. **Дельта счётчиков**: rx+tx выросли на ≥ 4096 байт с прошлого решения → живой UDP/QUIC-трафик → сброс часов, не гасим. Гейт сравнивает с порогом, а не ловит любое изменение: WG keepalive (32 Б/интервал) и rekey (~240 Б/~2 мин) двигают счётчики всегда. Пир с `persistent_keepalive` должен уметь засыпать, потому что глушение его таймеров — половина выигрыша. Молчащий QUIC-поток с редкими ping'ами ниже порога будет усыплён. Это согласованная цена: QUIC мигрирует или переустанавливается.
7. Всё тихо → `device.Down()`, лог `lx idle: suspend <tag>`.

## 5. Пробуждение после Down стоит +1 RTT, после Close — пересборку

`Down()` (уровни 1–2) — заморозка, а не Close. Закрывается UDP-сокет: recv-воркеры выходят и освобождают буферы, это главный выигрыш по RAM и GC. Сессионные ключи зануляются, останавливаются все таймеры пира: keepalive, retransmit, у AWG — junk-машинерия. Объекты и порт переживают цикл.

`Close()` (уровень 3, `lx.wg.idle.teardown`) — снос: уходят netstack, объекты Device/Peer, очереди, все горутины устройства; остаётся только конфиг в памяти. Пробуждение — пересборка с нуля: ~0.5–1 с на первом дайле вместо +1 RTT.

Что даёт каждый уровень, по замеру на устройстве CPH2411:

| Уровень | Что освобождает | Замер |
|---|---|---|
| 1–2 (`Down`) | recv-воркеры + их буферы (~8 МБ/воркер, 2 на устройство), таймеры | −134 МБ при 8 усыплённых узлах (`bufsArrs` 223.93→89.89 МБ) |
| 3 (`Close`) | netstack + Device-объекты + все горутины устройства | ~5.9 МБ/узел; на 3 узлах heap почти не двинулся (36.7→36.3 МБ) |

Дельта уровня 3 мала не из-за фичи: 63% кучи (23.4 МБ) держит глобальный пул `sing/common/buf` (`GetOutboundBuffer → buf.Get`). Пул общий на процесс, намеренно переживает и `Down`, и `Close` и системе память не возвращает. На его фоне три netstack'а незаметны.

Основную экономию RAM даёт уровень 1. Уровень 3 окупается при десятках узлов, а не при трёх: там он снимает ещё ~6 МБ на каждый спящий. На маленьком конфиге заметной экономии он не даёт. Вторая польза уровня 3 — меньше живых объектов под потолком `SetMemoryLimit`, то есть реже GC у активных узлов.

Разбудить эндпоинт может только дайл через него (`DialContext`/`ListenPacket`/L3-форвардинг). Дайл поднимает сокет и воркеров, а первый пакет ждёт свежий handshake: +1 RTT (14–21 мс на близком сервере, до ~450 мс на межконтинентальном). Throughput не страдает.

+1 RTT неустраним. Вариант будить с сохранением крипто-сессии (`BindUpdate` не трогает ключи) отвергнут по двум причинам. Сессия WireGuard живёт 120 с и невалидна после 180 с, а сон длится минутами, так что handshake нужен всё равно. На мобильном смена сети (Wi-Fi↔LTE) за время сна делает устаревшим endpoint, который знает сервер, и в CGNAT-сетях «экономия» оборачивается таймаутом вместо обычного handshake. Разбор — в [SPEC 020](../SPECS/TASKS/020-MULTI_WG_IDLE_BUFFER_HEAT/SPEC.md), раздел «ОТВЕРГНУТО: путь A».

Два частых вопроса о пробуждении:
- **Будит сама попытка, не её успех.** Пробуждение происходит в начале дайла, до отправки чего-либо. Если соединение дальше падает (цель не отвечает), туннель уже проснулся и снова уснёт через своё окно. Будит любое приложение, чей трафик маршрутизируется в этот туннель; трафик напрямую или через другой канал не будит.
- **Открытый TCP-сокет не даёт туннелю уснуть** (established-гейт, §4.5). Поэтому для TCP не бывает случая «приложение пишет в сокет, а туннель уже спит». Молчащая UDP/QUIC-сессия уснуть может; QUIC тогда переустановится новым дайлом, и этот дайл разбудит туннель.

Два события эндпоинт не будят: включение экрана и смена сети (pause-wake). Транспорт помнит флаг `suspended` и не поднимает такие устройства. Иначе один цикл экрана будил бы все устройства и ломал учёт до перезапуска.

Для назначений-доменов DNS-резолв идёт до пробуждения, поэтому неудачный lookup не платит handshake. Сон туннеля не ломает DNS. Обычный DNS через туннель не ходит: если резолв провалился, DNS сломан и при бодрствующем туннеле. DNS-сервер с detour через этот же туннель шлёт запрос отдельным дайлом на IP сервера, и этот дайл сам будит туннель. Deadlock «спит, потому и не резолвится» невозможен.

## 6. Пробы urltest будят спящих, поэтому их ограничивают пять механизмов

Проба health-check — обычный дайл через узел, поэтому она будит спящий узел. Пробы ограничивают пять механизмов:

| Механизм | Уровень | Что делает |
|---|---|---|
| `idle_timeout` (апстрим, 30m) | группа | нет трафика через группу дольше порога → тикер проб гаснет насовсем; первый новый дайл (`Touch`) заводит его и делает немедленный дотест |
| Гейт достижимости (lx) | группа | группа недостижима (селектор ушёл) → циклы пропускаются сразу, не дожидаясь idle_timeout; тикер жив и самовосстанавливается |
| `mode: failover` (lx) | режим | каждый `interval` пробуется только удерживаемый узел (одна проба вместо N); остальные — только при отказе удерживаемого (полный прогон) или ручном тесте |
| round_robin-пул (lx) | режим | пробуются только члены пула (напр. 3), а не все N узлов; узлы вне пула — только при доборе дырок |
| Ручной тест | — | всегда полный (force), ничем не гейтится |

Активная least_test-группа пробует всех членов каждый `interval` и будит спящих. Это семантика апстрима: чтобы выбрать лучший узел, нужно замерить все. Где эта цена важна, выбирайте `mode: failover`: группа держится за рабочий узел и пробует только его, остальные узлы спят, пока удерживаемый отвечает.

У `failover` своя цена: пока удерживаемый узел работает, группа не ищет более быстрый, а задержки остальных узлов в UI остаются от последнего полного прогона. Если удерживаемый узел не ответил на пробу или дайл через него упал с ошибкой «путь мёртв», выбор переезжает на самый быстрый живой узел; ручной тест меряет всех и перевыбирает самый быстрый. Семантика режимов — в [lx-urltest.ru.md](lx-urltest.ru.md#4-failover--держаться-до-отказа).

## 7. Таймлайны

### Ночь (round_robin pool=3, interval=15m, idle_timeout=30m, пороги 30s/30m)

```
T=0        последний пользовательский дайл
T=0..30m   хвост проб: тикер ещё жив, пробы в T=15m и T=30m дайлят пул
           (узлы не засыпают — каждая проба сбрасывает их часы)
T≈45m      Since(lastActive) > idle_timeout → тикер проб ГАСНЕТ
T≈60m      простой узлов (от последней пробы T=30m) > 30m →
           тик гасит все 3 узла — полная тишина до утра
УТРО       первый дайл будит ОДИН узел (+1 RTT); Touch заводит тикер;
           немедленный дотест обновляет пул свежими замерами за секунды
```

Проба не разбудит засыпающий узел: пробы смолкают в `T=idle_timeout`, а достижимые узлы засыпают не раньше `T=последняя проба + reachable`. При `reachable >= idle_timeout` к моменту сна пробы уже остановлены. Нарушение рекомендации ничего не ломает: в хвосте будет 1–2 цикла флапа.

### Уход селектора с группы

```
T=0   селектор переключён с группы AUTO на другой канал
      → InvalidateReachability: AUTO и её члены недостижимы
T=0+  очередные тики проб AUTO ПРОПУСКАЮТСЯ (гейт достижимости)
~30s+ члены AUTO засыпают по КОРОТКОМУ порогу (они недостижимы)
T=30m idle_timeout добивает тикер AUTO насовсем
```

Без гейта достижимости брошенная группа пробовала бы и будила всех членов ещё 30 минут: до 10 циклов × N handshake'ов впустую.

## 8. Рецепт конфигурации для мобильного клиента

```jsonc
{
  "lx": {
    "wg": {
      "idle": {
        "suspend": "30s",
        "suspend_reachable": "30m"
      }
    }
  },
  "outbounds": [{
    "type": "urltest",
    "tag": "auto",
    "outbounds": ["node-1", "…", "node-N"],
    "interval": "15m",          // реже циклы там, где они всё же идут
    "idle_timeout": "30m",      // = reachable-порогу (см. §7)
    "mode": "failover"          // держаться за рабочий узел, пробовать только его (одно пробуждение в interval)
    // для балансировки вместо этого: "mode": "round_robin", "balancer": { "pool": 3, "pool_tolerance": 0 }
  }]
}
```

Правила согласования порогов:

| Ограничение | Кем | Последствие нарушения |
|---|---|---|
| `interval <= idle_timeout` | ядро (апстрим), ошибка старта | — |
| `lx.wg.idle.suspend_reachable >= lx.wg.idle.suspend` | ядро (lx), ошибка старта | — |
| `lx.wg.idle.suspend_reachable >= idle_timeout` групп | рекомендация | 1–2 probe-флапа в хвосте засыпания |
| низкий reachable (напр. `5m`) | допустимо | быстрый сон при паузах; цена — те же 1–2 лишних handshake в первые ~полчаса тишины (пока пробы не заглохли) и +1 RTT на первом соединении после каждой ≥5m паузы |
| `interval` > masque idle (5m) для групп с MASQUE | рекомендация | проба не даёт туннелю MASQUE уснуть |
| `pool_tolerance <= 15000` | ядро (lx), ошибка старта | — |

Замечания:
- `pool_tolerance > 0` на мобильном не рекомендуется: в этом режиме группа меряет всех кандидатов каждый цикл и будит всех спящих вне пула.
- `persistent_keepalive` у пиров совместим с suspend: во сне таймер остановлен, шум keepalive не мешает засыпанию (§4.6). Бодрствующий узел с keepalive продолжает будить радио; это выбор пользователя.
- Без `lx.wg.idle.suspend` фича выключена целиком (kill-switch, нулевой оверхед). Она есть только в mobile-AAR (`with_lx_idle_suspend`); desktop-бинарь с этим ключом падает на старте с явной ошибкой.

## 9. Засыпание не рвёт соединения и не ломает учёт

- **Живые соединения не рвутся**: узел с established TCP-потоком или объёмным UDP-трафиком не гасится, каким бы «простаивающим» он ни выглядел по дайлам (§4.5–4.6). Обещание `interrupt_exist_connections=false` сохраняется.
- **Screen-off/on и смена сети не ломают учёт**: suspended-устройства переживают pause/wake-цикл спящими.
- **Первый запрос после сна работает всегда**: он идёт через последний известный узел и будит его, а немедленный дотест параллельно обновляет выбор. Если узел умер за ночь, один запрос падает, а дотест сразу чинит пул.
- **Kill-switch**: без `lx.wg.idle.suspend` не запускается даже тик.

## 10. Засыпание, пробуждение и разборка видны в логе

- `lx idle: suspend <tag> idle=…` / `lx idle: wake <tag> by=dial` — edge-triggered пары в логе. Частые пары suspend↔wake по одному тегу означают флап: проверьте согласование порогов (§8) и что probe-гейты активны.
- У спящего узла 0 recv-воркеров устройства (goroutine profile) и нулевой rx/tx.
- Узел не засыпает, хотя должен: проверьте, достижим ли он (селектор, пул, правило, DNS-detour — §2) и нет ли через него established TCP или объёмного UDP.
- Пробы идут ночью: проверьте, есть ли трафик через группу (`Touch` держит тикер). Фоновые push-соединения приложений — тоже трафик.
- `lx idle: teardown <tag> by=budget` — бюджет сборок разобрал узел, чтобы освободить место другому (§11); `lx idle: build over budget N+1/N <tag>` — сборка ушла сверх `build_max`, потому что все собранные узлы держали живые соединения (`build_overflow: "build"`); `lx idle: build <tag>: build budget exhausted (N built, none idle)` — дайл не дождался места (`build_overflow: "wait"`).

## 11. Ленивая сборка и бюджет не дают собирать устройства впустую

Сон и разборка освобождают память endpoint'а после простоя. На старте же конфиг с десятком AWG-узлов платит за все узлы сразу. Каждое устройство при запуске выделяет приёмные батчи: 128 × 64 КБ на приёмную рутину на Linux и Android, где 64-КБ сегменты питают GRO. По умолчанию это 16,4 МБ на узел (≈17,5 МБ в замере lx.8, до SPEC 158). Число уменьшает `lx.wg.buffers.read_datagram_count` в любой сборке ([lx-block.ru.md](lx-block.ru.md)). Два ключа не дают собирать устройства впустую.

**`lx.wg.idle.lazy_build: true`** — endpoint'ы стартуют на уровне 3 (§5): detour резолвится на старте, как и без ключа, но устройство и его netstack не собираются. Первый дайл через узел (пользовательское соединение или проба urltest) собирает его тем же путём, что и пробуждение после разборки, и платит один раз: сборка плюс первое рукопожатие. Endpoint в режиме прослушивания (`listen_port`) ленивым не бывает — его никто не дайлит. Требует `lx.wg.idle.suspend`.

**`lx.wg.idle.build_max: N`** — одновременно собрано не больше N устройств. Без потолка ленивость только откладывает пик: проба urltest по всей группе сразу после старта соберёт все узлы. С потолком дайл, которому нужно (N+1)-е устройство, сначала разбирает жертву:

1. первыми — устройства, собранные сверх потолка (`build_overflow: "build"`);
2. затем узел с наименьшим числом **ручных** ссылок — рёбер от текущего выбора селектора, от outbound'а `final`, от цели правила;
3. затем с наименьшим числом **авто**-ссылок — пул urltest, `detour` другого узла, `detour` DNS-сервера, позиция цепочки;
4. затем узел, через который дайлили давнее всего.

Порядок лексикографический: любое число авто-ссылок проигрывает одной ручной. Ссылка — ребро, ведущее прямо в узел; по дереву ничего не наследуется (селектор → urltest → X даёт X одну авто-ссылку). Сон в порядке не участвует: спящий узел со ссылкой переживёт бодрствующий без неё. Трафик тоже не участвует в порядке, а только охраняет: узел с дайлом в процессе, установленным TCP-потоком или ≥ 4096 байт с прошлой выборки бюджета не разбирается никогда. Узел без ссылок, собранный мгновение назад, — законная жертва: пробы не могут ждать порога сна.

Когда охраняются все собранные узлы, решает `lx.wg.idle.build_overflow`:

| Значение | Поведение |
|---|---|
| `wait` (дефолт) | дайл ждёт места до своего дедлайна, не дольше 15 с; освобождённое место, засыпание узла или конец потока (проверка раз в секунду) дают повторить выбор. После дедлайна дайл падает, и узел считается недоступным на этой пробе, а не мёртвым |
| `build` | устройство собирается сверх потолка с предупреждением; следующая сборка первым разбирает именно его |

Пробы под потолком идут волнами: группа из K узлов при `build_max: N` замеряется по N сборок за раз, так что круг проб дольше, а память ограничена. Если волна не укладывается в таймаут пробы, хвост группы на этом круге помечается недоступным.

`build_max` без `lazy_build` допустим: устройства собираются на старте, а потолок действует с первой пересборки (пробуждения после `idle.teardown`). Потолок ниже числа одновременно используемых узлов заставляет узлы разбирать друг друга при каждом переключении (каждый дайл платит сборку); LxBox выставляет `build_max` только для probe-сессий.

**Состояния.** `GetOutbounds` отдаёт состояние каждого WG/AWG-endpoint'а в `endpointState` (и секунды с последнего дайла в `idleSinceSeconds`):

| Состояние | Значение |
|---|---|
| `never_built` | ленивый endpoint, дайлов ещё не было |
| `building` | идёт сборка (включая ожидание бюджета) |
| `up` | устройство собрано и бодрствует |
| `asleep` | устройство собрано, в Down (уровни 1–2) |
| `torn_down` | устройство освобождено (уровень 3 или разборка бюджетом) |
| `down` | ещё не стартовал или закрыт |
| `disabled` | выключен вручную (§12), на любом уровне сна устройства |

«Не собран» — состояние, а не ошибка: приложение показывает «узел не поднят» и не принимает это за таймаут.

## 12. Ручной переключатель выключает endpoint без правки конфига

gRPC `SetEndpointEnabled(tag, enabled)` (`with_lx_command`, обслуживает `lxd`) выключает и включает WG/AWG-endpoint без правки конфига. В ответе — состояние endpoint'а после вызова. LxBox вызывает его через libbox `CommandClient.SetEndpointEnabled`, ответ — объект `EndpointToggleResult` (`State`).

- **Выключение:** бодрствующий endpoint усыпляется так же, как это делает тик простоя, поэтому установленные соединения через него рвутся. Каждый дайл, UDP-listen и пакет L3-форварда получает отказ `WireGuard endpoint is disabled`; ничто его не будит. Тик простоя всё равно может разобрать его по `idle.teardown`, а бюджет сборок — выбрать жертвой.
- **Включение:** спящий endpoint будится сразу (одно рукопожатие на следующем пакете). Разобранный или несобранный остаётся как есть и собирается следующим дайлом через бюджет. Если пробуждение не удалось, вызов возвращает `Unavailable`; endpoint включён, но спит, следующий дайл повторит.
- **Не сохраняется:** reload или `/admin/apply` создают все endpoint'ы включёнными.
- Работает без `with_lx_idle_suspend`; на десктопе выключенный endpoint держит устройство в Down, пока его не включат или не закроют.

Ошибки: `NotFound` (нет endpoint'а с таким тегом), `InvalidArgument` (не WG/AWG), `FailedPrecondition` (ядро не запущено, endpoint закрывается), `Unimplemented` (сборка без `with_lx_command`).
