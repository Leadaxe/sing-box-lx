# sing-box-lx — энергооптимизация на мобильных (idle-suspend × urltest)

> 🌐 English version: **[lx-energy.md](lx-energy.md)**.
>
> Фичи: [ENERGY](../SPECS/FEATURES/ENERGY/FEATURE.md) (idle-suspend), [URLTEST_BALANCE](../SPECS/FEATURES/URLTEST_BALANCE/FEATURE.md) (round_robin/пул/passive_check), [AWG2](../SPECS/FEATURES/AWG2/FEATURE.md). Конфиг-ключи всех lx-фич: [lx-config.ru.md](lx-config.ru.md).

Это главный документ о том, **почему форк экономит батарею на Android и как этим управлять**. Апстримный sing-box держит каждый WireGuard/AmneziaWG-эндпоинт живым 24/7 независимо от трафика: recv-воркеры с буферами (~8 МБ на воркера при мобильном `BatchSize=128` — главный источник GC-нагрева, замерено −134 МБ на устройстве при 8 усыплённых нодах), таймеры keepalive/handshake, которые будят радио. Форк добавляет выборочное **засыпание** простаивающих эндпоинтов и учит health-check **не мешать им спать**. Ниже — вся модель по шагам.

---

## 1. Картина целиком: три слоя

```
┌─────────────────────────────────────────────────────────────────┐
│ СЛОЙ 1 · ДОСТИЖИМОСТЬ (Router)                                  │
│ «Куда трафик может попасть прямо сейчас?»                       │
│ event-driven кэш: пересчёт только при смене активного дерева    │
└───────────────┬─────────────────────────────────────────────────┘
                │ reachable[tag] → bool
┌───────────────▼─────────────────────────────────────────────────┐
│ СЛОЙ 2 · ТИК (Router, каждые max(порог/2, 5s), pause-aware)     │
│ по всем WG/AWG-эндпоинтам: SuspendIfIdle(reachable, T1, T2)     │
└───────────────┬─────────────────────────────────────────────────┘
                │ решение по цепочке гейтов (§4)
┌───────────────▼─────────────────────────────────────────────────┐
│ СЛОЙ 3 · ЭНДПОИНТ (device Down/Up + Close/Rebuild)              │
│ Down: воркеры выходят, буферы свободны, таймеры молчат          │
│ Close (проспал lx_idle_teardown): уходит и netstack             │
│ Пробуждение — только по дайлу: +1 RTT / rebuild ~0.5-1 с        │
└─────────────────────────────────────────────────────────────────┘
```

Раздельно от этого живёт **health-check urltest** (пробы) — он не часть suspend-механизма, но каждая его проба является обычным дайлом и потому **будит** спящих. Половина оптимизаций — о том, чтобы пробы ходили только тогда, когда действительно нужны (§6).

## 2. Слой достижимости

Эндпоинт **достижим**, если новое соединение может попасть на него прямо сейчас. Точки входа (сиды) обхода:

- `route.final` (default outbound);
- цель каждого route/bypass-правила;
- **detour каждого DNS-сервера** — DNS дайлится при каждой резолюции, поэтому DNS-only узел всегда достижим (иначе он флапал бы Down/Up вокруг каждой паузы, добавляя handshake к первому DNS-запросу).

Обход вниз: селектор → только текущий выбор (`Now()`); round_robin-urltest → **весь текущий пул**; legacy-urltest → текущий выбранный; обычный outbound → его detour-цепочка. Всё транзитивно, циклы отсекаются.

Множество кэшируется и пересчитывается **только по событиям** (переключение селектора, авто-переключение urltest — включая самый первый выбор, перестройка пула, перезагрузка конфига). Между событиями тик читает готовую map — на тик приходится один map-lookup и пара атомиков на эндпоинт.

## 3. Два порога простоя

```jsonc
"route": {
  "lx_idle_suspend": "30s",            // порог для НЕДОСТИЖИМЫХ (выключатель фичи)
  "lx_idle_suspend_reachable": "5m",   // опционально: порог для ДОСТИЖИМЫХ
  "lx_idle_teardown": "5m"             // опционально: сколько СПАТЬ до полного сноса;
                                       //   дефолт = lx_idle_suspend_reachable, "0" = выкл
}
```

| | Недостижимый узел | Достижимый узел | Любой СПЯЩИЙ узел |
|---|---|---|---|
| Порог | `lx_idle_suspend` (30s простоя) | `lx_idle_suspend_reachable` (5m простоя); `0`/нет — не гасится | `lx_idle_teardown` (5m **сна**, отсчёт от засыпания) |
| Что происходит | `Down()` — заморозка | `Down()` — заморозка | **`Close()`** — полный снос: уходит и gVisor netstack (~6 МБ/узел) |
| Пробуждение | дайл, +1 RTT | дайл, +1 RTT | дайл, **rebuild ~0.5–1 с** на первом запросе |

Третий уровень — «глубокий сон»: заморозка (`Down`) освобождает recv-буферы и таймеры, но netstack живёт; узел, проспавший ещё одно окно, сносится целиком — от него остаётся только конфиг. Порог считается **от момента засыпания** (не от последнего дайла), поэтому не зависит от того, каким окном узел уснул. Живые соединения это не затрагивает по построению: узел с потоками просто не засыпает (§4), а сносятся только спящие.

Валидация: `reachable`-порог требует включённого `lx_idle_suspend` и значения `>=` него. Рекомендация: `>= idle_timeout` urltest-групп (объяснение в §7).

«Простой» = время с последнего **дайла** через эндпоинт (создания нового соединения). Данные уже установленных соединений идут мимо дайл-пути — их защищают гейты §4.5–4.6.

## 4. Решение тика: цепочка гейтов

На каждом тике для каждого эндпоинта, в порядке дёшево→дорого:

1. **listen-mode** (`listen_port` задан) → никогда не гасим: входящие пиры не могут его разбудить.
2. **Выбор окна**: недостижим → `lx_idle_suspend`; достижим → `lx_idle_suspend_reachable` (или выход, если та не задана).
3. **Часы простоя**: `IdleSince() < окна` → рано.
4. **Уже погашен** (guard/закрыт) → чужое состояние не трогаем.
5. **Живые TCP-потоки**: gauge `CurrentEstablished` gVisor-стека устройства > 0 → есть установленные соединения (закачка, push-сокет) → не гасим. Гейт точный и **иммунный к keepalive** (keepalive — не TCP-поток).
6. **Дельта счётчиков**: rx+tx выросли на **≥ 4096 байт** с прошлого решения → живой UDP/QUIC-трафик → сброс часов, не гасим. Именно порог, а не «изменилось»: WG keepalive (32 Б/интервал) и rekey (~240 Б/~2 мин) двигают счётчики вечно — пир с `persistent_keepalive` обязан уметь засыпать (глушение его таймеров — половина выигрыша). Молчащий QUIC-поток (редкие ping'и < порога) будет усыплён — согласованная цена, QUIC мигрирует/переустанавливается.
7. Всё тихо → `device.Down()`, лог `lx idle: suspend <tag>`.

## 5. Down, Close и цена пробуждения

`Down()` (уровни 1–2) — это заморозка, не Close: закрывается UDP-сокет (recv-воркеры выходят, их буферы освобождаются — главный RAM/GC-выигрыш), зануляются сессионные ключи, останавливаются **все** таймеры пира (keepalive, retransmit, у AWG — junk-машинерия). Объекты и порт переживают цикл.

`Close()` (уровень 3, `lx_idle_teardown`) — снос: уходят netstack, объекты Device/Peer, очереди, все горутины устройства; остаётся только конфиг в памяти. Пробуждение — пересборка с нуля (**~0.5–1 с** на первом дайле вместо +1 RTT).

**Сколько это даёт на самом деле** (замерено на устройстве, CPH2411 — не оценка):

| Уровень | Что освобождает | Замер |
|---|---|---|
| 1–2 (`Down`) | recv-воркеры + их буферы (~8 МБ/воркер, 2 на устройство), таймеры | **−134 МБ** при 8 усыплённых нодах (`bufsArrs` 223.93→89.89 МБ) |
| 3 (`Close`) | netstack + Device-объекты + все горутины устройства | ~5.9 МБ/нода; на 3 нодах heap почти не двинулся (36.7→36.3 МБ) |

Причина скромной дельты уровня 3 не в фиче: **63% кучи (23.4 МБ) держит глобальный пул `sing/common/buf`** (`GetOutboundBuffer → buf.Get`) — он общий на процесс, переживает и `Down`, и `Close` **by design** и системе память не возвращает. На фоне такого пула три netstack'а незаметны.

Вывод для настройки: **основную RAM даёт уровень 1**, а уровень 3 окупается при **многих** нодах (десятки), а не при трёх — там он снимает ещё ~6 МБ на каждую спящую. Ждать от него чуда на маленьком конфиге не стоит; его вторая ценность — меньше живых объектов под потолком `SetMemoryLimit`, то есть реже GC у активных нод.

Пробуждение — **единственный путь**: настоящий дайл через эндпоинт (`DialContext`/`ListenPacket`/L3-форвардинг). Он поднимает сокет и воркеров; первый пакет ждёт свежий handshake — **+1 RTT** (14–21 мс на близком сервере, до ~450 мс на межконтинентальном). Throughput не страдает.

> **Почему +1 RTT неустраним.** Теоретическая альтернатива — будить с сохранением крипто-сессии (`BindUpdate` не трогает ключи) — **отвергнута**: сессия WireGuard живёт 120 с и невалидна после 180 с, а спим мы минутами → handshake всё равно неизбежен; плюс на mobile смена сети (Wi-Fi↔LTE) за время сна делает известный серверу endpoint устаревшим, и в CGNAT-сетях «экономия» превращается в таймаут вместо честного handshake. Разбор — SPEC 020 §«ОТВЕРГНУТО: путь A».

Нюансы пробуждения (частые вопросы):
- **Будит сама попытка, не её успех.** Wake происходит в начале дайла, до отправки чего-либо; если соединение дальше фейлится (цель не отвечает), туннель уже проснулся и снова уснёт через своё окно. «Любое приложение» = любое, чей трафик маршрутизируется в этот туннель; идущие direct/другим каналом не будят.
- **Открытый TCP-сокет не даёт туннелю уснуть вовсе** (established-гейт §4.5) — поэтому кейса «приложение пишет в сокет, а туннель уже спит» для TCP не существует. Молчащая UDP/QUIC-сессия уснуть может; QUIC при этом сам переустановится новым дайлом — который и разбудит туннель.

Что пробуждением **не является**:
- включение экрана / смена сети (pause-wake): транспорт помнит флаг `suspended` и не поднимает такие устройства — иначе один цикл экрана воскрешал бы всех и ломал учёт до перезапуска;
- guard-suspended AWG (см. SPEC 007) не воскрешается ничем, кроме перезапуска ядра, — это защита от AWG-over-WG kernel hang.

Для domain-назначений DNS-резолв выполняется **до** пробуждения — неудачный lookup не платит handshake. **Это безопасно, сон туннеля не может «уронить DNS»**: резолв не ходит через спящий туннель вслепую — обычный DNS его вообще не касается (провал резолва означал бы сломанный DNS и при бодрствующем туннеле), а DNS-сервер, задетуренный через этот же туннель, шлёт запрос отдельным дайлом с IP-адресом сервера, и этот дайл **сам будит туннель**. Deadlock «спит, потому и не резолвится» невозможен по построению.

## 6. urltest: пробы и как они научены не мешать

Проба health-check — обычный дайл через узел, то есть **будит спящего**. Механизмы, ограничивающие пробы:

| Механизм | Уровень | Что делает |
|---|---|---|
| `idle_timeout` (апстрим, 30m) | группа | нет трафика через группу дольше порога → тикер проб **гаснет насовсем**; первый новый дайл (`Touch`) заводит его и делает немедленный дотест |
| Гейт достижимости (lx) | группа | группа недостижима (селектор ушёл) → циклы **пропускаются** сразу, не дожидаясь idle_timeout; тикер жив и самовосстанавливается |
| `passive_check` (lx, opt-in) | узел/цикл | успешный TCP-дайл через узел = доказательство живости (SYN/SYN-ACK прошёл всю цепочку); пока оно свежо (< interval): least_test пропускает циклы целиком, round_robin не пробует подтверждённые слоты |
| round_robin-пул (lx) | режим | пробуются только члены пула (напр. 3), а не все N нод; ноды вне пула — только при доборе дырок |
| Ручной тест | — | всегда полный (force), ничем не гейтится |

Важное следствие для активной least_test-группы: **без** `passive_check` она пробует всех членов каждый `interval`, будя спящих (это апстрим-семантика — выбор лучшего требует замеров всех). С `passive_check` при здоровом трафике пробы не ходят вообще.

## 7. Таймлайны

### Ночь (round_robin pool=3, interval=15m, idle_timeout=30m, пороги 30s/30m)

```
T=0        последний пользовательский дайл
T=0..30m   хвост проб: тикер ещё жив, пробы в T=15m и T=30m дайлят пул
           (узлы не засыпают — каждая проба сбрасывает их часы)
T≈45m      Since(lastActive) > idle_timeout → тикер проб ГАСНЕТ
T≈60m      простой узлов (от последней пробы T=30m) > 30m →
           тик гасит все 3 узла — полная тишина до утра
УТРО       первый дайл будит ОДИН узел (+1 RTT); Touch заводит тикер;
           немедленный дотест обновляет пул свежими замерами за секунды
```

Гонки «проба будит засыпающего» нет по построению: пробы молкнут в `T=idle_timeout`, сон достижимых — не раньше `T=последняя проба + reachable`. При `reachable >= idle_timeout` будильник к моменту сна уже мёртв. (Нарушение рекомендации — не поломка: 1–2 цикла флапа в хвосте.)

### Уход селектора с группы

```
T=0   селектор переключён с группы AUTO на другой канал
      → InvalidateReachability: AUTO и её члены недостижимы
T=0+  очередные тики проб AUTO ПРОПУСКАЮТСЯ (гейт достижимости)
~30s+ члены AUTO засыпают по КОРОТКОМУ порогу (они недостижимы)
T=30m idle_timeout добивает тикер AUTO насовсем
```

До этой ревизии брошенная группа пробовала (и будила) всех членов ещё 30 минут — до 10 циклов × N handshake'ов впустую.

## 8. Рецепт конфигурации для мобильного клиента

```jsonc
{
  "route": {
    "lx_idle_suspend": "30s",
    "lx_idle_suspend_reachable": "30m"
  },
  "outbounds": [{
    "type": "urltest",
    "tag": "auto",
    "outbounds": ["node-1", "…", "node-N"],
    "interval": "15m",          // реже циклы там, где они всё же идут
    "idle_timeout": "30m",      // = reachable-порогу (см. §7)
    "passive_check": true,      // трафик сам подтверждает живость — пробы молчат
    "mode": "round_robin",      // пробуется пул, а не все N
    "balancer": { "pool": 3, "pool_tolerance": 0 }
  }]
}
```

Правила согласования порогов:

| Ограничение | Кем | Последствие нарушения |
|---|---|---|
| `interval <= idle_timeout` | ядро (апстрим), ошибка старта | — |
| `lx_idle_suspend_reachable >= lx_idle_suspend` | ядро (lx), ошибка старта | — |
| `lx_idle_suspend_reachable >= idle_timeout` групп | рекомендация | 1–2 probe-флапа в хвосте засыпания |
| низкий reachable (напр. `5m`) | допустимо | быстрый сон при паузах; цена — те же 1–2 лишних handshake в первые ~полчаса тишины (пока пробы не заглохли) и +1 RTT на первом соединении после каждой ≥5m паузы |
| `interval` > masque idle (5m) для групп с MASQUE | рекомендация | проба не даёт туннелю MASQUE уснуть |
| `pool_tolerance <= 15000` | ядро (lx), ошибка старта | — |

Замечания:
- `pool_tolerance > 0` на мобильном не рекомендуется: режим обязан мерить **всех** кандидатов каждый цикл (будит всех спящих вне пула).
- `persistent_keepalive` у пиров совместим с suspend: во сне таймер остановлен, шум keepalive не мешает засыпанию (§4.6). Живой узел с keepalive продолжает будить радио — это выбор пользователя.
- Фича целиком выключается отсутствием `lx_idle_suspend` (kill-switch, нулевой оверхед) и существует только в mobile-AAR (`with_lx_idle_suspend`); desktop-бинарь с этим ключом падает на старте с явной ошибкой.

## 9. Гарантии (что НЕ сломается)

- **Живые соединения не рвутся**: узел с established TCP-потоком или объёмным UDP-трафиком не гасится, каким бы «простаивающим» он ни выглядел по дайлам (§4.5–4.6). Обещание `interrupt_exist_connections=false` сохраняется.
- **Screen-off/on и смена сети не ломают учёт**: suspended-устройства переживают pause/wake-цикл спящими.
- **AWG-guard сильнее idle-логики**: guard-опущенный AWG не будится ни дайлом, ни pause, ни пробой.
- **Первый запрос после сна работает всегда**: он идёт через последний известный узел (разбудив его), а немедленный дотест параллельно обновляет выбор. Если узел умер за ночь — один запрос фейлится, дотест тут же чинит пул.
- **Kill-switch**: без `lx_idle_suspend` не запускается даже тик.

## 10. Наблюдаемость и диагностика

- `lx idle: suspend <tag> idle=…` / `lx idle: wake <tag> by=dial` — edge-triggered пары в логе. **Частые пары suspend↔wake по одному тегу = флап** — проверьте согласование порогов (§8) и что probe-гейты активны.
- Спящий узел = 0 recv-воркеров его устройства (goroutine profile) и нулевой rx/tx.
- Узел «не засыпает, хотя должен»: он достижим? (селектор/пул/правило/DNS-detour — §2); через него есть established TCP? объёмный UDP?
- Узел «не просыпается»: смотрите SPEC 007 — это guard-down AWG? (`amneziawg endpoint suspended/will not start` в логе).
- Пробы «ходят ночью»: жив ли трафик через группу (`Touch` держит тикер)? Помните, фоновые push-соединения приложений — тоже трафик.
