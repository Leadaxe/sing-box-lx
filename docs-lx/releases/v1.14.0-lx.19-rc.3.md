A hotfix pre-release on top of `rc.2`: a trojan or VLESS node with TLS
switched off could crash the whole core — and with it the VPN — the moment a
URL test or a real connection reached it. Such a node can hide in a public
subscription for months before firing.

Хотфикс-пререлиз поверх `rc.2`: узел trojan или VLESS с выключенным TLS мог
уронить всё ядро — а с ним и VPN — в момент, когда до него добирался URL-тест
или настоящее соединение. Такая нода может месяцами прятаться в публичной
подписке, прежде чем выстрелит.

<summary><h2>🇬🇧 English</h2></summary>

## 🐛 Fixed

### 💥 A trojan or VLESS node with TLS switched off crashed the whole core

A field crash bundle showed a plain-trojan node from a public subscription
(`"tls": {"enabled": false}` — a legal config that passes `check`) taking the
VPN down the moment a URL test reached it. An upstream regression: with a
`tls` block present the TLS dialer was built unconditionally, while disabled
TLS legitimately produces no TLS config at all — so the dialer wrapped nil
and the process died with a nil-pointer panic on the first successful TCP
connect. That's why the node can sit dormant for months: while DPI drops its
TCP, nothing happens, and it fires the first time the path becomes passable.
Still unfixed in upstream `testing` at the time of this release. The dialer
is now created only when a TLS config was actually built (the same guard
upstream itself uses in vmess); disabled TLS is a plain TCP dial again, with
red/green regression tests in both protocols. (SPEC 045)

## 🐛 Исправлено

### 💥 Узел trojan или VLESS с выключенным TLS ронял всё ядро

Полевой краш-бандл показал plain-trojan-ноду из публичной подписки
(`"tls": {"enabled": false}` — легальный конфиг, проходящий `check`),
которая валила VPN в момент, когда до неё добирался URL-тест.
Upstream-регрессия: при наличии блока `tls` TLS-dialer строился безусловно,
хотя выключенный TLS законно не даёт TLS-конфига вовсе — dialer оборачивал
nil, и процесс умирал с nil-pointer-паникой при первом же успешном
TCP-коннекте. Потому нода и может месяцами лежать тихо: пока DPI режет её
TCP, ничего не происходит, а выстреливает она, как только путь становится
проходимым. В upstream `testing` на момент релиза не исправлено. Теперь
dialer создаётся только когда TLS-конфиг действительно построен (та же
защита, что у самого upstream в vmess); выключенный TLS — снова обычный
TCP, с red/green регрессионными тестами в обоих протоколах. (SPEC 045)
