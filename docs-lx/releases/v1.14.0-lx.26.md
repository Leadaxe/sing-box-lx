Teaches `sing-box lxd` to report on the machine it runs on: CPU per core,
memory, thermal sensors, disks and network interfaces, over the same mTLS port
as the rest of the daemon. Splits the daemon onto its own build tag, so a build
can keep the libbox command RPCs without shipping the daemon — the legacy
Windows 7 binary now does exactly that. Verified on a live OpenWrt router
(MediaTek MT7981) and read remotely from a Windows launcher.

Демон `sing-box lxd` научился рассказывать о машине, на которой работает: CPU
с разрезом по ядрам, память, температурные датчики, диски и сетевые
интерфейсы — через тот же mTLS-порт, что и остальные ручки. Демон вынесен на
собственный build-tag: сборка может сохранить командные RPC libbox, не таща
сам демон, — так теперь собирается legacy-бинарь под Windows 7. Проверено на
живом OpenWrt-роутере (MediaTek MT7981) и прочитано удалённо с
Windows-лаунчера.

## 🆕 What's new

### 📟 `GET /admin/host` — the machine, not the process

`/admin/memory` describes the daemon process. When the router itself starts
struggling that is a different question, and answering it meant an SSH session
with `top`, `free` and `df`.

- **`cpu`** — overall percentage plus **`per_core_percent`**: one pinned core
  among three idle is a diagnosis the average hides, and on a four-core MT7981
  that is the common case. `load_1/5/15` ride along.
- **`memory`** — `used_percent` is computed from `available_bytes`, never
  `free_bytes`: a router keeps most of its RAM in page cache, so a free-based
  figure reads "full" with 120 MB actually free.
- **`thermal`** — every sensor as `zones[]` plus `max_celsius` for a single
  indicator; boards carry several (CPU, radio). No sensors at all reports
  `null`, not an empty array.
- **`disk`** — `mounts[]` with `read_only` and `holds_state_dir`. The state
  directory's filesystem is found **by device id, not path prefix**: on OpenWrt
  `/etc` is a symlink into the overlay, so string matching would miss it.
  `max_used_percent` **skips read-only filesystems** — a squashfs root is
  permanently 100% full, and an always-red indicator is one nobody reads.
- **`fd`** — the daemon's open descriptors and the system's. Exhausting either
  stops new connections with a symptom that looks like nothing at all.

Percentages are deltas between two samples, so the first request after startup
reports `null` with `interval_seconds: 0` — a zero would read as "idle", a
different statement. `interval_seconds` says what window each percentage
describes. Cached for 500 ms, so a UI can poll at 2 Hz and get a fresh snapshot
every time; measured on an MT7981, that costs no measurable CPU. (SPEC 068)

### 🌐 `GET /admin/host/interfaces`

Every interface — `lo` and down ones included — with raw counters **and**
derived rates. A counter survives restarts and gaps; a rate is convenient but
lies across them, so both are reported and the client picks.

### 🏷️ Machine-readable platform fields

`os_family` (`linux`/`darwin`/`windows`), `os_id` and `os_id_like` come from
`/etc/os-release`, so a client never parses the human `os` string. The
distinction is not academic: a RouteRich router calls itself `RouteRich` while
reporting `ID="openwrt"` — matching the display name would fail to recognise
the platform, and with it the presence of `ubus`.

## 🔧 Changed

### 🧩 The daemon has its own build tag: `with_lxd`

One tag used to gate two unrelated things — the libbox command RPCs
(`URLTestOutbound`, `GetRules`, `GetGroups`) and the whole `lxd` package. You
could not build one without the other.

- `with_lx_command` — the RPCs, in `daemon/` and `experimental/libbox/`.
- `with_lxd` — the `lxd` package and the `sing-box lxd` subcommand.

**The legacy Windows 7 build now ships without the daemon**: the Windows
service is not implemented there and neither is log rotation, so the subcommand
would exist without the parts that make it a daemon. The RPCs stay — dropping
that tag instead would have quietly broken per-node latency tests and the rule
screen in LxBox, to save 0.3 MB out of 46. The Android AAR is unaffected: it
builds `experimental/libbox`, which never imported `lxd`. (SPEC 067)

## 🐛 Fixed

### 🔨 `linux/armv7` failed to build

`syscall.Utsname` fields are `[]int8` on arm64 and amd64 but `[]uint8` on
32-bit arm, so a helper written for one signature compiled on some Linux
targets and not others. The helper is now generic; every architecture in the
release matrix is built and checked.

## 🆕 Что нового

### 📟 `GET /admin/host` — машина, а не процесс

`/admin/memory` описывает процесс демона. Когда начинает тормозить сам роутер,
это другой вопрос, и ответ на него требовал сессии SSH с `top`, `free` и `df`.

- **`cpu`** — общий процент и **`per_core_percent`**: одно ядро в полке при
  трёх свободных среднее прячет, а на четырёхъядерном MT7981 это типовой
  случай. Рядом `load_1/5/15`.
- **`memory`** — `used_percent` считается от `available_bytes`, а не от
  `free_bytes`: роутер держит почти всю память в page cache, и процент от free
  показывает «занято» при реально свободных 120 МБ.
- **`thermal`** — все датчики массивом `zones[]` плюс `max_celsius` для одного
  индикатора; на плате их обычно несколько (CPU, радиочасть). Датчиков нет
  вовсе → `null`, а не пустой массив.
- **`disk`** — `mounts[]` с флагами `read_only` и `holds_state_dir`. Раздел со
  state-dir ищется **по device id, а не по префиксу пути**: на OpenWrt `/etc` —
  симлинк в оверлей, и сравнение строк дало бы промах. `max_used_percent`
  **игнорирует read-only ФС** — корень squashfs вечно занят на 100%, а всегда
  красный индикатор перестают замечать.
- **`fd`** — открытые дескрипторы демона и системы. Упереться в любой из них
  значит «новые соединения не открываются» без единой понятной строки в логе.

Проценты — дельты между двумя замерами, поэтому первый запрос после старта
отдаёт `null` и `interval_seconds: 0`: ноль читался бы как «простаивает», а это
другое утверждение. `interval_seconds` говорит, за какое окно посчитан
процент. Кеш 500 мс — UI может опрашивать на 2 Гц и каждый раз получать свежий
снимок; замерено на MT7981: на загрузку CPU это не влияет. (SPEC 068)

### 🌐 `GET /admin/host/interfaces`

Все интерфейсы, включая `lo` и лежачие, с сырыми счётчиками **и** посчитанными
скоростями. Счётчик переживает рестарты и разрывы, скорость удобна, но на
разрывах врёт — поэтому отдаются оба, а клиент выбирает.

### 🏷️ Машиночитаемые поля платформы

`os_family` (`linux`/`darwin`/`windows`), `os_id` и `os_id_like` берутся из
`/etc/os-release`, так что человеческую строку `os` клиенту парсить не нужно.
Разница не теоретическая: роутер RouteRich называет себя `RouteRich`, но
сообщает `ID="openwrt"` — сопоставление по отображаемому имени платформу бы не
опознало, а вместе с ней и наличие `ubus`.

## 🔧 Изменено

### 🧩 У демона собственный build-tag: `with_lxd`

Один тег гейтил две несвязанные вещи — командные RPC libbox
(`URLTestOutbound`, `GetRules`, `GetGroups`) и весь пакет `lxd`. Собрать одно
без другого было нельзя.

- `with_lx_command` — RPC, в `daemon/` и `experimental/libbox/`.
- `with_lxd` — пакет `lxd` и подкоманда `sing-box lxd`.

**Legacy-сборка под Windows 7 теперь идёт без демона**: служба Windows там не
реализована и ротация лога тоже, так что подкоманда существовала бы без того,
что делает её демоном. RPC при этом остаются — снять вместо этого второй тег
значило бы молча сломать в LxBox тест задержки по узлам и экран правил ради
0.3 МБ из 46. Android AAR не затронут: он собирает `experimental/libbox`,
который `lxd` никогда не импортировал. (SPEC 067)

## 🐛 Исправлено

### 🔨 Не собиралась цель `linux/armv7`

Поля `syscall.Utsname` — это `[]int8` на arm64 и amd64, но `[]uint8` на
32-битном arm, поэтому хелпер, написанный под одну сигнатуру, компилировался
на части Linux-целей и падал на остальных. Хелпер сделан дженериком; собраны и
проверены все архитектуры релизной матрицы.
