Turns `sing-box lxd` from a bare control channel into a manageable daemon: it
now serves its own log, memory, core traffic and pprof profiles over the same
mTLS port, delivers the config's `.srs`/geo files by REST, and answers who the
devices on the LAN are — a connection from `192.168.20.238` is labelled with the
device name, SSID and interface instead of a bare address. Fixes
`interrupt_exist_connections`, which never actually dropped connections, and
`urltest` groups reporting their mode to clients. **Breaking:** the `masque`
config schema was reworked — old field names still work but are deprecated and
go away in `v1.14.0-lx.30`.

Демон `sing-box lxd` из голого управляющего канала стал управляемым: он отдаёт

## 🆕 What's new

### 🏷️ The daemon answers who the devices on the LAN are

`GET /admin/clients-info` returns a directory keyed by IP: `name`, `mac`,
`ssid`, `iface`, `port` and `source` for every client the host knows about. A
connection inspector can label traffic with a device name instead of an
address.

- It is a **directory, not a per-connection field**: names change on a scale of
  hours, so a client fetches the map once a minute and joins it against source
  addresses itself. The connection stream is untouched.
- Five providers fill it, later ones refining earlier ones: DHCP leases
  (`name`, `mac`), `/proc/net/arp` (`mac`, interface — also covers clients with
  a static IP, which no lease knows), `bridge fdb show` (the physical port a
  wired client is plugged into), `ubus`/hostapd on OpenWrt (`ssid` and the
  precise AP interface), and your own labels.
- `source` is part of every entry: when a device loses its name, the question is
  always which provider went quiet.
- Labels are set with `PUT`/`DELETE /admin/clients-info/labels/{key}`, keyed by
  IP or MAC, and survive restarts. A MAC label follows the device across
  addresses — but phones randomize their MAC per network, so an IP label plus a
  DHCP reservation is the stabler pairing for those.
- An empty field is a state, not an error: a wired client has no `ssid`, and off
  Linux the platform providers report nothing while leases and labels still
  answer. The map is cached for 60 s; a label write takes effect immediately.
- No core edits: `route/`, `adapter/` and the proto are untouched. Verified on a
  live OpenWrt router. (SPEC 066)

### 🔍 The daemon reports on itself — log, memory, traffic, profiles

When the daemon itself misbehaved there was nothing to look at from outside: the
gRPC `SubscribeLog` stream carries the **core's** log, while the daemon's own
lines go to `lxd.log` on a remote host.

- `GET /admin/logs?tail=N` serves the tail of that file.
- `GET /admin/memory` reports heap/stack/sys, goroutines, GC and **two** RSS
  numbers — `rss_current_bytes` and `rss_peak_bytes`. The peak never decreases
  and hides leaks, so it is reported apart from the current size, and both carry
  their unit in the name.
- `GET /admin/stats` gives the **core's** uptime, `uplink_total`,
  `downlink_total` and live connections. With no core up every field is `null`
  and the status stays 200 — that is precisely the state a client polls it for.
- `GET /admin/pprof/{name}` serves `heap`, `allocs`, `goroutine`,
  `threadcreate`, `block` and `mutex` instantly from what the runtime already
  collects. `profile` and `trace` RECORD for N seconds (default 30, max 120); a
  second concurrent request gets 409. `block`/`mutex` cost nothing until enabled
  with `POST /admin/pprof/block?rate=N` or `.../mutex?fraction=N`.
- **No separate debug port by design.** These ride the normal control port
  behind the normal client certificate. (The core's own
  `experimental.debug.listen` opens a port with no authentication at all.)
  (SPEC 065)

### 📦 Config resources delivered over the admin plane

`GET /admin/resources` plus `PUT`/`GET`/`DELETE /admin/resources/{name}` deliver
the files a config REFERS to — `.srs` rule-sets, geo databases — addressed by
name with a sha256 for diffing, so a client uploads only what changed.

An integrity guard: a `PUT` or `DELETE` for a name referenced by the active or
last-good config returns 409. `GET /admin/info` reports the absolute resources
directory, so a client copies it verbatim into a config's `path:` instead of
hardcoding it. (SPEC 063)

### 🔎 Node probe and urltest group mode

- `GetURLViaOutbound` performs an HTTP probe through a chosen outbound — checking
  a node without routing the whole client through it. (SPEC 058)
- `Group.mode` exposes a urltest group's mode to clients. The meaning of
  `selected` was also documented more precisely; behaviour did not change.

### 🔗 XMUX — HTTP connection reuse in XHTTP

XHTTP can now reuse HTTP connections across requests, for compatibility with
Xray servers that expect it and to save handshakes. (SPEC 059)

## 🔧 Changed

### ⚠️ `masque` config schema reworked — old names deprecated

The schema was reorganised across this release line: the HTTP-version selector
is now `vhttp`, and several fields were renamed.

- **No action needed right now: existing configs keep working.** The old names
  are accepted and warn.
- **Support for the old names is removed in `v1.14.0-lx.30`** — migrate before
  that.
- If you adopted the intermediate `transport` field from an earlier pre-release,
  it is now `vhttp`; that name lived only within this rc line.
- Added `tls.disable_sni` — a ClientHello with no SNI at all (an empty `sni`
  does not do this).
- Unsupported fields now warn instead of being silently ignored.
- The default SNI for `masque` changed.

### 🧭 The daemon listens on several addresses at once

`listen` accepts an object with a list of addresses sharing one port, not just a
single `host:port` string. A daemon reachable both from a LAN interface and from
loopback cannot be expressed as one bind, and `0.0.0.0` would also expose every
other interface the host happens to have. The string form is unchanged.
(SPEC 055)

### 🧵 TLS fragment auto-enables on a detour chain

Chains going through a detour no longer silently fail to come up: **38/38** on
end-to-end 5 MB transfers with no interruption. (SPEC 060)

## 🐛 Fixed

### 🔌 `interrupt_exist_connections` did not drop connections

The option was accepted and did nothing. It now works — including for **nested
groups**, where a selector sits inside another group and the switch has to
propagate down.

### 🕳️ XHTTP packet-up/stream-up hung on dial behind a CDN

A node behind a CDN could hang at dial time instead of failing.

### 🔥 The daemon burned a CPU core with the launcher open

A launcher sending a subscription interval in the wrong unit spun the ticker at
microsecond resolution. The interval is now clamped.

### 💥 Two startup crashes

- A WireGuard endpoint whose detour chain contains a domain-addressed node
  crashed on start.
- The first `GetRules` call killed the core under the `api` service.

## 🆕 Что нового

### 🏷️ Демон отвечает, что за устройства в локальной сети

`GET /admin/clients-info` отдаёт справочник по IP: `name`, `mac`, `ssid`,
`iface`, `port` и `source` по каждому клиенту, о котором знает хост. Инспектор
соединений подписывает трафик именем устройства вместо адреса.

- Это **справочник, а не поле в соединении**: имена меняются раз в часы, поэтому
  клиент тянет карту раз в минуту и сшивает её с адресами источников сам. Поток
  соединений не трогается.
- Наполняют пять провайдеров, каждый следующий уточняет предыдущего: DHCP-лизы
  (`name`, `mac`), `/proc/net/arp` (`mac` и интерфейс — закрывает и клиентов со
  статическим IP, которых в лизах нет), `bridge fdb show` (физический порт, в
  который воткнут проводной клиент), `ubus`/hostapd на OpenWrt (`ssid` и точный
  AP-интерфейс) и ваши собственные метки.
- `source` есть в каждой записи: когда устройство теряет имя, вопрос всегда один
  — какой источник замолчал.
- Метки ставятся через `PUT`/`DELETE /admin/clients-info/labels/{ключ}`, ключ —
  IP или MAC, и переживают рестарт. Метка по MAC переезжает с устройством на
  другой адрес, но телефоны рандомизируют MAC на каждую сеть — для них надёжнее
  метка по IP при фиксированной DHCP-резервации.
- Пустое поле — состояние, а не ошибка: у проводного клиента нет `ssid`, а вне
  Linux платформенные провайдеры молчат, но лизы и метки продолжают отвечать.
  Карта кешируется на 60 с, запись метки видна сразу.
- Ядро не тронуто: ни `route/`, ни `adapter/`, ни proto. Проверено на живом
  OpenWrt-роутере. (SPEC 066)

### 🔍 Демон рассказывает о себе — лог, память, трафик, профили

Когда плохо становилось самому демону, смотреть на него снаружи было нечем:
gRPC-поток `SubscribeLog` несёт лог **ядра**, а строки самого демона уходят в
`lxd.log` на удалённом хосте.

- `GET /admin/logs?tail=N` отдаёт хвост этого файла.
- `GET /admin/memory` — heap/stack/sys, горутины, GC и **два** числа RSS:
  `rss_current_bytes` и `rss_peak_bytes`. Пик не убывает и прячет утечки,
  поэтому отдаётся отдельно от текущего; единица измерения — в имени поля.
- `GET /admin/stats` — uptime **ядра**, `uplink_total`, `downlink_total` и живые
  соединения. Без поднятого ядра всё `null`, статус остаётся 200 — именно ради
  этого состояния ручку и опрашивают.
- `GET /admin/pprof/{имя}` отдаёт `heap`, `allocs`, `goroutine`, `threadcreate`,
  `block` и `mutex` мгновенно из того, что рантайм копит и так. `profile` и
  `trace` **пишут** N секунд (дефолт 30, максимум 120), параллельный запрос
  получает 409. `block`/`mutex` не стоят ничего, пока не включены через
  `POST /admin/pprof/block?rate=N` или `.../mutex?fraction=N`.
- **Отдельного debug-порта нет по построению.** Всё идёт через обычный
  управляющий порт за обычным клиентским сертификатом. (Собственный
  `experimental.debug.listen` ядра поднимает порт вообще без аутентификации.)
  (SPEC 065)

### 📦 Файловые ресурсы конфига доставляются через admin-плоскость

`GET /admin/resources` и `PUT`/`GET`/`DELETE /admin/resources/{имя}` доставляют
файлы, на которые **ссылается** конфиг — `.srs`-рулсеты, geo-базы. Адресация по
имени с sha256 для дифа, так что клиент заливает только изменившееся.

Гуард целостности: `PUT` или `DELETE` для имени, на которое ссылается активный
или last-good конфиг, возвращает 409. `GET /admin/info` сообщает абсолютный путь
к каталогу ресурсов — клиент копирует его в `path:` конфига, а не хардкодит.
(SPEC 063)

### 🔎 Пробник узла и режим urltest-группы

- `GetURLViaOutbound` делает HTTP-пробу через выбранный outbound — проверить
  узел, не заворачивая в него весь клиент. (SPEC 058)
- `Group.mode` показывает клиенту режим urltest-группы. Заодно точнее описана
  семантика `selected`; поведение не менялось.

### 🔗 XMUX — переиспользование HTTP-соединений в XHTTP

XHTTP умеет переиспользовать HTTP-соединения между запросами: совместимость с
Xray-серверами, которые этого ждут, и экономия хендшейков. (SPEC 059)

## 🔧 Изменено

### ⚠️ Схема конфига `masque` переработана — старые имена устарели

Схема была реорганизована по ходу этой линии релизов: селектор HTTP-версии
теперь `vhttp`, несколько полей переименованы.

- **Действий прямо сейчас не требуется: существующие конфиги работают.** Старые
  имена принимаются с предупреждением.
- **Поддержка старых имён снимается в `v1.14.0-lx.30`** — до этого момента есть
  время мигрировать.
- Если вы успели перейти на промежуточное поле `transport` из раннего
  пререлиза — теперь оно называется `vhttp`; то имя прожило только внутри этой
  rc-линии.
- Добавлено `tls.disable_sni` — ClientHello вообще без SNI (пустой `sni` этого
  не даёт).
- На неподдерживаемых полях теперь предупреждение вместо молчания.
- Изменился дефолтный SNI у `masque`.

### 🧭 Демон слушает несколько адресов сразу

`listen` принимает объект со списком адресов, разделяющих один порт, а не только
строку `host:port`. Демон, доступный и с LAN-интерфейса, и с loopback, одним
биндом не выражается, а `0.0.0.0` открыл бы заодно все остальные интерфейсы
хоста. Строковая форма не изменилась. (SPEC 055)

### 🧵 TLS-фрагмент включается на detour-цепи автоматически

Цепочки «через detour» больше не поднимаются молча вхолостую: **38/38** по
сквозным 5 МБ без единого обрыва. (SPEC 060)

## 🐛 Исправлено

### 🔌 `interrupt_exist_connections` не разрывал соединения

Опция принималась и не делала ничего. Теперь работает — в том числе во
**вложенных группах**, где селектор лежит внутри другой группы и переключение
должно проходить вниз по вложенности.

### 🕳️ XHTTP packet-up/stream-up залипал на дайле за CDN

Узел за CDN мог зависнуть на этапе дайла вместо того, чтобы вернуть ошибку.

### 🔥 Демон жёг ядро CPU при открытом лаунчере

Лаунчер слал интервал подписки в неверных единицах, и тикер крутился с
микросекундным разрешением. Интервал теперь ограничивается снизу.

### 💥 Два краша на старте

- WireGuard-эндпоинт с доменным узлом в detour-цепи падал на старте.
- Первый же вызов `GetRules` убивал ядро под сервисом `api`.
