Two breaking config changes. A TLS node behind a `detour` no longer splits its ClientHello by default, and the config still loads: to keep the split through relays, add `"lx": {"sniff_guard": {"tls": {"method": "record_fragment"}}}`. `lx.quic_sniff_decoy` is removed and any value fails to load; its replacement is `lx.sniff_guard.quic`. The new `lx.sniff_guard` block protects TLS and QUIC handshakes from SNI-based redirection on a relay or a router, by default only for nodes whose SNI differs from `server`, and learns per path where protection is needed. Also fixed: XHTTP nodes inside `chain`, Tailscale stuck on DERP, a ~5 s stall of the first connection after wake-up on WireGuard, and DNS-group server health after cancelled queries.

Два несовместимых изменения конфига. TLS-узел через `detour` больше не режет ClientHello по умолчанию, а конфиг при этом загружается без ошибки: чтобы сохранить разрез через релеи, добавьте `"lx": {"sniff_guard": {"tls": {"method": "record_fragment"}}}`. `lx.quic_sniff_decoy` удалён, любое значение — ошибка загрузки; замена — `lx.sniff_guard.quic`. Также исправлены: XHTTP-узлы внутри `chain`, Tailscale, застревавший на DERP, задержка ~5 с первого соединения после пробуждения на WireGuard и здоровье серверов DNS-группы после отменённых запросов.

## 🆕 What's new

### 🛡️ `lx.sniff_guard`: nodes with a masquerade SNI work through relays and routers that redirect by SNI

- Problem: an Xray inbound with `sniffing.destOverride` and no `routeOnly` reads the SNI from the TLS ClientHello or QUIC Initial and sends the connection to that name instead of the dialled address. Such a hop can be the relay under `detour` or a router with a VPN or transparent proxy in the local network. With a masquerade SNI (REALITY, WARP, hysteria2/tuic with a fake SNI, AmneziaWG QUIC masquerade) the connection lands on a foreign host and the node looks dead.
- The block makes the first handshake packet unreadable for the sniffer; the server receives a valid handshake.
- Without the block, or without `method` in a section, the core behaves like upstream.
- Methods:
  - `tls.method`: `record_fragment` (ClientHello split into several TLS records, no delay), `fragment` (TCP segments, pause `fragment_fallback_delay`), `delay` (one record sent in two pieces with a pause, default `300ms`).
  - `quic.method`: `decoy_first_byte` (a one-byte `0x00` datagram before the first Initial), `delay` (the second Initial is held for the pause).
- Which nodes: `nodes.sni_mismatch` — default `true`, only nodes whose SNI differs from `server`; `false` — every node that supports protection. `nodes.outbound_type` — optional type filter, shared by `tls` and `quic`.
- Starting state per path: map `detour_type` with values `never` / `clean` / `suspect` and a `"*"` key; default `direct`, `ssh`, `socks` — `clean`, everything else — `suspect`. A section can override the map with its own. The path is `direct` or the nearest non-group relay; a group resolves to the member it has actually selected.
- Learning: a path label moves only on a pair of outcomes on one node — failed without protection and passed with it → `suspect`, the reverse → `clean`. Only nodes with SNI ≠ `server` move the label; a node with its own name (protected only with `sni_mismatch: false`) gets a personal opt-out instead. Probe back to the other state and a pending pair — once per 10 min.
- A network change resets `direct` and unencrypted carriers (`socks`, `http` without TLS); labels of encrypted relays survive it, and with `persist: true` also a restart (stored in `experimental.cache_file`, the relay fingerprint is checked on load).
- `override: true` — the block wins over per-node `fragment` / `record_fragment`; by default the node's explicit value wins.
- Covered: TLS over TCP with std/uTLS/REALITY, masque h2/h3, trusttunnel h2/QUIC, XHTTP h2/h3, hysteria2, tuic, AmneziaWG (`ip: quic` or `i1`).
- Not covered: naive, `engine: apple|windows`, full gRPC transport, shadowtls v3 without uTLS; on the direct path also shadowtls v2/v3 and nodes with `tcp_fast_open`.
- Tested with unit tests and loopback stands against the Xray sniffer (trojan+TLS, hysteria2, tuic, AmneziaWG through a sniffing relay and through a middlebox on the direct path); no field runs yet. (FEATURE 019)

## 🔧 Changed

### ⚠️ TLS nodes behind `detour` no longer split ClientHello by default — the config still loads

- Before: a TLS-over-TCP node behind a `detour` split its ClientHello into records on its own.
- Now: without `lx.sniff_guard` the core behaves like upstream; the split happens only with per-node `fragment` / `record_fragment`. TLS nodes behind relays that redirect by SNI stop connecting, with no load error.
- Minimal replacement: `"lx": {"sniff_guard": {"tls": {"method": "record_fragment"}}}` — relays other than `ssh`/`socks` start with the split, the direct path without it. All relays at once: add `"detour_type": {"ssh": "suspect", "socks": "suspect"}`.
- The block splits only nodes with SNI ≠ `server`; the old default also split nodes with their own name — for them add `"nodes": {"sni_mismatch": false}`.
- A `detour` into a group whose selected member is `direct` is now the direct path and is not split by default.
- Config generators (LxBox, singbox-launcher) add the block together with the core bump. (FEATURE 019)

### ⚠️ `lx.quic_sniff_decoy` removed — load error

- Any value of the key, including `null`, fails to load.
- Replacement: `"lx": {"sniff_guard": {"quic": {"method": "decoy_first_byte"}}}`.
- Mapping: `send: always` ≈ starting state `suspect`, `send: retry` ≈ `clean`; `mode` / `detour_type` → the `detour_type` map; `outbound_type` → `nodes.outbound_type`. (FEATURE 019)

### ⚡ AmneziaWG 3.x: less per-packet work with `header_protection_key` and S4

- Before: a new heap-allocated ChaCha20 cipher (384 B) per packet in both directions; S4 padding filled from `crypto/rand`, a syscall per packet on kernels without vDSO `getrandom` (Android before 6.11).
- Now: the cipher lives on the caller's stack; each encryption worker fills padding from its own ChaCha8 seeded from `crypto/rand`. The header-protection nonce stays unpredictable and non-repeating.
- Microbenchmark on Apple M: header protection 162 ns / 1 alloc → 147 ns / 0; 32-byte padding 176 ns → 15 ns.
- Packet format unchanged; compatibility checked against amneziawg-go 0.0.20250522.

## 🐛 Fixed

### 🔗 XHTTP node inside `chain` got HTTP 400 from Xray

- Before: the default `xhttp.padding` strip set `x_padding_bytes: "1"` and dropped `x_padding_obfs_mode`. Xray checks padding length against its range (100–1000 by default) and reads it from the configured placement, so a node at position ≥ 1 failed against a server with default padding or obfs mode.
- Now: the length is pinned to the lower bound of the node's range (`100` if no range is set); placement and obfs mode are kept. A single-number or unparsable value is left as is. (FEATURE 015)

### 🏁 Data race on the urltest selection between dial and reselect

- The penalty path read the selected outbound without a lock on every dial while reselection wrote it under another lock; the field is an interface, so a read could be torn.
- Now all reads and writes go through one lock; regression test under `-race`. (SPEC 139)

### 🌐 Tailscale fell back to DERP until restart

- Before: the WireGuard self-heal (socket rebuild after unanswered handshakes) was on for every device in the `wireguard-go` fork, including embedded Tailscale. Its magicsock closes sockets and does not reopen them, so one dial to an offline tailnet node stopped direct UDP after ~15 s: all peers, the exit node included, went through DERP.
- Now the self-heal is off unless the consumer enables it; WG/AWG endpoints enable it as before, tunnel behaviour unchanged. (SPEC 041)

### ⏱️ First connection after wake-up waited ~5 s on WireGuard with self-heal

- Before: the first initiation after wake-up went into the dead socket; after the socket rebuild the retry was swallowed by the `rekeyMinTimeout` limit, and the tunnel waited for the retransmit timer.
- Now the rebuild lifts the limit for an initiation sent before it, and the early trigger sends one initiation instead of two in a row (the server dropped the second as a replay).
- Fork unit test: ~20 ms instead of 5.02 s; not measured on a device. (SPEC 041)

### 🧭 DNS group: a cancelled query marked a healthy server as failed

- Before: when the caller dropped a query (connection closed during resolution), a single exchange or a survival-mode attempt recorded an error on the server for `error_ttl`; a slow but working server lost its current status and the group could enter survival mode.
- Now cancellation by the caller records nothing and does not start the fan-out; an expired query budget still counts as a server failure. (FEATURE 013)

## 🆕 Что нового

### 🛡️ `lx.sniff_guard`: узлы с маскировочным SNI работают через релеи и роутеры, перенаправляющие по SNI

- Проблема: Xray-инбаунд с `sniffing.destOverride` без `routeOnly` читает SNI из TLS ClientHello или QUIC Initial и отправляет соединение на это имя вместо набранного адреса. Такой узел бывает релеем под `detour` или роутером с VPN или прозрачным прокси в локальной сети. При маскировочном SNI (REALITY, WARP, hysteria2/tuic с подставным SNI, QUIC-маскировка AmneziaWG) соединение уходит на чужой хост, и узел выглядит мёртвым.
- Блок делает первый пакет рукопожатия нечитаемым для сниффера; сервер получает корректное рукопожатие.
- Без блока, как и без `method` в секции, ядро ведёт себя как апстрим.
- Методы:
  - `tls.method`: `record_fragment` (ClientHello разрезан на несколько TLS-записей, без задержки), `fragment` (TCP-сегменты, пауза `fragment_fallback_delay`), `delay` (одна запись двумя кусками с паузой, по умолчанию `300ms`).
  - `quic.method`: `decoy_first_byte` (датаграмма из одного байта `0x00` перед первым Initial), `delay` (второй Initial держится паузу).
- Кого защищать: `nodes.sni_mismatch` — по умолчанию `true`, только узлы с SNI ≠ `server`; `false` — все узлы, которые умеют защиту. `nodes.outbound_type` — необязательный фильтр по типам, общий для `tls` и `quic`.
- Стартовое состояние пути: карта `detour_type` со значениями `never` / `clean` / `suspect` и ключом `"*"`; по умолчанию `direct`, `ssh`, `socks` — `clean`, остальное — `suspect`. Секция может перекрыть карту своей. Путь — `direct` или ближайший не-групповой релей; группа разворачивается в фактически выбранного участника.
- Обучение: метка пути двигается только парой исходов на одном узле — упал без защиты и прошёл с ней → `suspect`, обратная пара → `clean`. Метку двигают только узлы с SNI ≠ `server`; узел с собственным именем (под защитой он только при `sni_mismatch: false`) вместо этого получает личный отказ от защиты. Проба в обратное состояние и ожидающая пара — раз в 10 мин.
- Смена сети сбрасывает `direct` и незашифрованные носители (`socks`, `http` без TLS); метки зашифрованных релеев её переживают, с `persist: true` — и перезапуск (хранятся в `experimental.cache_file`, отпечаток релея сверяется при загрузке).
- `override: true` — блок сильнее узловых `fragment` / `record_fragment`; по умолчанию сильнее явное значение узла.
- Защищаются: TLS поверх TCP с std/uTLS/REALITY, masque h2/h3, trusttunnel h2/QUIC, XHTTP h2/h3, hysteria2, tuic, AmneziaWG (`ip: quic` или `i1`).
- Не защищаются: naive, `engine: apple|windows`, полный gRPC-транспорт, shadowtls v3 без uTLS; на прямом пути также shadowtls v2/v3 и узлы с `tcp_fast_open`.
- Проверено юнит-тестами и loopback-стендами против сниффера Xray (trojan+TLS, hysteria2, tuic, AmneziaWG через сниффящий релей и через middlebox на прямом пути); полевых прогонов пока нет. (FEATURE 019)

## 🔧 Изменено

### ⚠️ TLS-узлы через `detour` больше не режут ClientHello по умолчанию — конфиг загружается без ошибки

- Было: TLS-over-TCP узел через `detour` сам резал ClientHello на записи.
- Стало: без `lx.sniff_guard` ядро ведёт себя как апстрим, разрез — только по узловым `fragment` / `record_fragment`. TLS-узлы через релеи, перенаправляющие по SNI, перестают подниматься, ошибки загрузки нет.
- Минимальная замена: `"lx": {"sniff_guard": {"tls": {"method": "record_fragment"}}}` — релеи, кроме `ssh`/`socks`, стартуют с разрезом, прямой путь без него. Все релеи сразу — плюс `"detour_type": {"ssh": "suspect", "socks": "suspect"}`.
- Блок режет только узлы с SNI ≠ `server`; прежний дефолт резал и узлы с собственным именем — для них `"nodes": {"sni_mismatch": false}`.
- `detour` в группу, где выбран `direct`, теперь прямой путь и по умолчанию не режется.
- Генераторы конфига (LxBox, singbox-launcher) добавляют блок вместе с бампом ядра. (FEATURE 019)

### ⚠️ `lx.quic_sniff_decoy` удалён — ошибка загрузки

- Любое значение ключа, включая `null`, — ошибка загрузки.
- Замена: `"lx": {"sniff_guard": {"quic": {"method": "decoy_first_byte"}}}`.
- Соответствие: `send: always` ≈ стартовое `suspect`, `send: retry` ≈ `clean`; `mode` / `detour_type` → карта `detour_type`; `outbound_type` → `nodes.outbound_type`. (FEATURE 019)

### ⚡ AmneziaWG 3.x: меньше работы на пакет с `header_protection_key` и S4

- Было: новый шифр ChaCha20 в куче (384 Б) на каждый пакет в обе стороны; паддинг S4 из `crypto/rand` — системный вызов на пакет на ядрах без vDSO `getrandom` (Android до 6.11).
- Стало: шифр на стеке вызывающего; каждый воркер шифрования берёт паддинг из своего ChaCha8, засеянного из `crypto/rand`. Nonce защиты заголовка остаётся непредсказуемым и неповторяющимся.
- Микробенчмарк на Apple M: защита заголовка 162 нс / 1 аллокация → 147 нс / 0; паддинг 32 байта 176 нс → 15 нс.
- Формат пакетов не меняется; совместимость проверена против amneziawg-go 0.0.20250522.

## 🐛 Исправлено

### 🔗 XHTTP-узел внутри `chain` получал HTTP 400 от Xray

- Было: strip `xhttp.padding` (в наборе по умолчанию) ставил `x_padding_bytes: "1"` и удалял `x_padding_obfs_mode`. Xray проверяет длину паддинга по своему диапазону (100–1000 без настройки) и читает его из настроенного размещения, поэтому узел на позиции ≥ 1 не поднимался против сервера с дефолтным паддингом или obfs-режимом.
- Стало: длина фиксируется на нижней границе диапазона узла (`100`, если диапазон не задан); размещение и obfs-режим сохраняются. Значение из одного числа и неразбираемое значение остаются как есть. (FEATURE 015)

### 🏁 Гонка на выборе узла urltest между дозвоном и переизбором

- Штрафной путь читал выбранный outbound без блокировки на каждом дозвоне, а переизбор писал его под другой блокировкой; поле — интерфейс, чтение могло быть рваным.
- Стало: все чтения и записи под одной блокировкой; регрессионный тест под `-race`. (SPEC 139)

### 🌐 Tailscale уходил на DERP до перезапуска

- Было: самолечение WireGuard (пересоздание сокета по неотвеченным рукопожатиям) в форке `wireguard-go` было включено для любого устройства, включая встроенный Tailscale. Его magicsock закрывает сокеты и не переоткрывает их, поэтому одно обращение к выключенному узлу tailnet через ~15 с отключало прямой UDP: все узлы, включая exit node, шли через DERP.
- Стало: самолечение выключено, пока его не включит потребитель; WG/AWG-endpoint включает его как раньше, поведение туннелей не меняется. (SPEC 041)

### ⏱️ Первое соединение после пробуждения ждало ~5 с на WireGuard с самолечением

- Было: первая инициация после пробуждения уходила в мёртвый сокет; после пересоздания сокета повтор глотал лимит `rekeyMinTimeout`, и туннель ждал таймер ретрансмита.
- Стало: пересоздание снимает лимит с инициации, отправленной до него, а досрочный триггер шлёт одну инициацию вместо двух подряд (вторую сервер отбрасывал как повтор).
- Юнит-тест форка: ~20 мс вместо 5,02 с; на устройстве не замерялось. (SPEC 041)

### 🧭 DNS-группа: отменённый запрос помечал здоровый сервер сбойным

- Было: если вызывающий бросал запрос (соединение закрылось во время резолва), одиночный обмен или попытка в режиме выживания записывали серверу ошибку на `error_ttl`; медленный, но рабочий сервер терял статус текущего, группа могла уйти в режим выживания.
- Стало: отмена вызывающим ничего не записывает и не запускает веер; истёкший бюджет запроса по-прежнему считается отказом сервера. (FEATURE 013)
