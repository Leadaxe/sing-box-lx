## 🆕 What's new

### 🔍 Sniffers: `wireguard`, `openvpn`, `ike`, `tailscale`, `sip`

Upstream recognises web and torrent protocols; the fork adds what a home router sees from other LAN devices — VPN tunnels and voice calls. Each name works in the `sniffer` list of a `sniff` rule action and in the `protocol` matcher of a routing rule:

- `wireguard` (UDP) — handshake initiation / response / cookie by exact size (148 / 92 / 64 B); transport data `>= 32 B` with `(len-32) % 16 == 0`. Reserved bytes are not checked, so Cloudflare WARP matches too.
- `openvpn` (UDP, TCP) — `P_CONTROL_HARD_RESET_CLIENT_V2/V3`: plain, tls-auth, tls-crypt / tls-crypt-v2; on TCP the same frame behind a 2-byte length.
- `ike` (UDP) — ISAKMP header with IKEv2 `IKE_SA_INIT` (Initiator flag) or IKEv1 Main / Aggressive mode; the non-ESP marker on UDP 4500 is skipped.
- `tailscale` (UDP) — disco ping by the `TS💬` magic; the tunnel itself shows up as `wireguard`.
- `sip` (UDP, TCP) — request-line `METHOD sip:… SIP/2.0`; the host of the Request-URI becomes `domain`, so domain rules apply to calls the same way they apply to TLS.
- Default order: packet sniffers run after `stun` and **before** uTP — upstream's uTP check accepts any 20+ byte packet starting with `01 00`, which is how a WireGuard initiation starts, so plain WireGuard used to be labelled `bittorrent` and routed by the torrent rule. Stream sniffers `sip`, `openvpn` run after `rdp`.
- Only the first datagram of a flow is inspected: AmneziaWG with junk (`jc > 0`) stays unnamed, AmneziaWG with a decoy (`ip=quic` / `dns` / `stun` / `sip`) is labelled as the decoy, non-default `h1`–`h4` / `s1`–`s4` are not recognised by design. Route obfuscated tunnels by `ip_cidr`.
- No upstream sniffer file is modified. Examples and diagnostics in `docs-lx/lx-sniff.md`. (SPEC 078 / 079)

## 🐛 Fixed

### 🛡️ AmneziaWG: data packets of handshake size are no longer lost on receive with wide `h1`–`h3`

The reference receiver tries message kinds in the order init → response → cookie → transport, accepting a handshake candidate by size and by the type word alone. The type word of a data packet is ciphertext, so with a wide range (an AWG2 export like `h1 = 43613244-384550127`) it lands in `H1` for ≈8 % of packets:

- AWG2: every data datagram of exactly `s1 + 148` / `s2 + 92` / `s3 + 64` bytes (possible when `s1=28` or `s1=44` with `s4=0`) was claimed as a handshake, failed MAC1 and was dropped.
- AWG 3.1 with `random_trailers`: the size check is `>`, so every data packet larger than `s1 + 148` was at risk; AWG3 exports keep `h1`–`h4 = 1..4`, where the trap does not fire.
- Now a datagram whose type word is in `H4` and whose receiver index belongs to one of our live keypairs is classified as transport first; on a miss the reference order runs unchanged, so everything accepted before is still accepted. The reverse risk (a real handshake claimed as transport) is ≈2⁻⁶⁴ with a single `h4` and fails AEAD; the handshake repeats after `rekey_timeout`.
- Downlink only: uplink is classified by the server's receiver. Wire format unchanged; verified red/green with a deterministic size collision (`s1=44`, `s4=0`, `h1=5-4294967295`). (SPEC 081)

## 🆕 Что нового

### 🔍 Снифферы `wireguard`, `openvpn`, `ike`, `tailscale`, `sip`

Апстрим распознаёт web- и torrent-протоколы; форк добавляет то, что домашний роутер видит от других устройств в LAN — VPN-туннели и голосовые звонки. Каждое имя работает в списке `sniffer` sniff-действия и в матчере `protocol` правила маршрутизации:

- `wireguard` (UDP) — handshake initiation / response / cookie по точному размеру (148 / 92 / 64 Б); transport-данные `>= 32 Б` с `(len-32) % 16 == 0`. Резервные байты не проверяются, поэтому Cloudflare WARP тоже матчится.
- `openvpn` (UDP, TCP) — `P_CONTROL_HARD_RESET_CLIENT_V2/V3`: plain, tls-auth, tls-crypt / tls-crypt-v2; по TCP тот же кадр за 2-байтной длиной.
- `ike` (UDP) — заголовок ISAKMP с IKEv2 `IKE_SA_INIT` (флаг Initiator) или IKEv1 Main / Aggressive; non-ESP-маркер на UDP 4500 пропускается.
- `tailscale` (UDP) — disco ping по магии `TS💬`; сам туннель виден как `wireguard`.
- `sip` (UDP, TCP) — request-line `METHOD sip:… SIP/2.0`; хост из Request-URI становится `domain`, поэтому доменные правила применяются к звонкам так же, как к TLS.
- Порядок по умолчанию: packet-снифферы идут после `stun` и **до** uTP — апстримная проверка uTP принимает любой пакет от 20 байт, начинающийся с `01 00`, а именно так начинается initiation WireGuard, поэтому обычный WireGuard помечался `bittorrent` и уезжал по torrent-правилу. Stream-снифферы `sip`, `openvpn` идут после `rdp`.
- Смотрится только первая датаграмма потока: AmneziaWG с junk (`jc > 0`) остаётся без имени, AmneziaWG с decoy (`ip=quic` / `dns` / `stun` / `sip`) помечается как decoy, нестандартные `h1`–`h4` / `s1`–`s4` не распознаются намеренно. Обфусцированные туннели маршрутизируйте по `ip_cidr`.
- Апстримные файлы снифферов не правятся. Примеры и диагностика — `docs-lx/lx-sniff.ru.md`. (SPEC 078 / 079)

## 🐛 Исправлено

### 🛡️ AmneziaWG: data-пакеты размером с handshake больше не теряются на приёме при широких `h1`–`h3`

Референсный приёмник перебирает виды сообщений в порядке init → response → cookie → transport и принимает handshake-кандидата по размеру и одному лишь слову типа. Слово типа data-пакета — шифротекст, поэтому при широком диапазоне (экспорт AWG2 вида `h1 = 43613244-384550127`) оно попадает в `H1` у ≈8 % пакетов:

- AWG2: каждая data-датаграмма ровно `s1 + 148` / `s2 + 92` / `s3 + 64` байт (возможно при `s1=28` или `s1=44` с `s4=0`) присваивалась как handshake, не проходила MAC1 и отбрасывалась.
- AWG 3.1 с `random_trailers`: проверка размера — `>`, поэтому под риском был каждый data-пакет крупнее `s1 + 148`; экспорты AWG3 держат `h1`–`h4 = 1..4`, где ловушка не стреляет.
- Теперь датаграмма, у которой слово типа ∈ `H4`, а receiver index принадлежит одному из наших живых ключей, классифицируется как transport первой; при промахе работает прежний референсный порядок, поэтому всё, что принималось раньше, принимается и теперь. Обратный риск (настоящий handshake принят за transport) ≈2⁻⁶⁴ при одиночном `h4` и не проходит AEAD; хендшейк повторяется через `rekey_timeout`.
- Только downlink: uplink классифицирует приёмник сервера. Формат на проводе не изменился; проверено red/green на детерминированной коллизии размера (`s1=44`, `s4=0`, `h1=5-4294967295`). (SPEC 081)
