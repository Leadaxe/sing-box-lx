<summary><h2>🇬🇧 English</h2></summary>

## 🐛 Fixed

### 🕸️ Tailscale: no ~15-minute loss of the coordination server after start

- Was: the Tailscale client first connects to `controlplane.tailscale.com` over plain HTTP on port 80 and upgrades the connection to its own protocol. Where DPI freezes such a flow after the upgrade, the connection stayed open but carried nothing; the client kept sending requests into it and switched to port 443 only after the OS dropped the socket, ~15 minutes later. Meanwhile the Tailscale console showed the node offline, and an exit node kept working on the old network map through DERP.
- Now: the channel to the coordination server always uses HTTPS on port 443 (the client's own `TS_FORCE_NOISE_443` switch, on by default).
- An explicitly set `TS_FORCE_NOISE_443` environment variable, including `false`, is respected.
- Not affected: direct UDP between nodes, DERP relays, routing. Only the transport of the service channel to the coordination server changes (SPEC 111).
