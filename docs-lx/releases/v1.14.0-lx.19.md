Hysteria2, TUIC and MASQUE-h3 work again on the Android devices where every
QUIC connection used to hang until timeout. A trojan or VLESS node with TLS
switched off no longer crashes the whole core on its first dial. And WG/AWG
tunnels come back within seconds of the device waking up instead of a minute
and a half.

Hysteria2, TUIC и MASQUE-h3 снова работают на Android-устройствах, где каждое
QUIC-соединение висело до таймаута. Узел trojan или VLESS с выключенным TLS
больше не роняет всё ядро при первом же подключении. А WG/AWG-туннели
оживают через секунды после пробуждения устройства, а не через полторы
минуты.

## 🔧 Changed

### ⏰ WG/AWG tunnels heal seconds after the device wakes, not a minute later

The socket self-heal shipped in `lx.17` proved itself in the field — dead
sockets do get recreated — but the cure arrived ~90 seconds after the first
traffic demand, while users measure ping within the first half-minute after
unlocking and read every node as dead. Two new triggers of the same rebind:
inside the handshake retry cycle a provably dead session (three initiations
unanswered, and no live keypair or a last handshake older than 180 s) now
rebinds at ~15 s; and a new libbox call `RebindStaleEndpoints()` lets the app
use screen unlock as a "device woke up" signal — every endpoint with a
provably dead session rebinds and re-initiates immediately, no traffic
needed, so the error window collapses to a single handshake. A live session
with transient packet loss keeps upstream behaviour byte for byte; healthy,
sleeping and stopped endpoints are strict no-ops. No config surface is added;
a pinned `listen_port` is still preserved. (SPEC 041)

## 🐛 Fixed

### 🚀 Hysteria2, TUIC and MASQUE-h3 dead on some Android devices

Reported on 4PDA: hysteria2 nodes never connected in LxBox while the same
server worked in other clients on the same phone and the same network. It
reproduced only on devices with vendor kernels (repro: OnePlus Nord CE 2,
Android 15): every quic-go connection inside the VPN process hung to
`context deadline exceeded`, while TCP protocols and WireGuard kept working —
and generic-kernel emulators never showed it. The source was clean: the same
code built with Go 1.25 works, built with Go 1.24 does not. The Android AAR
build jobs now pin a Go 1.26.x toolchain (device-verified) instead of taking
the version from `go.mod`; GSO/ECN offloads were explicitly ruled out
on-device. Desktop builds were never affected. (SPEC 044)

### 💥 A trojan or VLESS node with TLS switched off crashed the whole core

A field crash bundle showed a plain-trojan node from a public subscription
(`"tls": {"enabled": false}` — a legal config that passes `check`) taking the
VPN down the moment a URL test reached it. An upstream regression: with a
`tls` block present the TLS dialer was built unconditionally, while disabled
TLS legitimately produces no TLS config at all — so the dialer wrapped nil
and the process died on the first successful TCP connect. Such a node can sit
dormant in a subscription for months (DPI drops its TCP) and fire the first
time the path becomes passable. The dialer is now created only when a TLS
config was actually built; disabled TLS is a plain TCP dial again, with
red/green regression tests in both protocols. (SPEC 045)

## 🧰 Tools

### 🔬 Runtime QUIC offload knobs

New static libbox exports `SetQuicGSODisabled` / `SetQuicECNDisabled` toggle
quic-go's GSO and ECN offload mechanics at runtime, applied on the next
reconnect — an on-device A/B check takes two calls instead of a rebuild.
Built to investigate the vendor-kernel case above and kept for future field
diagnostics of that class (consumed by the LxBox Debug API
`POST /action/quic-knobs`). Diagnostics only; nothing changes unless called.

## 🔧 Изменено

### ⏰ WG/AWG-туннели оживают через секунды после пробуждения, а не через полторы минуты

Самолечение сокетов из `lx.17` подтвердилось в поле — мёртвые сокеты
действительно пересоздаются, — но лекарство приходило через ~90 секунд после
первого запроса трафика, а пользователи меряют пинг в первые полминуты после
разблокировки и видят все узлы мёртвыми. У того же rebind появились два новых
триггера: внутри цикла повторных рукопожатий доказуемо мёртвая сессия (три
инициации без ответа, и при этом нет живой keypair либо последнее рукопожатие
старше 180 с) переподнимается уже на ~15 с; а новый вызов libbox
`RebindStaleEndpoints()` позволяет приложению использовать разблокировку
экрана как сигнал «устройство проснулось» — каждый endpoint с доказуемо
мёртвой сессией переподнимается сразу, без ожидания трафика, и окно ошибок
сжимается до одного рукопожатия. Живая сессия с обычными потерями пакетов
сохраняет upstream-поведение байт в байт; здоровые, спящие и остановленные
endpoint'ы не трогаются. Новых полей конфига нет; закреплённый `listen_port`
по-прежнему сохраняется. (SPEC 041)

## 🐛 Исправлено

### 🚀 Hysteria2, TUIC и MASQUE-h3 были мертвы на части Android-устройств

Жалоба с 4PDA: hysteria2-ноды не подключались в LxBox, при том что тот же
сервер работал в других клиентах на том же телефоне и в той же сети.
Воспроизводилось только на устройствах с вендорским ядром (репро: OnePlus
Nord CE 2, Android 15): каждое quic-go-соединение внутри VPN-процесса висело
до `context deadline exceeded`, TCP-протоколы и WireGuard при этом работали,
а эмуляторы с обычным ядром дефект не показывали. Исходники чисты: тот же код,
собранный Go 1.25, работает, собранный Go 1.24 — нет. AAR-джобы сборки теперь
пинят тулчейн Go 1.26.x (проверено на устройстве), а не берут версию из
`go.mod`; offload-механики GSO/ECN исключены проверкой на устройстве.
Desktop-сборок дефект не касался. (SPEC 044)

### 💥 Узел trojan или VLESS с выключенным TLS ронял всё ядро

Полевой краш-бандл показал plain-trojan-ноду из публичной подписки
(`"tls": {"enabled": false}` — легальный конфиг, проходящий `check`),
которая валила VPN в момент, когда до неё добирался URL-тест.
Upstream-регрессия: при наличии блока `tls` TLS-dialer строился безусловно,
хотя выключенный TLS законно не даёт TLS-конфига вовсе — dialer оборачивал
nil, и процесс умирал при первом же успешном TCP-коннекте. Такая нода может
месяцами тихо лежать в подписке (DPI режет её TCP) и выстрелить, как только
путь станет проходимым. Теперь dialer создаётся только когда TLS-конфиг
действительно построен; выключенный TLS — снова обычный TCP, с red/green
регрессионными тестами в обоих протоколах. (SPEC 045)

## 🧰 Инструменты

### 🔬 Рантайм-ручки QUIC-offload

Новые статические экспорты libbox `SetQuicGSODisabled` /
`SetQuicECNDisabled` включают и выключают offload-механики quic-go (GSO,
ECN) на лету, с применением на следующем реконнекте — A/B-проверка на
устройстве занимает два вызова вместо пересборки. Сделаны для расследования
истории с вендорскими ядрами выше и остаются для будущих полевых диагнозов
этого класса (их использует Debug API LxBox `POST /action/quic-knobs`).
Только диагностика; без вызова ничего не меняют.
