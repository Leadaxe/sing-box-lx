The macOS system service of `sing-box lxd` no longer runs the binary from the launcher bundle as root: install puts a root-owned copy into `/Library/PrivilegedHelperTools/com.leadaxe.sing-box-lxd/` and the service runs that, which closes a local privilege escalation. New for launchers: `--service=copy` (the copy without a service), `--service=status` with exit codes, and the running binary's sha256 in `/admin/info`. A system service installed by an older core must be reinstalled once after the update.

Для лаунчеров: `--service=copy` (копия без службы), `--service=status` с кодами выхода, sha256 работающего бинаря в `/admin/info`. ## 🆕 What's new

### 🧾 `lxd --service=status`, `--service=copy`, `--exec-dir`

- `--service=status` — no root, changes nothing. Prints the plist, the program it runs, owner and mode, whether every path component from `/` is root-owned and not group/world-writable, the program's sha256 against the calling binary's, the sidecar, and the `launchctl print` state and pid. Exit code: `0` OK, `2` MISMATCH or UNSAFE (reinstall needed), `3` NOT INSTALLED, `4` COPY ONLY, `5` NOT RUNNING (consistent on disk, no running launchd job), `1` error.
- `--service=copy` (root) — the root-owned copy and its sidecar only: no plist, launchd untouched. For a launcher that runs the core as root itself. Repeating it with the same binary is a no-op (`already up to date <sha256>`); a later `--service=install` binds the copy without copying again.
- `--exec-dir <dir>` — another directory for the copy, under the same ownership check.
- `--service=uninstall --keep-copy` — removes the service but keeps the copy for non-service use (status becomes `COPY ONLY`).
- `/admin/info` — two new fields: `executable` and `executable_sha256`. Compare cores by hash: the daemon's path now always differs from the bundle's. ([SPEC 100](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/100-LXD_ROOT_OWNED_BINARY/SPEC.md))

## 🐛 Fixed

### ⏱ Reinstalling the service no longer leaves it unloaded

- Was: `--service=install` ran `launchctl bootstrap` right after `bootout`; a job with a live core takes seconds to exit, and the bootstrap failed with `Bootstrap failed: 5: Input/output error`, leaving the service unloaded until a manual bootstrap.
- Now: install waits for the old job to disappear (up to 10 s, printing `waiting for the old service to unload (Ns)`) and retries a bootstrap that answers "already in progress". `--service=status` reports such a state as `NOT RUNNING` (exit 5) with the bootstrap command instead of `OK`.

### 🔒 The lxd system service ran a user-writable binary as root

- Was: `--service=install` wrote the path it was started from into the LaunchDaemon plist — in practice the binary in the launcher bundle, owned by the user. launchd ran it as root on every boot and restart; any process of that user that replaced the file got root.
- Now: install copies the binary to `/Library/PrivilegedHelperTools/com.leadaxe.sing-box-lxd/sing-box` (`root:wheel 0755`) through a temporary file, fsync, sha256 check and atomic rename, and writes `install.json` beside it (`source`, `sha256`, `version`, `installed_at`, `plist_path`, `label`). An identical copy is not rewritten. Only `ProgramArguments[0]` in the plist changes; `daemon.json`, the address, the secret and the enrolled clients stay. The support directory is now `root:wheel`.
- Uninstall removes the copy only when its sha256 matches the sidecar; it never deletes an arbitrary program path from the plist.
- At start, a core running as root (`lxd`, `run`) checks its own binary. The launchd service refuses to start from a binary that is not root-owned and logs the path, owner and mode to `lxd.log`; any other root run only logs a WARN. `--allow-unsafe-exec` turns the refusal into a WARN for debugging.
- ⚠️ A system service installed by an older core keeps pointing at the bundle binary. After that binary is updated to this version, the service refuses to start at its next restart until `sudo sing-box lxd --service=install` is run once; `daemon.json`, clients and keys are kept.
- A launcher that compares the daemon's path with its own (before its core pin is bumped) shows "another core" — cosmetic. ([SPEC 100](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/100-LXD_ROOT_OWNED_BINARY/SPEC.md))

## 🧰 Tools

- CI: the per-push lint job vets `./lxd/` and `./cmd/sing-box/` with `GOOS=darwin`; the darwin-only daemon files were not compiled by the per-push gate before.

- Unchanged: configuration (no new keys), the wire formats, the tag sets of desktop, router and AAR builds, the Linux service recipes and the user-scope (`install-user`) agent, the Go toolchain. On any platform, a core running as root from a binary that is not root-owned now logs one WARN at start.

## 🆕 Что нового

### 🧾 `lxd --service=status`, `--service=copy`, `--exec-dir`

- `--service=status` — без root, ничего не меняет. Печатает plist, программу, которую он исполняет, владельца и режим, проходит ли каждый компонент пути от `/` проверку «владелец root, нет записи для group/other», sha256 программы против sha256 вызывающего бинаря, сайдкар, состояние и pid из `launchctl print`. - `--service=copy` (root) — только root-owned копия и сайдкар: plist не пишется, launchd не трогается. Для лаунчера, который сам запускает ядро от root. Повтор с тем же бинарём ничего не делает (`already up to date <sha256>`); последующий `--service=install` привязывает копию без повторного копирования.
- `--exec-dir <dir>` — другой каталог копии, с той же проверкой владельца.
- `--service=uninstall --keep-copy` — снимает службу, копию оставляет для запуска без службы (status становится `COPY ONLY`).
- `/admin/info` — два новых поля: `executable` и `executable_sha256`. Ядра сравнивать по хешу: путь демона теперь всегда отличается от пути в бандле. ([SPEC 100](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/100-LXD_ROOT_OWNED_BINARY/SPEC.md))

## 🐛 Исправлено

### ⏱ Переустановка службы больше не оставляет её незагруженной

- Было: `--service=install` вызывал `launchctl bootstrap` сразу после `bootout`; job с живым ядром выгружается несколько секунд, bootstrap падал с `Bootstrap failed: 5: Input/output error`, и служба оставалась незагруженной до ручного bootstrap.
- Стало: install ждёт исчезновения старого job'а (до 10 с, печатая `waiting for the old service to unload (Ns)`) и повторяет bootstrap на ответе «already in progress». `--service=status` такое состояние показывает как `NOT RUNNING` (exit 5) с командой bootstrap, а не `OK`.

### 🔒 Системная служба lxd исполняла от root бинарь, доступный пользователю на запись

- Было: `--service=install` записывал в plist LaunchDaemon путь, из которого его запустили, — на практике бинарь в бандле лаунчера с владельцем-пользователем. launchd исполнял его от root при каждой загрузке и рестарте; любой процесс этого пользователя, заменивший файл, получал root.
- Стало: install копирует бинарь в `/Library/PrivilegedHelperTools/com.leadaxe.sing-box-lxd/sing-box` (`root:wheel 0755`) через временный файл, fsync, сверку sha256 и атомарный rename и пишет рядом `install.json` (`source`, `sha256`, `version`, `installed_at`, `plist_path`, `label`). Одинаковая копия не переписывается. В plist меняется только `ProgramArguments[0]`; `daemon.json`, адрес, секрет и сопряжённые клиенты остаются. Support-каталог теперь `root:wheel`.
- Uninstall удаляет копию, только если её sha256 совпадает с сайдкаром; произвольный путь программы из plist не удаляется никогда.
- При старте ядро под root (`lxd`, `run`) проверяет собственный бинарь. Служба launchd на бинаре, который не принадлежит root, не стартует и пишет путь, владельца и режим в `lxd.log`; любой другой запуск от root — только WARN. `--allow-unsafe-exec` превращает отказ в WARN для отладки.
- ⚠️ Системная служба, поставленная старым ядром, продолжает указывать на бинарь в бандле. После обновления этого бинаря до этой версии служба на ближайшем рестарте не стартует, пока один раз не выполнен `sudo sing-box lxd --service=install`; `daemon.json`, клиенты и ключи сохраняются.
- Лаунчер, который сравнивает путь демона со своим (до бампа пина ядра), покажет «another core» — косметика. ([SPEC 100](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/100-LXD_ROOT_OWNED_BINARY/SPEC.md))

## 🧰 Инструменты

- CI: lint-джоба на каждом пуше прогоняет `go vet` по `./lxd/` и `./cmd/sing-box/` с `GOOS=darwin`; darwin-файлы демона раньше на пуше не компилировались.

- Не меняются: конфигурация (новых ключей нет), провод, наборы тегов desktop-, router- и AAR-сборок, рецепты службы на Linux и пользовательский агент (`install-user`), Go-тулчейн. На любой платформе ядро под root, запущенное с бинаря не во владении root, теперь пишет при старте один WARN.
