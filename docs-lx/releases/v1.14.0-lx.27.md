Adds `chain` — a multi-hop path built at runtime from the nodes and groups you
already have, with no duplicated config: positions are listed in packet order,
any position may be a group, and switching a group changes the path without a
restart. MASQUE gains `vhttp: "auto"`, which starts on h3 and falls back to h2
when the endpoint silently ignores QUIC from your exit address — a failure mode
that used to look like a hang, not an error. Plus a run of stability fixes that
came out of live incidents: a dead detour node no longer freezes the process
network machinery, stopping mid-start no longer crashes, and WireGuard nodes
come up on Windows adapters with IPv6 unchecked.

## 🆕 What's new

### 🔗 `chain` — a virtual multi-hop path of groups and nodes

A multi-hop route used to be assembled by hand: the exit node got a `detour`
onto the entry node, and the relation was baked into the nodes themselves. A
node needed in two roles had to be duplicated; a group could not be a hop at all.

```json
{
  "type": "chain",
  "tag": "virtualisation",
  "outbounds": ["selector-in", "selector-mid", "selector-exit"],
  "idle_timeout": "5m"
}
```

- **Positions are in packet order**: `outbounds[0]` is the first hop from the
  client, the last entry is the node whose address the destination sees. This is
  the opposite of how a `detour` chain reads.
- **Any position may be a node, an endpoint or a group** of any nesting. Groups
  are never copied — the chain calls the original group and lets it pick with all
  of its logic (manual selection, health check, sticky, penalties,
  `interrupt_exist_connections`).
- **`direct` at a position ≥ 1 is transparent**: put it in a selector and that
  hop switches off at runtime, shortening the path without touching the config.
- **Tunnel links get their MTU lowered automatically** by the exact overhead of
  the IP tunnels below them.
- **`strip` / `rewrite`** control what a node looks like when it acts as a link:
  one-sided DPI tricks are removed by default (the path fix `record_fragment`
  never is), and `rewrite` patches a node's config per type.
- Diagnostics: the resolved path lands in a connection's `detourList`,
  `GetChains` reports per-position state, and probing the internal hop tags
  `<tag>#0`, `<tag>#1`, … measures the path one layer at a time — which is how
  the slow hop in a three-layer chain is found in seconds.

Build tag `with_lx_chain`. Full reference:
[configuration §9](https://github.com/Leadaxe/sing-box-lx/blob/lx/docs-lx/lx-config.md).

### 🎭 MASQUE `vhttp: "auto"`

Cloudflare WARP silently ignores QUIC coming from the exit address of some
hosters. There is no error to see — the handshake simply never completes, and
the dial hangs until the caller's own deadline. TCP:443 is accepted from
everywhere, so the workaround was always "know about the hole and pin `h2`".

`"vhttp": "auto"` starts the h3 leg and, if it has not come up within 3 s,
starts h2 **without waiting for h3 to return** — a wedged leg can sit inside
third-party cleanup code for minutes, so the decision is taken on a timer rather
than on the leg answering. The winning mode is remembered, so only the first
tunnel of a process pays the wait. Measured on a live path: 3.3 s to a working
tunnel where the same setup used to hang for 40–90 s.

## 🐛 Fixed

### 🧊 A dead detour node no longer freezes the process network machinery

One unreachable node behind a `detour` could stall the whole process: dials
piled up behind a lock that the frozen leg still held. Reworked so a dead leg
fails its own dials and nothing else.

### 💥 Stopping during start no longer crashes the process

A stop that landed while `Box.Start()` was still running could tear a WireGuard
endpoint's device out from under its in-flight transport start. Reported from
the field on a 1755-outbound profile.

### 🪟 Windows: WireGuard nodes dead from the start with IPv6 unchecked

If the adapter had the IPv6 checkbox cleared, WG/AWG endpoints never came up.

### 🌐 XHTTP: a failed stream no longer kills a live one

A failure to raise an XHTTP stream now tears down its own upload pipe instead of
letting a healthy stream die on the dial deadline. Plus a deadlock in the
read-deadline path: the expiry callback ran while holding the mutex and blocked
there, stalling everyone else on that deadline — including quic-go, which calls
`SetReadDeadline` from its own dial path. A QUIC handshake over an XHTTP hop
could hang 20–90 s because of it.

## 🆕 Что нового

### 🔗 `chain` — виртуальная цепочка хопов из групп и узлов

Многохоповый маршрут раньше собирался руками: узлу-выходу прописывался `detour`
на узел-вход, и связь зашивалась в сами узлы. Узел, нужный в двух ролях,
приходилось дублировать; группа не могла быть хопом вовсе.

```json
{
  "type": "chain",
  "tag": "virtualisation",
  "outbounds": ["selector-in", "selector-mid", "selector-exit"],
  "idle_timeout": "5m"
}
```

- **Позиции — в порядке пакета**: `outbounds[0]` — первый хоп от клиента,
  последний — узел, чей адрес видит цель. Это обратно записи через `detour`.
- **Любая позиция — узел, endpoint или группа** любой вложенности. Группы не
  копируются: цепочка зовёт оригинальную группу, и та выбирает со всей своей
  логикой (ручной выбор, health-check, sticky, штрафы,
  `interrupt_exist_connections`).
- **`direct` на позиции ≥ 1 прозрачен**: положите его в селектор — и хоп
  выключается на лету, путь укорачивается без правки конфига.
- **Туннельным звеньям MTU понижается автоматически** на точные накладные
  IP-туннелей под ними.
- **`strip` / `rewrite`** задают, как узел выглядит в роли звена: односторонние
  DPI-приёмы снимаются по умолчанию (защита пути `record_fragment` — никогда),
  а `rewrite` правит конфиг узла по типу.
- Диагностика: разрешённый путь попадает в `detourList` соединения, `GetChains`
  отдаёт состояние по позициям, а проба внутренних тегов `<tag>#0`, `<tag>#1`, …
  меряет путь послойно — так медленный хоп в трёхслойной цепочке находится за
  секунды.

Build-tag `with_lx_chain`. Полный справочник:
[конфиг §9](https://github.com/Leadaxe/sing-box-lx/blob/lx/docs-lx/lx-config.ru.md).

### 🎭 MASQUE `vhttp: "auto"`

Cloudflare WARP молча игнорирует QUIC с выходных адресов части хостеров. Ошибки
нет — хендшейк просто не завершается, и дозвон висит до дедлайна вызывающего.
TCP:443 при этом принимается отовсюду, так что обходом всегда было «знать про
дыру и прописать `h2`».

`"vhttp": "auto"` стартует h3-ногу и, если за 3 с она не поднялась, запускает
h2, **не дожидаясь её возврата**: застрявшая нога может минутами сидеть в чужом
cleanup-коде, поэтому решение принимает таймер, а не возврат ноги. Победивший
режим запоминается — ожидание платит только первый туннель процесса. Замер на
живом пути: рабочий туннель за 3.3 с там, где та же связка висела 40–90 с.

## 🐛 Исправлено

### 🧊 Мёртвый detour-узел больше не морозит сетевую машинерию процесса

Один недоступный узел за `detour` мог застопорить весь процесс: дозвоны
копились за замком, который держала замёрзшая нога. Переделано так, что мёртвая
нога валит только свои дозвоны.

### 💥 Остановка во время старта больше не роняет процесс

Стоп, пришедший пока `Box.Start()` ещё идёт, мог выдернуть device
WireGuard-эндпоинта из-под его же стартующего транспорта. Прилетело из поля на
профиле с 1755 outbound'ами.

### 🪟 Windows: WG-узлы мертвы со старта при снятой галке IPv6

Если у адаптера снята галка IPv6, WG/AWG-эндпоинты не поднимались вовсе.

### 🌐 XHTTP: провал одного стрима больше не убивает живой

Провал поднятия XHTTP-стрима теперь рвёт собственный upload-пайп, а не даёт
здоровому стриму умереть по дедлайну дайла. Плюс дедлок в пути read-deadline:
колбэк истечения выполнялся под удерживаемым мьютексом и блокировался там,
подвешивая всех остальных потребителей дедлайна — включая quic-go, который
зовёт `SetReadDeadline` на своём dial-пути. Из-за этого QUIC-хендшейк поверх
XHTTP-хопа мог висеть 20–90 с.
