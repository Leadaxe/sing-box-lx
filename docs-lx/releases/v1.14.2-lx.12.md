## 🆕 What's new

### 🔁 `urltest` `mode: failover` — hold the node until it fails, one probe per `interval`

- Selection: the fastest node at the moment of choice; `tolerance` and the order of `outbounds` do not matter.
- Hold: while the node works the group stays on it, even if another one becomes faster. Each `interval` probes **only the held node**; the other nodes sleep.
- Failure: the held node fails a probe → a full run over every node → the fastest live one. A dial through it fails with a "path is dead" error → the selection moves at once, without `Interrupt`.
- Manual test (UI, `sing-box api group urltest <tag>`, Clash API) is always full: it probes every node and re-selects the fastest. This is the only way back to the best node while the held one is alive.
- `tolerance` is ignored (a startup warning says so); `balancer` is a startup error. Delays of non-held nodes in the UI are as of the last full run.

### 📡 WireGuard / AmneziaWG peer status: `GetWireGuardStatus(tag)`

- One request per endpoint returns `endpointState`, `idleSinceSeconds` and `peers[]`: the peer's public key, current address (on a server — learned from the client's handshake), last handshake time (`0` — none), rx / tx.
- The core does not judge "online": the app picks the threshold. Secrets are not returned; a sleeping endpoint is not woken up.
- Errors: `NotFound` / `InvalidArgument` / `FailedPrecondition`. `GetOutbounds` stays a list of nodes; `endpointState` / `idleSinceSeconds` remain in `GroupItem`.
- libbox: `CommandClient.GetWireGuardStatus(tag).Peers()`; CLI: `sing-box api peers [tag]`. Consumer guide: `SPECS/TASKS/114-WG_PEER_STATUS/CONSUMERS.md`. (SPEC 114)

### 🛰️ Tailscale peer path and `GetTailscaleStatus(tag)`

- `TailscalePeer` gains `path` (direct / peer relay / DERP / none — the core's verdict from magicsock), `endpoint`, `peerRelay`, `derpRegionCode`, `lastHandshake`; `TailscaleEndpointStatus` gains `health` (backend warnings).
- `GetTailscaleStatus` returns a fresh snapshot of the same shape as the `SubscribeTailscaleStatus` stream; the stream stays event-driven, no ticker.
- libbox: `CommandClient.GetTailscaleStatus(tag)`, `TailscalePeer.Path` as a string, `Health()`; CLI: `sing-box api tailscale peers`. Consumer guide: `SPECS/TASKS/115-TAILSCALE_PEER_PATH_STATUS/CONSUMERS.md`. (SPEC 115)

## 🔧 Changed

### ⚠️ `passive_check` removed — a config with it does not start

- The flag on `urltest` with `mode: least_test` implicitly did what `failover` now does explicitly. Removed without a compatibility period: the key is unknown and the config fails to load. Replace it with `"mode": "failover"`. (SPEC 116)

### 🧩 Synced with upstream `stable`: scoped component lifecycle

- Upstream replaced `Start(stage)` + `Close()` with `Start(stage, scope)`; managers no longer have `Close` / `Remove`. Our seams moved along: parallel shutdown of WireGuard endpoints, the endpoint's own `Close` (sleep, lazy build, manual off) and the idle ticker register in the scope; `chain` and `masque` use the new interface.
- Also from upstream: usage and cache files are no longer overwritten when loading fails; the TUN DNS mode is consistent without `auto_route`; Tailscale SSH auth banners are sent. (SPEC 117)

## 🧰 Under the hood

- Base: sing-box `v1.14.2` + 26 upstream `stable` commits, drift 0. The sing-tun fork carries the new upstream commit under our changes. Go 1.26.8, cronet and JDK match upstream; NDK r28c is deliberate.
- Known, not fixed: stopping the core with `services: [{type: api}]` logs `close service/api[0]: use of closed network connection` — an upstream defect (double close of the listener), reproducible on clean upstream `stable`, no effect on operation.

## 🆕 Что нового

### 🔁 `urltest` `mode: failover` — держать узел до отказа, одна проба в `interval`

- Выбор: самый быстрый узел на момент выбора; `tolerance` и порядок `outbounds` не влияют.
- Удержание: пока узел работает, группа остаётся на нём, даже если другой стал быстрее. Каждый `interval` пробуется **только удерживаемый узел**; остальные спят.
- Отказ: удерживаемый узел не ответил на пробу → полный прогон по всем → самый быстрый живой. Дайл через него упал с ошибкой «путь мёртв» → переезд сразу, без `Interrupt`.
- Ручной тест (UI, `sing-box api group urltest <tag>`, Clash API) всегда полный: меряет все узлы и перевыбирает самый быстрый. Это единственный путь обратно на лучший узел, пока удерживаемый жив.
- `tolerance` не действует (предупреждение на старте); `balancer` — ошибка старта. Задержки неудерживаемых узлов в UI — по последнему полному прогону.

### 📡 Статус пиров WireGuard / AmneziaWG: `GetWireGuardStatus(tag)`

- Один запрос по эндпоинту возвращает `endpointState`, `idleSinceSeconds` и `peers[]`: публичный ключ пира, текущий адрес (на сервере — выученный из хендшейка клиента), время последнего хендшейка (`0` — не было), rx / tx.
- Вердикт «на связи» ядро не выносит: порог выбирает приложение. Секреты не отдаются; спящий эндпоинт не будится.
- Ошибки: `NotFound` / `InvalidArgument` / `FailedPrecondition`. `GetOutbounds` остаётся списком узлов; `endpointState` / `idleSinceSeconds` в `GroupItem` остались.
- libbox: `CommandClient.GetWireGuardStatus(tag).Peers()`; CLI: `sing-box api peers [тег]`. Руководство потребителя: `SPECS/TASKS/114-WG_PEER_STATUS/CONSUMERS.md`. (SPEC 114)

### 🛰️ Путь к пиру Tailscale и `GetTailscaleStatus(tag)`

- У `TailscalePeer` появились `path` (direct / peer relay / DERP / none — вердикт ядра по выбору magicsock), `endpoint`, `peerRelay`, `derpRegionCode`, `lastHandshake`; у `TailscaleEndpointStatus` — `health` (предупреждения бэкенда).
- `GetTailscaleStatus` отдаёт свежий снимок того же вида, что поток `SubscribeTailscaleStatus`; поток остаётся событийным, без тика.
- libbox: `CommandClient.GetTailscaleStatus(tag)`, `TailscalePeer.Path` строкой, `Health()`; CLI: `sing-box api tailscale peers`. Руководство потребителя: `SPECS/TASKS/115-TAILSCALE_PEER_PATH_STATUS/CONSUMERS.md`. (SPEC 115)

## 🔧 Изменено

### ⚠️ `passive_check` удалён — конфиг с ним не стартует

- Флаг у `urltest` с `mode: least_test` неявно делал то, что теперь явно делает `failover`. Удалён без периода совместимости: ключ неизвестен, конфиг не загружается. Замена — `"mode": "failover"`. (SPEC 116)

### 🧩 Синк с апстримным `stable`: жизненный цикл компонентов на scope

- Апстрим заменил `Start(stage)` + `Close()` на `Start(stage, scope)`; у менеджеров больше нет `Close` / `Remove`. Наши швы перенесены: параллельное закрытие WireGuard-эндпоинтов, собственный `Close` эндпоинта (сон, ленивая сборка, ручное выключение) и idle-тик регистрируются в scope; `chain` и `masque` переведены на новый интерфейс.

- Известно, не чинится: при остановке ядра с `services: [{type: api}]` в лог пишется `close service/api[0]: use of closed network connection` — дефект апстрима (двойное закрытие listener'а), воспроизводится на чистом апстримном `stable`, на работу не влияет.
