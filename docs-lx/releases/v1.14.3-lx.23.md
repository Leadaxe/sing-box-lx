Two fixes around `urltest` and shutdown, plus a diagnostic. A `round_robin` pool no longer sends new connections to a node that failed its last probe while a live node is available. Stopping the core with many WireGuard/AmneziaWG endpoints is fast again: the socket pre-pass had been silently dead since `lx.37`. And a stop that hangs for more than 20 s now writes a full goroutine dump to the core log on its own, so the next report of a stuck stop comes with evidence.

Два исправления вокруг `urltest` и выключения плюс диагностика. Пул `round_robin` больше не отправляет новые соединения узлу, провалившему последнюю пробу, пока есть живой узел. ## 🐛 Fixed

### 🎯 `urltest` `round_robin`: a dead pool node kept its share of new connections for the whole outage

- Field setup on a router: four nodes on two physical servers, pool 4 of 4. While one server was down, half of the new connections went into it; with pool 3 of 4, a third. The pool never shrinks by design, and the per-connection pick returned the slot occupant without looking at its liveness.
- The pick now skips a slot whose node failed its last probe. Without stickiness the rotation runs over the live slots; with `sticky_hash` the keys of live slots never move, keys of dead slots spread evenly over the live slots and return once the node answers again. When every slot is dead (cold start, total outage) the behaviour is unchanged.
- The pool, the slot layout, references and the reachability cache are untouched; a dial error still never changes the pool. The skip starts when the dead node's probe fails: up to `interval` plus the probe timeout. Liveness is the node's shared URL test history, so a manual delay test that does not complete also takes the node out of the rotation until the next pool health check.
- A/B on the router, pool 3 of 4, ~20 s server blink: 0 failed connections against ~1/3 with the stock core for the whole outage. Reported and co-developed by @tmmgn. (SPEC 138)

### ⏹️ Stopping the core with many WireGuard/AmneziaWG endpoints is fast again

- The shutdown pre-pass that releases every WireGuard/AmneziaWG socket before the endpoints are torn down relied on the device-pause event. Upstream removed the WireGuard reaction to that event on purpose, and the fork inherited it in `lx.37`: since then the pre-pass closed no socket and every endpoint teardown waited out its own receive worker, one after another. No test caught it: the regression test lived in a module that does not build.
- The pre-pass is now an explicit walk over the endpoints: each one marks itself closing and brings its device down up front. WireGuard still stays up through device sleep, as upstream intends. The regression test moved to `lx-test/startclose`, and CI now runs the WireGuard endpoint, route and shutdown suites on every push.
- Affected: `v1.14.0-lx.37` … `v1.14.3-lx.22`. (SPEC 030)

## 🧰 Tools

### 🔍 A stop that hangs writes a goroutine dump to the core log

- If the endpoint close pass, or the whole core close, has not returned after 20 s, the core writes once, at `Warn`: a header with the tags of the endpoints that have not returned from `Close` yet (`not returned yet: [...]`), the full goroutine dump in `goroutine dump [i/M]` records of at most 3 KiB each so logcat does not truncate them, and `completed after …` if the close finishes later.
- The close is never interrupted or sped up; a stop that finishes in time leaves nothing in the log. Works in every client, including libbox on Android where pprof is not reachable.
- If your stop hangs, attach the core log for that minute: all `goroutine dump [i/M]` records plus the `not returned yet` line. (SPEC 030)

## 🐛 Исправлено

### 🎯 `urltest` `round_robin`: мёртвый узел пула получал свою долю новых соединений весь простой

- Полевой стенд на роутере: четыре узла на двух физических серверах, пул 4 из 4. Пока один сервер лежал, в него уходила половина новых соединений; при пуле 3 из 4 — треть. Пул по дизайну не сжимается, а выбор узла на соединение отдавал занимающего слот, не глядя на его живость.
- Выбор теперь обходит слот, чей узел провалил последнюю пробу. Без закрепления ротация идёт по живым слотам; с `sticky_hash` ключи живых слотов не двигаются, ключи мёртвых поровну расходятся по живым и возвращаются, как только узел ответит. Если мёртвы все слоты (холодный старт, тотальный простой) — поведение прежнее.
- Пул, раскладка слотов, references и кэш достижимости не меняются; ошибка дайла пул по-прежнему не трогает. Обход начинается с провала пробы: до `interval` плюс таймаут пробы. Сигнал живости — общая history узла, поэтому несостоявшийся ручной тест задержки тоже выводит узел из ротации до ближайшего дотеста пула.
- A/B на роутере, пул 3 из 4, простой сервера ~20 с: 0 отказов против ~1/3 у стокового ядра весь простой. Репорт и совместная разработка — @tmmgn. (SPEC 138)

### ⏹️ Остановка ядра с многими WireGuard/AmneziaWG-endpoint'ами снова быстрая

- Пре-пасс выключения, который отпускает каждый WireGuard/AmneziaWG-сокет до разбора endpoint'ов, опирался на событие паузы устройства. Апстрим намеренно убрал реакцию WireGuard на это событие, форк унаследовал это в `lx.37`: с тех пор пре-пасс не закрывал ни одного сокета, и каждый разбор endpoint'а ждал своего приёмного воркера, один за другим. Тест не поймал: регресс-тест лежал в модуле, который не собирается.
- Теперь пре-пасс — явный обход endpoint'ов: каждый помечает себя закрывающимся и заранее опускает устройство. WireGuard по-прежнему живёт через сон устройства, как и задумано апстримом. Регресс-тест переехал в `lx-test/startclose`, CI гоняет наборы WireGuard-endpoint, route и выключения на каждом пуше.
- Затронуты: `v1.14.0-lx.37` … `v1.14.3-lx.22`. (SPEC 030)

## 🧰 Инструменты

### 🔍 Зависшая остановка пишет дамп горутин в лог ядра

- Если проход закрытия endpoint'ов или всё закрытие ядра не вернулись за 20 с, ядро один раз пишет на `Warn`: заголовок с тегами endpoint'ов, ещё не вернувших `Close` (`not returned yet: [...]`), полный дамп горутин записями `goroutine dump [i/M]` не больше 3 КиБ каждая, чтобы logcat их не обрезал, и `completed after …`, если закрытие потом всё же завершилось.
- Закрытие не прерывается и не ускоряется; остановка, уложившаяся в срок, ничего в лог не пишет. Работает в любом клиенте, включая libbox на Android, где pprof недоступен.
- Если stop у вас завис — приложите лог ядра за эту минуту: все записи `goroutine dump [i/M]` и строку `not returned yet`. (SPEC 030)
