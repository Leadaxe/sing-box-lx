Fixes a startup crash: a WireGuard endpoint whose detour chain contains a
domain-addressed node took the core down before it finished starting. Fixes a
crash in the `api` service: the first `GetRules` call killed the process. Adds
`sing-box lxd run` — a headless daemon subcommand that hosts the core in-process
behind a control channel that survives reloads and broken configs.

Исправлен краш на старте: WireGuard-эндпоинт с доменным узлом в detour-цепи ронял
ядро до того, как оно поднималось. Исправлен краш в сервисе `api`: первый же вызов

## 🆕 What's new

### 🧩 `sing-box lxd run` — headless daemon subcommand

The core runs in-process behind a long-lived gRPC control channel, modelled on
upstream's desktop daemon (`experimental/boxdd`) but headless and shipped as a
subcommand of the existing binary — one artifact, no separate extractor path, no
version skew.

```
sing-box lxd run -c config.json --listen 127.0.0.1:9091 --secret …
```

- The control channel **survives reload and a broken config**: if the core fails
  to start or reload, the daemon logs it and keeps listening in FATAL state
  instead of exiting.
- `SIGHUP` re-reads the config file and swaps the instance under the live server.
  `SIGINT`/`SIGTERM` shut down in order: service → gRPC server → close.
- Bearer authentication, health and reflection are served on the same listener.
- Requires the `with_lx_command` build tag; without it the subcommand does not
  exist and the package is an empty stub. No upstream files are touched — the
  subcommand self-registers via `init()`.

This is the skeleton only: the admin plane (applying a config programmatically,
rollback) is a later task. (SPEC 055, FEATURE 014)

## 🐛 Fixed

### 💥 Startup crash with a domain-addressed node in a WireGuard detour chain

Endpoints start before DNS transports do. An early WireGuard bind dial through a
detour chain containing a domain-addressed node resolved through a `dns_group`
that had not started yet: the member list was empty and the survival branch
picked `best[rand.IntN(0)]` — a panic on a zero argument, so the core never came
up at all.

An empty member list is now read as "not started" and returns a typed error; the
caller retries once the transports are up. Field crash on 1.14.0-lx.22
(android/arm64). (SPEC 033)

### 💥 `GetRules` killed the core under the `api` service

With `services: [{"type": "api"}]` the core attaches to an already-running box
from the outside and has no `*box.Box` of its own — only the owning start path
builds one. `GetRules` reached for the routing table through that missing object,
so the first call to the RPC brought the whole process down.

The router is now resolved from the service context (where it is registered
anyway, and where the Clash API already reads it) and stored on the instance, so
both start paths have it. If it is genuinely absent, the RPC degrades to
`Unavailable` instead of panicking — the same discipline `GetRunningConfig`
already followed. No other lx RPC had this pattern. (FEATURE 006)

## 🆕 Что нового

### 🧩 `sing-box lxd run` — сабкоманда headless-демона

Ядро работает in-process за долгоживущим управляющим каналом gRPC — по модели
десктопного демона апстрима (`experimental/boxdd`), но headless и в форме
сабкоманды существующего бинаря: один артефакт, отдельный путь распаковки не
нужен, рассинхрон версий невозможен.

```
sing-box lxd run -c config.json --listen 127.0.0.1:9091 --secret …
```

- Управляющий канал **переживает reload и битый конфиг**: если ядро не смогло
  стартовать или перезагрузиться, демон пишет это в лог и остаётся слушать в
  состоянии FATAL, а не завершается.
- `SIGHUP` перечитывает файл конфига и подменяет инстанс под живым сервером.
  `SIGINT`/`SIGTERM` гасят по порядку: сервис → gRPC-сервер → закрытие.
- Bearer-аутентификация, health и reflection обслуживаются на том же listener'е.
- Требуется тег сборки `with_lx_command`; без него сабкоманды нет, а пакет —
  пустой стаб. Апстримные файлы не затронуты: сабкоманда самонавешивается через
  `init()`.

Это только скелет: admin-плоскость (программная подача конфига, откат) — задача
следующего этапа. (SPEC 055, FEATURE 014)

## 🐛 Исправлено

### 💥 Краш на старте с доменным узлом в detour-цепи WireGuard

Эндпоинты стартуют раньше DNS-транспортов. Ранний дайл WG-bind через detour-цепь
с доменным узлом уходил резолвиться в группу `dns_group`, которая ещё не
стартовала: список членов пуст, и survival-ветка выбирала `best[rand.IntN(0)]` —
паника на нулевом аргументе, ядро не поднималось вовсе.

Пустой список членов теперь читается как «не стартована» и возвращает
типизированную ошибку; вызывающий повторяет попытку, когда транспорты поднимутся.
Полевой краш на 1.14.0-lx.22 (android/arm64). (SPEC 033)

### 💥 `GetRules` убивал ядро под сервисом `api`

С `services: [{"type": "api"}]` ядро прицепляется снаружи к уже поднятому box и
собственного `*box.Box` не имеет — его строит только владеющий путь запуска.
`GetRules` тянулся за таблицей маршрутизации через этот отсутствующий объект,
поэтому первый же вызов RPC ронял весь процесс.

Теперь роутер резолвится из сервисного контекста (где он и так зарегистрирован и
откуда его уже берёт Clash API) и хранится в инстансе, так что он есть у обоих
путей запуска. Если роутера действительно нет, RPC деградирует в `Unavailable`
вместо паники — та же дисциплина, что уже была у `GetRunningConfig`. У остальных
lx-RPC этого паттерна не было. (FEATURE 006)
