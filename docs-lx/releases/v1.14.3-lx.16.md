## 🆕 What's new

### ⬆️ `sing-box lxd update`: the core updates itself on Linux

- Before: updating the core on a router meant SSH — find the right asset, download, verify, stop, replace, start.
- Now one command does it. The binary knows its own path, version, release asset (`linux-armv7`, `linux-mipsle-softfloat`, …) and the host's init (`procd` / `systemd` / `openrc`).
- Source: `SHA256SUMS` of the latest stable release (`--prerelease` — the newest one). Same version → `already up to date`; an installed newer version is not downgraded. Needs free space ≥ 1.1 × archive size.
- The archive streams into `<binary>.new` on the same filesystem (nothing in `/tmp`), the sum is checked, the new binary must pass `version` and `check -c last_good.json`, then an atomic `rename` (old one kept as `.old`).
- Restart through the detected init; the service must be up within 15 s and stay up for 3 s, otherwise the old binary is restored (exit code 2). If the restart command itself fails or the init is not recognized, the new binary stays and you are asked to restart by hand.
- Flags: `--dry-run`, `--no-restart`, `--service`. Proxy: `HTTPS_PROXY` / `ALL_PROXY`. The repository is hardcoded.
- `sing-box version` now also prints `Platform:`, `Init:`, `Update:`. The OpenWrt installer registers `update` as a daemon command — the launcher's Update button. (SPEC 129)

### 🛠️ Named root commands in `daemon.json`

- Before: the root daemon does not run client code, so the launcher could not update the core or restart the service.
- Now the operator lists commands on the host: `"commands": {"update": "/usr/bin/sing-box lxd update"}`. The client only picks a name; it passes no arguments and no input.
- API: `GET /admin/commands` (list and last outcome), `POST /admin/commands/{name}` (`202` / `404` / `409`), `GET /admin/commands/{name}` (status and last 64 KiB of the log). Same authorization as other admin routes.
- A command runs detached, so restarting the service does not kill it; its outcome (`done` / `running` / `lost`) survives a daemon restart. Environment: `LXD_PLATFORM`, `LXD_VERSION`, `LXD_INIT_SYSTEM`, `LXD_STATE_DIR`, `LXD_BIN`, `LXD_CLIENT`.
- Names: `[a-z0-9][a-z0-9_-]{0,31}`; a bad name or empty command stops the daemon from starting. Unix only; ignored on Windows with a warning. (SPEC 128)

### 🪪 `GET /admin/info` reports platform and init system

- New fields: `goos`, `goarch`, `platform` (release asset suffix for this binary, e.g. `linux-armv7`, `windows-386-legacy-windows-7`), `init_system` (`procd` / `systemd` / `openrc` / `launchd` / `scm`, empty if not recognized) and `service` (whether this process runs as a service).
- The launcher no longer has to rely on a hand-entered platform (a wrong `amd64` record would have downloaded the wrong core). Init detection now also recognizes `openrc`. (SPEC 127)

## 🐛 Fixed

### 🪟 Windows 7: the core did not start since lx.14

- Symptom: `FATAL start service: initialize network: watch registry key SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\Interfaces: The parameter is incorrect`.
- Cause: the DNS change watcher added upstream in sing-tun with v1.14.3 uses a registry notification flag that exists only since Windows 8.
- Now the watcher retries without the flag on Windows 7. Windows 8 and later behave as before. (SPEC 130)

## 🧰 Under the hood

- Base: sing-box `v1.14.3`, zero drift from `upstream/stable` (the one merged upstream commit only changes the Linux GUI client build). Go 1.26.8.
- SPEC 127/128/129: unit tests; the version card and `lxd update --dry-run` checked on an OpenWrt router; the full update through the launcher is next. SPEC 130: Windows 386/amd64 builds; the run on Windows 7 is with the reporter.

## 🆕 Что нового

### ⬆️ `sing-box lxd update`: ядро обновляет себя само на Linux

- Было: обновить ядро на роутере — это SSH: найти нужный ассет, скачать, сверить, остановить, подменить, запустить.
- Стало: одна команда. Бинарь знает свой путь, версию, релизный ассет (`linux-armv7`, `linux-mipsle-softfloat`, …) и init хоста (`procd` / `systemd` / `openrc`).
- Источник — `SHA256SUMS` последнего stable-релиза (`--prerelease` — самого нового). Та же версия → `already up to date`; установленная более новая версия не откатывается. Нужно свободного места ≥ 1,1 × размер архива.
- Архив пишется потоком в `<бинарь>.new` на той же ФС (в `/tmp` ничего), сумма сверяется, новый бинарь должен пройти `version` и `check -c last_good.json`, затем атомарный `rename` (старый остаётся как `.old`).
- Рестарт через найденный init; служба должна подняться за 15 с и продержаться 3 с, иначе возвращается старый бинарь (код выхода 2). Если упала сама команда рестарта или init не распознан, новый бинарь остаётся, команда просит перезапустить вручную.
- Флаги: `--dry-run`, `--no-restart`, `--service`. Прокси — `HTTPS_PROXY` / `ALL_PROXY`. Репозиторий зашит в бинарь.
- `sing-box version` дополнительно печатает `Platform:`, `Init:`, `Update:`. Инсталлятор OpenWrt регистрирует `update` как команду демона — это кнопка Update в лаунчере. (SPEC 129)

### 🛠️ Именованные root-команды в `daemon.json`

- Было: демон под root не исполняет код клиента, поэтому обновить ядро или перезапустить службу из лаунчера было нельзя.
- Стало: оператор перечисляет команды на хосте: `"commands": {"update": "/usr/bin/sing-box lxd update"}`. Клиент только выбирает имя — ни аргументов, ни ввода он не передаёт.
- API: `GET /admin/commands` (список и последний исход), `POST /admin/commands/{name}` (`202` / `404` / `409`), `GET /admin/commands/{name}` (статус и последние 64 КиБ лога). Авторизация та же, что у остальных admin-маршрутов.
- Команда запускается отвязанно, поэтому рестарт службы её не убивает; исход (`done` / `running` / `lost`) переживает рестарт демона. Окружение: `LXD_PLATFORM`, `LXD_VERSION`, `LXD_INIT_SYSTEM`, `LXD_STATE_DIR`, `LXD_BIN`, `LXD_CLIENT`.
- Имена: `[a-z0-9][a-z0-9_-]{0,31}`; плохое имя или пустая команда — демон не стартует. Только Unix; на Windows ключ игнорируется с предупреждением. (SPEC 128)

### 🪪 `GET /admin/info` сообщает платформу и init-систему

- Новые поля: `goos`, `goarch`, `platform` (суффикс релизного ассета для этого бинаря, например `linux-armv7`, `windows-386-legacy-windows-7`), `init_system` (`procd` / `systemd` / `openrc` / `launchd` / `scm`, пусто — не распознан) и `service` (запущен ли этот процесс службой).
- Лаунчеру больше не нужна платформа, введённая руками (ошибочная запись `amd64` скачала бы чужое ядро). Определение init теперь распознаёт и `openrc`. (SPEC 127)

### 🪟 Windows 7: ядро не запускалось с lx.14
