All fork-wide knobs now live in one root `lx` config block; the old `route.lx_idle_*` keys still work for one release with a warning. WireGuard/AmneziaWG endpoints can start without a device and build it on the first dial, with a cap on how many devices exist at once, so a profile with a dozen tunnels no longer holds ~17.5 MB per tunnel from start-up. Apps can tell "not built yet" from "dead" through a new endpoint state field. A successful UDP GSO fallback on the handshake path no longer prints an ERROR.

Глобальные ручки форка собраны в корневом блоке конфига `lx`; старые ключи `route.lx_idle_*` ещё принимаются один релиз с предупреждением. WireGuard/AmneziaWG-узлы могут стартовать без устройства и собирать его при первом обращении, с потолком одновременно собранных устройств: профиль с дюжиной туннелей больше не держит ≈17.5 МБ на туннель с момента старта. Приложение отличает «не поднят» от «мёртв» по новому полю состояния узла. Успешная переотправка хендшейка без UDP GSO больше не печатается как ERROR.

## 🆕 What's new

### 🧩 Root `lx` config block

- All fork-wide settings are grouped under a root `lx` block by subsystem: `lx.wg` (WireGuard/AmneziaWG endpoints) and `lx.masque` (MASQUE outbounds). Per-node settings stay in their nodes, as upstream does.
- `lx.wg.idle_suspend`, `lx.wg.idle_suspend_reachable`, `lx.wg.idle_teardown` replace `route.lx_idle_suspend` / `_reachable` / `_teardown`. Same semantics. The old keys are accepted for this release with a WARN per key; the same value in both places is a WARN, a different value is a start error naming both keys.
- `lx.masque.idle_timeout` is a global idle window for every `masque` outbound without its own `idle_timeout`. The node's key wins; an explicit `"0"` in a node keeps that tunnel up whatever the global value.
- Validation errors name the full key path. An unknown key or sub-block is an error, not a silent default. Running-config always shows the block in canonical `lx.*` form. ([SPEC 098](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/098-LX_ROOT_CONFIG_BLOCK/SPEC.md))

### 💤 WireGuard/AmneziaWG: lazy device build and a build cap

- `lx.wg.lazy_build: true` — endpoints start without a device (the detour is still resolved at start); the first dial builds it. Endpoints with `listen_port` are not affected. Every device held ~17.5 MB of buffers from start-up before; 11 endpoints held 192 MB.
- `lx.wg.build_max: N` — at most N devices exist at once. Building the (N+1)-th first tears down a victim: fewest manual references (selector choice, `final`, rule target) → fewest automatic references (urltest pool, detour, chain, DNS detour) → longest since its last dial. A node with a dial in flight, a live TCP flow or ≥ 4096 B of traffic since the previous check is never torn down. `0` = no cap (default).
- `lx.wg.build_overflow` — when every device is busy: `wait` (default) waits up to the dial deadline, at most 15 s; `build` builds over the cap with a warning.
- Mobile builds only (`with_lx_idle_suspend`); a desktop build refuses any `lx.wg` key at start. ([SPEC 097](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/097-LAZY_WG_DEVICE_BUILD/SPEC.md))

### 👁 Endpoint state in `GetOutbounds`

- `GroupItem` gains `endpointState` (`never_built` / `building` / `up` / `asleep` / `torn_down` / `down`) and `idleSinceSeconds` for WireGuard/AmneziaWG endpoints; empty for other outbounds. libbox `OutboundGroupItem` carries `EndpointState` and `IdleSinceSeconds`. "Not built yet" is a state to show, not a timeout.

## 🐛 Fixed

### 🔇 Handshake retry without UDP GSO logged as ERROR

- Was: after the kernel rejected UDP GSO, the socket disabled offload and resent the handshake without it, yet the log said `ERROR … failed to send handshake initiation: disabled UDP GSO on …` although the packet had gone out.
- Now: a successful resend is a Verbose line; ERROR appears only when the resend itself failed. The data path already behaved this way. Wire unchanged. ([SPEC 101](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/101-WG_HANDSHAKE_GSO_RETRY_LOG_NOISE/SPEC.md))

## 🆕 Что нового

### 🧩 Корневой блок конфига `lx`

- Все глобальные ручки форка собраны в корневом блоке `lx` по подсистемам: `lx.wg` (WireGuard/AmneziaWG-узлы) и `lx.masque` (MASQUE-outbound'ы). Настройки конкретного узла остаются в узле, как в апстриме.

Старые ключи в этом релизе принимаются с WARN на каждый; одинаковое значение в двух местах — WARN, разное — ошибка старта с обоими ключами в тексте.
- `lx.masque.idle_timeout` — глобальное окно простоя для всех `masque`-узлов без своего `idle_timeout`. Ключ узла сильнее; явный `"0"` в узле держит туннель поднятым при любом глобальном значении.
- Ошибки валидации называют полный путь ключа. Неизвестный ключ или подблок — ошибка, не тихий дефолт. Running-config отдаёт блок в канонической форме `lx.*`. ([SPEC 098](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/098-LX_ROOT_CONFIG_BLOCK/SPEC.md))

### 💤 WireGuard/AmneziaWG: ленивая сборка устройства и потолок

- `lx.wg.lazy_build: true` — узлы стартуют без устройства (detour резолвится на старте), устройство собирается первым обращением. Узлы с `listen_port` не затрагиваются. Раньше каждое устройство держало ≈17.5 МБ буферов с момента старта: 11 узлов — 192 МБ.
- `lx.wg.build_max: N` — одновременно собрано не больше N устройств. Сборка (N+1)-го сначала разбирает жертву: меньше ручных ссылок (выбор селектора, `final`, цель правила) → меньше автоматических (пул urltest, detour, цепочка, DNS-detour) → дольше всех без обращений. Узел с обращением в процессе, живым TCP-потоком или ≥ 4096 Б трафика с прошлой проверки не разбирается. `0` = без потолка (дефолт).
- `lx.wg.build_overflow` — когда все устройства заняты: `wait` (дефолт) ждёт до дедлайна обращения, не дольше 15 с; `build` собирает сверх потолка с предупреждением.
- Только мобильные сборки (`with_lx_idle_suspend`); десктопная отвергает любой ключ `lx.wg` на старте. ([SPEC 097](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/097-LAZY_WG_DEVICE_BUILD/SPEC.md))

### 👁 Состояние узла в `GetOutbounds`

- В `GroupItem` добавлены `endpointState` (`never_built` / `building` / `up` / `asleep` / `torn_down` / `down`) и `idleSinceSeconds` для WireGuard/AmneziaWG-узлов; у остальных outbound'ов пусто. В libbox `OutboundGroupItem` — `EndpointState` и `IdleSinceSeconds`. «Ещё не собран» — состояние для показа, не таймаут.
