The core is synced with sing-box `stable` (15 commits past v1.14.2): connections that nothing refers to any more are closed when idle, the `udp_fragment` default now really allows fragmentation on Linux and Android, and several TUN and DNS fixes arrive. Configs are unchanged.

Ядро синхронизировано с `stable` sing-box (15 коммитов после v1.14.2): простаивающие соединения, на которые больше никто не ссылается, закрываются; дефолт `udp_fragment` теперь действительно разрешает фрагментацию на Linux и Android; пришли исправления TUN и DNS. Конфиги не меняются.

<summary><h2>🇬🇧 English</h2></summary>

## 🔧 Changed

### 🔌 Idle connections of unused nodes are closed

- Was: an outbound or DNS server kept its idle connections (multiplex sessions, QUIC sessions, DNS connections) even when no rule and no group selection pointed at it any more.
- Now: the core tracks what is in use: route and DNS rules, endpoints, the selected node of a `selector` or `urltest`, detours. Everything else has its idle connections closed. On Android, pausing the device closes idle connections too.
- A `urltest` group in `round_robin` mode counts its whole pool as in use, not one node.
- Not affected: XHTTP with `xmux` keeps its own pool rules; WireGuard and AmneziaWG idle-suspend works as before.

### 📦 Nested tunnels: fragmentation is really allowed on Linux and Android

- Was: WireGuard, AmneziaWG and `masque` leave the outer UDP socket free to fragment by default, but on Linux and Android the option was never set and the kernel kept the DF bit on its own. An oversized outer datagram of a tunnel inside a tunnel was dropped.
- Now: the socket option is set explicitly. `"udp_fragment": false` still forces DF.
- Hysteria, Hysteria2 and TUIC no longer allow fragmentation by default (upstream change): QUIC finds the path MTU itself.

## 🐛 Fixed

### 🧱 TUN and DNS fixes from upstream

- OpenVPN and OpenConnect on a system TUN interface: a write error no longer stops the read loop.
- GSO on the TUN inbound is enabled by what an endpoint can actually carry, not by its network list.
- The local DNS server honours the global DNS servers of systemd-resolved.
- Switching a nested `selector` no longer closes connections while holding the group lock. This is the fix the fork has carried since `v1.14.0-lx.38`; it is now upstream's.

## 🔧 Изменено

### 🔌 Простаивающие соединения неиспользуемых узлов закрываются

- Было: outbound или DNS-сервер держал простаивающие соединения (сессии мультиплекса, QUIC-сессии, DNS-соединения), даже когда на него уже не указывало ни одно правило и ни один выбор группы.
- Стало: ядро отслеживает, что используется: правила маршрутизации и DNS, endpoint'ы, выбранный узел `selector` и `urltest`, detour. У всего остального простаивающие соединения закрываются. На Android их закрывает и пауза устройства.
- Группа `urltest` в режиме `round_robin` считает используемым весь пул, а не один узел.
- Не затронуто: XHTTP с `xmux` живёт по своим правилам пула; idle-suspend WireGuard и AmneziaWG работает как раньше.

### 📦 Вложенные туннели: фрагментация действительно разрешена на Linux и Android

- Было: WireGuard, AmneziaWG и `masque` по умолчанию оставляют внешнему UDP-сокету право фрагментировать, но на Linux и Android опция не ставилась вовсе, и ядро само держало бит DF. Слишком большая внешняя датаграмма туннеля внутри туннеля отбрасывалась.
- Стало: опция сокета ставится явно. `"udp_fragment": false` по-прежнему включает DF.
- Hysteria, Hysteria2 и TUIC больше не разрешают фрагментацию по умолчанию (изменение апстрима): QUIC сам находит MTU пути.

## 🐛 Исправлено

### 🧱 Исправления TUN и DNS из апстрима

- OpenVPN и OpenConnect на системном TUN-интерфейсе: ошибка записи больше не останавливает цикл чтения.
- GSO на TUN-inbound включается по тому, что endpoint реально умеет нести, а не по списку его сетей.
- Локальный DNS-сервер учитывает глобальные DNS-серверы systemd-resolved.
- Переключение вложенного `selector` больше не закрывает соединения под замком группы. Это исправление форк нёс сам с `v1.14.0-lx.38`; теперь оно апстримное.
