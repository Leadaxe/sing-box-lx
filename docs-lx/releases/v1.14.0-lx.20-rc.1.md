## 🔧 Changed

### 🏗️ Every build job pins the Go 1.25.x toolchain

Until now the desktop, router and lint jobs took their Go from `go.mod`
(`go 1.24.7`). That line is the *language floor* the fork keeps for upstream
parity — not a choice of build toolchain. Upstream itself pins **1.25.x** in
every release job of its own workflow, so this fork was the only party
shipping go1.24 binaries.

That is the same toolchain that made every quic-go outbound
(hysteria2/tuic/masque-h3) hang on some vendor Android kernels — the AAR was
already pinned away from it in the previous release. It is also below the gate
upstream put on `badtls`, which needs `go1.25 && badlinkname`, so desktop
binaries were quietly shipping it as a stub.

All twelve build jobs across the three workflows now pin `go-version: '1.25.x'`,
and the Android AAR moves from `1.26.x` down to that same line — one toolchain
across the whole CI, and the line upstream actually ships. The defect
threshold from the vendor-kernel case is ">= 1.25", and both 1.25.5 and 1.26.5
are device-verified, so this stays inside proven ground. `go.mod` is unchanged.
The Windows 7 build is untouched — it builds its own patched toolchain from
the go1.25 release branch. Desktop binaries gain active `badtls` for the first
time. (SPEC 044)

## 🔧 Изменено

### 🏗️ Все сборочные джобы пинят тулчейн Go 1.25.x

До сих пор desktop-, роутерные и lint-джобы брали Go из `go.mod`
(`go 1.24.7`). Эта строка — *языковой минимум*, который форк держит ради
паритета с upstream, а не выбор сборочного тулчейна. Сам upstream во всех
своих релизных джобах пинит **1.25.x**, так что форк оказался единственным,
кто отгружал бинарники на go1.24.

Это ровно тот тулчейн, из-за которого все quic-go-аутбаунды
(hysteria2/tuic/masque-h3) висели на части вендорских Android-ядер — AAR от
него увели ещё в прошлом релизе. Он же ниже гейта, который upstream поставил
на `badtls` (`go1.25 && badlinkname`), поэтому desktop-бинари тихо отгружались
с заглушкой вместо него.

Теперь все двенадцать сборочных джоб в трёх воркфлоу пинят
`go-version: '1.25.x'`, а Android-AAR опускается с `1.26.x` на ту же линию —
один тулчейн на весь CI, и именно тот, который отгружает upstream. Порог
дефекта из истории с вендорскими ядрами — «>= 1.25», а на устройстве
проверены и 1.25.5, и 1.26.5, так что мы остаёмся внутри проверенного.
`go.mod` не тронут. Сборка под Windows 7 не затронута — она строит свой
патченный тулчейн из релизной ветки go1.25. Desktop-бинари впервые получают
активный `badtls`. (SPEC 044)
