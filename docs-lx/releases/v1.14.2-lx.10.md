Tailscale nodes pass traffic to peers over a direct UDP path again. Before this release, a node could see its peers and ping them, but TCP connections to a peer on the same network timed out after 15 seconds once the direct path was chosen. Configs are unchanged.

Узлы Tailscale снова передают трафик пирам по прямому UDP-пути. До этого релиза узел видел пиров и пинговал их, но TCP-соединения к пиру в той же сети обрывались через 15 секунд, как только выбирался прямой путь. Конфиги не меняются.

## 🐛 Fixed

### 🕸️ Tailscale: traffic to a peer over a direct path

- Was: as soon as the node found a direct UDP path to a peer (for example, both on the same Wi-Fi), every WireGuard packet to that peer failed to send. The node looked healthy: status running, peer list filled, the built-in peer ping answered. Connections to the peer ended with `context deadline exceeded`. Traffic through DERP relays worked, so a node behind `detour` was not affected. The error was only visible at the `trace` log level: `RebindingUDPConn.WriteWireGuardBatchTo: [unexpected] offset (0) != Geneve header length (8)`.
- Cause: our AmneziaWG changes to wireguard-go removed 8 bytes of free space in front of each outgoing packet. The Tailscale node uses the same wireguard-go, and on a direct path it needs that space.
- Now: the space is back on every send path. WireGuard and AmneziaWG (2.0 and 3.x) nodes send the same bytes on the wire as before (SPEC 112, [#33](https://github.com/Leadaxe/sing-box-lx/issues/33)).

## 🐛 Исправлено

### 🕸️ Tailscale: трафик к пиру по прямому пути

- Было: как только узел находил прямой UDP-путь к пиру (например, оба в одной Wi-Fi), каждый пакет WireGuard к этому пиру не отправлялся. Снаружи узел выглядел исправным: статус running, список пиров заполнен, встроенный пинг пира отвечал. Соединения к пиру заканчивались `context deadline exceeded`. Через ретрансляторы DERP трафик шёл, поэтому узел за `detour` не страдал. Ошибка была видна только на уровне лога `trace`: `RebindingUDPConn.WriteWireGuardBatchTo: [unexpected] offset (0) != Geneve header length (8)`.
- Причина: наши правки AmneziaWG в wireguard-go убрали 8 свободных байт перед каждым исходящим пакетом. Узел Tailscale использует тот же wireguard-go, и на прямом пути ему это место нужно.
- Стало: запас возвращён на всех путях отправки. Узлы WireGuard и AmneziaWG (2.0 и 3.x) отправляют в сеть те же байты, что и раньше (SPEC 112, [#33](https://github.com/Leadaxe/sing-box-lx/issues/33)).
