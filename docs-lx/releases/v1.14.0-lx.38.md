## 🆕 What's new

### 🤖 Tailscale in the Android core

- Was: `with_tailscale` was in every desktop and router binary since lx.32, but stripped from the Android AAR — LxBox had no Tailscale UI and it is the heaviest dependency in the APK.

- LxBox gates Tailscale nodes on core `1.14.0-lx.38` or newer; on an older core the node is skipped with a warning and the rest of the config still builds.
- Unchanged: desktop and router binaries and their tag set, configuration, wire format, the upstream base (sing-box `v1.14.0` + 33). (FEATURE 001, SPEC 004)

## 🐛 Fixed

### 🔒 Switching a nested selector could freeze all traffic until restart

- Was: chain `selector → selector → node` with `interrupt_exist_connections: true` on the inner selector, plus any connection dialed through the outer one (DoH with `detour`, rule-set `download_detour`, an outbound with `detour` to the outer group). Switching the inner selector (Clash API, LxBox, launcher) at the moment such a connection was being closed deadlocked both groups: new TCP and UDP connections hung at registration, later switches hung too, the UI already showed the new tag. Only a restart helped. Reported from OpenWrt (issue #20): after one switch 67 goroutines were parked on the two locks.
- Cause: the connection group closed underlying connections while holding its own lock. Nested selectors wrap an inbound connection outer-then-inner and a dialed one inner-then-outer, so the two `Close` paths took the two locks in opposite orders — a classic ABBA deadlock. Regression of this fork since lx.25 (the inbound wrapper that made `interrupt_exist_connections` reach inbound traffic); upstream has no such nesting and is not affected.
- Now: the lock is held only while the registry is updated; connections are closed after it is released. Nesting order is irrelevant. `interrupt_exist_connections` semantics are unchanged: it still decides whether external connections are cut on a switch.
- Verified: a unit test on all three wrapper kinds and an end-to-end test on real nested selectors; both fail by timeout on the old code and pass on the new one, race detector clean.
- Unchanged: config, single (non-nested) selectors, `urltest`, `chain`.
- Workaround for older builds: `interrupt_exist_connections: false` on the inner selector avoids the switch path, but a narrow window remains when two such connections close at the same moment. (SPEC 084)

## 🐛 Исправлено

### 🔒 Переключение вложенного selector'а могло заморозить весь трафик до рестарта

- Было: цепочка `selector → selector → узел` с `interrupt_exist_connections: true` у внутреннего selector'а плюс любое соединение, поднятое через внешний (DoH с `detour`, `download_detour` rule-set'ов, outbound с `detour` на внешнюю группу). Переключение внутреннего selector'а (Clash API, LxBox, лаунчер) в момент закрытия такого соединения блокировало обе группы: новые TCP- и UDP-соединения вставали на регистрации, следующие переключения тоже висли, UI при этом уже показывал новый тег. Помогал только рестарт. Отчёт с OpenWrt (issue #20): после одного переключения 67 goroutine стояли на двух замках.
- Причина: группа соединений закрывала нижележащие соединения, удерживая собственный замок. Вложенные selector'ы оборачивают входящее соединение «внешний, затем внутренний», а исходящее — «внутренний, затем внешний», поэтому два пути `Close` брали два замка в противоположном порядке — классический ABBA-дедлок. Регресс форка с lx.25 (обёртка входящего, благодаря которой `interrupt_exist_connections` стал доставать до inbound-трафика); у апстрима такой вложенности нет, он не затронут.
- Стало: замок удерживается только на время правки реестра; соединения закрываются после его освобождения. Порядок вложенности безразличен. Семантика `interrupt_exist_connections` не менялась: она по-прежнему решает, рвать ли внешние соединения при переключении.
- Проверено: юнит-тест на всех трёх видах обёрток и e2e-тест на настоящих вложенных selector'ах; оба падают по таймауту на старом коде и проходят на новом, race detector чист.
- Не меняется: конфиг, одиночные (невложенные) selector'ы, `urltest`, `chain`.
- Обход для старых сборок: `interrupt_exist_connections: false` у внутреннего selector'а убирает путь через переключение, но узкое окно при одновременном закрытии двух таких соединений остаётся. (SPEC 084)
