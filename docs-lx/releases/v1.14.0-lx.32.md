## 🆕 What's new

### 🛡️ AmneziaWG 3.0 / 3.1 endpoints

An AWG 3.x server (Amnezia's `amnezia-awg2` container, `protocol_version 3.1`) encrypts the header of every packet, so an AWG2 client could not even recognise its handshake response. The `wireguard` endpoint now speaks the full AWG 3.1 set, byte-compatible with amneziawg-go v3.1:

- `header_protection_key` — the server's 32-byte base64 key (`HeaderProtectionKey` in the `.conf`, `awg genkey`). Server-side: must match. Requires each of `s1`–`s4` ≥ 12; `sing-box check` refuses a shorter padding, a malformed or an all-zero key, naming the field.
- `content_padding_addition` — `"min-max"` bytes of extra padding inside every data packet, replacing the multiple-of-16 pad.
- `random_trailers` — random-length tails on handshake messages and inside data packets, so no message kind has a fixed size.
- `disable_cookies` — no cookie replies and no under-load mac2 gate.
- `rekey_after_time`, `rekey_timeout`, `reject_after_time`, `keepalive_timeout`, `max_handshake_attempts` — `"min-max"` overrides of the WireGuard timing constants (seconds / attempts), re-picked from the range at every use. Unset = WireGuard defaults 120 / 5 / 180 / 10 / 18.
- `peers[].persistent_keepalive_interval` — a plain number as before, or an AWG3 range such as `"25-35"`.
- Every ranged field takes a JSON number or a `"min-max"` string; `h1`–`h4` may stay at `1`–`4` (AWG3 exports do) because the header cipher already masks the type word.
- Mapping from `.conf` / `vpn://` is 1:1; example configs and the field reference are in `docs-lx/lx-protocols-transports.md` §2.10. Tag `with_awg` as for AWG2; without it the new fields (and a ranged keepalive) are rejected, a numeric keepalive still works. (SPEC 080)

## 🔧 Changed

### 📐 AWG transport packets are assembled in place

The `s4` padding, the header and the sealed content of a data packet are built in one buffer on every send path (TUN, gVisor injection, keepalive, priority message), which the header cipher requires. A batch read from the TUN before the device configuration was applied is relocated under the current `s4` instead of leaving with the old layout. Plain WireGuard is byte-identical to before; AWG2 endpoints keep their wire format (verified with ranged `h1`–`h4`, `s1`–`s4` and `i1`).

## 🆕 Что нового

### 🛡️ Endpoint'ы AmneziaWG 3.0 / 3.1

Сервер AWG 3.x (контейнер Amnezia `amnezia-awg2`, `protocol_version 3.1`) шифрует заголовок каждого пакета, поэтому AWG2-клиент не мог даже распознать его ответ на хендшейк. `wireguard`-endpoint теперь говорит на полном наборе AWG 3.1, байт-совместимо с amneziawg-go v3.1:

- `header_protection_key` — 32-байтный base64-ключ сервера (`HeaderProtectionKey` в `.conf`, `awg genkey`). Серверный параметр: обязан совпадать. Требует `s1`–`s4` ≥ 12; `sing-box check` отвергает более короткий паддинг, битый или нулевой ключ, называя поле.
- `content_padding_addition` — `"min-max"` байт дополнительного паддинга внутри каждого data-пакета вместо выравнивания по 16.
- `random_trailers` — хвосты случайной длины у handshake-сообщений и внутри data-пакетов: ни у одного вида сообщения нет фиксированного размера.
- `disable_cookies` — без cookie reply и без under-load-гейта mac2.
- `rekey_after_time`, `rekey_timeout`, `reject_after_time`, `keepalive_timeout`, `max_handshake_attempts` — `"min-max"`-переопределения констант таймингов WireGuard (секунды / попытки), перевыбираются из диапазона при каждом использовании. Не заданы = дефолты WireGuard 120 / 5 / 180 / 10 / 18.
- `peers[].persistent_keepalive_interval` — число как раньше или AWG3-диапазон вида `"25-35"`.
- Любое диапазонное поле принимает JSON-число или строку `"min-max"`; `h1`–`h4` можно оставить `1`–`4` (так делают экспорты AWG3): шифр заголовка и так маскирует слово типа.
- Маппинг из `.conf` / `vpn://` 1:1; примеры и справочник полей — `docs-lx/lx-protocols-transports.ru.md` §2.10. Тег `with_awg`, как у AWG2; без него новые поля (и диапазонный keepalive) отвергаются, числовой keepalive работает. (SPEC 080)

## 🔧 Изменено

### 📐 Transport-пакеты AWG собираются in-place

Паддинг `s4`, заголовок и зашифрованное содержимое data-пакета строятся в одном буфере на всех путях отправки (TUN, инжекция gVisor, keepalive, приоритетное сообщение) — этого требует шифр заголовка. Батч, прочитанный из TUN до применения конфига устройства, переносится под актуальный `s4`, а не уходит в старой раскладке. Обычный WireGuard байт-в-байт как раньше; AWG2-endpoint'ы сохраняют формат на проводе (проверено с диапазонными `h1`–`h4`, `s1`–`s4` и `i1`).
