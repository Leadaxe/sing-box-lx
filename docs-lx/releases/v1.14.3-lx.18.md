The legacy `network` key of the `masque` outbound is gone. Since the schema migration it only duplicated `vhttp` (the HTTP version, h3/h2) under a name that means the tcp/udp list on every other outbound. A masque outbound that still carries `network` no longer loads: the core reports `outbounds[N].network: json: unknown field "network"` — rename the key to `vhttp`, the values are the same. LxBox and the launcher have written `vhttp` for a long time and are not affected; the flat TLS aliases (`sni`, `skip_cert_verify`, `fragment*`) still work with a deprecation warning.

## 🔧 Changed

### 🧹 `masque`: the legacy `network` key is no longer accepted

- Before: `network: "h3"` / `"h2"` was read as an alias of `vhttp` with a deprecation warning; a disagreeing pair was an error.
- Now: the key does not exist on the masque outbound. A config carrying it fails to load like any unknown outbound field: `decode config at …: outbounds[N].network: json: unknown field "network"`.
- Fix: rename `network` to `vhttp` (`h3`, `h2` or `auto`). The tcp/udp list stays `network_list`; no new meaning is given to `network`.
- Not affected: configs written by LxBox or the launcher (they emit `vhttp` and strip `network` before the core); the flat TLS aliases `sni`, `skip_cert_verify`, `fragment`, `fragment_fallback_delay`, `record_fragment` — still accepted with one deprecation line per outbound. (SPEC 131)

## 🧰 Under the hood

- Base: sing-box `v1.14.3`, zero drift from `upstream/stable`; submodules and dependencies unchanged since lx.17. Go 1.26.8.
- Verified by the unit tests of the masque option resolution and a live `sing-box check` on both shapes: the legacy one is rejected with the message above, the `vhttp` one decodes.
