## 🐛 Fixed

### ⏱️ WireGuard connect now times out in 15 s (was ~127 s)

TCP dials through a WireGuard/AmneziaWG node's netstack had no timeout at any
layer. On a silent blackhole (network dropping the tunnel's UDP, node down)
each dial waited out gVisor's SYN backoff — 1+2+4+8+16+32+64 = ~127 s — with no
error. Domain destinations retried per resolved address: up to N×127 s.

Now bounded by a one-shot 15 s connect deadline, released as soon as the
connection is established (established connections and downloads are never
affected). 15 s matches the health-check budget, so a node cannot pass probes
while user dials time out; measured legitimate worst case is 4.8 s local,
8–10 s mobile. Per-address budget in serial dials. UDP unchanged.

Also applied to OpenVPN, OpenConnect and Tailscale endpoints (same defect).
Upstream behaviour, not an lx regression. (SPEC 052)

### 🎯 Auto-select groups leave a dead node on failure

`urltest` in the default mode reconsidered its selection only at the end of a
probe run — up to `interval` (default 3 min), longer with `passive_check`.
Dial failures changed nothing.

Now:

- Path-dead failures (connect timeout, `EHOSTUNREACH`/`ENETUNREACH`/`ETIMEDOUT`)
  → node gets +1 penalty and the request retries once through the next best
  node. Max 2 attempts per dial; a successful retry moves the group's selection
  there, without interrupting existing connections.
- `ECONNREFUSED`/`ECONNRESET` and caller cancellation → no penalty, no retry.
- Fastest node at 3 penalties → ranking switches to penalties ascending, then
  delay (ties compete on speed as usual).
- Penalties clear only on proof of life: successful dial or answered probe.
  Never on a timer.
- All candidates penalised → forced probe run, at most once per 2 min, measured
  from the end of the previous run.
- `passive_check` probe-skip is disabled while the penalty ranking is active.

No new timers — all checks are timestamp deltas evaluated on events, so device
sleep and process freezing cannot desynchronise them. `round_robin` unaffected;
UDP accrues no penalties but uses the shared selection. (SPEC 054)

### 🔒 REALITY: announce client version 26.3.27

Xray v26.7.11 defaults `minClientVer` to `26.3.27`; sing-box announced `1.8.1`
(hardcoded since 2023) and was silently proxied to the camouflage `dest` — no
error, node simply appears broken. Announced version now matches the required
minimum; comparison is `>=`, so older servers are unaffected. (SPEC 053)

## 🐛 Исправлено

### ⏱️ Таймаут соединения через WireGuard — 15 с (было ~127 с)

TCP-дайлы через netstack WireGuard/AmneziaWG-узла не имели таймаута ни на одном
слое. На тихой чёрной дыре (сеть режет UDP туннеля, узел выключен) каждый дайл
отстаивал SYN-бэкофф gVisor — 1+2+4+8+16+32+64 = ~127 с — без ошибки. Доменные
назначения перебирали адреса по очереди: до N×127 с.

Теперь ограничено одноразовым connect-дедлайном 15 с, который снимается сразу
после установки соединения (установленные соединения и загрузки не затрагиваются
никогда). 15 с совпадает с бюджетом проверки здоровья — узел не может проходить
пробы, пока пользовательские дайлы падают по таймауту; замеренный легитимный
максимум 4.8 с локально, 8–10 с на мобильной сети. В серийных дайлах бюджет на
каждый адрес отдельный. UDP не затронут.

Применено также к эндпоинтам OpenVPN, OpenConnect и Tailscale (тот же дефект).
Апстримное поведение, не регрессия lx. (SPEC 052)

### 🎯 Группы с автовыбором уходят с мёртвого узла по отказу

`urltest` в режиме по умолчанию пересматривал выбор только в конце пробного
прогона — до `interval` (по умолчанию 3 мин), дольше с `passive_check`. Отказы
дайлов не меняли ничего.

Теперь:

- Отказы класса «путь мёртв» (таймаут соединения,
  `EHOSTUNREACH`/`ENETUNREACH`/`ETIMEDOUT`) → узлу +1 штраф, запрос один раз
  повторяется через следующий по качеству узел. Максимум 2 попытки на дайл;
  успешный повтор переносит туда выбор группы, не разрывая существующие
  соединения.
- `ECONNREFUSED`/`ECONNRESET` и отмена вызывающим → без штрафа и без повтора.
- 3 штрафа у самого быстрого узла → ранжирование переключается на «штрафы по
  возрастанию, затем задержка» (равные по штрафам соревнуются по скорости).
- Штрафы снимаются только доказательством жизни: успешный дайл или ответ на
  пробу. Никогда по таймеру.
- Оштрафованы все кандидаты → принудительный прогон проб, не чаще раза в 2 мин,
  отсчёт от конца предыдущего прогона.
- Пропуск проб по `passive_check` отключён, пока действует штрафное
  ранжирование.

Новых таймеров нет — все проверки считаются дельтами меток времени в момент
события, поэтому сон устройства и заморозка процесса их не сбивают. `round_robin`
не затронут; UDP штрафов не копит, но пользуется общим выбором. (SPEC 054)

### 🔒 REALITY: объявляемая версия клиента 26.3.27

Xray v26.7.11 по умолчанию ставит `minClientVer` = `26.3.27`; sing-box объявлял
`1.8.1` (зашито с 2023 года) и молча проксировался на камуфляжный `dest` — без
ошибки, узел просто выглядит нерабочим. Объявляемая версия теперь совпадает с
требуемым минимумом; сравнение `>=`, поэтому старые серверы не затронуты.
(SPEC 053)
