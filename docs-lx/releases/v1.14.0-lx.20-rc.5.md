This pre-release brings the fork up to date with two months of upstream
sing-box work — 235 commits of fixes and improvements, including a TUN deadlock,
a DNS routing race, and several WireGuard corrections. OpenVPN and OpenConnect
are now available as connection types, and the network stack underneath was
updated as well.

Этот пререлиз подтягивает форк к текущему состоянию upstream sing-box — 235
коммитов исправлений за два месяца, среди них дедлок в TUN, гонка в
DNS-маршрутизации и несколько исправлений WireGuard. Появились OpenVPN и
OpenConnect как типы подключения, и обновлён сетевой стек под капотом.

## 🆕 What's new

### 🔌 OpenVPN and OpenConnect connections

Upstream added both protocols, and this build enables them. You can now point a
configuration at an OpenVPN or OpenConnect server the same way you would at any
other node type: `openvpn-client` and `openconnect`. Upstream ships client and
server behind a single build flag, so the server side comes along; nothing runs
unless a configuration asks for it.

These are new arrivals, not something the fork has field experience with — treat
them as untested until you have run them yourself.

## 🔧 Changed

### 🔄 Two months of upstream fixes are now in

The fork tracks SagerNet's sing-box, and that base had moved 235 commits ahead.
This release closes that gap entirely. Most of it is invisible plumbing, but a
few things matter in daily use: a deadlock in the TUN packet dispatcher, a race
in DNS rule matching where one rule could block another, DNS suffix matching and
TCP DNS retries, and several WireGuard corrections around peer lookup and packet
batching.

Everything the fork adds on top — AmneziaWG, XHTTP, the post-quantum VLESS
layer, node balancing, the idle power saving, DNS groups — is unchanged and was
verified piece by piece after the merge. Upstream features outside a VPN
client's job (OpenVPN, OpenConnect, USB/IP, bridges, desktop-only builds) are
deliberately not compiled in, as before.

Nothing in this release changes how the app behaves for you. It exists so the
next feature lands on a current base instead of a two-month-old one. (SPEC 051)

### 🧱 The network stack under the tunnel was updated too

The user-space network stack the tunnel runs on (gVisor) had been pinned to a
version from last summer; it is now on the one upstream expects. Among the year
of fixes that brings, one is worth naming: connections used to start with an
inflated retransmission timeout when the initial acknowledgement was delayed
inside the stack, and that inflated value persisted for several round trips.
Path MTU discovery was improved as well. Our own guard against a crash on
connections to unreachable nodes was carried over — upstream has not fixed that
one.

<summary><h2>🇷🇺 Русский</h2></summary>

## 🆕 Что нового

### 🔌 Подключения OpenVPN и OpenConnect

Upstream добавил оба протокола, и в этой сборке они включены. Теперь можно
указать в конфигурации сервер OpenVPN или OpenConnect так же, как узел любого
другого типа: `openvpn-client` и `openconnect`. Upstream держит клиент и сервер
за одним флагом сборки, поэтому серверная часть идёт следом; ничего не
запускается, пока этого не попросит конфигурация.

Это новинка, полевого опыта с ней у форка нет — считайте её непроверенной, пока
не прогоните сами.

## 🔧 Изменено

### 🔄 Подтянуты два месяца исправлений upstream

Форк живёт поверх sing-box от SagerNet, и эта база ушла вперёд на 235 коммитов.
Релиз закрывает разрыв целиком. Большая часть — невидимая внутренняя работа, но
кое-что заметно в повседневном использовании: дедлок в обработчике пакетов TUN,
гонка при сопоставлении DNS-правил, когда одно правило могло блокировать другое,
исправления сопоставления DNS-суффиксов и повторов TCP-DNS, а также несколько
исправлений WireGuard — поиск пира и пакетная обработка.

Всё, что форк добавляет сверху, — AmneziaWG, XHTTP, постквантовый слой VLESS,
балансировка нод, энергосбережение в простое, DNS-группы — не изменилось и было
проверено поштучно после слияния. Возможности upstream за рамками задач
VPN-клиента (OpenVPN, OpenConnect, USB/IP, мосты, сборки только для десктопа) в
сборку по-прежнему не входят.

На поведение приложения этот релиз не влияет. Он нужен, чтобы следующая
функция ложилась на актуальную базу, а не на двухмесячной давности. (SPEC 051)


### 🧱 Обновлён и сетевой стек под туннелем

Пользовательский сетевой стек, на котором работает туннель (gVisor), был
зафиксирован на версии прошлого лета — теперь он на той, которую ожидает
upstream. Из года исправлений стоит назвать одно: соединения начинались с
завышенного таймаута повторной передачи, если первое подтверждение задерживалось
внутри стека, и это завышенное значение держалось несколько циклов обмена.
Также доработано определение MTU пути. Наша защита от падения при соединении с
недоступным узлом перенесена — upstream её так и не исправил.
