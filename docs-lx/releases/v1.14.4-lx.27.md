The WireGuard/AmneziaWG peer status no longer shows a dead session as live: after a node is switched back on, wakes from idle sleep or the network comes back after a pause, the peer reads "no handshake yet" until a new handshake completes, instead of the previous session's handshake. Each peer now also reports the bytes of the current session next to the device totals.

Статус пира WireGuard/AmneziaWG больше не показывает мёртвую сессию живой: после включения узла, пробуждения после сна по простою или возврата сети после паузы пир показывается как «хендшейка ещё не было», пока не пройдёт новый, а не с хендшейком прошлой сессии. Кроме того, каждый пир теперь отдаёт байты текущей сессии рядом с итогом устройства.

## 🆕 What's new

### 📊 WireGuard peer status: bytes of the current session

- `PeerStatus` gets `sessionRxBytes` / `sessionTxBytes` (libbox `SessionRxBytes` / `SessionTxBytes`): bytes since the current session started. `rxBytes` / `txBytes` stay the device totals since it was built.
- A session starts when the device is built and again every time it comes up after going down: switched on, woken from idle sleep, network back after a pause (on Android, after the screen was off). Bringing up a device that is already up does not start one.
- `sing-box api peers` shows session bytes with the totals in parentheses. Older clients keep working; they just do not read the new fields. (SPEC 145)

## 🐛 Fixed

### 🔌 A peer looked connected right after the node was switched back on

- Taking the device down destroys the session keys but kept the last handshake time. Switched off and on within a minute, the node card showed the peer as connected with a handshake "1 min ago" while no session existed yet.
- `lastHandshakeUnix` now reports the handshake of the current session only: `0` right after the node comes up, a fresh time after the first new handshake. While the node stays asleep or switched off, the previous session is still shown as before.
- Unit-tested, including a live off/on run on a pair of endpoints; not yet checked on a device. (SPEC 145)

## 🆕 Что нового

### 📊 Статус пира WireGuard: байты текущей сессии

## 🐛 Исправлено

### 🔌 Пир выглядел подключённым сразу после включения узла

- Остановка устройства уничтожает ключи сессии, но время последнего хендшейка оставалось. После выключения и включения в пределах минуты карточка узла показывала пира подключённым с хендшейком «1 min ago», хотя сессии ещё не было.
