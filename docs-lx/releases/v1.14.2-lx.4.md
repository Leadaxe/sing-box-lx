A WireGuard or AmneziaWG node can now be switched off and on at runtime over the lxd gRPC API and the libbox command client, without editing the config or reloading the core. A disabled node drops its device, cuts established flows and refuses every dial until it is enabled again. The OpenWrt installer now sets a Go memory limit for the lxd service on small-RAM routers.

WireGuard- и AmneziaWG-узел теперь можно выключить и включить на лету через gRPC lxd и командный клиент libbox, без правки конфига и перезагрузки ядра. Выключенный узел опускает устройство, рвёт установленные соединения и отвергает обращения, пока его не включат. Инсталлятор OpenWrt задаёт службе lxd лимит памяти Go для роутеров с малым объёмом ОЗУ.

## 🆕 What's new

### 🔌 WireGuard/AmneziaWG node on/off switch at runtime

- gRPC `SetEndpointEnabled(tag, enabled)` in the `lx_command` block of the lxd daemon; libbox `CommandClient.SetEndpointEnabled(tag, enabled)` returns `EndpointToggleResult` with the node state after the call.
- Disable: the device goes down the same way idle-suspend puts it to sleep, established flows are cut, every dial, UDP listen and forwarded packet gets `WireGuard endpoint is disabled`. Nothing wakes the node until it is enabled.
- Enable: a suspended device is woken at once; a torn-down or never-built one is built by the next dial, through the build budget as usual.
- New node state `disabled` in `GetOutbounds` (`endpointState`), reported over any sleep level.
- Errors: `NotFound` (no such tag), `InvalidArgument` (not a WG/AWG node), `FailedPrecondition` (core not started, node closing), `Unavailable` (wake failed, node stays asleep and the next dial retries).
- Not persisted: a config reload or apply starts every node enabled. Works in builds without `with_lx_idle_suspend` too. (SPEC 106)

## 🧰 Tools

### 🧭 OpenWrt installer: Go memory limit for the lxd service

- The installer computes `GOMEMLIMIT` = MemTotal/3, clamped to 64..512 MiB, and writes it with `GOGC=50` into the procd init script; the decision is printed during install. The core's oom-killer service only reacts near its `memory_limit`, so on a small-RAM router the GC has to keep the heap down beforehand. Installer version 1.2.

## 🆕 Что нового

### 🔌 Выключение и включение WireGuard/AmneziaWG-узла на лету

- gRPC `SetEndpointEnabled(tag, enabled)` в блоке `lx_command` демона lxd; в libbox `CommandClient.SetEndpointEnabled(tag, enabled)` возвращает `EndpointToggleResult` с состоянием узла после вызова.
- Выключение: устройство опускается так же, как при усыплении по простою, установленные соединения рвутся, каждый dial, UDP-listen и форвард пакетов получает `WireGuard endpoint is disabled`. Ничто не будит узел, пока его не включат.
- Включение: усыплённое устройство просыпается сразу; освобождённое или ещё не собранное собирает следующий dial через бюджет сборок, как обычно.
- Новое состояние узла `disabled` в `GetOutbounds` (`endpointState`), отдаётся поверх любого уровня сна.
- Ошибки: `NotFound` (нет такого тега), `InvalidArgument` (узел не WG/AWG), `FailedPrecondition` (ядро не запущено, узел закрывается), `Unavailable` (пробуждение не удалось, узел остаётся спящим, следующий dial повторит).
- Не сохраняется: reload или apply конфига стартуют все узлы включёнными. Работает и в сборках без `with_lx_idle_suspend`. (SPEC 106)

## 🧰 Инструменты

### 🧭 Инсталлятор OpenWrt: лимит памяти Go для службы lxd

- Инсталлятор считает `GOMEMLIMIT` = MemTotal/3 в пределах 64..512 МиБ и пишет его вместе с `GOGC=50` в init-скрипт procd; решение печатается при установке. Служба oom-killer ядра реагирует только у своего `memory_limit`, поэтому на роутере с малым ОЗУ GC должен заранее держать кучу. Версия инсталлятора 1.2.
