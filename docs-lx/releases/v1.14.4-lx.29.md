## 🆕 What's new

### 🧮 Memory limit is compared with the core's own memory, not the whole app process

- Before: with the core inside the app process (LxBox on Android: Go core, Flutter and Dalvik in one process), the "Memory limit" (200/384/512/768 MB) was compared with the RSS of the whole process. At RSS 461 MB and a 200 MB limit the network was reset 100 ms after start (all connections dropped), the check then stayed triggered and polled memory 10 times a second, and any limit switched the system free-memory watch off.
- Now the limit is compared with the memory held by the Go runtime (`runtime/metrics`: total minus released heap), read without stop-the-world.
- Thresholds are unchanged: "200 MB" = GC target 160 MiB, network reset at 195 MiB of runtime memory.
- The system free-memory watch stays on in this mode.
- The app has to enable the mode (`SetupOptions.OomMemoryLimitHeap`). Without it, with limit 0, on iOS, in boxdd and lxd nothing changes.
- Unit-tested; not yet checked on a device. (SPEC 148)

### 📊 Core memory shown separately from process RSS

- Status carries a new field `memoryRuntime` (`StatusMessage.MemoryRuntime` in libbox): memory held by the Go runtime, on every status tick, regardless of the memory-limit settings. `memory` stays the process RSS.
- One additive field: apps that do not read it are unaffected. (SPEC 148)

### 📊 Память ядра отдаётся отдельно от RSS процесса

- В статусе новое поле `memoryRuntime` (`StatusMessage.MemoryRuntime` в libbox): память Go-рантайма, на каждом тике статуса, независимо от настроек лимита памяти. `memory` остаётся RSS процесса.
- Одно аддитивное поле: приложений, которые его не читают, это не касается. (SPEC 148)
