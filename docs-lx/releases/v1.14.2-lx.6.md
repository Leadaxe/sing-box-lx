XHTTP without an explicit `xmux` section now keeps at most three connections to the server instead of opening a new one per stream. This is the current Xray-core default, which it adopted because TSPU cuts a burst of parallel connections to one server.

XHTTP без явной секции `xmux` теперь держит к серверу не больше трёх соединений, а не открывает новое на каждый поток. Это текущий дефолт Xray-core, который там ввели, потому что ТСПУ режет пачку параллельных соединений к одному серверу.

<summary><h2>🇬🇧 English</h2></summary>

## 🔧 Changed

### 🔌 XHTTP no longer opens a connection per stream by default

- Was: when a config or subscription carried no `xmux` section (or an empty one), the core used `max_concurrency 1`, meaning a fresh TLS connection for every stream. On a phone that is dozens to hundreds of parallel connections to one IP, the pattern reported to be cut on Russian mobile networks.
- Now: the same case selects `max_connections 3`: all streams share at most three connections. `h_max_request_times 600-900` and `h_max_reusable_secs 1800-3000` are unchanged. The values follow Xray-core ([`18e2839`](https://github.com/XTLS/Xray-core/commit/18e283909ca253d4220136eccca0a27006ea709f), [XTLS/Xray-core#6376](https://github.com/XTLS/Xray-core/issues/6376)).
- Not affected: an `xmux` section with at least one field set is still taken as written, with no defaults filled in. ([#32](https://github.com/Leadaxe/sing-box-lx/issues/32))

<summary><h2>🇷🇺 Русский</h2></summary>

## 🔧 Изменено

### 🔌 XHTTP больше не открывает соединение на каждый поток по умолчанию

- Было: если в конфиге или подписке нет секции `xmux` (или она пустая), ядро ставило `max_concurrency 1`, то есть новое TLS-соединение на каждый поток. На телефоне это десятки и сотни параллельных соединений к одному IP, и по отчётам именно такой паттерн режут на мобильном интернете в РФ.
- Стало: в том же случае ставится `max_connections 3`, все потоки делят не больше трёх соединений. `h_max_request_times 600-900` и `h_max_reusable_secs 1800-3000` не менялись. Значения взяты из Xray-core ([`18e2839`](https://github.com/XTLS/Xray-core/commit/18e283909ca253d4220136eccca0a27006ea709f), [XTLS/Xray-core#6376](https://github.com/XTLS/Xray-core/issues/6376)).
- Не затронуто: секция `xmux` хотя бы с одним заполненным полем по-прежнему берётся как есть, без подстановки дефолтов. ([#32](https://github.com/Leadaxe/sing-box-lx/issues/32))
