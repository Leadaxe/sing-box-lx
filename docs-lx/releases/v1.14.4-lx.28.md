## 🐛 Fixed

### ⏹️ Stopping the VPN hung while a MASQUE node with `detour` was connecting

- A MASQUE node with a `detour` (for example WARP over vless + WebSocket) was being pinged or connecting when Stop was pressed. The core never finished stopping: the app showed "Stopping" until its limit, and the next start could fail.
- Now the stop finishes at once; the unfinished connection attempt is cancelled and returns an error. MASQUE nodes without `detour` are not affected.
- Unit-tested; not yet checked on a device. (SPEC 146)

### 💾 Start after a hung stop failed with `initialize cache-file: timeout`

- After a stop that hung, the next start waited 10 s for the cache file and failed with `initialize cache-file: timeout`. Only a force-stop or "Clear DNS cache" helped, and the latter deletes the cache.
- Now the new start takes `cache.db` over from the hung instance by itself, without waiting, and keeps the node selection in groups, FakeIP assignments and the remote rule-set cache.
- If two instances run at the same time (VPN and a test session), the older one loses its cache; the file stays intact.
- Unit-tested; not yet checked on a device. (SPEC 147)

- Если два экземпляра работают одновременно (VPN и пробная сессия), старший теряет кеш; файл остаётся целым.
- Юнит-тесты; на устройстве пока не проверялось. (SPEC 147)
