## 🐛 Fixed

### 📡 "The ping is lost" — node checks that hung forever and survived restarts

Reported from the field with a memory dump attached. Some servers accept the
connection and then go quiet: the handshake is never answered, but nothing is
refused either. A node check that ran into one of those simply stopped — and
because there was no way to interrupt it, it stayed stopped forever.

Worse, stopping the VPN did not clear it. The check kept running in the
background, still holding the entire node list it had started with — in the
reported case 2806 nodes from a subscription that was no longer even loaded.
Every start added a fresh one on top: the dump showed two of them aged 100 and
43 minutes. Because the group waits for all its checks to finish before
publishing results, the ping column stayed empty, and memory climbed to the
point where the system started shooting the app down. Restarting the VPN did
not help; only rebuilding the config did.

Three things had to go wrong together, so all three were fixed: connections of
this transport type now support timeouts at all, cancelling a check now reaches
the handshake it is stuck in, and stopping a group now stops the checks it
started. Nodes that are simply slow are unaffected — the timeout only ends a
check that has genuinely stalled, and a node that answers keeps working exactly
as before. The bug is older than this release. (SPEC 050)

### 📡 «Утерялся пинг» — проверки нод висели вечно и переживали перезапуск
