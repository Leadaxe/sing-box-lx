Node diagnostics no longer crashes the app on a NaiveProxy node. No configuration changes.

## 🔧 Changed

### 🔄 Upstream sync: sing-box v1.14.1 + 34 commits of `stable`

- WireGuard/AWG: the initial handshake with a peer given by a domain name now completes on the first attempt. Before, the first attempt was lost and the log showed `handshake did not complete after 5 seconds, retrying`; switching to such a node cost 5.4–5.7 s. Measured on the emulator after the sync: 1.1 s to switch, retry count 0.
- HTTP/2 error types from `sing` (`baderror.WrapH2`): the v2ray HTTP and gRPC-lite transports now use the upstream mapping, so an `http2.StreamError` no longer reaches the relay as a raw type. Our own wrappers for those two transports are removed; XHTTP keeps its own handling.
- Carried from upstream: dial contexts of live connections, DNS timeouts under query deduplication, half-close through connection wrappers, rotation of temporary IPv6 addresses, a read-loop spin on persistent errors, a crash on a corrupted cache file, the OOM report on clean shutdown, `sing-mux` v0.3.8, hardened TUN read loops in sing-tun.
- Submodules: the wireguard-go fork is re-based onto v0.0.7 (required by the domain-peer fix), the sing-tun fork onto the upstream pin. All fork patches (AWG, batch paths, acceptLoop self-heal) are carried over and verified.
- libbox API: one additive method from upstream, `Libbox.hasTunInbound(String)`. Nothing removed or changed; apps need no update to consume this core. ([SPEC 095](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/095-UPSTREAM_SYNC_1_14_1_PLUS_34/SPEC.md))

## 🐛 Fixed

### 🧯 Node diagnostics no longer crashes the app on a NaiveProxy node

- Was: with the tunnel up, running diagnostics on a `naive` node killed the process at once, regardless of the memory limit. The diagnostics probe read the remote address of the connection inside the tunnel; a Cronet connection has no address, and dereferencing that nil took the whole core down. Traffic through the node and `urltest` were not affected.
- Now: the probe returns the HTTP status, body and elapsed time as for any other node. The `remoteAddr` field stays empty for `naive` nodes — that is the expected value, not an error.
- Other protocols were never affected. ([SPEC 099](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/099-GETURL_NAIVE_NIL_REMOTEADDR_PANIC/SPEC.md))

- Unchanged: configuration (no new keys), the wire formats, Clash API, gRPC/lxd, the tag sets of desktop, router and AAR builds, the Go toolchain (1.26.8).
- Upstream base: sing-box `v1.14.1` + 34 commits = `upstream/stable` at the cut; drift is zero.

## 🔧 Изменено

### 🔄 Синк с апстримом: sing-box v1.14.1 + 34 коммита `stable`

- WireGuard/AWG: первое рукопожатие с пиром, заданным доменным именем, теперь проходит с первой попытки. Раньше первая попытка терялась, в логе было `handshake did not complete after 5 seconds, retrying`, переключение на такой узел стоило 5,4–5,7 с. Замер на эмуляторе после синка: переключение 1,1 с, повторов 0.
- Типы ошибок HTTP/2 из `sing` (`baderror.WrapH2`): транспорты v2ray HTTP и gRPC-lite используют апстримное отображение, `http2.StreamError` больше не доходит до релея сырым типом. Наши обёртки для этих двух транспортов сняты; XHTTP сохраняет свою обработку.
- Из апстрима: dial-контексты живых соединений, таймауты DNS при дедупликации запросов, half-close через обёртки соединений, ротация временных IPv6-адресов, спин цикла чтения на постоянных ошибках, падение на битом cache-файле, OOM-отчёт при чистом завершении, `sing-mux` v0.3.8, укреплённые циклы чтения TUN в sing-tun.
- Сабмодули: форк wireguard-go пересажен на v0.0.7 (его требует фикс доменных пиров), форк sing-tun — на апстримный пин. Все патчи форков (AWG, батч-пути, самолечение acceptLoop) перенесены и проверены.
- libbox API: один аддитивный метод из апстрима, `Libbox.hasTunInbound(String)`. Ничего не удалено и не изменено; приложениям для перехода на это ядро правки не нужны. ([SPEC 095](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/095-UPSTREAM_SYNC_1_14_1_PLUS_34/SPEC.md))

## 🐛 Исправлено

### 🧯 Диагностика узла больше не роняет приложение на узле NaiveProxy

- Было: при живом туннеле запуск диагностики `naive`-узла завершал процесс мгновенно, независимо от лимита памяти. Пробник диагностики читал адрес соединения внутри туннеля; у соединения Cronet адреса нет, и обращение к этому nil роняло ядро целиком. Трафик через узел и `urltest` не страдали.
- Стало: пробник отдаёт HTTP-статус, тело и время, как для любого другого узла. Поле `remoteAddr` у `naive`-узлов остаётся пустым — это ожидаемое значение, не ошибка.
- Остальные протоколы затронуты не были. ([SPEC 099](https://github.com/Leadaxe/sing-box-lx/blob/lx/SPECS/TASKS/099-GETURL_NAIVE_NIL_REMOTEADDR_PANIC/SPEC.md))

- Не меняются: конфигурация (новых ключей нет), провод, Clash API, gRPC/lxd, наборы тегов desktop-, router- и AAR-сборок, Go-тулчейн (1.26.8).
- База апстрима: sing-box `v1.14.1` + 34 коммита = `upstream/stable` на момент среза; дрейф нулевой.
