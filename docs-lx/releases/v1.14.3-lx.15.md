## 🆕 What's new

### 🐢 `failover` leaves a degraded node, not only a dead one

- Before: the held node was kept while it answered the probe at all, even in seconds.
- Now: a held node that answers more than 2× slower than the fastest other node of the same network (by that node's last delay) is probed once more at once; still more than 2× slower → full run over all nodes → the group moves to the fastest node only if it is more than 1.5× faster, otherwise it stays (the network got slower, not the node).
- Fresh delays of the others silence the trigger on the next tick: at most one full run per change of network conditions. A regular tick is still one probe.
- No config key. `least_test` and `round_robin` are unchanged. (SPEC 126)

## 🔧 Changed

### 🧠 uTLS/REALITY connections release the handshake state: −18…−25 KB per connection

- The ClientHello, the key share private keys (an ML-KEM-768 key alone is 7.8 KiB) and the extension objects stayed in every connection until it closed.
- Now they are dropped after a successful TLS 1.3 handshake. 200 live connections, per connection: Chrome 42.1 → 16.6 KB, Firefox 36.1 → 18.4 KB. Matters on routers with hundreds to thousands of connections.
- The transport's ALPN is set in the ClientHello once instead of on every handshake call. The wire is unchanged. TLS 1.2 connections keep the state (browser presets enable renegotiation there). (SPEC 122)

## 🐛 Fixed

### ⏱️ `urltest` probed nodes once per 2×`interval`

- A probe stamps its time when the answer arrives, the ticker fires exactly every `interval`, so at the next tick the node looked fresh and was skipped. With the default 3 min: `least_test` re-measured every node every 6 min, `failover` probed the held node every 6 min and noticed its death up to twice as late.
- Now every tick probes; a manual test or a nested group's own probe is still not repeated.
- A tick less than `interval/2` after the end of the previous run is skipped: a run longer than `interval` (hundreds of nodes, some dead) no longer runs back to back.
- `least_test` now probes twice as often as before — as often as `interval` says. (SPEC 125)

### 🎲 `fingerprint: "random"` / `"randomized"` could leave REALITY nodes dead until a restart

- Both are picked once per process. `randomized` decided the X25519MLKEM768 group, the hybrid key share and ALPN by independent coins: without the share Xray ≥ v26.9.8 answers `reality verification failed`, without ALPN gRPC/XHTTP over h2 do not come up — ~25 % of processes worked. `random` included `edge` and `ios`, which carry no hybrid share: dead in 2 processes of 5.
- Now `randomized` always carries ALPN and X25519MLKEM768 in groups and key shares (shares: X25519MLKEM768, X25519, P-256); ciphers, signatures, extension set and order stay random. `random` picks among `chrome`, `firefox`, `safari`.
- ClientHello of `randomized` is now always long (~1.9 KB); `key_share: classical` still strips the hybrid. (SPEC 123)

### 🍎 `lxd --service=install` / `copy` failed on a clean macOS

- `/Library/PrivilegedHelperTools` does not exist until some app installs a privileged helper. Install, copy, the launcher's Install button and `install-macos.sh` failed with `exec dir … does not exist`.
- Now the directory is created `root:wheel 0755`; `--dry-run` prints `would create`; status and uninstall do not create it. (SPEC 124)

## 🧰 Under the hood

- Security: `google.golang.org/grpc` v1.79.1 → v1.83.1 (GHSA-p77j-4mvh-x3m3, critical `:path` authorization bypass; HTTP/2 DATA fragmentation OOM and three more), `go-jose/v4` v4.1.3 → v4.1.4 (JWE panic). Upstream still pins the old versions.
- Base: sing-box `v1.14.3`, zero drift from `upstream/stable`; Go 1.26.8 as stable. The utls fork carries eight commits (new: `UConn.ReleaseHandshakeState`).
- SPEC 125/126 and 122/123 are covered by unit tests (REALITY end to end on loopback); on-device and live-Xray runs are ahead.

## 🆕 Что нового

### 🐢 `failover` уходит с деградировавшего узла, а не только с мёртвого

- Было: удерживаемый узел держался, пока вообще отвечал на пробу, хоть за секунды.
- Стало: удерживаемый узел, ответивший больше чем вдвое медленнее самого быстрого из остальных узлов той же сети (по его последней задержке), сразу пробуется ещё раз; снова больше 2× → полный прогон по всем → переезд на самого быстрого, только если тот больше чем в 1,5 раза быстрее, иначе остаёмся (просела сеть, а не узел).
- Свежие задержки соседей гасят триггер на следующем тике: не больше одного полного прогона на смену условий сети. Обычный тик — по-прежнему одна проба.
- Ключа конфига нет. `least_test` и `round_robin` не меняются. (SPEC 126)

## 🔧 Изменено

### 🧠 uTLS/REALITY-соединения отпускают состояние рукопожатия: −18…−25 КБ на соединение

- ClientHello, приватные ключи key share (один ключ ML-KEM-768 — 7,8 КиБ) и объекты расширений лежали в каждом соединении до его закрытия.
- Теперь они освобождаются после успешного TLS 1.3-рукопожатия. 200 живых соединений, на соединение: Chrome 42,1 → 16,6 КБ, Firefox 36,1 → 18,4 КБ. Заметно на роутерах с сотнями–тысячами соединений.
- ALPN транспорта ставится в ClientHello один раз, а не на каждом вызове рукопожатия. Провод не меняется. Соединения на TLS 1.2 состояние сохраняют (браузерные пресеты включают там ренегоциацию). (SPEC 122)

## 🐛 Исправлено

### ⏱️ `urltest` пробовал узлы раз в 2×`interval`

- Проба ставит отметку времени по приходу ответа, тикер стреляет ровно каждый `interval` — на следующем тике узел выглядел свежим и пропускался. При дефолте 3 мин: `least_test` перемерял узлы раз в 6 мин, `failover` пробовал удерживаемый узел раз в 6 мин и замечал его смерть до двух раз позже.
- Теперь пробует каждый тик; ручной тест и собственная проба вложенной группы по-прежнему не дублируются.
- Тик, пришедший раньше чем через `interval/2` после конца прошлого прогона, пропускается: прогон длиннее `interval` (сотни узлов, часть мёртвых) больше не идёт встык.
- `least_test` теперь пробует вдвое чаще прежнего — с той частотой, что задаёт `interval`. (SPEC 125)

### 🎲 `fingerprint: "random"` / `"randomized"` могли оставить узлы REALITY мёртвыми до рестарта

- Оба выбираются раз на процесс. `randomized` решал группу X25519MLKEM768, гибридный шар и ALPN независимыми монетами: без шара Xray ≥ v26.9.8 отвечает `reality verification failed`, без ALPN не поднимаются gRPC/XHTTP поверх h2 — работало ~25 % процессов. В пул `random` входили `edge` и `ios` без гибридного шара: мёртв в 2 процессах из 5.
- Теперь `randomized` всегда несёт ALPN и X25519MLKEM768 в группах и шарах (шары: X25519MLKEM768, X25519, P-256); шифры, подписи, набор и порядок расширений остаются случайными. `random` выбирает из `chrome`, `firefox`, `safari`.
- ClientHello у `randomized` теперь всегда длинный (~1,9 КБ); `key_share: classical` по-прежнему вырезает гибрид. (SPEC 123)

### 🍎 `lxd --service=install` / `copy` падали на чистой macOS

- `/Library/PrivilegedHelperTools` не существует, пока какое-нибудь приложение не поставит привилегированный помощник. Install, copy, кнопка Install лаунчера и `install-macos.sh` падали с `exec dir … does not exist`.
- Теперь каталог создаётся `root:wheel 0755`; `--dry-run` печатает `would create`; status и uninstall его не создают. (SPEC 124)
