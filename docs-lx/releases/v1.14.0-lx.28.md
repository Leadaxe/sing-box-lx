## 🆕 What's new

### 🔗 chain: per-position runtime toggles

Disabling one hop of a chain used to mean editing the config and restarting.
Now every position has an on/off switch, applied live:

- A disabled position ≥ 1 is a passthrough to the previous hop — the group is
  not polled, no link is created. A disabled entry position dials hop 0
  directly into the real network (interface binding and marks preserved). Any
  combination is valid: everything off degenerates the chain into `direct`.
- The set of disabled positions persists in the cache-file **by position tag**,
  like a selector's `selected`: a config edit does not shift the mapping, a
  vanished tag is silently ignored.
- Toggling interrupts the chain's connections by the selector model; the new
  option `interrupt_exist_connections` (default `false`) gates interrupting
  user connections.
- Diagnostics: `disabled` per position in `GetChains` / Clash API, and
  `GetChainCloneConfig` returns the effective JSON of a link (after strip →
  rewrite → MTU → detour), so a client shows exactly what a hop runs as.

RPC (`with_lx_command`): `SetChainPositionEnabled(chainTag, position, enabled)`;
a warmup failure on re-enable is reported as data, not as an RPC error.

### 🪪 XHTTP: `session_table` / `session_length` — session id form

By default an XHTTP session id is a dashed UUID — a recognizable fingerprint
(36 chars, hex, dashes at fixed positions). Ported from Xray
(`sessionIDTable` / `sessionIDLength`): the two options replace it with a
random string of a chosen alphabet and length —
`"session_table": "Base62"` + `"session_length": "16-32"` gives
`/api/v3/k7Qm2XpR9vLdA3wZ/0`.

- Alphabet: a predefined set name (`hex`, `HEX`, `number`, `alphabet`,
  `Alphabet`, `ALPHABET`, `base36`, `BASE36`, `Base62` — byte-for-byte the
  Xray sets, case-sensitive) or a custom ASCII set. Length: `"n"` or
  `"min-max"`.
- Purely client-side: the server treats the id as an opaque grouping key, any
  Xray server accepts any form. Without the fields the id stays a dashed UUID.
- Deliberate deviation from Xray: configuring one option without the other is
  rejected with an error instead of silently degrading to UUID.

## 🔧 Changed

### 🎭 MASQUE: `vhttp: auto` is now the default

An empty `vhttp` now means `auto`: on a clean path it is the same h3 (only the
first tunnel of a process pays the 3 s budget), behind a TCP-only hop it
self-rescues into h2 — the chain case where h3 datagrams silently vanish and
the dial used to hang to the caller's deadline. Explicit `h3` / `h2` still pin
the mode; on the `standard` build profile the default quietly degrades to h3.

### 📄 lxd: configurable log path, 1 MB rotation default

- `log_file` in `daemon.json` overrides the rotated-log path (empty = the old
  `<parent of state-dir>/lxd.log`; a relative path is resolved to absolute at
  startup). `GET /admin/info` and `GET /admin/logs` report and serve the
  actual path.
- The `log_max_size_mb` default dropped 20 → 1: at most ~2 MB on disk with the
  backup. Age rotation (24 h) unchanged.
- The OpenWrt installer writes `"log_file": "/tmp/lxd.log"` — the log lives on
  tmpfs, zero overlay-flash wear (lost on reboot, the right trade for a
  router).

## 🐛 Fixed

### 🎭 MASQUE: a dying tunnel now names its cause

Both pumps (stack↔tunnel) used to die silently — the death was only visible as
the next `establishing`. A pump dying on its own now leaves exactly one line:
`masque: tunnel died: <operation>: <cause>`. Normal closes (idle-suspend,
`Close`, chain-link eviction) stay silent.

## 🆕 Что нового

### 🔗 chain: рантайм-тумблеры по позициям

Выключить один хоп цепочки раньше означало правку конфига и перезапуск.
Теперь у каждой позиции есть вкл/выкл, применяемый вживую:

- Выключенная позиция ≥ 1 — passthrough в предыдущий хоп: группа не
  опрашивается, звено не создаётся. Выключенный вход — прямой дозвон хопа 0 в
  реальную сеть (привязка к интерфейсу и марки сохраняются). Валидна любая
  комбинация: всё выключено = цепочка вырождается в `direct`.
- Набор выключенных позиций персистентен в cache-file **по тегам позиций**,
  как `selected` у селектора: правка конфига не сбивает соответствие, ушедший
  тег молча игнорируется.
- Тумблер рвёт соединения цепочки по селекторной модели; новая опция
  `interrupt_exist_connections` (default `false`) гейтит разрыв
  пользовательских соединений.
- Диагностика: `disabled` по позициям в `GetChains` / Clash API, а
  `GetChainCloneConfig` отдаёт эффективный JSON звена (после strip → rewrite →
  MTU → detour) — клиент показывает, чем хоп реально работает.

RPC (`with_lx_command`): `SetChainPositionEnabled(chainTag, position, enabled)`;
провал прогрева при включении едет данными, не ошибкой RPC.

### 🪪 XHTTP: `session_table` / `session_length` — форма session id

По умолчанию session id XHTTP — дашед-UUID, узнаваемый отпечаток (36 символов,
hex, дефисы на фиксированных позициях). Портировано из Xray
(`sessionIDTable` / `sessionIDLength`): две опции заменяют его случайной
строкой заданного алфавита и длины —
`"session_table": "Base62"` + `"session_length": "16-32"` даёт
`/api/v3/k7Qm2XpR9vLdA3wZ/0`.

- Алфавит: имя предопределённого набора (`hex`, `HEX`, `number`, `alphabet`,
  `Alphabet`, `ALPHABET`, `base36`, `BASE36`, `Base62` — байт-в-байт наборы
  Xray, регистрозависимо) либо свой ASCII-набор. Длина: `"n"` или `"min-max"`.
- Чисто клиентская ручка: сервер видит id как непрозрачный ключ группировки,
  любой Xray-сервер принимает любую форму. Без полей id остаётся дашед-UUID.
- Осознанный отход от Xray: одна опция без второй отвергается с ошибкой, а не
  молча вырождается в UUID.

## 🔧 Изменено

### 🎭 MASQUE: `vhttp: auto` теперь дефолт

Пустое `vhttp` теперь значит `auto`: на чистом пути это тот же h3 (3-секундный
бюджет платит только первый туннель процесса), за TCP-only-хопом —
самоспасение в h2: случай цепочки, где h3-датаграммы молча пропадают и дозвон
висел до дедлайна вызывающего. Явные `h3` / `h2` по-прежнему пин; на
build-профиле `standard` дефолт тихо вырождается в h3.

### 📄 lxd: настраиваемый путь лога, дефолт ротации 1 МБ

- `log_file` в `daemon.json` переопределяет путь ротируемого лога (пусто =
  прежний `<родитель state-dir>/lxd.log`; относительный путь резолвится в
  абсолютный при старте). `GET /admin/info` и `GET /admin/logs` отдают
  фактический путь.
- Дефолт `log_max_size_mb` снижен 20 → 1: максимум ~2 МБ на диске вместе с
  бэкапом. Ротация по возрасту (24 ч) не тронута.
- OpenWrt-инсталлятор пишет `"log_file": "/tmp/lxd.log"` — лог живёт на tmpfs,
  ноль износа overlay-флеша (теряется на ребуте — для роутера это правильный
  размен).

## 🐛 Исправлено

### 🎭 MASQUE: умирающий туннель называет причину

Оба пампа (стек↔туннель) умирали молча — смерть была видна только следующим
`establishing`. Памп, умирающий сам, теперь оставляет ровно одну строку:
`masque: tunnel died: <операция>: <причина>`. Штатные закрытия (idle-suspend,
`Close`, эвикшн звена цепочки) молчат.
