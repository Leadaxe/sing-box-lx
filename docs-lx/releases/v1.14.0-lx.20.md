A stable release, promoting the `lx.20` pre-release line. Two months of upstream
sing-box work are now in — 452 commits across two merges — and every dependency
sits on the revision upstream expects. Every binary is built with a Go 1.25.x
toolchain. OpenVPN and OpenConnect are available as connection types. Several
freezes and crashes are fixed, including two that killed the app outright.

Стабильный выпуск, промоут линии пререлизов `lx.20`. Перенесены два месяца
работы upstream sing-box — 452 изменения в двух слияниях, — и все зависимости
стоят на тех версиях, которые ожидает upstream. Все бинарники собраны тулчейном
Go 1.25.x. Доступны типы подключения OpenVPN и OpenConnect. Исправлено
несколько зависаний и крашей, включая два, при которых приложение падало
целиком.

<summary><h2>🇬🇧 English</h2></summary>

## ✨ New

### 🔌 OpenVPN and OpenConnect

Both are now available as connection types, arriving with the upstream merge.

## 🐛 Fixed

### 🧊 A sleeping node could wake up dead

WireGuard and AmneziaWG nodes are put to sleep when idle to save battery, and
woken again on the next connection through them. If that wake-up failed — the
socket could not be re-opened, which happens when the network switches at
exactly the wrong moment — the node was still marked as awake. It then sat there
accepting traffic and silently discarding all of it.

Nothing could bring it back. Switching networks did not help, and neither did
the self-healing that normally rebuilds a stalled tunnel, because both need the
device to be up in the first place. Connections through such a node hung for
about two minutes before failing, then the next attempt hung the same way.
Restarting the app was the only cure.

A failed wake-up now leaves the node asleep, and the next connection simply
tries again — so the node recovers on its own as soon as the network settles.

This was found by reading the code, not from a report: it needs a network change
to land inside the wake-up itself, which is rare. But when it did happen, the
node stayed dead until restart, which is why it is fixed here.

### 🧊 A dead DNS server could freeze the whole tunnel

If one of your DNS servers was routed through a node that had gone dark, the
tunnel stopped forwarding anything at all — not just DNS. The logs stayed clean,
which made it look like a network problem rather than a stuck lookup.

### 💥 Two crashes that killed the app

One hit when the network switched while the tunnel was still starting; the other
when a connection to an unreachable node failed.

### ♾️ Node checks that ran forever

A check stuck on a broken server used to survive stopping and restarting the VPN
entirely, each restart leaving another one behind. The group stopped showing
ping times and memory kept climbing; only rebuilding the config cleared it.

### 📡 Upstream fixes

Among the 452 upstream commits: a TUN dispatcher deadlock, a DNS routing race,
inconsistent URLTest results, several WireGuard corrections, and a TLS fragment
fix for Windows.

## 🔧 Internal

- The fork is fully caught up with upstream, with no feature of ours dropped
  along the way. Two defects introduced by the merges themselves were caught and
  fixed before release.
- Two spots in the code that broke on every upstream merge were restructured so
  they stop breaking.
- All builds use a Go 1.25.x toolchain, and the Android NDK is pinned to a fixed
  revision instead of a floating one.

## ✨ Новое

### 🔌 OpenVPN и OpenConnect

Оба доступны как типы подключения — пришли вместе со слиянием upstream.

## 🐛 Исправлено

### 🧊 Спящая нода могла проснуться мёртвой

Ноды WireGuard и AmneziaWG усыпляются при простое ради батареи и просыпаются на
следующем соединении через них. Если пробуждение не удавалось — сокет не
открывался, что случается при смене сети ровно в этот момент, — нода всё равно
помечалась проснувшейся. После чего принимала трафик и молча выбрасывала его
целиком.

Вернуть её не могло ничто. Смена сети не помогала, самолечение, которое обычно
перестраивает зависший туннель, — тоже, потому что обоим нужно, чтобы
устройство было поднято. Соединения через такую ноду висели около двух минут,
затем отваливались, и следующая попытка висела так же. Лечил только перезапуск
приложения.

Теперь неудачное пробуждение оставляет ноду спящей, а следующее соединение
просто пробует снова — и нода поднимается сама, как только сеть устоится.

Найдено чтением кода, не по жалобе: нужно, чтобы смена сети попала внутрь
самого пробуждения, а это редкость. Но если попадала — нода оставалась мёртвой
до перезапуска, поэтому исправлено здесь.

### 🧊 Мёртвый DNS-сервер мог заморозить весь туннель

Если один из ваших DNS-серверов ходил через переставшую отвечать ноду, туннель
прекращал передавать вообще всё — не только DNS. Логи при этом оставались
чистыми, из-за чего это выглядело проблемой сети, а не застрявшим запросом.

### 💥 Два краша, при которых падало приложение

Один ловился при смене сети в момент запуска туннеля, второй — при неудачном
соединении с недоступной нодой.

### ♾️ Вечные проверки нод

Проверка, застрявшая на сломанном сервере, переживала даже полную остановку и
перезапуск VPN, и с каждым перезапуском оставалась ещё одна. Группа переставала
показывать пинги, память росла; лечила только пересборка конфигурации.

### 📡 Исправления upstream

Среди 452 изменений: дедлок диспетчера TUN, гонка в маршрутизации DNS,
несогласованные результаты URLTest, несколько правок WireGuard и фикс
фрагментации TLS для Windows.

## 🔧 Внутреннее

- Форк полностью догнал upstream, ни одна возможность форка при этом не
  потеряна. Два дефекта, внесённые самими слияниями, пойманы и исправлены до
  выпуска.
- Два места в коде, ломавшиеся при каждом слиянии с upstream, перестроены так,
  чтобы перестать ломаться.
- Все сборки используют тулчейн Go 1.25.x, а Android NDK закреплён на
  фиксированной ревизии вместо плавающей.
