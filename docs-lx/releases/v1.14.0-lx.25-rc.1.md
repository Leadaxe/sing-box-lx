A node can now be probed with a real HTTP GET through it, addressed by tag, and
the response body comes back to the client. That answers what a latency figure
cannot — which exit IP a node gives you, what geo services see, whether WARP is
actually on — without switching the active selector and breaking live
connections. Body is capped at 256 KiB by default (1 MiB ceiling), and a non-2xx
response is data, not a failure.

Узел теперь можно опросить настоящим HTTP GET через него, адресуясь тегом, и
получить тело ответа в клиент. Это отвечает на то, чего не скажет задержка: какой
exit-IP даёт узел, какую гео видят сервисы, включён ли на самом деле WARP — без
переключения активного selector'а и обрыва живых соединений. Тело ограничено
256 KiB по умолчанию (потолок 1 MiB), а не-2xx — это данные, а не сбой.

## 🆕 What's new

### 🌐 HTTP probe through a single node — `GetURLViaOutbound`

Node diagnostics stopped at one number: `URLTestOutbound` reports "alive, N ms"
and discards the body. Complaints of the shape "ping is fine but sites don't
open", "the node works but services place me in another country", "WARP is
connected yet `warp=off`" need the response data, not the fact of a response.

The new unary RPC performs an HTTP GET to an arbitrary URL through a node
addressed **by tag**, and returns the body:

- Addressing by tag means a group member can be inspected without switching the
  active selector — live connections are not disturbed.
- The tag resolves in **both managers**, so WG/AWG endpoints are probed by the
  same call as ordinary outbounds.
- **A non-2xx status is a result, not an error.** A 403 from Cloudflare is
  exactly the kind of answer this exists to surface. Errors are reserved for an
  exchange that never happened: unknown tag, dial/TLS failure, timeout.
- Body is clamped in the core: `maxBytes=0` → 256 KiB, ceiling 1 MiB, and a cut
  body is flagged `Truncated` — truncation is never silent.
- `RemoteAddr` is the address reached from inside the tunnel (where the target
  resolved to through that node), not the node's exit IP — the exit IP is
  carried by the body.
- `ElapsedMs` covers the whole exchange including the body read and is
  deliberately **not** written into the node's urltest history, so probing does
  not corrupt the latency figures shown for that node.
- Cancellation by dropping the call, same model as `URLTestOutbound`.
- HTTPS on Android uses the same certificate store as libbox's own HTTP client
  (the system x509 pool is empty inside a mobile process).

Client shape: the result is an object with getters; optional request headers are
a nullable `HTTPHeaders` builder (`Add(key, value)`), since the gomobile bridge
carries neither maps nor slices of pairs. A `Host` header is moved to the
request's Host field.

Scope, by design: **GET only** — an arbitrary-method HTTP client reachable
through every tunnel of the user is a far larger surface than diagnostics needs.
The core does not parse the body, so a format change at Cloudflare or
ip2location never becomes a core bug. The probe sends real traffic and wakes
sleeping WG endpoints, so it belongs behind an explicit user action, not a
background sweep of the node list. It also does not answer "where am I coming
from right now" — the live route is only exercised by an ordinary request from
the device. (SPEC 058)

Builds without `with_lx_command` answer `Unimplemented`, staying behaviourally
equivalent to upstream.

## 🆕 Что нового

### 🌐 HTTP-проба через отдельный узел — `GetURLViaOutbound`

Диагностика узла упиралась в одно число: `URLTestOutbound` отвечает «жив, N мс»
и выбрасывает тело. Жалобы вида «пинг есть, а сайты не открываются», «узел
работает, но сервисы считают меня другой страной», «WARP подключён, а
`warp=off`» требуют данных ответа, а не факта ответа.

Новый unary-RPC делает HTTP GET по произвольному URL через узел, адресуемый
**тегом**, и возвращает тело:

- Адресация тегом позволяет проверить участника группы, не переключая активный
  selector — живые соединения не рвутся.
- Тег резолвится **в обоих менеджерах**, поэтому WG/AWG-эндпоинты проверяются
  тем же вызовом, что и обычные outbound'ы.
- **Не-2xx — результат, а не ошибка.** 403 от Cloudflare — ровно тот ответ, ради
  которого проба и существует. Ошибка остаётся за несостоявшимся обменом:
  неизвестный тег, отказ dial/TLS, таймаут.
- Тело клампится в ядре: `maxBytes=0` → 256 KiB, потолок 1 MiB, обрезка помечена
  `Truncated` — молчаливого усечения нет.
- `RemoteAddr` — адрес, достигнутый изнутри туннеля (куда резолвилась цель через
  этот узел), а не exit-IP узла: exit-IP приносит тело.
- `ElapsedMs` включает чтение тела и намеренно **не** пишется в историю urltest
  узла — иначе проба испортила бы показания задержек этого узла.
- Отмена — закрытием вызова, та же модель, что у `URLTestOutbound`.
- HTTPS на Android работает через тот же certificate-store, что и собственный
  HTTP-клиент libbox (системный пул x509 в mobile-процессе пуст).

Форма на клиенте: результат — объект с геттерами; опциональные заголовки —
nullable-билдер `HTTPHeaders` (`Add(key, value)`), поскольку мост gomobile не
несёт ни map, ни slice пар. Заголовок `Host` перекладывается в поле запроса.

Границы, осознанно: **только GET** — HTTP-клиент с произвольным методом,
доступный через все туннели пользователя, это куда большая поверхность, чем
нужно диагностике. Ядро не парсит тело, поэтому смена формата у Cloudflare или
ip2location не становится багом ядра. Проба — реальный трафик и пробуждение
спящих WG-узлов, поэтому она за явным действием пользователя, а не за фоновым
обходом списка узлов. И она не отвечает на вопрос «через что я хожу сейчас» —
живой маршрут проверяется только обычным запросом с устройства. (SPEC 058)

Сборки без `with_lx_command` отвечают `Unimplemented`, оставаясь поведенчески
эквивалентными апстриму.
