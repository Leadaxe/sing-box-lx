## 🔧 Changed

### 📦 Base: upstream sing-box 1.14.0 stable + 16 post-release commits

Until now the fork sat on the 1.14 beta line as of mid-August; this release carries the released 1.14.0 and everything upstream landed on `stable` afterwards. The fork's own layer (AmneziaWG, XHTTP, MASQUE, DNS groups, chains, sniffers, lxd, the command protocol) is unchanged in configuration and on the wire.

- Submodules: wireguard-go on v0.0.5 (adds socket activity callbacks used by the power report); sing-tun on the upstream tip required by 1.14.0, which brings the system-stack fixes listed below; gVisor pin unchanged.
- Upstream's own CI moved to Go 1.26.7; the fork's build pin stays at go1.26.6 until the AAR has been exercised on a device.

### 🧭 Manual URL test always tests every node

Upstream changed `URLTest` to `force` semantics: a manual test of a group now probes all nodes, regardless of how fresh their history is. For `round_robin` groups the pool is rebuilt from the fresh results; the periodic ticker keeps the lazy, pool-bounded check. `passive_check`, penalties and the round_robin pool behave as before, now on top of upstream's new nested-group test engine.

### 🎛️ Clash mode no longer needs the Clash API server

Rule / global / direct mode lives in its own manager; the daemon reports it via `GetClashModeStatus`. Builds without `with_clash_api` (the Android AAR) get mode switching without a Clash server.

## 🐛 Fixed

### ⏱️ URL test could hang on a node that accepts the connection but never answers

Each probe now runs under its own 15 s deadline in a separate goroutine, so one stuck node cannot block the whole run; the SSH outbound got a context on its handshake for the same reason. (upstream)

### 🪆 Nested groups are tested recursively

A urltest or selector inside another group used to contribute only its current node; now every member is probed and the group's result is taken from its resolved node. (upstream)

### 🌐 DNS

- Resolver-discovery queries (`_dns.resolver.arpa` and any `_dns.*` SVCB) are answered with an empty NOERROR instead of being forwarded, so clients do not learn an upstream DoH/DoT endpoint and bypass the tunnel.
- Inverted DNS rules whose address filters (`ip_cidr`, `ip_is_private`, `ip_accept_any`) come from a rule set or a logical rule are deferred to the response phase and match again; they had been rejected before the lookup since 1.12.22.
- fakeip: UDP replies map back to the right address.

### 🔌 Network

- Interface-change callbacks run in the background with cancellation of the previous update; switching Wi-Fi ↔ cellular no longer blocks the monitor.
- UDP sockets were bound to the interface twice under auto-detect; fixed.
- A start / interface-update race in the network manager found by the fork's race tests is fixed with an atomic flag (fork).
- WireGuard endpoint: packets to non-IP destinations are dropped with a debug log instead of failing the write.

### 🧱 System stack (sing-tun)

- TCP NAT no longer reuses ports across the IPv4 and IPv6 stacks (each family has its own table).
- No panic on a TCP packet of an address family the TUN has not configured.
- auto_redirect: the prerouting pre-match chain runs before DNAT; forwarded traffic is no longer skipped by the pre-match.
- gVisor stack: excessive TCP keepalive traffic removed.

### 🚀 QUIC / protocols

- Congestion control reported "application limited" incorrectly after idle, feeding low samples into BBR; long-lived TUIC and naive connections lost throughput after light traffic. Fixed; `bbr2` variants removed from naive.
- naive: performance and receive-window options; NaiveProxy updated to 150.
- websocket: early data with smux / yamux multiplex; no panic on a failed handshake.
- daemon: a start-or-reload race; remote rule-set cache is invalidated when its URL changes; cache file survives a stale bbolt lock and recovers from a corrupted database.

## 🧰 Tools

- Fewer allocations in rule matching, logging and the cache file.
- OOM report: memory is recorded continuously into a draft; drafts written by a previous app version are discarded. The fork's report-archive rotation (32 reports / 64 MB) is preserved.
- Power report service (`service/powerreport`): per-outbound traffic, DNS and connection attribution with system energy statistics, for the platform clients.

## 🔧 Изменено

### 📦 База: апстрим sing-box 1.14.0 stable + 16 пострелизных коммитов

До сих пор форк сидел на бета-линии 1.14 по середину августа; этот релиз несёт выпущенную 1.14.0 и всё, что апстрим положил в `stable` после неё. Собственный слой форка (AmneziaWG, XHTTP, MASQUE, DNS-группы, цепочки, снифферы, lxd, command-протокол) в конфигурации и на проводе не изменился.

- Сабмодули: wireguard-go на v0.0.5 (добавлены колбэки активности сокета, их использует power report); sing-tun на вершине апстрима, которую требует 1.14.0, с фиксами системного стека ниже; пин gVisor без изменений.
- CI апстрима перешёл на Go 1.26.7; пин сборки форка остаётся go1.26.6, пока AAR не прогнан на устройстве.

### 🧭 Ручной URL-тест всегда тестирует все узлы

Апстрим перевёл `URLTest` на семантику `force`: ручной тест группы теперь пробует все узлы независимо от свежести истории. Для групп `round_robin` пул перестраивается по свежим результатам; периодический тикер сохраняет ленивую проверку в пределах пула. `passive_check`, штрафы и пул round_robin работают как прежде, теперь поверх нового апстримного прогона с вложенными группами.

### 🎛️ Clash-режим больше не требует Clash API-сервера

Режим rule / global / direct живёт в отдельном менеджере; daemon отдаёт его через `GetClashModeStatus`. Сборки без `with_clash_api` (Android AAR) получают переключение режима без Clash-сервера.

## 🐛 Исправлено

### ⏱️ URL-тест мог зависнуть на узле, который принимает соединение, но не отвечает

Каждая проба теперь идёт под собственным дедлайном 15 с в отдельной горутине, и один застрявший узел не блокирует прогон; SSH-outbound по той же причине получил контекст на handshake. (апстрим)

### 🪆 Вложенные группы тестируются рекурсивно

urltest или selector внутри другой группы давал только свой текущий узел; теперь пробуются все члены, а результат группы берётся по её разрешённому узлу. (апстрим)

### 🌐 DNS

- Запросы discovery-резолвера (`_dns.resolver.arpa` и любые `_dns.*` SVCB) получают пустой NOERROR вместо пересылки, поэтому клиенты не узнают внешний DoH/DoT-эндпоинт и не уходят мимо туннеля.
- Инвертированные DNS-правила, чьи адресные фильтры (`ip_cidr`, `ip_is_private`, `ip_accept_any`) приходят из rule-set или логического правила, откладываются до фазы ответа и снова матчатся; с 1.12.22 они отклонялись ещё до запроса.
- fakeip: UDP-ответы маппятся на правильный адрес.

### 🔌 Сеть

- Колбэки смены интерфейса выполняются в фоне с отменой предыдущего обновления; переключение Wi-Fi ↔ сотовая больше не блокирует монитор.
- UDP-сокеты при auto-detect привязывались к интерфейсу дважды; исправлено.
- Гонка старта и фонового обновления интерфейса в менеджере сети, найденная race-тестами форка, закрыта атомарным флагом (форк).
- WireGuard-эндпоинт: пакеты на не-IP адреса отбрасываются с debug-записью вместо ошибки записи.

### 🧱 Системный стек (sing-tun)

- TCP NAT больше не переиспользует порты между стеками IPv4 и IPv6 (у каждого семейства своя таблица).
- Нет паники на TCP-пакете семейства адресов, которое TUN не настроил.
- auto_redirect: цепочка prerouting pre-match выполняется до DNAT; форвардируемый трафик больше не пропускается pre-match'ем.
- Стек gVisor: убран избыточный TCP keepalive-трафик.

### 🚀 QUIC / протоколы

- Congestion control неверно сообщал «application limited» после простоя, и в BBR попадали низкие замеры; долгие соединения TUIC и naive теряли скорость после лёгкого трафика. Исправлено; из naive убраны варианты `bbr2`.
- naive: производительность и опции receive window; NaiveProxy обновлён до 150.
- websocket: early data с мультиплексом smux / yamux; нет паники при неудачном handshake.
- daemon: гонка start-or-reload; кеш удалённого rule-set сбрасывается при смене URL; файл кеша переживает протухший lock bbolt и восстанавливается после повреждения базы.

## 🧰 Инструменты

- Меньше аллокаций в матчинге правил, логировании и файле кеша.
- OOM-отчёт: память пишется непрерывно в черновик; черновики прошлой версии приложения выбрасываются. Ротация архива отчётов форка (32 отчёта / 64 МБ) сохранена.
- Сервис power report (`service/powerreport`): атрибуция трафика, DNS и соединений по outbound с системной статистикой энергии, для платформенных клиентов.
