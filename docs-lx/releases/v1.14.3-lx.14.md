## 🆕 What's new

### 📏 `lx.mtu_align` — one MTU / packet-size alignment along the path for `chain` and `detour`

- A node that sits on top of an IP tunnel — via `detour`, a group under `detour`, a transitive `detour`, or as a `chain` link — gets `mtu` (wireguard, masque) or `initial_packet_size` + `disable_path_mtu_discovery: true` (hysteria2, tuic, hysteria) sized to what the node below can carry.
- Capacity is computed recursively by type: tunnel → its effective `mtu`; tailscale → `system_interface_mtu` or 1280; group → the minimum over members at start; node with `detour` → transitively; proxies without an IP layer → no limit.
- Modes `off` / `fill` / `clamp` (default `clamp`: explicit values are only ever lowered; in `fill` an explicit value that does not fit produces a warning) and `except` — tags left untouched. The key takes a string or `{"mode","except"}`.
- Over WARP by default hysteria2 gets 1232 (IPv6 server) / 1252 (IPv4), PMTUD off. Every changed field is an Info line `mtu_align: <tag> <field> → <effective> (<reason>)`; warnings are Warn.
- Previously only `chain` subtracted the overhead, and only for tunnels; a plain `detour` did nothing, QUIC proxies were never aligned. (SPEC 120)

## 🔧 Changed

### 🚀 MASQUE outer QUIC starts with `InitialPacketSize` = `mtu + 51` (clamped 1200…1452; 1331 at mtu 1280) instead of the constant 1242

- quic-go budgets datagrams conservatively (`InitialPacketSize − 37`); with 1242 the budget was 1205 while an inner 1280-byte packet plus the context-id byte needs 1281. The budget only grew through PMTUD (first probe ~5 RTT after the handshake), so for ~6 RTT after the tunnel came up every inner packet of 1205…1280 bytes was dropped as `DatagramTooLarge`.
- The already aligned `mtu` is used, so MASQUE under WireGuard gets a consistent value.

### 📨 ICMP Packet Too Big from MASQUE names the actual datagram budget

- Minus the context-id byte, not the constant 1280; never below 1280 (IPv6 minimum).

## 🐛 Fixed

### 🌐 XHTTP: a `path` with a query was percent-encoded into the path (issue #36)

- `"path": "/?proxyip=149.56.109.62"` went on the wire as `/%3Fproxyip=149.56.109.62/`. Xray treats everything after the first `?` as the request query; Shadowrocket and sing-box-extended do the same.
- A Cloudflare Worker relay (edgetunnel) reads `proxyip` from the query; without it, Cloudflare-hosted destinations (x.com, claude.ai, www.cloudflare.com) failed with `502 Bad Gateway` after 20–60 s while other sites worked.
- Now the part of `path` after the first `?` is sent verbatim as the query; session, seq and padding query parameters are added on top of it. All modes and HTTP/1.1, HTTP/2, HTTP/3. Confirmed by the reporter on the relay. (SPEC 119)
- Launcher and LxBox link parsers strip the `?…` tail of an xhttp `path` on their side; fixes for both are prepared and ship with the client releases that bundle this core.

### 📡 hysteria2 over `detour` to MASQUE (WARP) was silent to an IPv6 server, worked to IPv4 (issue #37)

- quic-go inside hysteria2 sends 1280-byte UDP payloads: 1308-byte IP packets over IPv4, 1328 over IPv6 — neither fits the tunnel's `mtu` 1280, gvisor fragments them, and WARP passes IPv4 fragments but drops IPv6 ones. Measured on a clean link: with `mtu` 1280 at most 1232 bytes of payload pass over IPv6, with 1340 — at most 1280.
- Fixed by `lx.mtu_align` above: hysteria2 under WARP gets `initial_packet_size` 1232 (IPv6) / 1252 (IPv4) with PMTUD off. Verified on a bench with an IPv4 hysteria2 server (first 1280-byte packet right after the tunnel came up: 5/6 vs 0/5 before); the reporter's IPv6 server is to be confirmed.

### 🔁 `vhttp: auto` parked a WARP node on h2 until restart after one quick h3 failure

- About 25 % of h3 tunnel bring-ups to WARP fail at once with `PROTOCOL_VIOLATION (remote)` and succeed on retry. The mode memory treated that as "h3 failed, h2 won" and remembered h2 for good (until h2 itself failed).
- Now an h2 win is remembered for a window on a ladder — 1 s, 10 s, 30 s, 5 min, 10 min — one step per consecutive h2 win; an h3 win returns to the first step; bring-ups on the remembered h2 do not extend the window. One random failure costs one tunnel on h2; a permanently closed h3 converges to a probe every 10 min. (SPEC 121)

- Base: sing-box `v1.14.3`, zero drift from `upstream/stable`. No upstream files touched: new package `common/lxmtu`, `option/lx.go`, `box_lx.go`, `protocol/chain`, `protocol/masque`, `transport/masque/connectip`, `transport/v2rayxhttp`.

## 🆕 Что нового

### 📏 `lx.mtu_align` — одно выравнивание MTU и размера пакета по пути для `chain` и `detour`

- Узел над IP-туннелем — через `detour`, группу под `detour`, транзитивный `detour` или как звено `chain` — получает `mtu` (wireguard, masque) или `initial_packet_size` + `disable_path_mtu_discovery: true` (hysteria2, tuic, hysteria) под ёмкость узла снизу.
- Ёмкость считается рекурсивно по типу: туннель → его эффективный `mtu`; tailscale → `system_interface_mtu` или 1280; группа → минимум по членам на старте; узел с `detour` → транзитивно; прокси без уровня IP → без предела.
- Режимы `off` / `fill` / `clamp` (дефолт `clamp`: явные значения только понижаются; в `fill` явное значение, которое не влезает, даёт предупреждение) и `except` — теги без правок. Ключ принимает строку или `{"mode","except"}`.
- Через WARP по умолчанию hysteria2 получает 1232 (IPv6-сервер) / 1252 (IPv4), PMTUD off. Каждое изменённое поле — Info-строка `mtu_align: <tag> <field> → <effective> (<причина>)`, предупреждения — Warn.
- Прежде накладные вычитал только `chain` и только у туннелей; обычный `detour` не делал ничего, QUIC-прокси не выравнивались нигде. (SPEC 120)

## 🔧 Изменено

### 🚀 Внешний QUIC MASQUE стартует с `InitialPacketSize` = `mtu + 51` (кламп 1200…1452; 1331 при mtu 1280) вместо константы 1242

- quic-go считает бюджет датаграммы консервативно (`InitialPacketSize − 37`): при 1242 бюджет был 1205, а внутренний пакет 1280 байт с байтом context-id требует 1281. Бюджет рос только по PMTUD (первая проба через ~5 RTT после хендшейка), поэтому ~6 RTT после подъёма туннеля каждый внутренний пакет 1205…1280 байт отбивался `DatagramTooLarge` и пропадал.
- Берётся уже выровненный `mtu`, так что MASQUE под WireGuard получает согласованное значение.

### 📨 ICMP Packet Too Big от MASQUE называет фактический бюджет датаграммы

- Минус байт context-id, а не константу 1280; ниже 1280 не опускается (минимум IPv6).

## 🐛 Исправлено

### 🌐 XHTTP: `path` с query кодировался внутрь пути (issue #36)

- `"path": "/?proxyip=149.56.109.62"` уходил на провод как `/%3Fproxyip=149.56.109.62/`. Xray считает всё после первого `?` query запроса; так же делают Shadowrocket и sing-box-extended.
- Релей на Cloudflare Worker (edgetunnel) читает `proxyip` из query; без него сайты за Cloudflare (x.com, claude.ai, www.cloudflare.com) падали с `502 Bad Gateway` через 20–60 с, остальные работали.
- Теперь часть `path` после первого `?` уходит дословно как query; параметры сессии, seq и паддинга добавляются поверх. Все режимы и HTTP/1.1, HTTP/2, HTTP/3. Подтверждено автором репорта на релее. (SPEC 119)
- Парсеры ссылок лаунчера и LxBox срезают хвост `?…` у xhttp `path` на своей стороне; исправления для обоих подготовлены и выйдут с релизами клиентов на этом ядре.

### 📡 hysteria2 через `detour` на MASQUE (WARP) молчал на IPv6-сервер, работал на IPv4 (issue #37)

- quic-go внутри hysteria2 шлёт UDP-payload 1280 байт: по IPv4 это IP-пакет 1308 байт, по IPv6 — 1328; оба не влезают в `mtu` 1280 туннеля, gvisor режет их на фрагменты, WARP IPv4-фрагменты пропускает, IPv6-фрагменты теряет. Замер на чистом канале: при `mtu` 1280 по IPv6 проходит ≤ 1232 байт payload, при 1340 — ≤ 1280.
- Исправлено через `lx.mtu_align` выше: hysteria2 под WARP получает `initial_packet_size` 1232 (IPv6) / 1252 (IPv4) с PMTUD off. Проверено на стенде с IPv4-сервером hysteria2 (первый пакет 1280 байт сразу после подъёма туннеля: 5/6 против 0/5 до); IPv6-сервер автора репорта — впереди.

### 🔁 `vhttp: auto` после одного быстрого отказа h3 парковал узел WARP на h2 до рестарта

- Около 25 % подъёмов h3-туннеля к WARP падают сразу с `PROTOCOL_VIOLATION (remote)` и проходят повтором. Память режима считала это «h3 упал, h2 победил» и запоминала h2 насовсем (до отказа самого h2).
- Теперь победа h2 помнится на окно по лестнице — 1 с, 10 с, 30 с, 5 мин, 10 мин — ступень за каждую следующую победу h2; победа h3 возвращает на первую ступень; подъём по памяти окно не продлевает. Один случайный отказ стоит один туннель на h2; постоянно закрытый h3 сходится к пробе раз в 10 мин. (SPEC 121)
