Upstream sing-box fixes from 2026-09-29: stricter validation of incoming protocol data, correct UDP checksums from the TUN stack, and UDP reads on macOS that no longer spin after the peer is gone. The fork is back in sync with upstream `stable`. Configs are unchanged.

Исправления апстрима sing-box от 2026-09-29: строже проверка входящих данных протоколов, корректные контрольные суммы UDP из TUN-стека, чтение UDP на macOS без холостого цикла после ухода пира. Форк снова синхронен с апстримным `stable`. Конфиги не меняются.

## 🐛 Fixed

### 🛡️ Stricter validation of incoming protocol data

- Upstream added bounds and length checks for data coming from the network or from the TUN interface: the QUIC and TLS (JA3) sniffers, FakeIP, the TUN stack (DNS, ICMP ping, packet parsing), the gRPC-lite, HTTP and WebSocket transports, Shadowsocks multi-user, the OpenVPN and OpenConnect devices, and Tailscale DNS and Taildrop. Malformed input is rejected instead of being processed further.

### 📦 UDP checksum 0 from the TUN stack

- Was: when the computed UDP checksum happened to be exactly 0, the TUN stack wrote 0 into the header. For UDP over IPv4 that means "no checksum", and for IPv6 such a packet is invalid, so some systems dropped it.
- Now: such a checksum is written as `0xffff`, as the standard requires. Affects the `system` and `mixed` TUN stacks and GSO splitting.

### 🍏 macOS / BSD: connected UDP sockets

- Was: after the peer went away, a read from a connected UDP socket could return 0 bytes without an error, over and over.
- Now: this case is reported as the end of the connection, for outbound UDP connections and for WireGuard / AmneziaWG endpoints (a rebind is triggered).

## 🧰 Under the hood

- Synced with upstream `stable` (sing-box `v1.14.2` + 20 commits), drift 0. Our wireguard-go and sing-tun forks carry the new upstream commits under our changes.

## 🐛 Исправлено

### 🛡️ Строже проверка входящих данных протоколов

- Апстрим добавил проверки границ и длин для данных из сети и из TUN-интерфейса: снифферы QUIC и TLS (JA3), FakeIP, TUN-стек (DNS, ICMP ping, разбор пакетов), транспорты gRPC-lite, HTTP и WebSocket, многопользовательский Shadowsocks, устройства OpenVPN и OpenConnect, DNS и Taildrop у Tailscale. Некорректные данные отбрасываются, а не обрабатываются дальше.

### 📦 Контрольная сумма UDP, равная 0, из TUN-стека

- Было: если вычисленная контрольная сумма UDP оказывалась ровно 0, TUN-стек так и записывал 0 в заголовок. Для UDP поверх IPv4 это значит «суммы нет», а для IPv6 такой пакет недопустим, и часть систем его отбрасывала.
- Стало: такая сумма записывается как `0xffff`, как требует стандарт. Касается TUN-стеков `system` и `mixed` и разбиения GSO.

### 🍏 macOS / BSD: подключённые UDP-сокеты

- Было: после ухода пира чтение из подключённого UDP-сокета могло раз за разом возвращать 0 байт без ошибки.
- Стало: это считается концом соединения — для исходящих UDP-соединений и для эндпоинтов WireGuard / AmneziaWG (запускается перепривязка).

## 🧰 Под капотом

- Синк с апстримным `stable` (sing-box `v1.14.2` + 20 коммитов), дрейф 0. Наши форки wireguard-go и sing-tun несут новые апстримные коммиты под нашими правками.
