## 🐛 Fixed

### 💥 The tunnel could crash on start

Reported straight after `rc.5` shipped, with a crash dump from the device. The
tunnel died while bringing up a WireGuard endpoint — sometimes immediately,
sometimes only after a few attempts, which is what made it awkward: a restart
often "fixed" it, so the build looked healthy.

The cause was in how the previous release updated the WireGuard component. That
component had fallen fourteen commits behind what the rest of the code expected,
and only three of them were taken — the three the compiler complained about.
The eleven left behind included fixes for timing races and a rework of internal
locking: exactly the kind of change that compiles fine and passes tests, then
misbehaves under real traffic. The result was a combination that never existed
upstream.

This release takes the component whole and puts our own changes on top, rather
than the other way round. The AmneziaWG obfuscation, the transport padding and
the socket self-healing were all re-applied and verified against the new base.

The lesson has been written into our release procedure: a dependency is checked
by machine against the exact revision the build expects, and its history is
taken complete — never cherry-picked by what the compiler happens to notice.
