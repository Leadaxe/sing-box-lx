# sing-box-lx — outbound `chain`: цепочка хопов из групп и узлов

> EN: [lx-chain.md](lx-chain.md) · Фича: [CHAIN](../SPECS/FEATURES/015-CHAIN/FEATURE.md) · Задача: [SPEC 165](../SPECS/TASKS/165-CHAIN_DETOUR_REWRITE/SPEC.md)

Outbound `chain` строит многохоповый путь из существующих узлов и групп: вход, середину и выход
выбирает своя группа, а цепочка идёт за её выбором, не копируя узлы.

Build-тег `with_lx_chain` входит в десктопные `LX_TAGS` и в AAR. Без него `"type": "chain"`
отвергается при чтении конфига. Разбор — в [фиче CHAIN](../SPECS/FEATURES/015-CHAIN/FEATURE.md).

```json
{
  "type": "chain",
  "tag": "virtualisation",
  "outbounds": ["selector-in", "selector-mid", "selector-exit"],
  "rewrite": { "wireguard": { "mtu": 1200 } },
  "interrupt_exist_connections": false
}
```

Позиции в `outbounds` идут в порядке пакета. `outbounds[0]` — первый хоп от клиента: он касается
реальной сети и используется как есть, с его dial-полями. Последняя позиция — узел, чей адрес
видит цель. Запись через `detour` читается наоборот: там узел с `detour` — выход. Любая позиция
— узел, endpoint или группа любой вложенности. Все три формы работают одинаково, длина любая (≥
2):

```
["selector-in", "selector-mid", "selector-exit"]   // все группы
["node-in",     "node-mid",     "node-exit"]       // все узлы
["node-in",     "selector-mid", "node-exit"]       // смешанно
```

| Ключ | Тип | Дефолт | Смысл |
|------|-----|--------|-------|
| `outbounds` | список тегов, ≥ 2, все различны | обязательное | позиции в порядке пакета; повтор тега — ошибка загрузки, см. ниже |
| `rewrite` | карта тип → JSON-объект | `{}` | merge-patch ([RFC 7396](https://www.rfc-editor.org/rfc/rfc7396)) к конфигу каждого узла этого типа, который перехватывает позиция ≥ 1; `detour` менять нельзя |
| `interrupt_exist_connections` | bool | `false` | при переключении позиции рвать и пользовательские соединения через цепочку; соединения, которые узлы держат через хопы, рвутся всегда |

`idle_timeout`, `strip_evasion` и `strip` — не ключи цепочки: конфиг с любым из них не
загружается, и ошибка называет замену. Звеньев, которые надо держать живыми, нет, а что ядро
снимает с узла под `detour`, задаёт
[`lx.detour.strip`](lx-block.ru.md#lxdetour--что-ядро-делает-с-узлом-под-detour).

Теги в `outbounds` должны различаться: повтор валит загрузку с
`chain <tag>: duplicate outbound <tag> (position <i>): one node or group has one path`, потому что в списке, который читается как
путь, это почти всегда описка. Чтобы поставить один узел на несколько позиций намеренно, объявите
его отдельным тегом на каждую позицию; учётные данные в объявлениях могут совпадать. Так строится
«сэндвич» `WARP → чужой узел → WARP`: внешние слои прячут середину от вашего адреса, а цель — от
середины. Каждое объявление — отдельный узел со своим `detour`. У WireGuard-ключа на сервере одна
сессия, поэтому двум WireGuard-объявлениям нужны два ключа.

## Как собирается цепочка

Цепочка переписывает конфиг при загрузке, до создания узлов:

- добавляет в список исходящих хопы `<tag>#0 … <tag>#n−1`. Хоп — исходящий внутреннего типа
  `chain-hop` с полями `chain`, `position`, `outbound` (тег своей позиции) и, начиная с позиции 1,
  `below` (хоп позиции ниже). Хоп `i` дозванивается через позицию `i`; сама цепочка — через
  верхний хоп;
- каждому узлу, до которого доходит позиция `i ≥ 1`, ставит `detour` = `<tag>#<i−1>`. Доходит —
  это сама позиция, если она узел, или каждый лист группы на ней любой вложенности, выбранный или
  нет, кроме `direct` и `block`. Собственный `detour` узла перекрывается;
- затем к каждому перехваченному узлу применяет `rewrite` по его типу;
- позицию 0 не трогает: её узлы идут своими путями. Группы тоже не переписываются, только их
  листья; вся логика выбора остаётся у группы (ручной выбор, health-check, sticky, штрафы,
  `interrupt_exist_connections`).

У узла один экземпляр и один путь. Маршрут прямо на перехваченный узел тоже идёт путём цепочки, и
ручная проверка узла из UI — тоже. Группа на позиции ≥ 1 проверяет те самые экземпляры, что несут
её трафик: узел, мёртвый на пути цепочки, уходит из пула, даже если на своём `detour` он бы
работал. Апстрим не применяет опции сокета узла под `detour`, поэтому `bind_interface`,
`routing_mark`, `tcp_fast_open` и подобные у перехваченного узла не действуют, как под любым
`detour`; `GetOutboundConfig` показывает их записями `lx.detour`
([lx-block](lx-block.ru.md#что-detour-не-применяет)). `domain_resolver` продолжает действовать.

Хопы — обычные исходящие: они видны в списках исходящих (`GetOutbounds`, Clash API) с типом
`chain-hop`, и UI скрывает их по типу. Конфиг, где тип `chain-hop` объявлен вручную или тег хопа
занят своим исходящим, не загружается.

**Во время работы** хоп `i` дозванивается так:

| Позиция `i` | Куда идёт дозвон |
|---|---|
| узел | через узел, который доходит до своего сервера через `<tag>#<i−1>` |
| группа | через группу; выбранный ею член идёт своим `detour`, `<tag>#<i−1>` |
| `direct` на `i ≥ 1` — сама позиция или выбор группы на ней | в хоп ниже, `<tag>#<i−1>`: мимо нижних позиций трафик не уходит |
| выключена, `i ≥ 1` | в хоп ниже |
| выключена, `i = 0` | в сеть через прямой dialer ядра |
| `block` | отказ |

Если все позиции ≥ 1 — `direct`, цепочка равна позиции 0. `direct` в селекторе на позиции
выключает эту позицию на лету.

**Выключение позиции.** `SetChainPositionEnabled(chain, position, enabled)` выключает или включает
одну позицию без перезагрузки; допустима любая комбинация, а со всеми выключенными позициями
цепочка идёт напрямую. Набор выключенных хранится в `experimental.cache_file` по тегам позиций,
поэтому переживает перезапуск и правку конфига, которая сдвигает позиции. Переключение всегда рвёт
соединения, которые узлы держат через хопы; пользовательские соединения через цепочку — только с
`interrupt_exist_connections: true`.

## Что валит загрузку

`sing-box check` ловит то же самое. Ошибка называет цепочку, позицию и узел.

- Конфликт перезаписи: узел или группа нужны в двух местах — в двух цепочках, если хотя бы
  одно место — позиция ≥ 1 (вход одной и позиция другой тоже; общий вход двух цепочек —
  можно) или на двух позициях ≥ 1 одной цепочки, — через
  группы любой вложенности, по всем членам. Ошибка:
  `<tag> is needed on chain … position … and on chain … position …`. Для двух цепочек копируют
  группу и её узлы под другими тегами (WireGuard-узлам нужны другие ключи).
- Вложенный `chain` выше позиции 0 или позиция, которая содержит саму цепочку.
- Тип узла, который не умеет дозваниваться через `detour`.
- Узел на позиции ≥ 1 с фиксированным локальным портом: WireGuard `listen_port`, Tailscale
  `listen_port` / `relay_server_port`, OpenConnect `dtls_local_port`. Опции сокета — не ошибка:
  под `detour` они не действуют, как в апстриме.
- Кольцо — цикл `detour` через хоп: `[A, Dir{A, X}]` (A и на входе, и в группе выше) или
  `[A, N]`, где у `A` свой `detour: N`. Его ловит апстримная проверка порядка запуска:
  `circular outbound dependency` с тегами хопов `<tag>#<i>`.
- `rewrite`, который трогает `detour`; значение `rewrite`, которое не объект; патч, после которого
  в узле остаётся неизвестное поле.

## MTU, strip и запись изменений

- **MTU и размер пакета** перехваченных узлов выравнивает
  [`lx.detour.mtu_align`](lx-block.ru.md#lxdetourmtu_align--выравнивание-mtu-и-размера-пакета-по-пути),
  тот же механизм, что под обычным `detour`. `mtu` в конфиге узла означает «как у
  самостоятельного узла». Хоп несёт `min(позиция, хоп ниже)`: позиция может быть выключена или
  выбрать `direct`, и узел над хопом подходит в любом из этих состояний. Цепочка как цель `detour`
  несёт то же, что её верхний хоп. Над любым прокси (vless/trojan/ss/hysteria2/…) ничего не
  меняется. Режим и `except_outbounds` действуют на перехваченные узлы как на любые другие.
- **Фильтры strip.** Сама цепочка ничего не снимает. Перехваченный узел — узел с `detour`, и
  [`lx.detour.strip`](lx-block.ru.md#lxdetour--что-ядро-делает-с-узлом-под-detour) действует на
  него как на любой другой: на каждом рукопожатии, если под соединением нет сокета ядра, узел не
  режет ClientHello, не шлёт `tls.spoof`, не включает kTLS и не берёт движок `apple`. Контракты с
  сервером — `flow`, `obfs`, `shadowtls`, `plugin`, `udp_over_tcp`, `ech`, пути транспортов — не
  трогаются никогда.
- **Порядок** для перехваченного узла: `detour` → `rewrite` → MTU. Каждое изменённое поле — запись
  изменения. `GetOutboundConfig(tag)` отдаёт узел как написан (`original`), как собран
  (`effective`) и список `changes`, у каждой записи `by.type` — `chain`, `chain_rewrite`, `lx.detour` или
  `mtu_align`; применённые к `original`, они дают `effective`. `GetEffectiveConfig` отдаёт весь
  собранный конфиг вместе с хопами ([lx-observability.ru.md](lx-observability.ru.md)).

> ⚠️ С `lx.detour` по умолчанию перехваченный узел над позицией-прокси или туннелем не режет
> ClientHello. Это подходит для обычного случая, когда DPI стоит между вами и первым хопом. Если
> позиция 0 — домашний relay, а DPI стоит на границе (`["relay", "foreign-node"]`), разрез нужен
> на позиции 1: добавьте `foreign-node` в `lx.detour.except_outbounds`. Это выключает для узла и
> выравнивание MTU. Через relay разрез ждёт `fragment_fallback_delay` (500 мс) между кусками.

## Наблюдаемость

`detourList` соединения ([§8](lx-observability.ru.md)) показывает разрешённый путь.
`GetChainStatus(tag)` (CommandClient, gRPC lxd) и Clash API `/proxies/<tag>` → `chain` отдают
состояние по позициям: тег позиции, группа ли это, узел, в который она разрешается сейчас,
`transparent` (`direct` на позиции ≥ 1), `disabled` и ошибки дозвона позиции; плюс счётчики
дозвонов и ошибок цепочки. Ошибки дозвона называют позицию и хоп под ней:
`chain[virtualisation] #2 (warp-exit) via #1 (node-m): …`. Задержку по слоям меряет URLTest по
тегам хопов `<tag>#0`, `<tag>#1`, …; каждый тег меряет путь до своей позиции.

Известные границы: туннель над хопом без UDP падает при дозвоне, и ошибка называет обе позиции;
узел или группа принадлежит одной позиции одной цепочки; вложенный `chain` допустим только на
позиции 0.

Ещё два примера.

«Сэндвич» `WARP → чужой узел → WARP`: один узел на двух позициях объявлен двумя тегами с теми же
учётными данными.

```jsonc
{ "type": "chain", "tag": "sandwich", "outbounds": ["warp-in", "node-mid", "warp-out"] }
```

Домашний релей на позиции 0, DPI на границе: фрагментация ClientHello нужна на позиции 1, поэтому
выходной узел исключён из `lx.detour`.

```jsonc
{ "type": "chain", "tag": "via-home", "outbounds": ["relay", "foreign-node"] }
"lx": { "detour": { "except_outbounds": ["foreign-node"] } }
```
